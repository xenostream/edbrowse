## Stream Editing

아직 `sed` 프로그램에 대해서는 다루지 않았습니다. 이 프로그램은 화면 편집기가 아닌 줄 편집기일 뿐만 아니라, 한 단계 더 나아가 “비-대화형” 줄 편집기입니다. 이 프로그램은 스크립트로 편집할 때만 사용할 수 있습니다. 이 프로그램은(원본 문서에 따르면) 1978년에 `ed` 의 확장 기능으로 다음 세 가지 특정 용도를 위해 개발되었습니다.

- 대화형 편집으로 처리하기에 너무 큰 파일을 편집할 때
- 편집 명령어 순서가 너무 복잡해서 대화형 모드에서 편하게 입력하기 어려운 모든 크기의 파일을 편집할 때
- 입력을 한 번만 처리해서 여러 가지 “전역” 편집 기능을 효율적으로 수행할 때

이 모든 것은 여전히 sed를 사용해야 할 타당한 이유입니다. 하지만 이런 사례들은 이미 살펴본 `ex` 의 스크립트 기능을 통해 해결할 수 있습니다. 굳이 또 다른 편집기를 배울 필요가 있을까요?

한 가지 답은 세 번째 용도에 있습니다. sed는 스크립트와 함께 작동하도록 특별히 설계되었기 때문에, 비슷한 스크립트를 사용할 때 ex보다 상당히 빠릅니다. 또 다른 답은 sed가 편집 필터로 사용될 수 있는 독특한 기능에 있습니다. 즉, 데이터가 다른 프로그램으로 전달되는 파이프를 통과하는 동안 즉석에서 편집을 수행하는 프로그램입니다.

sed 프로그램은 ex에서 사용하는 구문과 매우 유사하므로 배우는 데 큰 어려움이 없습니다. 하지만 몇 가지 중요한 차이점이 있으므로, 숙련된 ed나 ex 사용자가 무턱대고 바로 시작하기에는 바람직하지 않습니다.

여기서는 sed를 범용 편집기가 아닌, 특정 작업을 수행하기 위한 도구로서 자세히 살펴보겠습니다. 따라서 모든 명령어를 다루지는 않고, ex 명령어와 현저히 다르거나 우리가 활용하고자 하는 특정 이점을 제공하는 명령어만 다룰 것입니다.

먼저, 사용법에 대해 간략히 설명하겠습니다. sed 명령어에는 두 가지 형식이 있습니다:

```bash
sed -e command editfiles
sed -f scriptfile editfiles
```

- 첫 번째 형식인 `-e` 를 사용하면 명령줄에서 바로 편집 명령을 지정할 수 있습니다. 같은 줄에 여러 개의 `-e` 옵션을 지정할 수도 있습니다.
- 두 번째 형식인 `-f` 를 사용하면 편집 명령이 포함된 스크립트의 이름을 지정합니다. 우리는 sed를 사용할 때 이 형식을 선호합니다.

또한 다음과 같이 여러 줄로 구성된 편집 스크립트 전체를 sed의 인수로 지정할 수도 있습니다:

```bash
sed ’
Editing script begins here
.
.
.
Editing script ends here’ editfiles
```

이 마지막 형식은 곧 보게 되겠지만, 셸 스크립트에서 특히 유용합니다. 하지만 이 형식은 대화형으로도 사용할 수 있습니다. Bourne 셸은 첫 번째 작은 따옴표를 감지하면 “다음 줄을 입력하라” 는 프롬프트를 표시합니다. 또한 세미콜론으로 구분해서 같은 줄에 여러 명령을 결합할 수도 있습니다:

```bash
sed -e ’command1; command2; ...’ editfiles
```

마지막으로 한 가지 더: `sed -e` 를 사용할 때는 표현식을 따옴표로 묶어야 합니다. 비록 이것이 꼭 필수적인 것은 아니지만, 나중에 심각한 문제를 예방할 수 있습니다. 다음 예제를 살펴보겠습니다.

```bash
$ sed -e s/thier/their own/g myfile
```

`s/thier/their own/g` 라는 표현식은 `-f` 옵션을 사용한 sed 스크립트에서는 올바르게 작동합니다. 하지만 명령줄에서 실행하면 “Command garbled” 라는 오류 메시지가 표시됩니다. 셸이 공백을 인자 간의 “구분자” 로 해석해서 명령 표현식을 `s/thier/their` 로 파싱하고, 줄의 나머지 부분을 `own/g` 와 `myfile` 이라는 두 개의 파일 이름으로 처리하기 때문입니다. `s` 명령에 닫는 슬래시(`/`)가 없기 때문에, sed는 오류를 보고하고 종료됩니다.


### Differences between ex and sed

sed와 ed, ex 같은 대화형 줄 편집기 간의 첫 번째 차이점은 줄을 지정하는 방식입니다. ex에서는 기본적으로 지정된 행에만 작업이 적용되므로, 여러 행을 지정하기 위해 `g` 와 같은 명령어가 존재합니다. 반면 sed 프로그램은 기본적으로 모든 행에 작동하므로, 특정 행을 제외할 수 있는 명령어가 필요합니다. sed 프로그램은 암묵적으로 전역적입니다. 

ex에서는 기본적으로 현재 행만 편집되며, 전역 편집을 하려면 명시적으로 요청하거나 편집하려는 특정 행을 지정해야 합니다. sed에서는 기본적으로 모든 줄을 편집하며, 줄 주소를 사용해서 편집 작업을 제한합니다.

예를 들어, 다음 형식의 명령을 해석하는 방식에서 ex와 sed의 차이를 살펴보겠습니다:

```bash
/pattern/s/oldstring/newstring/
```

ex에서 이는 `pattern` 과 일치하는 첫 번째 줄을 찾아, 해당 줄에서 지정된 치환을 수행함을 의미합니다. sed에서는 동일한 명령이 `pattern` 을 포함하는 모든 줄을 찾아내어 지정된 편집을 수행합니다. 다시 말해, sed에서 이 명령은 ex의 `global` 플래그와 동일하게 작동합니다:

```bash
g/pattern/s/oldstring/newstring/
```

sed와 ex 모두에서 다음과 같은 형식의 명령:

```bash
/pattern1/,/pattern2/command
```

는 `pattern1` 과 `pattern2` 사이의 모든 줄에 지정된 편집을 수행함을 의미합니다.

sed 스크립트에서 절대 행 번호 주소를 사용할 수는 있지만, sed는 스트림 내에서 “여러 파일을 한 번에 편집할 수 있는 기능을 가지고 있다” 는 점을 기억해야 합니다. 이런 경우, 행 번호는 각 파일마다 다시 시작되는 것이 아니라 전체 스트림에 걸쳐 연속적으로 부여됩니다.

주소 지정 방식의 특이점 외에도, sed가 “자동으로 표준 출력으로 결과를 기록한다!” 는 사실에 익숙해져야 합니다. 편집 결과를 출력하기 위해 별도의 (출력) 명령을 내릴 필요는 없으며, 오히려 출력을 중지하려면 명령줄 옵션을 사용해야 합니다.

이런 점을 명확히 하기 위해, 다소 인위적인 예시이긴 하지만 다음 예시를 살펴보겠습니다. 파일에 다음과 같은 세 줄이 포함되어 있습니다:

```bash
The files were writeable by thier owner, not by all.
The files were writeable by thier owner, not by all.
The files were writeable by thier owner, not by all.
```

다음과 같은 편집 스크립트(edscript 라는 파일)를 사용합니다:

```bash
/thier/s//their/
/writeable/s//writable/
1,$p
```

ex와 sed를 사용했을 때 나타나는 매우 다른 결과는 다음과 같습니다:

```bash
$ ex - junk < edscript
The files were writeable by their owner, not by all.
The files were writable by thier owner, not by all.
The files were writeable by thier owner, not by all.
$ sed -f edscript junk
The files were writable by their owner, not by all.
The files were writable by their owner, not by all.
The files were writable by their owner, not by all.
The files were writable by their owner, not by all.
The files were writable by their owner, not by all.
The files were writable by their owner, not by all.
```

수정 내용을 전역으로 적용하는 `g` 접두사가 없는 ex 명령어는 스크립트의 첫 번째 줄을 파일의 첫 번째 줄에 적용한 다음, 두 번째 줄로 넘어가 스크립트의 두 번째 줄을 적용합니다. 세 번째 줄에는 어떤 수정도 수행되지 않습니다. 버퍼의 내용은 스크립트의 마지막 줄에 의해 표준 출력으로 출력됩니다. 이는 ex에서 동일한 명령어를 수동으로 실행했을 때와 유사한 결과입니다.

반면 sed 명령어는 스크립트의 각 줄을 파일의 모든 줄에 적용한 다음, 그 결과를 표준 출력으로 보냅니다. 스크립트의 마지막 줄은 입력의 두 번째 사본을 표준 출력으로 출력합니다.

ex와 sed 모두에서 동일한 스크립트가 거의 동일하게 작동하지만, sed 스크립트는 다음과 같이 좀 더 간단하게 작성할 수 있습니다.

```bash
s/thier/their/
s/writeable/writable/
```

기본적으로 모든 줄에 편집이 적용되므로, 초기 패턴 주소를 생략하고 단순히 `s` 명령만 지정할 수 있습니다. 또한, 성가신 입력의 두 번째 사본을 출력했던 `print` 명령도 생략하고자 합니다.

또한 sed의 비-대화형 작동을 지원하는 몇 가지 특수 명령어가 추가되어 있습니다. 이 명령어들에 대해서는 나중에 자세히 다루겠습니다. 하지만 어떤 면에서는 익숙한 명령어보다 특수 명령어를 배우는 것이 좀 더 쉬울 수도 있습니다. 앞서 제시한 주의 사례는 겉보기에는 똑같아 보이는 명령어가 매우 다른 결과를 산출할 때 “혼란이 발생할 가능성이 있다!” 는 사실을 강조하기 위한 것이었습니다.


### Some Shell Scripts Using sed

처음으로 가장 먼저 접하게 될 sed 명령어는 `s` (또는 `substitute`)일 것입니다. 왜냐하면 sed의 고급 제어 구조에 대해 아무것도 몰라도 이 명령어를 곧바로 활용할 수 있기 때문입니다. 다른 sed 명령어를 하나도 배우지 않더라도 이번 섹션은 꼭 읽어보셔야 합니다. 이 명령어는 배우기 쉬울 뿐만 아니라 편집 능력을 크게 확장해 줄 것이기 때문입니다.

방금 설명한 제약 조건 내에서 `s` 명령어는 ex의 해당 명령어와 유사하게 작동합니다. sed를 사용하는 몇 가지 셸 스크립트를 살펴보겠습니다.

먼저, 많은 파일을 대대적으로 편집할 때는 처리 속도가 확실히 중요한 요소이므로, 앞서 ex를 사용해서 보여준 correct 스크립트를 다음과 같이 재작성할 수 있습니다.

```bash
for file in $*
do
    sed -f sedscr $file > $file.tmp
    mv $file.tmp $file
done
```

이 스크립트는 항상 sedscr 이라는 로컬 편집 스크립트를 찾아, correct 에 전달된 인자 목록에 있는 각 파일에 편집 내용을 적용합니다. sed는 작업 결과를 표준 출력으로 보내므로, 그 출력을 임시 파일에 저장한 다음, 다시 원본 파일로 옮겨줍니다.

사실, 이 방식에는 심각한 위험이 도사리고 있습니다! sed 스크립트에 오류가 있으면, sed는 아무런 출력도 생성하지 않고 중단됩니다. 그 결과, 임시 파일은 비어 있게 되며, 이 파일을 원본 파일에 다시 복사하면 사실상 원본 파일이 삭제되는 꼴이 됩니다.

이 문제를 방지하려면 correct 셸 스크립트에 다음과 같은 테스트를 포함시켜야 합니다:

```bash
for file in $*
do
    sed -f sedscr $file > $file.tmp
    if [ -s $file.tmp ]
    then
        mv $file.tmp $file
    else
        echo "Sed produced an empty file."
    fi
done
```

`[-s]` 테스트는 파일이 비어 있는지 여부를 확인합니다. 이는 스크립트를 편집할 때 매우 유용한 기능입니다.

sed를 사용하여 간단한 오류를 수정하는 또 다른 간단한 셸 스크립트를 만들 수 있습니다. 이 스크립트의 이름을 change 라고 하겠습니다:

```bash
sed -e "s/$1/$2/g" $3 > $3.tmp
if [ -s $3.tmp ]
then
    mv $3.tmp $3
else
    echo "Possible error using regular expression syntax."
```

이 스크립트는 세 번째 인수로 지정된 파일에서 첫 번째 인수를 두 번째 인수로 간단히 변경합니다.

```bash
$ change mispeling misspelling myfile
```

(실제 편집 스크립트는 우리가 제어하므로, 가장 가능성이 높은 오류는 처음 두 인수 중 하나에서 잘못된 정규 표현식 구문에서 발생할 수 있습니다. 따라서 오류 메시지의 문구를 변경했습니다).



### Integrating sed into format

sed가 진정한 스트림 편집기로서의 역할을 수행하며, 파이프라인 내에서 편집을 수행하는—파일에 기록하지 않는 편집을 수행하는—간단한 응용 프로그램을 살펴보겠습니다.

이 스크립트의 배경을 이해하기 위해, 잠시 조판에 대해 다시 살펴볼 필요가 있습니다. 타자기 같은 장치(CRT 포함)에서는 엠-대시가 일반적으로 하이픈 두 개(`--`)로 입력됩니다. 조판 시에는 이것이 하나의 긴 대시(`—`)로 인쇄됩니다. troff 프로그램은 엠-대시에 대한 특수 문자 이름을 제공하지만, 엠-대시가 필요할 때마다 파일에 `\(em` 을 입력하는 것은 불편합니다.

다음과 같은 sed 스크립트를 만들어

```bash
s/--/\\(em/g
```

포맷 스크립트에 직접 포함시킨다면 어떨까요? 그러면 엠-대시에 대해 전혀 걱정할 필요가 없습니다. sed가 자동으로 엠-대시를 삽입해 줄 테니까요. (“문자열 `\(em` 내의 백슬래시를 두 개로 써야 한다!” 는 점에 유의하십시오. 백슬래시는 troff 뿐만 아니라 sed에서도 의미를 가지기 때문에, sed에 의해 제거될 것이기 때문입니다.)

이제 포맷 스크립트는 다음과 같이 보일 수 있습니다:

```bash
eqn=""; pic=""; macros="ms"; col=""; roff="ditroff -Tlj"
sed="| sed -e ’s/--/\\(em/g’"
while [ $# -gt 0 ]
do
    case $1 in
        -E) eqn="| eqn";;
        -P) pic="| pic";;
        -N) roff="nroff"; col="| col"; sed="";;
        -*) options="$options $1";;
        *) if [ -f $1 ]; then
            files="$files $1"
           else echo "format: $1: file not found"; exit
           fi;;
    esac
    shift
done
eval "cat $files $sed | tbl $eqn $pic | $roff $options $col | lp"
```

(nroff에 `-N` 옵션을 설정해서 sed 변수를 `null` 로 설정했다는 점에 유의하십시오. 이는 troff 를 사용할 때만 이 변경을 적용하기 위함입니다).


### Excluding Lines from Editing

더 진행하기 전에, 스크립트가 완벽하게 작성되었는지 잠시 확인해 봅시다.

누군가 하이픈을 사용해서 가로선을 그리는 경우는 어떨까요? 우리는 하이픈이 세 개 이상 연속으로 나열된 줄은 편집 대상에서 제외하고 싶습니다. 이를 위해 `!` (하지 마세요!) 명령을 사용합니다:

```bash
/---/!s/--/\(em/g
```

이 구문을 이해하는 데 시간이 조금 걸릴 수 있습니다. 간단히 말해, “하이픈이 세 개 연속으로 포함된 줄을 발견하면 편집하지 마라!” 는 뜻입니다. sed 프로그램은 그 외의 모든 줄을 편집 대상으로 처리할 것입니다. (“`!` 명령은 `s` 명령에 적용되는 것이 아니라 패턴 일치에 적용된다!” 는 점을 이해하는 것이 중요합니다. 비록
이 경우, 명령어를 “--- 가 포함된 줄은 일치시키지 마라!” 라고 읽든 “--- 가 포함된 줄을 일치시키되 치환하지 마라!” 라고 읽든 결과가 같아 보일 수 있지만, sed가 인식하는 방식과 다르게 해석하면 매우 혼란스러워질 수 있는 다른 사례들도 있습니다).

또한, troff 구문인 `\ˆ` 를 사용해서 대시 끝과 앞뒤 단어 사이에 아주 작은 공백을 삽입함으로써 가독성을 더욱 높일 수도 있습니다. 이 구문은 1/12-em 크기의 공백을 생성합니다:

```bash
/---/!s/--/\\ˆ\\(em\\ˆ/g
```

알고 보니, 하이픈을 엠-대시로 바꾸는 것만이 조판 시 우리가 원할 수 있는 유일한 “미적 개선” 편집은 아닙니다. 예를 들어, 일부 레이저 프린터는 진정한 조판용 따옴표(`“` 와 `”` 같은 형태가`"` 와 `"` 와 대조적으로)가 없습니다. 이런 제한이 있는 출력 장치를 사용하는 경우, sed를 사용해서 각 큰따옴표 문자를 (문맥에 따라) 여는 작은따옴표나 닫는 작은따옴표 한 쌍으로 변경할 수 있으며, 이렇게 처리하면 조판 시 올바른 큰따옴표 모양이 나타납니다.

정규 표현식 구문을 사용해서 고려해야 할 개별 사례가 많기 때문에, 이 편집 작업은 상당히 까다롭습니다. 스크립트는 다음과 같이 작성해야 할 수 있습니다:

```bash
s/ˆ"/‘‘/
s/"$/’’/
s/"? /’’? /g
s/"?$/’’?/g
s/ "/ ‘‘/g
s/" /’’ /g
s/|——|"/|——|‘‘/g
s/"|——|/’’|——|/g
s/")/’’)/g
s/"]/’’]/g
s/("/(‘‘/g
s/\["/\[‘‘/g
s/";/’’;/g
s/":/’’:/g
s/,"/,’’/g
s/",/’’,/g
s/\."/.\\\&’’/g
s/"\./’’.\\\&/g
s/"\\ˆ\\(em/’’\\(em/g
s/\\(em\\ˆ"/\\(em‘‘/g
s/"\\(em/’’\\(em/g
s/\\(em"/\\(em‘‘/g
```

(이 목록은 `\([...]\)` 정규식 구문을 적절히 적용해서 줄일 수도 있지만, 효과를 위해 전체 형태로 표시했습니다. 기호 `|——|` 는 탭을 나타낸다는 점에 유의하십시오).


### Branching to Selective Parts of a Script

이와 같은 기술 서적에서는 일반적으로 각 문자가 실제로 표시되는 모습을 명확하게 보여주는 고정폭 글꼴로 예제를 제시하는 것이 바람직합니다. 고정폭 글꼴에서 사용되는 한 쌍의 작은 따옴표는 가변폭 글꼴에서 제대로 조판된 큰 따옴표와 전혀 비슷하게 보이지 않습니다. 요컨대, 앞서 보여준 대체 방식을 항상 적용하는 것이 바람직하지는 않습니다.

하지만 예제는 어떤 종류의 매크로 쌍(이 책에서 예를 들면 시작을 의미하는 .ES 와 끝을 의미하는 .EE 를 사용했습니다)으로 구분될 것이라고 가정할 수 있으며, 이를 제외의 기준으로 삼을 수 있습니다.

이를 수행하는 방법에는 두 가지가 있습니다:

- 앞서 했던 것처럼 `!` 명령을 사용합니다.
- `b` (branch) 명령을 사용해서 편집 스크립트의 일부를 건너뜁니다.

먼저 `!` 명령어를 사용하는 방법을 살펴보겠습니다.

각 줄에 `!` 명령어를 적용할 수 있습니다:

```bash
/ˆ\.ES/,/ˆ\.EE/!s/ˆ"/‘‘/
/ˆ\.ES/,/ˆ\.EE/!s/"$/’’/
/ˆ\.ES/,/ˆ\.EE/!s/"? /’’? /g
.
.
.
```

하지만 좀 더 나은 방법이 있을텐데... 실제로 있습니다. sed 프로그램은 명령을 그룹화하기 위한 흐름 제어 기호 `{` 와 `}` 를 지원합니다. 따라서 다음과 같이 간단히 작성하면 됩니다:

```bash
/ˆ\.ES/,/ˆ\.EE/!{
s/ˆ"/‘‘/
s/"$/’’/
s/"? /’’? /g
.
.
.
s/\\(em\\ˆ"/\\(em‘‘/g
s/"\\(em/’’\\(em/g
s/\\(em"/\\(em‘‘/g
}
```

중괄호로 묶인 모든 명령은 초기 패턴 주소에 따라 처리됩니다.

같은 작업을 수행할 수 있는 또 다른 방법이 있습니다. sed 프로그램의 `b` (branch) 명령을 사용하면 선택적으로 지정된 레이블이 붙은 스크립트 내의 다른 줄로 제어 흐름을 넘길 수 있습니다. 이 기능을 활용하면, 앞서 소개한 스크립트를 다음과 같이 작성할 수 있습니다:

```bash
/ˆ\.ES/,/ˆ\.EE/bend
s/ˆ"/‘‘/
s/"$/’’/
s/"? /’’? /g
.
.
.
s/\\(em\\ˆ"/\\(em‘‘/g
s/"\\(em/’’\\(em/g
s/\\(em"/\\(em‘‘/g
:end
```

라벨은 콜론(`:`) 뒤에 최대 8자의 문자로 구성됩니다. 라벨이 누락된 경우, `b` 명령어는 스크립트의 끝 부분으로 분기합니다. (현재 이 지점 이후에는 더 이상 내용이 없으므로, 이 경우는 실제로 라벨이 필요하지 않습니다. 이것이 앞으로 우리가 사용할 형식입니다.)

`b` 명령어는 스크립트 내의 흐름 제어를 위해 고안되었습니다. 이를 통해 특정 패턴과 일치하는 줄에만 적용되고 그 외에는 적용되지 않는 하위 스크립트를 만들 수 있습니다. 하지만 이 경우와 같이, 단일 레벨 스크립트의 동작에서 텍스트의 일부를 제외시키는 강력한 방법으로도 활용할 수 있습니다.

우리 용도에서 `b` 가 `!` 보다 갖는 장점은 피해야 할 “여러 조건을 좀 더 쉽게 지정할 수 있다!” 는 점입니다. `!` 기호는 단일 명령어에 적용될 수도 있고, 바로 뒤에 중괄호로 묶인 일련의 명령어에 적용될 수도 있습니다. 반면 `b` 명령어는 스크립트 내 이동에 대해 거의 무제한적인 제어권을 제공합니다.

예를 들어, 여러 매크로 패키지를 사용하는 경우, sed 스크립트를 적용하고 싶지 않은 텍스트를 둘러싸고 있는 매크로 쌍이 .ES 와 .EE 외에 더 있을 수 있습니다. 따라서 다음과 같이 작성할 수 있습니다.

```bash
/ˆ.ES/,/ˆ.EE/b
/ˆ.PS/,/ˆ.PE/b
/ˆ.G1/,/ˆ.G2/b
```

또한, 따옴표는 troff 고유의 주석 구문(`\"` 로 시작하는 주석)의 일부로 사용되므로, `.` 또는 `’` 로 시작하는 줄의 따옴표는 변경하지 않도록 처리해야 합니다:

```bash
/ˆ[.’]/b
```

sed가 어떻게 작동하는지 염두에 두지 않으면 이런 분기 구조가 어떻게 작동하는지 이해하기가 다소 어려울 수 있습니다.

1. sed는 파일의 각 줄을 한 줄씩 (패턴) 버퍼로 읽어들입니다.
2. 그런 다음 스크립트에 있는 모든 명령을 해당 한 줄에 적용한 후, 다음 줄로 넘어갑니다.

패턴 일치에 의존하는 분기가 발견되면, 이는 해당 패턴과 일치하는 줄이 버퍼로 읽어졌을 때, 분기 명령에 따라 스크립트의 해당 부분이 그 줄에 대해서는 건너뛰어짐을 의미합니다. 레이블이 사용된 경우 스크립트는 레이블에서 계속 진행되며, 레이블이 사용되지 않은 경우 스크립트는 사실상 그 줄에 대해서는 종료됩니다. 다음 줄이 버퍼로 읽어지면 스크립트는 다시 처음부터 시작됩니다.

앞서 본 예제는 파일에서 작지만 명확하게 구분된 부분을 sed 스크립트의 처리 대상에서 제외하는 방법을 보여주었습니다. 이와 반대되는 효과, 즉 sed 스크립트가 파일의 일부에만 영향을 미치고 나머지는 무시하도록 처리하려면, 원하는 편집 내용을 둘러싸는 패턴에 고정하면 됩니다.

예를 들어, .ES 및 .EE 매크로의 범위 내에서만 편집을 수행하고 다른 곳에서는 편집하지 않으려면 다음과 같이 처리할 수 있습니다.

```bash
/ˆ\.ES/,/ˆ\.EE/{
여기에 편집 명령어
}
```

스크립트가 상당히 복잡해서 좀 더 포괄적인 제외 방법을 원한다면, `!` 를 결합해서 분기 방향을 반대로 바꿀 수 있습니다.

```bash
/ˆ\.ES/,/ˆ\.EE/!b
```

스크립트의 첫 번째 줄이 입력의 각 줄에 적용될 때, 이는 다음과 같이 해석됩니다. 

“이 줄이 패턴과 일치합니까? 아니요? 스크립트의 끝으로 분기합니다. (즉, 입력의 다음 줄부터 다시 시작합니다.) 예? 스크립트의 다음 줄로 넘어가서 편집을 수행합니다.”


### Back to format

지금까지 sed를 사용해서 보여드린 편집 작업들은 매우 유용하므로, 이를 format 스크립트에 제대로 통합해야 합니다. 이제 단 한 번의 편집이 아닌 일련의 대규모 편집 작업을 수행하므로, `-e` 옵션을 사용하는 한 줄짜리 스크립트 대신 스크립트 파일을 통해 sed를 사용해야 합니다. 따라서 format 스크립트 내의 변수 할당문을 다음과 같이 변경하겠습니다.

```bash
sed="| sed -f /usr/local/cleanup.sed"
```

여기서 cleanup.sed 파일은 편집 명령어가 포함된 스크립트의 이름이며, `/usr/local` 은 일반적으로 접근 가능한 디렉터리라면 어디든 될 수 있습니다. 나중에 이 파일에 추가적인 서식 명령어를 더 추가할 예정입니다.


### Inserting Lines of Text

sed 프로그램은 ex나 vi와 마찬가지로 새로운 텍스트 줄을 삽입하는 명령어를 가지고 있습니다. `i` (insert) 명령어는 현재 줄 앞에 텍스트를 추가하고, `a` (append) 명령어는 현재 줄 뒤에 텍스트를 추가합니다. ex에서는 삽입 모드로 진입한 후, 원하는 만큼 텍스트를 입력할 수 있으며, 캐리지 리턴을 사용해서 줄을 나눌 수 있습니다.[^2] 

[^2]: 여기서 “캐리지 리턴” 과 “줄바꿈” 이라는 용어는 다소 느슨하게 사용되고 있습니다. 사실 이 둘은 ASCII 문자 집합에서 서로 다른 문자이며, 각각 `ˆM` (캐리지 리턴)과 `ˆJ` (줄바꿈)에 해당합니다. 이런 혼동이 발생하는 이유는 유닉스(UNIX)가 입력 시 캐리지 리턴 키로 생성된 캐리지 리턴(`ˆM`)을 줄바꿈(`ˆJ`)으로 변환하기 때문입니다. (즉, 파일을 편집할 때 캐리지 리턴을 입력하면 실제로 저장되는 것은 라인피드입니다.) 출력 시에는 라인피드가 두 문자로 매핑됩니다. 즉, 파일 내의 `ˆJ` 는 실제로 터미널에 캐리지 리턴/라인피드의 쌍(`ˆMˆJ`) 형태로 출력됩니다.

삽입 모드는 줄 시작 부분에 마침표를 입력한 직후 캐리지 리턴을 입력하면 종료됩니다. 반면 sed에서는 삽입하는 각 줄 끝에 백슬래시를 입력해야 합니다. 삽입 모드는 이런 방식으로 백슬래시로 “이스케이프” 되지 않은 첫 번째 줄바꿈 문자가 나타나면 종료됩니다. 예를 들어, 다음 sed 스크립트:

```bash
1a\
The backslash is a ubiquitous escape character used by\
many UNIX programs. Perhaps its most confusing appearance\
is at the end of a line, when it is used to "hide a\
newline." It appears to stand alone, when in fact it is\
followed by a nonprinting character-a newline.
```

이 sed 스크립트가 적용되는 파일에서 1번째 줄 다음에 예제에 표시된 5줄을 추가합니다. sed는 앞에 백슬래시가 붙지 않은 줄바꿈 문자를 만나면 삽입 작업은 5번째 줄에서 종료됩니다.


### A sed Script For Extracting Information From a File

sed의 `-n` (nocopy)옵션은 기본 출력 작업을 억제하고, 사용자가 `p` 명령어를 사용해서 명시적으로 요청한 출력만 표시하도록 처리합니다.

`p` 명령어는 두 가지 형태가 있습니다:

- 절대 출력 명령어로서. 예를 들어:

```bash
/pattern/p
```

는 `pattern` 과 일치하는 줄을 항상 출력합니다.

- 대체 명령어와 함께 사용하는 경우(플래그), 이 경우 실제로 대체가 이루어진 경우만 해당 줄이 출력됩니다. 예를 들어:

```bash
/pattern/s/oldstring/newstring/gp
```

는 `pattern` 이 포함된 줄이 발견되더라도 oldstring 이 newstring 으로 바뀌지 않은 경우는 출력되지 않습니다.

다음과 같은 형식의 줄:

```bash
s/oldstring/newstring/p
```

는 제한이 없어 파일 내의 모든 줄과 일치하지만, 성공적인 “치환 결과만 출력한다!” 는 점을 이해하면 이런 점은 훨씬 명확해집니다.

`p` 명령과 `sed -n` 옵션을 함께 사용하면, 단순히 단일 줄뿐만 아니라 좀 더 큰 텍스트 블록을 선택할 수 있는 `grep` 과 유사한 기능을 얻을 수 있습니다.

예를 들어, 다음의 축약된 예시 같이, 주제가 시작 제목과 고유한 종료 문자열로 구분되는 간단한 온라인 빠른 참조 문서를 만들 수 있습니다:

```bash
$ cat alcuin_online
.
.
.
Output Devices
Alcuin requires the use of a graphics device with at least
300 dpi resolution, and the ability to store at least
one-half page of graphics at that resolution ...
%%%%
.
.
.
Type Styles
There are a number of ornamental type styles available on
many typesetters. For example, many have an Old English
font. But no typesetter currently on the market has the
capability of Alcuin to create unique characters in the
style of medieval illuminated manuscripts.
%%%%
.
.
.
$
```

이 “전체 텍스트 데이터베이스” 의 항목을 표시하려면 다음과 같은 셸 프로그램 하나면 충분합니다:

```bash
pattern=$*
sed -n “/$pattern/,/%%%%/p” alcuin_online
```

(명령어에 전달된 전체 인자 목록(`$*`)이 `pattern` 변수에 할당되므로, 사용자는 따옴표를 입력하지 않고도 공백이 포함된 문자열을 입력할 수 있습니다).

좀 더 현실적인 예를 들어보겠습니다. 기존 패키지와 함께 사용할 매크로를 개발할 때, 현재 사용 중이거나 영향을 미칠까 우려되는 패키지의 매크로를 자주 참조해야 할 필요가 있을 수 있습니다. 물론, 편집기를 사용해서 파일 전체를 불러올 수도 있습니다. 하지만 작업을 좀 더 쉽게 처리하기 위해, sed를 사용해서 원하는 매크로 정의를 출력하는 간단한 셸 스크립트를 사용할 수 있습니다. 저희 시스템은 이 스크립트의 변형 버전을 사용하며, 이를 getmac 이라고 부릅니다:

```bash
mac="$2"
case $1 in
    -ms) file="/usr/lib/macros/tmac.s";;
    -ms) file="/usr/lib/macros/tmac.s";;
    -mm) file="/usr/lib/macros/mmt";;
    -man) file="/usr/lib/macros/an";;
esac
sed -n -e “/ˆ\.de *$mac/,/ˆ\.\.$/p” $file
done
```

이 스크립트에 대해 언급할 만한 몇 가지 사항이 있습니다. 

- 첫째, 매크로 이름은 `.de` 요청 명령과 공백으로 구분할 필요가 없습니다. ms 패키지는 공백을 사용하지만, mm 과 man 패키지는 사용하지 않습니다. 이것이 검색 패턴에 공백 뒤에 별표가 포함된 이유입니다(이 패턴은 0개 이상의 공백과 일치합니다).

- 둘째, 파일 전체가 출력되는 것을 방지하기 위해 sed의 `-n` 옵션을 사용합니다. 이제 일치하는 행, 즉 지정된 매크로 정의의 시작 부분(`.de *$mac`)부터 정의를 끝내는 `..` 까지의 행만 출력됩니다(정규 표현식을 처음 접하는 분이면, 정규 표현식 구문을 troff 및 셸 특수 문자와 구분하는 것이 다소 어려울 수 있지만, 이 스크립트는 sed를 제대로 활용하는 좋은 예시이므로 꼭 노력해 보시기 바랍니다. 여러분의 기술 레퍼토리에 추가하면 좋습니다).

이 스크립트는 처리 결과를 표준 출력으로 표시하지만, 파일로 쉽게 리디렉션할 수 있으며, 해당 파일은 여러분이 직접 재정의할 때 기초가 될 수 있습니다. 이 스크립트는 이후 장에서 유용하게 쓰일 것입니다.

sed를 사용해서 파일에서 정보를 추출(및 조작)하는 또 다른 예를 다음 스크립트에서 볼 수 있는데, 이 스크립트는 우리가 작성 중인 문서의 구조를 확인하는 데 주로 사용합니다.

이 스크립트는 troff 매크로(이 경우, 이 책을 서식화할 때 사용된 매크로)가 섹션을 구분하는 용도로 사용된다고 가정하며, 제목들을 출력합니다. 구조를 좀 더 명확하게 보여주기 위해, 이 스크립트는 섹션 매크로 자체를 제거하고, 제목을 들여쓰기된 개요 형식으로 출력합니다.

이제 sed가 수행할 작업은 세 가지입니다:

1. 챕터(.CH) 또는 섹션 제목(.H1 또는 .H2) 매크로로 시작하는 줄을 찾습니다.
2. 해당 줄에서 매크로를 텍스트로 대체합니다.
3. 해당 줄들만 출력합니다.

sed 스크립트 do.outline 은 명령줄에 지정된 모든 파일(`$*`)을 대상으로 작동합니다. 이 스크립트는 처리 결과를 표준 출력으로 표시하며 파일 자체는 어떤 변경도 가하지 않습니다.

```bash
sed -n ’/ˆ\.[CH][H12]/ {
    s/"//g
    s/ˆ\.CH /\
CHAPTER /
    s/ˆ\.H1/  A. /
    s/ˆ\.H2/  B. /
    p
}’ $*
```

sed 명령어는 `-n` 옵션을 사용해서 호출되며, 이 옵션은 줄의 자동 출력 기능을 억제합니다. 그런 다음 처리할 줄을 선택하는 패턴을 지정한 뒤, 여는 중괄호({)를 붙입니다. 이는 닫는 중괄호(})까지의 명령어 그룹이 해당 패턴과 일치하는 줄에만 적용됨을 의미합니다. 이 구문은 보기만큼 낯설지 않습니다. 

ex의 전역 정규 표현식을 사용하면 단 한 번의 치환만 수행할 경우(`g/ˆ\.[CH][H12]/s/"//g`)는 여기서도 작동할 수 있습니다. sed 명령어는 다음과 같은 여러 작업을 수행합니다:

1. 큰따옴표를 제거합니다.
2. 장 제목용 매크로를 줄바꿈(빈 줄을 만들기 위해)과 그 뒤에 ‘CHAPTER’ 라는 단어로 대체합니다.
3. 절 제목을 적절한 문자와 탭으로 들여쓰기된 형태로 대체합니다.
4. 해당 줄을 출력합니다.

do.outline 스크립트의 처리 결과는 다음과 같습니다:

```bash
$ do.outline ch13/sect1

CHAPTER 13 Let the Computer Do the Dirty Work
    A.   Shell Programming
    B.   Stored Commands
    B.   Passing Arguments to Shell Scripts
    B.   Conditional Execution
    B.   Discarding Used Arguments
    B.   Repetitive Execution
    B.   Setting Default Values
    B.   What We’ve Accomplished
```

이 명령은 일련의 파일이나 “챕터” 에 실행할 수 있으므로, 책 전체의 목차를 단 몇 초 만에 생성할 수 있습니다. 이 스크립트를 ms 또는 mm 섹션 제목 매크로에 맞게 수정하거나, C급 제목을 포함하도록 조정할 수도 있습니다.


### The Quit Command

`q` 명령을 사용하면 sed가 새로운 입력 줄을 더 이상 읽지 않으며(출력으로 보내는 것도 중단됩니다). 예를 들어 파일 앞부분만 편집하려면, 편집 대상인 마지막 줄만 유일하게 일치하는 패턴을 선택하고, 스크립트의 마지막 줄에 다음 명령을 포함시키면 됩니다:

```bash
/pattern/q
```

패턴과 일치하는 줄에 도달하면 스크립트는 즉시 종료됩니다.[^3]

[^3]: 수정 내용을 원본 파일에 다시 저장하는 프로그램(앞서 소개한 correct 셸 스크립트 같은)에서 `q` 명령을 절대 사용하지 않도록 각별히 주의해야 합니다. `q` 명령이 실행된 후에는 더 이상 출력이 발생하지 않습니다. 따라서 파일 앞부분만 편집하고 나머지 부분은 변경 없이 그대로 전달할 경우는 `q` 명령을 사용해서는 안 됩니다. 이런 상황에서 `q` 명령을 사용하는 것은 매우 위험한 초보자의 실수입니다.

이 명령은 파일의 특정 부분을 보호하는 데는 그다지 유용하지 않습니다. 하지만 복잡한 sed 스크립트와 함께 사용할 경우, 스크립트의 성능을 향상시키는 데 유용합니다. sed는 상당히 빠르지만, getmac 같은 애플리케이션은 sed가 찾는 대상을 이미 발견한 후에도 대용량 파일을 계속 스캔하는 데 약간의 비-효율이 발생합니다.

따라서, getmac 스크립트를 다음과 같이 다시 작성할 수 있습니다:

```bash
mac="$2"
case $1 in
    -ms) file="/usr/lib/macros/tmac.s";;
    -mm) file="/usr/lib/macros/mmt";;
    -man) file="/usr/lib/macros/an";;
esac
shift
sed -n "
/ˆ\.de *$mac/,/ˆ\.\./{
p
/ˆ\.\./q
}" $file
done
```

명령을 그룹화하면, sed가 우리가 찾고 있는 매크로의 끝에 도달할 때까지

```bash
/ˆ\.\./q
```

라는 줄이 실행되지 않게 됩니다. (이 줄만 있다면 첫 번째 매크로 정의가 끝나는 시점에 스크립트는 종료될 것입니다.) sed 프로그램은 그 자리에서 종료되며, 나머지 파일을 검색해서 다른 일치 항목을 찾지 않습니다.

매크로 정의 파일의 길이가 그리 길지 않고 스크립트 자체도 그리 복잡하지 않기 때문에, 이 버전의 스크립트로 인해 실제로 절약되는 시간은 미미합니다. 하지만 파일이 매우 크거나, 파일 일부만 적용해야 하는 복잡하고 여러 줄로 구성된 스크립트의 경우, 이 스크립트를 사용하면 상당한 시간을 절약할 수 있습니다.

예를 들어, 다음의 간단한 셸 프로그램은 sed를 사용해서 파일 맨 위의 10줄을 출력합니다(표준 UNIX head 프로그램과 매우 유사합니다):

```bash
for file
do
    sed 10q $file
done
```

이 예제는 다음과 같이 작성된 동일한 스크립트에 비해 성능이 획기적으로 향상되었음을 보여줍니다:

```bash
for file
do
    sed -n 1,10p $file
done
```


### Matching Patterns across Two Lines

줄 단위 편집기의 큰 약점 중 하나는, 변경 대상이 되는 “패턴이 한 줄 이상을 가로지르는 전역 변경에 대해 무력하다!” 는 점입니다.

최근 우리 작가 중 한 명이 작업 중이던 매뉴얼에서 예시를 하나 들어보겠습니다. 그 작성자는 메뉴 항목의 첫 글자를 박스 처리하기 위해 ms 패키지의 .BX 매크로를 사용했는데(나중에 보니 잘못된 처리 방식이었습니다), 이를 통해 사용자가 특정 명령에 도달하기 위해 선택해야 할 메뉴 선택 순서를 시각적으로 강조하려 했습니다. 예를 들면 다음과 같습니다.

```bash
[M] ain menu
[P] ortfolio commands
[E] valuate portfolios
[S] hock factors
```

그는 수많은 파일로 나뉜 메뉴 참조 문서를 작성했으며, 수백 개의 명령이 다음과 같이 하드 코딩되어 있었습니다.

```bash
.in 5n
.BX “\s-2M\s0”\c
ain menu
.in +5n
.BX “\s-2P\s0”\c
ortfolio commands
.in +5n
.BX “\s-2E\s0”\c
valuate portfolios
.in +5n
.BX “\s-2S\s0”\c
hock factors
.in 0
```

갑자기 작성자는 사용자가 이 키를 누를 필요가 없기 때문에 메인 메뉴(Main Menu)의 M 문자에 상자를 둘러서는 안 된다는 사실을 깨달았습니다. 그는 다음 줄에 “ain menu” 라는 문자열이 포함된 경우만 M 주위의 상자를 제거할 방법이 필요했습니다.

(troff 에 관한 부연 설명: `\c` 이스케이프 시퀀스는 다음 줄의 텍스트를 현재 줄로 가져옵니다. 예를 들어, 매크로의 인수가 채우기 과정에서 일반적으로 삽입되는 공백으로 인해 다음 줄의 첫 단어와 분리되는 것을 원치 않을 때 이 기능을 사용합니다. .BX 매크로는 이미 이런 경우를 대비해서, 두 번째 선택적 인자로 이어지는 텍스트를 제공할 수 있게 해준다는 사실은 이 예제와는 다소 무관합니다. 파일들은 여기에 표시된 대로 하드 코딩되어 있었고, 실수가 발생했으며, 수정해야 할 사례가 수백, 어쩌면 수천 건이나 있었습니다).

`N` 명령어를 사용하면 sed를 통해 이런 종류의 문제를 처리할 수 있습니다. 이 명령어는 패턴 일치 처리를 위해 현재 줄과 다음 줄을 일시적으로 “결합” 합니다. 결합된 줄에서 줄바꿈 위치는 `\n` 이스케이프 시퀀스로 지정할 수 있습니다. 따라서 이 경우, 다음 두 줄로 구성된 sed 스크립트를 사용하여 문제를 해결할 수 있습니다:

```bash
/.BX “\s-2M\s0”/N
s/.BX “\s-2M\s0”\c\nain Menu/Main Menu/
```

특정 패턴을 검색한 후, 해당 패턴을 찾으면 `N` 명령을 사용해서 다음 줄을 “추가” 합니다. 이제 다음 치환 작업은 결합된 줄에 적용됩니다.

이 해결책이 유용하기는 했지만, 입력에서 새 줄이 정확히 어디에 나올지 알고 있는 경우는 제한적입니다. 다행히 sed는 한 걸음 더 나아가, 새 줄이 어느 지점에서나 나타날 수 있는 여러 줄로 구성된 패턴을 조작할 수 있는 명령어를 제공합니다. 이제 이런 명령어들을 살펴보겠습니다.


### The Hold Space and the Pattern Space

다음 명령어 세트인 hold (`h` 또는 `H`), get (`g` 또는 `G`), exchange (`x`)는 이해하기 어려울 수 있는데, 특히 대부분의 유닉스 시스템에 포함된 난해한 설명서를 읽어본 적이 있다면 더욱 그렇습니다. sed의 작동 방식에 대해 이미 설명한 몇 가지 요점을 다시 짚어보는 비유를 들어보면 이해하는 데 도움될 것입니다.

sed의 작동 원리는, 다소 비유적으로 말하자면, 원고의 사본을 만들기 위해 고군분투하는 지극히 꼼꼼한 필사자나 서기라는 관점에서 설명할 수 있습니다. 

그의 작업은 몇 가지 공간적인 제약에 묶여 있습니다. 원본 원고는 한 방에 놓여 있고, 원고의 사본을 만들기 위한 일련의 지침은 중간 방에 보관되어 있으며, 깃펜, 잉크, 그리고 양피지는 또 다른 방에 준비되어 있습니다. 원본 원고와 편집 지침은 모두 돌에 새겨져 있어서 이동할 수 없습니다. 성실한 필사자는 정신보단 육체가 더 튼튼하기 때문에, 방을 오가면서 한 번에 한 줄씩만 작업함으로써 사본을 만들 수 있습니다. 

원본 원고가 있는 방에 들어서면, 그는 가운에서 종이 조각을 꺼내서 원고의 첫 줄을 적어 내려갑니다. 그런 다음 편집 지침 목록이 있는 방으로 이동합니다. 그는 각 지침을 읽어보며, 방금 적어 둔 한 줄에 해당되는지 확인합니다.

특별한 기호로 작성된 각 지시문은 ‘패턴’ 과 ‘절차’ 라는 두 부분으로 구성됩니다. 필사자는 첫 번째 지시문을 읽고, 그 패턴을 자신의 줄과 대조해서 확인합니다. 일치하는 부분이 없으면 절차에 대해 신경 쓸 필요가 없으므로 다음 지시문으로 넘어갑니다. 일치하는 부분을 발견하면, 필사자는 절차에 명시된 하나 또는 여러 가지 행동을 따릅니다.

그는 다음 지시문의 패턴과 일치시키려 시도하기 전에 자신의 종이에 수정을 가합니다. 기억하십시오. 필사자는 일련의 지시문을 모두 읽어야 하며, 패턴과 일치하는 첫 번째 지시문뿐만 아니라 모든 지시문을 읽습니다. 그는 진행하면서 수정을 가하기 때문에, 항상 최신 버전을 다음 패턴과 일치시키려 노력하며, 원래 문장은 기억하지 못합니다.

지시 사항 목록 맨 아래에 도달하고, 자신의 종이에 필요한 수정을 모두 마친 후, 그는 다음 방으로 가서 그 줄을 베껴 씁니다. (그 줄을 베껴 쓰라는 지시를 따로 받을 필요는 없습니다). 그 작업이 끝나면, 그는 첫 번째 방으로 돌아와서 새로운 종이 조각에 다음 줄을 적습니다. 두 번째 방으로 갈 때, 그는 다시 한번 떠나기 전에 모든 지침을 처음부터 끝까지 읽습니다.

이것이 그가 평소에 처리하는 방식입니다. 물론, 다른 지시를 받지 않는 한 말입니다. 예를 들어, 시작하기 전에 모든 줄을 출력하지 말라는 지시(`-n` 옵션)를 받을 수 있습니다. 이 경우, 그는 출력하라는 지시(`p`)가 나올 때까지 기다려야 합니다. 만약 그런 지시를 받지 못하면, 그는 종이 한 장을 버리고 다시 시작합니다. 참고로,
줄을 적으라는 지시를 받았는지 여부와 관계없이, 그는 항상 목록의 마지막 지시어까지 처리합니다.

이제 필사자가 해석해야 하는 다른 종류의 지시어들을 살펴보겠습니다. 우선, 지시어에는 패턴이 0개, 1개, 또는 2개 지정될 수 있습니다:

- 패턴이 지정되지 않은 경우, 각 줄에 대해 동일한 절차가 수행됩니다.
- 패턴이 하나만 지정된 경우, 해당 패턴과 일치하는 모든 줄에 대해 절차를 따릅니다.
- 패턴 뒤에 `!` 가 따라오면, 해당 패턴과 일치하지 않는 모든 줄에 대해 절차를 따릅니다.
- 두 개의 패턴이 지정된 경우, 절차에 설명된 작업은 첫 번째 일치하는 줄과 두 번째 패턴과 일치하는 줄이 나올 때까지 이어지는 모든 줄에 대해 수행됩니다.

필사자는 한 번에 한 줄만 처리할 수 있으므로, 여러 줄로 이루어진 범위를 어떻게 처리하는지 궁금할 수 있습니다. 매번 지시 사항을 검토할 때마다, 그는 두 가지 패턴 중 첫 번째 패턴과 일치하는 줄만 찾으려고 시도합니다. 이제 첫 번째 패턴과 일치하는 줄을 찾은 후, 새로운 줄을 처리할 때마다 두 번째 패턴과 일치시키려 시도합니다. 그는 두 번째 패턴을 `pattern!` 으로 해석하므로, 일치하는 부분이 없을 때만 해당 절차가 수행됩니다. 두 번째 패턴이 일치하면, 그는 다시 첫 번째 패턴을 찾기 시작합니다.

각 절차에는 하나 이상의 명령어나 동작이 포함됩니다. 기억하십시오. 절차에 패턴이 지정된 경우, 절차가 실행되기 전에 해당 패턴이 일치해야 합니다. 우리는 이미 다른 편집 명령과 유사한 일반적인 명령들을 많이 살펴봤습니다. 하지만, 매우 특이한 명령들도 몇 가지 있습니다. 예를 들어, 

- `N` 명령어는 필사자에게 당장 돌아가서 다른 줄을 가져와서 같은 종이에 추가하라고 지시합니다. 필사자에게 하나의 메모지를 “보관” 하라는 지시를 내릴 수도 있습니다. 
- `h` 명령어는 그에게 다른 종이에 그 줄을 복사해서 주머니에 넣으라고 지시합니다. 
- `x` 명령어는 그에게 주머니에 있는 여분의 종이와 손에 들고 있는 종이를 바꾸라고 지시합니다. 
- `g` 명령어는 그에게 손에 들고 있는 종이를 버리고 주머니에 있는 종이로 교체하라고 지시합니다. 
- `G` 명령어는 그가 들고 있는 줄을 눈 앞에 있는 종이에 추가하라고 지시합니다. 
- `d` 명령어를 만나면, 그는 그 종이 조각을 버리고 지시 목록의 맨 위에서 다시 시작합니다. 
- `D` 명령어는 그가 종이에 두 줄을 추가하라는 지시를 받았을 때만 효력을 발휘합니다. D 명령은 그에게 그 두 줄 중 첫 번째 줄을 삭제하라고 지시합니다.

이 비유를 컴퓨터 용어로 다시 환원하면, 이 중 저택의 첫 번째와 마지막 방은 “표준 입력” 과 “표준 출력” 입니다. 따라서 원본 파일은 절대 변경되지 않습니다. 필사자의 종이 조각에 적힌 줄은 “패턴 공간” 에 있고, 주머니에 넣고 있는 종이 조각에 적힌 줄은 “보관 공간” 에 있습니다. 보관 공간을 사용하면 패턴 공간에 있는 원본을 변경하는 동안에도 해당 줄의 복사본을 유지할 수 있습니다. 

이제 두 줄에 걸쳐 있을 수도 있는 특정 구문을 검색하는 sed 프로그램이라는 실제 적용 사례를 살펴보겠습니다.

정규 표현식이 아무리 강력하더라도 한 가지 한계가 있습니다. 바로 “두 줄에 걸쳐 있는 구문은 일치하지 않는다!” 는 점입니다. 앞서 살펴본 것 같이, 줄바꿈을 지정할 수는 있지만, 그 줄바꿈이 어떤 두 단어 사이에 있을지 정확히 알아야 합니다. sed를 사용하면 두 줄에 걸쳐 범용적인 패턴 일치 처리를 위한 명령어를 작성할 수 있습니다.

```bash
N
h
s/ *\n/ /
/패턴 매칭 구문/{
g
p
d
}
g
D
```

이 sed 스크립트는 입력 파일에서 ‘패턴 매칭 구문’ 이라는 문구가 두 줄에 걸쳐 있더라도 이를 인식합니다.

패턴 공간과 홀드 공간이 이를 어떻게 처리하는지 살펴보겠습니다.

처음에는 패턴 공간에 한 줄이 있습니다. 첫 번째 작업(`N`)은 또 다른 줄을 가져와서 첫 번째 줄 뒤에 추가하는 것입니다. 이렇게 하면 검토할 줄이 두 개가 되지만, 제거해야 할 내장된 줄바꿈 문자가 있습니다(그렇지 않으면 줄바꿈이 패턴 어느 위치에 올지 알아야 하기 때문입니다). 그 전에, 패턴 공간의 내용을 홀드 공간으로 복사(`h`)해서 줄바꿈 문자가 포함된 사본을 확보합니다.

그런 다음, 삽입된 줄바꿈 문자(`\n`)와 그 앞에 있을 수 있는 공백을 단일 공백으로 대체합니다. (sed 명령어는 패턴 공간에서 줄을 종료할 때 줄바꿈 문자를 제거하지 않습니다).

이제 해당 구문을 패턴 공간의 내용과 대조합니다. 일치하는 부분이 있으면, 줄바꿈 문자가 그대로 포함된 복사본을 홀드 공간에서 불러와서(`g`) 출력합니다(`p`). `d` 명령어는 제어권을 명령어 목록의 맨 위로 되돌려, 패턴 공간에 다른 줄이 읽히도록 처리합니다. 이는 (원래 sed 문서의 표현을 빌리자면) “삭제된 줄의 잔해” 에 대해서는 더 이상 편집을 시도하지 않기 때문입니다. 

반대로 일치하는 부분이 없다면, 홀드 버퍼의 내용은 패턴 공간의 내용으로 대체(`g`)됩니다. 이제 패턴 공간에는 줄바꿈으로 구분된 원본 두 줄이 들어 있습니다. 이 중 첫 번째 줄은 버리고, 두 번째 줄은 다음 줄과 짝을 이루도록 유지하고자 합니다. `D` 명령어는 줄바꿈까지의 패턴 영역을 삭제하고, 다음 줄을 추가하기 위해 맨 위로 되돌려줍니다.

이 스크립트는 sed에서 흐름 제어의 한계를 보여줍니다. 입력의 첫 번째 줄이 읽힌 후, `N` 액션이 모든 입력을 처리합니다. 또한, `d` 와 `D` 명령을 사용해서 명령어 목록의 맨 아래에 도달하지 않도록 함으로써, sed는 (`-n` 옵션과 상관없이) 해당 줄을 자동으로 출력하지도 않고 패턴 공간을 지우지도 않습니다.

앞서 예로든 비유로 돌아가면, 필사자가 두 번째 방에 들어간 후에도 원고에서 읽을 줄이 남아 있는 한, 항상 다음에 어떤 방으로 가야하는지, 또 다른 줄을 가져와야 하는지 아니면 그 줄을 써내려가야 하는지를 지시하는 명령이 계속 내려집니다.

앞서 강조했듯이, 스크립트는 언제든지 다듬어 동작 방식을 개선하거나 기능을 추가할 수 있습니다. 하지만 이 스크립트의 작동 방식에 세 가지 문제가 있습니다. 

- 첫째이자 가장 중요한 점은, 특정 문자열을 검색하도록 설정되어 있으므로 충분히 “일반적이지 않다!” 는 것입니다. 이 sed 프로그램을 기반으로 셸 스크립트를 작성하면 이 문제를 해결할 수 있습니다. 

- 둘째, 이 프로그램은 sed의 “흐름” 을 따르지 않습니다. `b` (branch) 명령어를 사용해서 재작성하면, sed가 명령어 목록의 끝까지 도달했을 때 sed의 기본 동작을 활용할 수 있습니다.

- 마지막으로, 이 프로그램은 검색 문자열이 입력의 한 줄에서 전체적으로 발견된 경우도 항상 일치하는 줄을 쌍으로 출력합니다. 입력의 각 새 줄이 이전 줄과 쌍을 이루기 전에 패턴과 일치하는지 확인해야 합니다.

다음은 ‘phrase’ 라고 불리는 이 sed 스크립트의 일반화된 버전으로, 검색 문자열을 따옴표로 묶은 첫 번째 인수로 지정할 수 있게 해줍니다. 추가적인 명령줄 인수는 파일 이름을 나타냅니다.

```bash
search=$1
shift
for file
do
    sed ’
    /’"$search"’/b
    N
    h
    s/.*\n//
    /’"$search"’/b
    g
    s/ *\n/ /
    /’"$search"’/ {
    g
    b
    }
    g
    D’ $file
done
```

셸 변수를 통해 명령줄의 첫 번째 인수를 검색 문자열로 정의합니다. 이제 sed 프로그램은 세 군데에서 검색 문자열과 일치하는지 확인합니다. 표준 입력에서 읽은 새 줄에서 검색 문자열이 발견되면 해당 줄이 출력됩니다. `b` 명령어를 사용해서 목록의 맨 아래로 이동하며, sed는 해당 줄을 출력하고 패턴 공간을 지웁니다. 

해당 한 줄에 패턴이 포함되어 있지 않으면, 다음 입력 줄이 패턴 공간에 추가됩니다. 이제 이 줄 자체가 검색 문자열과 일치할 가능성이 있습니다. 우리는
(패턴 공간을 홀드 공간으로 복사한 후) 내장된 줄바꿈까지의 이전 줄을 제거해서 이를 확인합니다. 

일치하는 부분이 발견되면, 제어 흐름은 목록의 맨 아래로 이동하고 해당 줄이 출력됩니다. 일치하는 항목이 없으면, 홀드 공간에 저장된 중복 항목의 사본을 가져옵니다. 이제 이전 버전과 마찬가지로, 내장된 줄바꿈 문자를 제거하고 패턴에 대한 일치를 확인합니다. 일치하는 항목이 발견되면, 해당 ‘Let the Computer Do the Dirty Work 303’ 두 줄을 출력하고자 합니다. 따라서 줄바꿈 문자가 포함된 중복 항목의 또 다른 사본을 가져오고, 제어권은 스크립트의 맨
아래로 넘어갑니다. 

일치하는 항목이 발견되지 않으면, 중복된 줄을 가져와서 그 앞부분을 제거합니다. 삭제 작업으로 인해 제어권이 맨 위로 돌아가며, 그곳에서 `N` 명령을 통해 다음 줄이 이전 줄 뒤에 추가됩니다.

이 섹션에 프로그램을 실행했을 때의 결과는 다음과 같습니다:

```bash
$ phrase “the procedure is followed” sect3
If a pattern is followed by a \f(CW!\fP, then the procedure
is followed for all lines that do \fInot\fP match the
so that the procedure is followed only if there is
```

### In Conclusion

여기에 제시된 예시들은 sed의 고급 명령어가 지닌 강력한 기능의 겉핥기 수준에 불과합니다. 예를 들어, hold 명령어의 `H` 변형 명령어는 hold 공간의 초기 내용을 덮어쓰는 대신, 일치하는 줄을 hold 공간에 추가합니다. 마찬가지로, get 명령어의 `G` 변형 명령어는 현재 줄을 대체하는 대신 hold 공간의 내용을
현재 줄 끝에 추가합니다. `X` 명령어는 패턴 공간의 내용을 홀드 공간의 내용과 서로 바꿉니다. 짐작하시겠지만, 이런 명령어들은 복잡한 편집 작업을 수행하는 데 매우 강력한 기능을 제공합니다.

하지만 sed를 사용하기 위해 “sed에 대한 모든 것을 이해할 필요는 없다” 는 점을 기억하는 것이 중요합니다. 앞서 살펴본 것 같이, sed는 다재다능한 편집기로, 초보자가 대량의 파일에 간단한 전역 편집을 수행하는 데 추천할 만큼 빠르면서도, 일반 편집기로는 감히 시도조차 할 수 없을 법한 작업도 처리할 수 있을 만큼 복잡합니다.

구문은 숙련된 컴퓨터 사용자조차 복잡하게 느껴질 수 있지만, sed에는 흐름 제어 메커니즘이 있어, 약간의 고민과 실험을 거치면 편집 프로그램을 설계할 수 있습니다. 파일의 특정 부분에 서로 다른 작업을 수행하고, 특정 조건이 충족되면 종료되는, 라벨을 통해 분기되는 편집 “서브루틴” 을 포함하는 sed 스크립트를 상상하는 것은 쉽습니다(비록 실행하기는 좀 더 어렵겠지만...).

우리 중 그 정도까지 나아가는 사람은 거의 없겠지만, 이 도구의 활용 범위를 이해하는 것은 중요합니다. 끝없이 반복적인 작업을 수 시간 동안 해야만 해결할 수 있는 까다로운 과제에 직면했을 때, 어느 순간 자기도 모르게 이렇게 말하게 될지 누가 알겠습니까?
