# Stream Editing

아직까지 `sed` 프로그램을 살펴보지 않았다. sed는 화면 기반 편집기가 아니라 줄 기반 편집기일 뿐만 아니라, 한 단계 더 나아가 비-대화형(*non-interactive*) 줄 편집기이다. 따라서 스크립트로 사용할 수 있다. sed는 1978년 ed의 확장으로 개발됐으며, 원래 문서에 따르면 다음 세 가지 특수한 경우를 위해 만들어졌다:

- 대화형 편집으로 처리하기에 불편할 정도로 큰 파일을 편집하기 위해
- 대화형 모드로 입력하기에 너무 복잡한 편집 명령을 가진 어떤 크기의 파일을 편집하기 위해
- 입력을 한 번만 통과하면서 여러 “전역” 편집 기능을 효율적으로 수행하기 위해

이 모든 이유는 여전히 sed를 사용하는 좋은 이유이다. 하지만 이미 살펴본 ex 스크립팅 기능으로 충분히 해결할 수 있다. 그렇다면 왜 또 다른 편집기를 배워야 할까?

해답은 바로 세 번째 항목에 있다. sed는 스크립트와 함께 작동하도록 특별히 설계됐기 때문에, 스크립트로 사용할 경우 ex 보다 훨씬 빠르다. 또 다른 답은 sed만의 독특한 처리 기능에 있다. sed는 편집 필터(*filter*) 로 사용할 수 있는 프로그램이다.

> [!NOTE]
> sed는 데이터가 다른 프로그램으로 전달되는 파이프로 지나가는 동안 실시간으로 편집을 수행한다.

sed 프로그램은 ex 편집기와 유사한 구문을 사용하므로 배우기 어렵지 않다. 하지만 몇 가지 중요한 차이점도 있으므로 ed 나 ex 에 익숙한 사용자가 아무 생각없이 사용하는 것은 바람직하지 않다.

여기서는 sed를 범용 텍스트 편집기가 아니라, 특정 작업을 수행하기 위한 “도구” 로 자세히 살펴볼 것이다. 따라서 모든 명령을 다루지 않고, ex 와 다른 명령이나 특정한 이점을 제공하는 명령만 다룰 것이다.

먼저 사용법에 대한 간단한 설명이다. sed 명령은 두 가지 형태가 있다:

```
sed -e command editfiles
sed -f scriptfile editfiles
```

- 첫 번째 형태인 `-e` 옵션을 사용하면 편집 명령을 명령줄에서 직접 지정할 수 있다. 여러 개의 `-e` 옵션을 같은 줄에 지정할 수 있다.

- 두 번째 형태인 `-f` 옵션을 사용하면 편집 명령을 포함한 스크립트 파일 이름을 지정한다. sed를 사용할 때 이 형태를 사용하는 것을 선호한다.

또한 여러 줄의 스크립트를 시스템 쉘에서 sed에 인자로 지정할 수 있다. 예를 들면 다음과 같다:

```
sed ’ 
편집 스크립트 시작
. 
. 
. 
편집 스크립트 끝’ editfiles
```

이 형태는 쉘 스크립트에서 유용하며, 곧 살펴볼 것이다. 위의 명령은 대화형으로 사용할 수 있다. Bourne 쉘은 첫 번째 작은따옴표를 인식하면 계속 줄을 입력하라고 2차 프롬프트(`$PS2`)를 표시한다.

또한 여러 명령을 같은 줄에서 세미콜론 문자로 구분해서 결합할 수 있다:

```
sed -e ’command1; command2; ...’ editfiles
```

마지막으로 한 가지 더하면 `sed -e` 를 사용할 때는 표현식을 따옴표 문자로 감싸야 한다. 반드시 필요한 것은 아니지만, 나중에 발생할 수 있는 심각한 문제를 피할 수 있다.

다음과 같은 예를 살펴보자:

```
$ sed -e s/thier/their own/g myfile
```

표현식 `s/thier/their own/g` 는 `-f` 옵션으로 사용하는 sed 스크립트에선 제대로 작동한다. 하지만 명령줄에선 “Command garbled” 오류 메시지가 나타난다. 이것은 쉘에서 공백 문자를 인자의 “구분자” 로 해석하고, 표현식을 `s/thier/their` 로 파싱하면서 나머지는 두 개의 파일 이름인 `own/g` 와 `myfile` 로 처리하기 때문이다. 또한 `s` 명령에 닫는 `/` 문자가 없으므로 sed는 오류 메세지를 표시하고 종료한다.


## Differences between ex and sed

sed 와 ed, ex 같은 대화형 줄 편집기와 차이점은 “줄(주소)을 지정하는 방식” 이다.

ex 는 기본적으로 특정 줄만 영향을 받으며, 여러 줄을 지정하기 위한 `g` 같은 명령이 존재한다. 반면 sed는 “기본적으로 모든 줄에 작동” 하므로, 오히려 선택한 줄을 건너뛰기 위한 명령이 필요하다. 즉, sed는 암묵적으로 “전역적” 이다. 

ex 는 현재 줄(*current line*)을 편집하는 것이 기본이며, 전역 편집을 처리하려면 명시적으로 요청하거나 편집할 특정 줄을 명시적으로 지정해야 한다. sed는 “모든 줄을 편집하는 것이 기본” 이며, “줄 주소는 편집 작업의 범위를 제한” 하는 용도로 사용된다.

예를 들어, 다음과 같은 형식의 명령을 ex 와 sed 가 어떻게 해석하는지 비교해보자:

```
/pattern/s/oldstring/newstring/
```

- ex 는 *pattern* 과 일치하는 첫 번째 줄을 찾고 그 줄에 지정한 치환 작업을 수행한다. 

- sed 는 *pattern* 과 일치하는 모든 줄과 일치하며, 지정한 치환 작업을 수행한다. 즉, sed는 ex 의 전역 플래그(`g`)와 동일하게 작동한다:

```
g/pattern/s/oldstring/newstring/
```

sed 와 ex 모두 다음과 같은 형식의 명령:

```
/pattern1/,/pattern2/command
```

은 *pattern1* 과 *pattern2* 사이의 모든 줄에 지정한 편집 작업을 수행한다는 뜻이다.

sed 스크립트에 (절대) 줄 번호 주소를 사용할 수 있지만, sed 는 “여러 파일을 하나의 스트림으로 편집한다!” 는 점을 기억해야 한다. 이런 경우 줄 번호는 전체 스트림에 연속으로 이어지며, 각 파일마다 다시 시작하지 않는다.

주소 지정 방식 외에도 sed 는 “자동으로 표준 출력에 결과를 쓰는 점” 도 익숙해져야 한다. 따라서 편집 결과를 출력하기 위해 출력 명령을 사용할 필요가 없으며, 오히려 출력을 억제하기 위해 명령줄 옵션을 사용해야 한다.

이런 점을 명확히 하기 위해 다음과 같은 인위적인 예를 살펴보자. 파일에 다음과 같은 세 줄이 포함되어 있다:

```
The files were writeable by thier owner, not by all.
The files were writeable by thier owner, not by all.
The files were writeable by thier owner, not by all.
```

다음과 같은 편집 스크립트(*edscript*)를 사용한다:

```
/thier/s//their/
/writeable/s//writable/
1,$p
```

ex 와 sed 의 처리 결과는 많이 다르다!!:

```
$ ex - junk < edscript
The files were writeable by their owner, not by all.
The files were writable by thier owner, not by all.
The files were writeable by thier owner, not by all.

$ sed -f edscript junk
The files were writable by their owner, not by all.
The files were writable by their owner, not by all. 
The files were writable by their owner, not by all. 
The files were writable by their owner, not by all. 
The files were writable by their owner, not by all. 
The files were writable by their owner, not by all.
```

ex 는 `g` 접두어 명령이 없으면 전역 편집을 수행하지 않기 때문에, 스크립트의 첫 번째 줄은 대상 파일의 첫 번째 줄에 적용하고, 두 번째 줄은 스크립트의 두 번째 줄을 적용한다. 세 번째 줄은 아무런 편집 작업도 수행되지 않는다. 스크립트의 마지막 줄은 버퍼의 내용을 표준 출력으로 출력한다. 이는 ex 에서 동일한 명령을 수동으로 입력했을 때와 유사한 처리 결과이다.

반면 sed 는 스크립트의 각 명령을 파일의 모든 줄에 적용하고, 처리 결과를 표준 출력으로 (기본적으로) 보낸다. 스크립트의 마지막 줄은 입력의 두 번째 복사본을 표준 출력으로 중복 출력한다.

동일한 스크립트는 ex 와 sed 에서 작동하지만, sed 스크립트는 좀 더 간단히 작성할 수 있다:

```
s/thier/their/
s/writeable/writable/
```

편집은 “기본적으로 모든 줄에 적용” 되므로 초기에 사용한 패턴 주소는 생략하고 `s` 명령만 제공한다. 또한 입력의 두 번째 복사본을 출력했던 *print* 명령은 생략한다.

sed 의 비-대화형 작업을 지원하는 특별한 명령들도 있다. 이런 명령들은 곧 살펴볼 것이며, 어떤 면에선 익숙한 명령보다 배우기 쉬운 경우도 있다. 이런 경고성 예시는 “동일하게 보이는 명령(스크립트)이 다른 결과를 낼 수도 있다!” 는 점을 강조하기 위한 것이다.


## Some Shell Scripts Using sed

sed 명령 중에서 가장 먼저 사용할 가능성 높은 것은 `s` (또는 *substitute*) 명령이다. 이 명령은 sed의 고급 제어 구조를 몰라도 곧바로 사용할 수 있기 때문이다. 다른 sed 명령을 배우지 않더라도 이번 섹션은 반드시 읽어야 한다. `s` 명령은 배우기 쉽지만 편집 능력을 크게 확장시켜 준다.

앞서 설명한 제약 조건 예제의 `s` 명령은 ex 와 동등한 명령과 유사하게 작동한다. sed를 사용하는 여러 가지 (셸) 스크립트를 살펴보자.

우선, 수많은 파일에 대규모 편집 작업을 수행할 때는 속도가 매우 중요한 요소이므로, 앞서 ex 로 작성했던 스크립트를 다음과 같이 sed로 다시 작성할 수 있다:

```sh
for file in $*
do
  sed -f sedscr $file > $file.tmp
  mv $file.tmp $file
done
```

이 스크립트는 항상 *sedscr* 라는 로컬 편집 스크립트를 찾고, 인자로 받은 각 파일에 편집 작업을 모두 적용한다. sed 는 작업 결과를 표준 출력으로만 보내므로, 출력 결과를 임시 파일에 저장한 후 원래 파일로 다시 이동시킨다.

하지만 이 방식은 실제 위험이 포함되어 있다!! 만약 sed 스크립트에 오류가 있으면 sed 는 출력을 생성하지 않고 그대로 중단된다! 그 결과로 임시 파일은 비어 있고, 원래 파일로 덮어쓰면서 원본 파일은 사실상 “삭제” 된다!!

이런 문제를 피하려면 *correct* 셸 스크립트에 테스트 과정을 포함시켜야 한다:

```sh
for file in $*
do
  sed -f sedscr $file > $file.tmp
  if [ -s $file.tmp ]
  then
    mv $file.tmp $file
  else
    echo "Sed produced an empty file."
  fi
done
```

`[-s]` 테스트는 파일이 비어 있는지 확인한다.

> [!NOTE]
> 이런 처리 방식은 스크립트를 작성할 때 유용한 기능이다.

또한 sed 를 사용해서 간단한 오류를 수정하는 또 다른 쉘 스크립트를 만들 수 있다. 이 스크립트의 이름은 *change* 로 부르자:

```sh
sed -e "s/$1/$2/g" $3 > $3.tmp
if [ -s $3.tmp ]
then
  mv $3.tmp $3
else
  echo "Possible error using regular expression syntax."
fi
```

이 스크립트는 첫 번째 인자를 두 번째 인자로 바꾸며, 세 번째 인자로 지정한 파일에 작업을 수행한다.

```
$ change mispeling misspelling myfile
```

> [!NOTE]
> 스크립트는 직접 제어하기 때문에, 발생하기 가장 가능성 높은 오류는 첫 번째나 두 번째 인자에 잘못된 정규 표현식 문법에서 발생할 수 있다. 따라서 오류 메시지의 문구를 약간 변경했다.


## Integrating sed into format

sed가 진정한 스트림 편집기로 작동하는 모습을 보여줄 수 있는 간단한 예를 살펴보자. 이 경우 sed 는 파이프라인에서 작업하므로, 편집 결과를 파일에 쓰지 않는다.

이 스크립트를 설명하기 위해 잠시 조판(*typesetting*) 설명으로 돌아가자. 타자기나 CRT 같은 장치는 em 대시 문자를 일반 하이픈 두 개(`--`) 로 입력한다. 하지만 조판에선 em 대시는 하나의 긴 대시(`—`) 문자로 출력된다. `troff` 프로그램은 em 대시에 특별한 문자 이름을 제공하지만, 파일에 em 대시를 입력할 때마다 `\(em` 을 타이핑한다는 것은 번거롭다.

다음과 같은 sed 스크립트를 가정해보자:

```
s/--/\\(em/g
```

그리고 이를 스크립트에 통합하려면? em 대시에 대해 전혀 걱정할 필요가 없어지고, sed 가 자동으로 이를 삽입해준다. 

> [!NOTE]
> 여기서 `\(em` 문자열에 백슬래시를 두 번 사용한 이유는 백슬래시 문자는 sed 와 troff 모두 특별한 의미를 가지므로, sed 가 이를 제거하지 않도록 처리하기 위함이다.

스크립트는 다음과 같이 구성할 수 있다:

```sh
eqn=""; pic=""; macros="ms"; col=""; roff="ditroff -Tlj"
sed="| sed -e 's/--/\\(em/g'"
while [ $# -gt 0 ]
do
  case $1 in
    -E) eqn="| eqn";;
    -P) pic="| pic";;
    -N) roff="nroff"; col="| col"; sed="";;
    -*) options="$options $1";;
    *) if [ -f $1 ]; then
         files="$files $1"
       else
         echo "format: $1: file not found"; exit
       fi;;
  esac
  shift
done
eval "cat $files $sed | tbl $eqn $pic | $roff $options $col | lp"
```

> [!NOTE]
> 여기서 `-N` 옵션은 nroff 를 위한 설정이며, sed 변수를 null 로 설정한 이유는 이 작업을 troff 를 사용할 때만 적용하기 위해서이다.


## Excluding Lines from Editing

앞으로 나가기 전에, 스크립트가 완전한지 잠시 확인해보자.

가령 누군가가 하이픈 문자로 수평선을 그릴 경우는 어떻게 될까? 즉, 하이픈 세 개 이상 연속된 줄은 편집에서 제외하고 싶다. 이를 위해 `!` (반전 - 하지마!) 명령을 사용할 수 있다:

```
/---/!s/--/\(em/g
```

이 구문은 이해가 필요할 수 있다. 간단히 말해 “하이픈 세 개가 연속된 줄을 찾으면 편집하지 마라!” 는 뜻이다. sed 는 나머지 줄은 자유롭게 편집을 적용한다. 

> [!NOTE]
> `!` 명령은 `s` 명령이 아니라“ 패턴 매치에 적용된다!” 는 점을 이해하는 것이 중요하다. 이 경우 “--- 가 포함된 줄은 매치하지 마라!” 또는 “---가 포함된 줄은 매치하고 치환하지 마라!” 로 읽어도 결과는 같지만, 다른 경우는 sed 의 방식대로 읽지 않으면 혼란스러울 수 있다.

미학적으로 좀 더 개선할 수 있다. 대시 앞뒤에 아주 작은 공간을 넣어 보기 좋게 만들 수 있는데, troff 의 `\ˆ` 구문을 사용하면 1/12-em 공간을 생성할 수 있다:

```
/---/!s/--/\\ˆ\\(em\\ˆ/g
```

하이픈을 em 대시로 바꾸는 것 외에도, 조판 시 “보기 좋게” 편집할 다른 경우도 있다. 예를 들어, 일부 레이저 프린터는 조판용 따옴표(`“`와 `”`)를 지원하지 않고 일반적인 쌍따옴표(`"`)만 출력한다. 출력 장치에 이런 제한이 있다면, sed 로 쌍따옴표를 문맥에 따라 열린 또는 닫힌 조판용 따옴표로 바꿀 수 있다. 이렇게 처리하면 조판 시 올바른 쌍따옴표처럼 보이게 된다.

하지만, 이 단순한 작업은 생각보다 훨씬 더 복잡하다. 다양한 모든 상황을 정규 표현식으로 처리해야 하기 때문이다. 스크립트는 다음과 같이 구성될 수 있다:

```
s/^"/‘‘/
s/"$/’’/
s/"? /’’? /g
s/"?$/’’?/g
s/ "/ ‘‘/g
s/" /’’ /g
s/|——|"/|——|‘‘/g
s/"|——|/’’|——|/g
s/")/’’)/g
s/"]/’’]/g
s/("/(‘‘/g
s/\["/\[‘‘/g
s/";/’’;/g
s/":/’’:/g
s/,"/,’’/g
s/",/’’,/g
s/\."/.\\\&’’/g
s/"\./’’.\\\&/g
s/"\\ˆ\\(em/’’\\(em/g
s/\\(em\\ˆ"/\\(em‘‘/g
s/"\\(em/’’\\(em/g
s/\\(em"/\\(em‘‘/g
```

> [!NOTE]
> 이 목록은 \([...]\) 부분 문자열을 적절히 활용하면 좀 더 간결하게 만들 수 있지만, 여기서는 설명을 위해 장황하게 보여줬다. 참고로 여기서 사용한 “|——|” 는 탭을 의미한다.


## Branching to Selective Parts of a Script

기술 서적에서 예제 코드를 일정한 폭의 고정 글꼴로 보여주는 것이 일반적이다. 이렇게 처리하면 각 문자가 실제로 어떻게 나타나는지 명확하게 보여줄 수 있다. 하지만 고정폭 글꼴의 단일 따옴표 두 개는 가변폭 글꼴의 조판용 쌍따옴표와 비슷하게 보이지 않는다. 즉, 앞서 보여준 치환을 항상 적용하는 것이 바람직하지 않다.

하지만 예제는 일반적으로 특정 매크로 쌍으로 구분되므로(이 책에서 `.ES` 와 `.EE` 를 사용함), 이를 기준으로 편집에서 제외할 수 있다. 이를 위한 방법은 두 가지가 있다:

- 앞서 사용한 것처럼 `!` 명령을 사용하는 방법 
- `b` (*branch*) 명령을 사용해서 스크립트 일부를 건너뛰는 방법

먼저 `!` 명령을 사용하는 방법을 살펴보자. 각 줄에 `!` 명령을 개별적으로 적용할 수 있다:

```sh
/^\.ES/,/^\.EE/!s/^"/‘‘/
(/^\.ES/,/^\.EE/!s/"$/’’/
(/^\.ES/,/^\.EE/!s/"? /’’? /g
...
```

하지만 좀 더 나은 방법이 있다. sed 는 `{` 와 `}` 를 사용한 흐름 제어를 지원하므로, 명령들을 그룹화할 수 있다:

```sh
/^\.ES/,/^\.EE/!{
  s/^"/‘‘/
  s/"$/’’/
  s/"? /’’? /g
  ...
  s/\\(emˆ"/\\(em‘‘/g
  s/"\\(em/’’\\(em/g
  s/\\(em"/\\(em‘‘/g
}
```

중괄호로 묶인 모든 명령은 초기 패턴 주소에 영향을 준다.

다른 방법은 `b` 명령을 사용하는 것이다. `b` 명령은 스크립트에 흐름 제어를 가능하게 만들며, 선택적으로 라벨을 붙여 특정 지점으로 이동할 수 있다. 이를 활용하면 스크립트를 다음과 같이 작성할 수 있다:

```sh
/^\.ES/,/^\.EE/b
s/^"/‘‘/
s/"$/’’/
s/"? /’’? /g
...
s/\\(emˆ"/\\(em‘‘/g
s/"\\(em/’’\\(em/g
s/\\(em"/\\(em‘‘/g
```

라벨은 콜론(`:`) 문자로 시작하며 최대 8자까지 사용할 수 있다. 라벨이 없으면 `b` 명령은 스크립트의 끝으로 분기한다. 

> [!NOTE]
> 현재 지점 이후에 아무 것도 없으므로 라벨은 생략 가능하며, 앞으로 이런 형식을 자주 사용할 것이다.

`b` 명령은 스크립트에서 조건에 따라 특정 명령을 건너뛰는 데 사용된다. 특정 패턴만 적용되는 하위 스크립트를 만들 수 있으며, 이처럼 단일 수준의 스크립트에서 일부 텍스트를 제외하는 강력한 도구가 된다.

이 에제에서 `b` 명령이 `!` 명령보다 유리한 점은 “제외할 조건을 유연하게 지정할 수 있다!” 는 것이다. `!` 명령은 단일 명령이나 중괄호로 묶인 명령 집합만 적용되지만, `b` 명령은 스크립트 전체 범위에서 거의 무제한의 흐름 제어를 제공한다.

예를 들어, 여러 매크로 패키지를 사용할 경우 `.ES` 와 `.EE` 외에도 적용하지 않는 매크로 쌍이 더 있을 수 있다. 다음과 같이 작성할 수 있다:

```sh
/^\.ES/,/^\.EE/b
/^\.PS/,/^\.PE/b
/^\.G1/,/^\.G2/b
```

또한 따옴표 문자는 troff 프로그램의 주석문으로 사용된다. (`\"` 는 주석문 시작). 따라서 `.` 또는 `'` 로 시작하는 줄의 따옴표 문자는 변경하지 않아야 한다:

```sh
/^[.’]/b
```

이런 분기 방식은 sed의 작동 방식을 이해하면 쉽게 파악할 수 있다:

1. sed는 파일에서 한 줄을 읽고 (패턴 공간) 버퍼에 저장한다.
2. 읽은 줄에 스크립트의 모든 명령을 적용한 후 다음 줄로 이동한다.

패턴 매치에 따라 분기 명령이 실행되면, 해당 줄에 대한 스크립트 관련 부분을 건너뛴다. 라벨이 있으면 그 지점으로 이동하고, 없으면 해당 줄에 대한 처리를 종료하고 다음 줄로 넘어간다.

앞선 예제는 sed 스크립트의 작동을 파일 일부만 적용하고 나머지는 제외하는 방법을 보여준다. 이와 반대로, 파일 일부만 sed 스크립트를 적용하고 나머지를 무시하려면, 편집 명령을 해당 패턴으로 고정시키면 된다:

```sh
/^\.ES/,/^\.EE/{
  Editing commands here
}
```

스크립트가 충분히 복잡해져서 전역적인 제외 방식이 필요하면, `b` 명령과 `!` 명령을 결합해서 분기의 의미를 반대로 만들 수 있다:

```sh
/^\.ES/,/^\.EE/!b
```

이 명령은 각 입력 줄에 다음과 같이 작동한다: “이 줄이 패턴과 일치하는가? 아니면 스크립트 끝으로 분기한다. (즉, 다음 줄로 넘어감) 일치하면 다음 명령으로 진행하면서 편집 작업을 수행한다!”


## Back to format

sed 로 보여준 편집 작업은 유용하므로 이를 *format* 명령과 통합하는 것은 중요하다. 단일 편집이 아닌 여러 편집 작업을 수행하기 때문에, `-e` 옵션을 사용하는 단일 라인 스크립트 대신 스크립트 파일을 사용해서 sed 를 실행한다. 따라서 *format* 명령에서 변수 할당을 다음과 같이 변경한다:

```sh
sed="| sed -f /usr/local/cleanup.sed"
```

여기서 *cleanup.sed* 파일은 편집 명령들을 담고 있는 스크립트 파일 이름이며, `/usr/local` 은 (일반적으로) 접근 가능한 디렉터리일 수 있다. 이후 이 파일에 추가적인 서식 관련 명령들을 계속 추가할 예정이다.

## Inserting Lines of Text

sed 프로그램은 ex와 vi처럼 새로운 *텍스트 줄을 삽입하는 명령* 을 가지고 있다. `i` (insert) 명령은 *현재 줄 앞에 텍스트를 추가* 하고, `a` (append) 명령은 *현재 줄 뒤에 텍스트를 추가* 한다. 

ex에서는 삽입 모드에 들어간 후 원하는 만큼 입력할 수 있으며, 줄 바꿈은 캐리지 리턴으로 처리된다. #footnote[여기서 “캐리지 리턴”(carriage return)과 “줄 바꿈”(newline)이라는 용어는 다소 느슨하게 사용되고 있다. 이들은 실제로 ASCII 문자 집합에서 서로 다른 문자이며 캐리지 리턴은 `ˆM`, 줄 바꿈(라인피드)은 `ˆJ` 에 해당한다. 혼동이 생기는 주된 이유는 UNIX가 텍스트 입력 시 캐리지 리턴 키로 생성된 `ˆM` 을 줄 바꿈 문자인 `ˆJ` 로 변경하기 때문이다. (즉, 파일을 편집할 때 캐리지 리턴을 입력하면 실제로 저장되는 것은 줄 바꿈 문자이다). 출력 시에는 줄 바꿈 문자가 두 문자로 매핑되는데 즉, 파일에 있는 `ˆJ` 는 터미널에 출력될 때 캐리지 리턴/줄 바꿈 쌍(`ˆMˆJ`)으로 출력된다.] 삽입 모드는 줄의 시작에 마침표를 입력하고 곧바로 캐리지 리턴을 입력함으로써 종료된다. 

하지만 sed에서는 삽입할 *줄 끝에 백슬래시 문자를 입력* 해야 한다. 삽입 모드는 백슬래시 문자로 “이스케이프” 되지 않은 첫 번째 줄 바꿈을 만났을 때 종료된다. 예를 들어, 다음 sed 스크립트는:

```sh
1a\
The backslash is a ubiquitous escape character used by\
many UNIX programs. Perhaps its most confusing appearance\
is at the end of a line, when it is used to "hide a\
newline." It appears to stand alone, when in fact it is\
followed by a nonprinting character-a newline.
```

파일의 첫 번째 줄 다음에 예시로 나온 다섯 줄을 추가한다. 삽입 작업은 다섯 번째 줄에서 sed가 백슬래시 문자로 끝나지 않은 줄 바꿈을 만났을 때 종료된다.


## A sed Script For Extracting Information From a File
sed의 `-n` 옵션은 일반적인 출력 작업을 억제하고, `p` 명령을 사용해서 명시적으로 요청한 출력만 표시하도록 한다.

`p` 명령에는 두 가지 형태가 있다:

- 절대 출력 명령으로 사용하는 경우. 예를 들어:
```sh
  /pattern/p
  ```
  이 명령은 패턴에 일치하는 줄을 *항상 출력* 한다.

- 치환 명령과 함께 사용할 경우. 실제로 치환 작업이 이루어진 경우에만 줄이 출력된다. 예를 들어:
```sh
  /pattern/s/oldstring/newstring/gp
  ```
  이 명령은 패턴이 포함된 줄이 발견되더라도 `oldstring` 이 `newstring` 으로 치환되지 않으면 출력되지 않는다.

다음과 같은 형식의 줄을 보면 더욱 명확해진다:

```sh
s/oldstring/newstring/p
```
이 명령은 파일의 모든 줄에 일치하지만, 실제로 치환이 성공한 경우에만 결과를 출력할 때 사용된다.

`sed -n` 과 `p` 명령을 함께 사용하면 `grep` 과 유사한 기능을 제공하면서 단일 줄뿐만 아니라 더 큰 텍스트 블록을 선택할 수 있다. 예를 들어, 다음과 같이 주제별로 시작 헤딩과 고유한 종료 문자열로 구분된 간단한 온라인 참조 문서를 만들 수 있다:

```sh
$ cat alcuin_online
.
.
.
Output Devices
Alcuin requires the use of a graphics device with at least
300 dpi resolution, and the ability to store at least
one-half page of graphics at that resolution ...
%%%%
.
.
.
Type Styles
There are a number of ornamental type styles available on
many typesetters. For example, many have an Old English
font. But no typesetter currently on the market has the
capability of Alcuin to create unique characters in the
style of medieval illuminated manuscripts.
%%%%
.
.
.
$
```

다음과 같은 쉘 프로그램만 있다면 이 “전체 텍스트 데이터베이스” 내에서 원하는 항목을 표시할 수 있다:

```sh
pattern=$*
sed -n "/$pattern/,/%%%%/p" alcuin_online
```

> [!NOTE]
> 명령에 제공한 전체 인자 목록 $* 은 변수 pattern 에 할당되므로, 사용자가 따옴표 없이 공백이 포함된 문자열을 입력할 수 있다.

좀 더 현실적인 예를 들어보자. 기존 패키지에서 사용할 매크로를 개발할 때, 현재 사용 중이거나 영향을 줄 수 있는 패키지의 매크로를 참조할 경우가 있다. 물론 전체 파일을 편집기로 읽어들일 수도 있지만, 더 쉽게 처리하기 위해 원하는 매크로 정의를 sed로 출력하는 간단한 쉘 스크립트를 사용할 수 있다. 

이 스크립트는 시스템에서 `getmac` 이라는 이름으로 사용한다:

```sh
mac="$2"
case $1 in
-ms) file="/usr/lib/macros/tmac.s";;
-mm) file="/usr/lib/macros/mmt";;
-man) file="/usr/lib/macros/an";;
esac
sed -n -e "/ˆ\.de *$mac/,/ˆ\.\.$/p" $file
done
```

이 스크립트는 언급할 만한 몇 가지 사항이 있다. 

- 첫째, 매크로 이름은 `.de` 요청과 공백으로 구분될 필요가 없다. `ms` 패키지는 공백을 사용하지만, `mm` 과 `man` 패키지는 그렇지 않다. 그래서 검색 패턴에 공백 다음에 별표(`\*`)를 포함시켰는 데, 이 패턴은 공백이 0개 이상 있는 경우를 모두 일치시킨다.

- 둘째, sed의 `-n` 옵션을 사용해서 전체 파일이 출력되지 않도록 처리했다. 이제 지정한 매크로 정의의 시작(`.de *$mac`)부터 정의의 끝(`..`)까지의 줄만 출력된다.

> [!NOTE]
> 정규 표현식이 처음이라면, 정규 표현식 문법과 troff 및 쉘의 특수 문자들을 구분하는 것이 다소 어려울 수 있지만, 꼭 노력해보길 바란다. 이는 sed의 훌륭한 활용 사례이며, 여러분의 도구 목록에 추가할 가치가 충분히 있다.

이 스크립트는 처리 결과를 *표준 출력으로 출력* 하지만, 쉽게 파일로 *리디렉션* 할 수 있으며, 그 파일은 사용자 정의 매크로의 기초가 될 수 있다. 이 스크립트는 이후 장에서도 유용하게 사용할 것이다.

sed를 사용해서 특정 파일에서 정보를 추출(및 조작)하는 또 다른 예로는 현재 작성 중인 *문서의 구조를 확인* 하기 위해 사용하는 다음과 같은 스크립트이다.

이 스크립트는 troff 매크로(이 책의 서식을 지정하는 데 사용한 매크로)를 사용해서 *섹션을 구분한다* 고 가정하고, 제목을 출력한다. 구조를 보다 명확히 하기 위해, 스크립트는 섹션 매크로 자체를 제거하고 제목을 들여쓰기된 개요 형식으로 출력한다.

따라서 sed가 수행할 작업은 크게 세 가지이다:

1. 챕터(`.CH`) 또는 섹션 제목(`.H1` 또는 `.H2`) 매크로로 시작하는 줄을 찾는다.
2. 해당 줄에서 매크로를 텍스트로 치환한다.
3. 해당 줄만 출력한다.

sed 명령 `do.outline` 은 명령줄에서 지정한 모든 파일(`$*`)에 대해 작동한다. 처리 결과는 표준 출력으로 출력되며, 파일 자체에는 아무런 변경을 가하지 않는다!!

```sh
sed -n ’/ˆ\.[CH][H12]/ {
s/"//g
s/ˆ\.CH /\
CHAPTER /
s/ˆ\.H1/  A. /
s/ˆ\.H2/  B. /
p
}’ $*
```

sed 명령은 `-n` 옵션으로 호출되며, 이는 줄의 *자동 출력을 억제* 한다. 그런 다음 작업하려는 줄을 선택하는 패턴을 지정하고, 여는 중괄호(`{`)를 사용한다. 이는 닫는 중괄호(`}`)까지의 *명령 그룹이 해당 패턴과 일치하는 줄에만 적용된다* 는 것을 의미한다. 이 구조는 보기보다 낯설지는 않다. ex의 전역 정규 표현식도 한 번의 치환만 원한다면 사용할 수 있다. (`g/ˆ\.[CH][H12]/s/"//g`) 

sed 명령은 여러 작업을 수행한다:

1. 쌍따옴표를 제거한다.
2. 챕터 제목 매크로를 줄 바꿈(빈 줄 생성)과 CHAPTER 라는 단어로 치환한다.
3. 섹션 제목을 적절한 문자와 탭 들여쓰기로 치환한다.
4. 해당 줄을 출력한다.

`do.outline` 의 실행 결과는 다음과 같다:

```sh
$ do.outline ch13/sect1
CHAPTER 13 Let the Computer Do the Dirty Work
  A. Shell Programming
  B. Stored Commands
  B. Passing Arguments to Shell Scripts
  B. Conditional Execution
  B. Discarding Used Arguments
  B. Repetitive Execution
  B. Setting Default Values
  B. What We’ve Accomplished
```

이 명령은 일련의 파일이나 “챕터” 에 실행할 수 있기 때문에, 전체 책이나 문서의 개요를 단 몇 초 만에 생성할 수 있다. 이 스크립트는 ms 나 mm 섹션 제목 매크로에 맞게 쉽게 수정할 수 있으며, C 수준의 제목을 포함하도록 확장할 수도 있다.


## The Quit Command
`q` 명령은 sed가 입력의 새로운 줄을 읽는 것을 중단하며, 출력으로 보내는 것도 멈춘다! 따라서 파일의 처음 일부만 편집하고 싶다면, 영향받을 마지막 줄과 고유하게 일치하는 패턴을 선택하고, 스크립트의 마지막 줄에 다음과 같은 명령을 포함하면 된다:

```sh
/pattern/q
```

패턴과 일치하는 줄에 도달하면 스크립트는 곧바로 종료된다.#footnote[`q` 명령은 편집 결과를 원본 파일에 다시 쓰는 프로그램에는 절대 사용하지 않도록 매우 주의해야 한다. (앞서 보여준 올바른 셸 스크립트처럼). `q` 명령이 실행되면 이후의 출력은 전혀 생성되지 않는다. 따라서 파일 앞부분을 편집하고 나머지 부분은 변경 없이 그대로 통과시킬 경우에는 절대 사용해서는 안 된다. 이 경우 `q` 명령을 사용하는 것은 매우 위험한 초보자의 실수인 것이다.]

이 명령은 파일의 일부를 보호하는 데는 크게 유용하지 않다. 하지만 복잡한 sed 스크립트에 사용할 경우, 스크립트의 처리 성능을 향상시키는 데 유용하다. sed는 매우 빠르지만, `getmac` 같은 응용 프로그램에서는 sed가 원하는 내용을 찾은 후에도 큰 파일을 계속해서 스캔하는 비효율이 발생할 수 있다.

예를 들어, `getmac` 을 다음과 같이 다시 작성할 수 있다:

```sh
mac="$2"
case $1 in
-ms) file="/usr/lib/macros/tmac.s";;
-mm) file="/usr/lib/macros/mmt";;
-man) file="/usr/lib/macros/an";;
esac
shift
sed -n "
/ˆ\.de *$mac/,/ˆ\.\./{
  p
  /ˆ\.\./q
}" $file
done
```

다음과 같은 명령 그룹화는

```sh
/ˆ\.\./q
```

이것은 sed가 현재 찾는 매크로의 끝에 도달할 때까지 실행되지 않도록 한다. (이 줄만 단독으로 사용하면 첫 번째 매크로 정의가 끝나는 시점에 스크립트는 종료된다). sed는 해당 지점에서 *즉시 종료* 되며, 파일의 나머지 부분을 계속해서 검색하지 않는다.

매크로 정의 파일은 그리 길지 않고, 스크립트 자체도 복잡하지 않기 때문에 이 버전의 스크립트로 절약되는 실제 시간은 미미하다. 하지만 매우 큰 파일이나 복잡하거나 여러 줄에 걸친 스크립트를 파일의 일부에만 적용할 경우에는 이 스크립트가 상당한 시간 절약을 가져올 수 있다.

예를 들어, 다음과 같은 간단한 쉘 프로그램은 sed를 사용해서 파일의 상위 10줄을 출력한다. (표준 UNIX `head` 프로그램과 유사):

```sh
for file
do
  sed 10q $file
done
```

이 예제는 다음과 같이 작성한 동일한 스크립트보다 성능 면에서 현저한 향상을 보여준다:

```sh
for file
do
  sed -n 1,10p $file
done
```


## Matching Patterns across Two Lines
줄 단위 편집기의 큰 약점 중 하나는 *패턴이 여러 줄에 걸쳐 있을 때 전역적인 변경에 무력하다* 는 점이다.

최근에 우리 작가 중 한 명이 작업하던 매뉴얼에서 예를 들어보자. 

그는 메뉴 항목의 첫 글자를 박스로 강조하기 위해 ms의 `.BX` 매크로를 사용하고 있었는 데, 알고 보니 잘못된 처리 방식이었다. 이렇게 처리하면 사용자가 특정 명령에 도달하기 위해 선택할 메뉴 항목의 순서를 시각적으로 강조할 수 있다. 예를 들면 다음과 같다:

```
[M] ain menu  
[P] ortfolio commands  
[E] valuate portfolios  
[S] hock factors
```

그는 수많은 파일로 나뉜 메뉴 참조를 만들었고, 수백 개의 명령을 다음과 같이 코딩했다:

```
.in 5n  
.BX "\s-2M\s0"\c  
ain menu  
.in +5n  
.BX "\s-2P\s0"\c  
ortfolio commands  
.in +5n  
.BX "\s-2E\s0"\c  
valuate portfolios  
.in +5n  
.BX "\s-2S\s0"\c  
hock factors  
.in 0
```

그런데 갑자기 작가는 *Main Menu 의 M 은 박스로 표시하면 안 된다* 는 사실을 깨달았다. 사용자가 이 키를 누를 필요가 전혀 없었기 때문이다. 그는 다음 줄에 _ain menu_ 라는 문자열이 포함된 경우에만 M 을 박스에서 제거할 방법이 필요했다.

> [!NOTE]
> troff 관련 설명: \c 이스케이프 시퀀스는 다음 줄의 텍스트를 현재 줄로 이어서 붙여준다. 예를 들어, 매크로의 인자가 다음 줄 첫 단어와 일반적으로 생기는 공백 없이 연결되길 원할 때 주로 사용한다. .BX 매크로는 이미 이 경우를 처리할 수 있도록 프로그램되어 있으며, 두 번째 선택적 인자로 이어지는 텍스트를 제공할 수 있지만, 이 예에서는 그 점은 중요하지 않다. 파일은 위와 같이 코딩되었고, 실수도 있었으며, 수정할 사례가 수백, 어쩌면 수천 개에 달했다.

`N` 명령은 sed에서 이러한 문제를 처리할 수 있게 해준다. 이 명령은 패턴 매치를 위해 *현재 줄과 다음 줄을 임시로 결합* 한다. 결합된 줄에서 줄 바꿈의 위치는 `\n` 이스케이프 시퀀스로 표시할 수 있다. 이 경우, 다음과 같은 두 줄짜리 sed 스크립트로 이 문제를 해결할 수 있다:

```sh
/.BX "\s-2M\s0"/N  
s/.BX "\s-2M\s0"\c\nain Menu/Main Menu/
```

특정 패턴을 검색한 후, `N` 명령을 사용해서 다음 줄을 “덧붙인다.” 이제 다음 치환 명령은 새로 결합된 줄에 적용된다.

이 해결책은 유용하지만, 입력에서 줄 바꿈이 정확히 어디서 발생할지 아는 경우는 많지 않을 것이다. 다행히 sed는 더 나아가 줄 바꿈이 어디서든지 발생할 수 있는 *다중 줄 패턴을 조작할 수 있는 명령* 들을 제공한다. 이제부터 이러한 명령들을 살펴보자.


## The Hold Space and the Pattern Space
다음에 소개할 명령들—hold(`h` 또는 `H`), get(`g` 또는 `G`), exchange(`x`)-은 대부분의 UNIX 시스템에서 제공되는 난해한 문서를 읽어본 사람이라면 특히 이해하기 어려울 수 있다. sed의 작동 방식에 대해 지금까지 설명한 내용을 복습하는 비유를 통해서 이해를 돕는 것이 좋을 것이다.

sed의 동작은 상상력을 약간 발휘해서, 원고를 복사하는 데 힘쓰는 매우 신중한 서기(scrivener) 또는 필사자(amanuensis)의 작업으로 설명할 수 있다. 

그의 주된 작업은 몇 가지 *공간적 제약* 을 받는다: 원본 원고는 한 방에 전시되어 있고, 원고를 복사하기 위한 *명령 목록* 은 중간 방에 저장되어 있으며, 깃펜과 잉크, 종이는 또 다른 방에 준비되어 있다. 원본 원고와 명령 목록은 돌에 새겨져 있어서 절대 이동할 수 없다. 

이 성실한 서기는 정신력보다 육체가 튼튼해서, 방에서 방으로 이동하면서 *한 번에 한 줄씩 복사 작업을 수행* 한다. 먼저 원본 원고가 있는 방에 들어가면, 그는 자신의 주머니에서 종이 조각을 꺼내서 원고의 첫 줄을 받아 적는다. 그런 다음 명령 목록이 있는 방으로 이동해서, 자신이 받아 적은 줄에 적용되는 명령이 있는지 확인한다.

각 명령은 특수한 표기법으로 작성되어 있으며, 크게 *패턴과 절차* 두 부분으로 구성된다: 서기는 첫 번째 명령을 읽고 자신의 줄과 패턴을 비교한다. 일치하지 않으면 해당 절차는 무시하고 다음 명령으로 넘어간다. 일치할 경우에는 명령에 지정한 동작을 수행한다.

서기는 다음 명령의 패턴과 비교하기 전에 종이 조각에 편집을 수행한다. 서기는 일련의 명령을 모두 읽어야 하며, 패턴과 일치하는 첫 번째 명령만 읽는 것이 아니다. 편집은 앞으로 진행하면서 수행하므로, 서기는 항상 최신 버전의 줄을 다음 패턴과 비교하며, 원래 줄은 기억하지 않는다.

명령 목록의 맨 아래에 도달하면, 필요한 편집을 마친 종이 조각을 다음 방으로 가져가서 줄을 복사한다. (줄을 출력하라는 명령이 없더라도 복사한다!) 그 작업이 끝나면 다시 첫 번째 방으로 돌아가서 새로운 종이 조각에 다음 줄을 받아 적는다. 두 번째 방으로 가면 다시 처음부터 끝까지 모든 명령을 읽는다.

이것이 서기가 일반적으로 수행하는 작업이며, *특별한 지시가 없는 한* 이렇게 처리한다. 예를 들어, 시작 전에 모든 줄을 출력하지 말라는 지시(`-n` 옵션)를 받을 수 있다. 이 경우, 출력하라는 명령(`p`)을 받을 때까지 기다려야 한다. 

그런 명령을 받지 못했다면 종이 조각을 버리고 다시 시작한다. 참고로, 줄을 출력하라는 지시 여부와 관계없이 서기는 항상 명령 목록의 마지막까지를 읽는다.

이제 서기가 해석할 다른 종류의 명령도 살펴보자. 먼저, 명령은 0개, 1개 또는 2개의 *패턴* 을 가질 수 있다:

- 패턴이 없으면 모든 줄에 동일한 절차를 따른다.
- 하나의 패턴만 있으면, 해당 패턴과 일치하는 줄에 절차를 수행한다.
- 패턴 뒤에 `!` 가 있으면, 해당 패턴과 일치하지 않는 모든 줄에 절차를 수행한다.
- 두 개의 패턴이 지정되면, 첫 번째 패턴과 일치하는 줄부터 두 번째 패턴과 일치하는 줄까지 절차가 수행된다.

서기는 한 번에 한 줄만 작업할 수 있으므로, 범위 지정이 어떻게 처리되는지 궁금할 수 있다. 명령을 읽을 때마다 두 개의 패턴 중 첫 번째 패턴만 비교한다. 첫 번째 패턴과 일치하는 줄을 찾은 후에는, 각 줄에 두 번째 패턴을 비교한다. 서기는 두 번째 패턴을 `pattern!` 로 해석해서, 일치하지 않는 경우에만 해당 절차를 수행한다. 두 번째 패턴과 일치하면 다시 첫 번째 패턴을 찾기 시작한다.

각 절차는 하나 이상의 *명령* 또는 *동작* 을 포함한다. 패턴이 절차와 함께 지정될 경우, 절차가 실행되기 위해서는 반드시 패턴이 일치해야 한다. 이미 다른 편집 명령과 유사한 일반적인 명령들을 많이 살펴봤다. 

하지만 sed에는 매우 *특이한 명령* 들도 몇 가지 존재한다. 예를 들어, 

- `N` 명령은 서기에게 지금 당장 다른 줄을 가져와서 *같은 종이 조각에 추가하라* 고 지시한다. 서기는 하나의 종이 조각을 “보관” 하도록 지시받을 수 있다. 
- `h` 명령은 현재 줄을 다른 종이에 복사해서 주머니에 넣으라고 지시한다. 
- `x` 명령은 주머니 속의 종이와 손에 들고 있는 종이를 교환하라고 지시한다. 
- `g` 명령은 손에 들고 있는 종이는 버리고 주머니 속의 종이로 교체하라고 지시한다. 
- `G` 명령은 주머니 속의 줄을 현재 들고 있는 종이에 덧붙이라고 지시한다. 
- `d` 명령을 만나면 서기는 종이 조각을 버리고 명령 목록의 맨 위로 돌아가 다시 시작한다. 
- `D` 명령은 두 줄이 종이에 추가된 경우에만 효과가 있으며, 첫 번째 줄만 삭제하라고 지시한다.

이 비유를 컴퓨터로 다시 바꾸면, 중세 시대 저택의 첫 번째 방과 마지막 방은 *표준 입력* 과 *표준 출력* 이다. 따라서 원본 파일은 절대 변경되지 않는다!! 서기의 종이 조각에 있는 줄은 패턴 공간에 있고, 주머니 속 종이에 있는 줄은 홀드 공간에 있다. 

*홀드 공간* 은 원본 줄을 변경할 동안 복사본을 유지할 수 있게 해준다. 실용적인 응용 예로, 두 줄에 걸쳐 나뉘어져 있을 수 있는 특정 구문을 검색하는 sed 프로그램을 살펴보자.

정규 표현식이 강력하긴 하지만, 한 가지 제한 사항이 있다: *구문이 두 줄에 걸쳐 나뉘어 있으면 일치하지 않는다.* 

앞서 보여준 것처럼 줄 바꿈 문자를 지정할 수는 있지만, 줄 바꿈이 어떤 단어 사이에 있을지를 정확히 알아야 한다. sed를 사용하면 두 줄에 걸친 일반적인 패턴 매칭을 위한 명령을 작성할 수 있다.

```sh
N
h
s/ *\n/ /
/pattern-matching syntax/{
  g
  p
  d
}
g
D
```

이 sed 스크립트는 `pattern-matching syntax` 라는 구문이 입력 파일에서 두 줄에 걸쳐 나뉘어져 있을 때라도 제대로 인식할 수 있다. 패턴 공간과 홀드 공간이 어떻게 이를 가능하게 하는지 살펴보자.

처음에는 패턴 공간에 한 줄만 있다. 첫 번째 동작(`N`)은 다른 줄을 가져와서 첫 줄에 덧붙인다. 이제 두 줄을 검사할 수 있지만, 그 사이에는 줄 바꿈도 포함되어 있으므로 이를 제거해야 한다. (그렇지 않으면 줄 바꿈이 어디에 있을지를 정확히 알아야 한다). 그 전에 `h` 명령으로 패턴 공간의 내용을 홀드 공간으로 복사해서 줄 바꿈을 유지한 복사본을 확보한다. 그런 다음 줄 바꿈(`\n`)과 그 앞에 있을 수 있는 공백을 하나의 공백으로 치환한다. 

> [!NOTE]
> sed 명령은 패턴 공간의 줄 끝에 있는 줄 바꿈을 제거하지 않는다.

이제 패턴 공간의 내용과 구문을 비교한다. 일치한다면 줄 바꿈을 포함한 복사본을 홀드 공간에서 다시 가져와서(`g`) 출력하고(`p`), `d` 명령으로 명령 목록의 맨 위로 돌아가서 다음 줄을 읽는다. 

> [!NOTE]
> sed 원본 문서의 표현을 빌리자면, “삭제된 줄의 시체에 더 이상의 편집은 시도하지 않는다. 

반면, 일치하지 않는다면 홀드 버퍼의 내용을 패턴 공간으로 교체한다.(`g`) 이제 원래 두 줄이 줄 바꿈으로 구분된 상태로 패턴 공간에 있다. 첫 번째 줄은 버리고 두 번째 줄만 유지해서 다음 줄과 짝지으려 한다. `D` 명령은 줄 바꿈까지의 패턴 공간을 삭제하고 다음 줄을 덧붙이기 위해 명령 목록의 맨 위로 돌아간다.

이 스크립트는 sed의 흐름 제어 한계를 절실히 보여준다. 첫 번째 입력 줄이 읽힌 후에는 `N` 명령이 모든 입력을 담당한다. 그리고 `d` 와 `D` 명령을 사용해서 명령 목록의 끝에 도달하지 않도록 함으로써, sed는 줄을 자동으로 출력하거나 패턴 공간을 지우지 않는다. (`-n` 옵션과 관계없이) 

다시 비유로 돌아가면, 서기가 두 번째 방에 들어간 후에는 다음에 어느 방으로 갈지, 또 줄을 가져올지 출력할지를 항상 명령이 지시하며, 원고에서 읽을 줄이 있는 한 이 작업은 계속된다.

앞서 강조했듯이, 스크립트는 항상 개선할 수 있으며, 동작 방식을 다듬거나 기능을 추가할 수 있다. 이 스크립트의 작동 방식에는 세 가지 문제가 있다. 

+ 첫째이자 가장 중요한 문제는 특정 문자열을 검색하도록 고정되어 있어서 일반성이 부족하다는 것이다. 이 sed 프로그램을 감싸는 쉘 스크립트를 작성한다면 이 문제는 해결할 수 있다. 

+ 둘째, 이 프로그램은 sed의 흐름에 “따르지 않는다.” `b`(branch) 명령을 사용해서 명령 목록의 끝에 도달했을 때 sed의 기본 동작을 활용하도록 다시 작성할 수 있다. 

+ 마지막으로, 이 프로그램은 검색 문자열이 입력의 한 줄에 완전히 포함되어 있을 때도 항상 두 줄을 출력한다. 새로운 입력 줄이 이전 줄과 짝지어지기 전에 패턴을 일치시켜야 한다.

다음은 이 sed 스크립트의 보다 일반화된 버전인 `phrase` 이다. 첫 번째 인자로 검색 문자열을 따옴표로 감싸서 지정하고, 추가적인 명령줄 인자는 파일 이름을 나타낸다:

```sh
search=$1
shift
for file
do
  sed '
  /'"$search"'/b
  N
  h
  s/.*\n//
  /'"$search"'/b
  g
  s/ *\n/ /
  /'"$search"'/ {
    g
    b
  }
  g
  D' $file
done
```

셸 변수는 명령줄의 첫 번째 인자를 검색 문자열로 정의한다. 이제 sed 프로그램은 세 가지 지점에서 검색 문자열을 일치시키려고 시도한다. 검색 문자열이 표준 입력에서 읽은 새로운 줄에 있으면 해당 줄을 출력한다. `b` 명령을 사용해서 명령 목록의 끝으로 이동하면 sed는 줄을 출력한 후 패턴 공간을 지운다. 

단일 줄에 패턴이 없으면 다음 입력 줄이 패턴 공간에 덧붙여진다. 이제 이 줄 자체가 검색 문자열과 일치할 가능성이 있다. (패턴 공간을 홀드 공간에 복사한 후) 이전 줄을 줄 바꿈까지 제거해서 이를 테스트한다. 일치한다면 명령 목록의 끝으로 이동해서 줄을 출력한다. 일치하지 않으면 홀드 공간에 저장된 복사본을 가져온다. 이제 앞서 처리한 것 같이 줄 바꿈을 제거하고 패턴을 테스트한다. 

일치하면 두 줄을 출력하므로 줄 바꿈이 포함된 복사본을 다시 가져오고, 제어는 스크립트의 끝으로 넘어간다. 일치하지 않으면 복사본을 가져와서 첫 번째 부분을 제거한다. 삭제 동작은 제어를 다시 맨 위로 돌려보내며, `N` 명령이 다음 줄을 이전 줄에 덧붙인다.

다음은 이 프로그램을 실행했을 때의 실행 결과이다:

```sh
$ phrase "the procedure is followed" sect3
If a pattern is followed by a \f(CW!\fP, then the procedure
is followed for all lines that do \fInot\fP match the
so that the procedure is followed only if there is
```


## In Conclusion
여기서 제시된 예제들은 sed의 고급 명령들이 가진 강력함의 일부분만을 보여줄 뿐이다. 예를 들어, 

- hold 명령의 변형인 `H` 명령은 일치한 줄을 홀드 공간에 덧붙이며, 기존의 홀드 공간 내용을 덮어쓰지 않는다. 

- 마찬가지로, get 명령의 변형인 `G` 명령은 홀드 공간의 내용을 현재 줄에 덧붙이며, 이를 교체하지 않는다. 

- `X` 명령은 패턴 공간의 내용과 홀드 공간의 내용을 서로 교환한다. 

상상할 수 있듯이, 이러한 명령들은 복잡한 편집 작업을 수행할 수 있는 강력한 기능을 제공한다.

하지만 sed를 사용하기 위해 *모든 것을 전부 이해할 필요는 없다* 는 점을 기억하는 것이 중요하다. 앞서 보여준 것처럼, sed는 매우 유연한 편집기이며, 초보자에게도 대규모 파일 집합에 간단한 전역 편집을 수행하는 데 추천할 만큼 빠르다. 동시에, 일반적인 편집기로는 생각도 못할 작업을 처리할 수 있을 만큼 복잡한 기능까지 갖추고 있다.

비록 그 문법은 숙련된 컴퓨터 사용자라 하더라도 복잡하게 느껴질 수 있지만, sed에는 흐름 제어 메커니즘이 존재하며, 약간의 사고와 실험을 통해서 편집 프로그램을 고안할 수 있다. 레이블을 통해 분기되는 편집 “서브루틴” 을 포함하거나, 파일의 일부에 서로 다른 작업을 수행하며, 특정 조건이 충족되면 종료하는 sed 스크립트를 상상하는 것은 그다지 어렵지 않다. (물론 실행은 더 어렵다).

대부분의 사람들은 그 정도까지는 가지 않겠지만, *도구의 범위를 이해하는 것은 중요* 하다. 끝없는 반복 작업이 필요한 까다로운 과제에 직면했을 때, 여러분은 이렇게 말할지도 모른다:

# A Proofreading Tool You Can Build
이제 sed는 최소한만 사용하고 쉘 프로그래밍을 광범위하게 활용하는 좀 더 복잡한 스크립트를 살펴보자. 

이것은 쉘로 구축한 본격적인 도구의 첫 번째 예제로, 구성 요소 하나하나보다 훨씬 더 강력한 기능을 제공한다.

이 스크립트의 이름은 `proof` 이다. 이 스크립트는 `spell` 명령을 사용해서 파일의 철자 오류를 검사하고, 문제가 있는 줄을 문맥 속에서 보여준 다음, `sed` 를 사용해서 수정한다. 문서에는 기술 용어, 고유 명사 등이 포함되어 있어서 오류로 표시될 수도 있으므로, 이 스크립트는 철자 오류로 표시되지 않아야 할 예외들을 담은 *로컬 사전 파일* 도 생성하고 유지한다.

이 스크립트는 원래 1985년 6월호 UNIX World 의 Rebecca Thomas 칼럼에 `spellproofer` 라는 이름으로 Mike Elola 가 제출한 것이다. 원래 공개된 스크립트에는 몇 가지 오류가 있었고, 이에 대해 수정 사항을 제출했다. 따라서 아래의 스크립트는 그런 수정 사항을 반영해서 1986년 1월호에 다시 실린 것이며, UNIX World 의 허가를 받아서 재인쇄한 것이다. 

> [!NOTE]
> 사실 이후에 몇 가지 개선을 추가했기 때문에, 원래 공개한 것과는 정확히 일치하지 않는다.

스크립트의 내용을 살펴보기 전에 실제 동작 결과를 먼저 본다면 이해가 훨씬 쉬우므로, 거꾸로 접근해서 스크립트의 결과부터 살펴보자. 다음 예제는 2장에서 사용한 스크립트를 실행한 샘플 결과를 보여준다. 이 예제에서 `<CR>` 은 사용자가 프롬프트에 응답해서 캐리지 리턴을 입력했음을 의미한다.

```bash

the name or press RETURN for the default dictionary: <CR>

working ...

Save corrections in "sect1" file (y or n)?
y

a directory "/work/textp" and under that directories for
```

이제 스크립트를 자세히 살펴보자. 지금까지 살펴본 것들보다 훨씬 복잡하기 때문에, 여백에 줄 번호를 함께 표시했다. 따라서 이 번호들은 스크립트의 일부가 아니며, 이후 설명에서 참조용으로만 사용된다. 중첩된 루프 등의 들여쓰기를 통해 프로그램을 훨씬 더 읽기 쉽게 만들 수 있다는 점도 확인할 수 있을 것이다.

```bash
1 echo "Do you want to use a local dictionary? If so, enter"
2 echo "the name or press RETURN for the default dictionary: "
3 read localfile
4 if [ -z "$localfile" ]; then
5  localfile=dict
6  echo Using local dictionary file $localfile
7 fi
8 echo "working ..."
9 touch $localfile
10 filelist="$*"; excused=""
11 if [ -z "$filelist" ]; then
12  echo ’Usage: proof file...’
13  exit 1
14 fi
15 for word in ‘spell $filelist‘
16 do
17  found=‘grep "ˆ$word$" $localfile
18  if [ -z "$found" ] ; then
19  echo
20  echo "The word $word appears to be misspelled."
21  echo "Do you want to see it in context (y or n)? "
22  read context
23  if [ "$context" = y ]; then
24  grep $word $filelist
25  fi
26  echo
27  echo "Press RETURN for no change or replace \"$word\" with:"
28  read correction
29  if [ -n "$correction" ]; then
30  hitlist="‘grep -l $word $filelist‘"
31  for file in $hitlist
32  do
33  echo
34  sed -n -e "s/$word/$correction/gp" <$file
35  echo "Save corrections in \"$file\" file (y or n)? "
36  read response
37  if [ "$response" = y ]; then
38  sed -e "s/$word/$correction/g" <$file>/usr/tmp/$file
39  if test -s /usr/tmp/$file; then
40  mv /usr/tmp/$file $file
41  fi
42  fi
43  done
44  else
45  excused="$excused $word"
46  fi
47  fi
48 done
```

*1-8* UNIX 프로그래밍 철학은 일반적인 도구로 사용할 수 있는 작은 프로그램을 만들고, 이를 *파이프라인으로 연결하는 것* 이다. 이러한 이유로, 대부분의 프로그램은 사용자에게 프롬프트를 표시하거나, 대화형으로만 작동하도록 제한하는 “사용자 친화적인” 기능을 포함하지 않는다. 하지만 UNIX에서도 (!) 이러한 기능이 적절한 경우가 있다.

셸에는 프롬프트를 표시하고, 그에 대한 응답은 파일로 읽어들이는 명령이 있다. 여기서 사용된 `echo` 명령은 프롬프트를 출력하고, `read` 명령은 사용자가 입력한 내용을(캐리지 리턴까지) 쉘 변수에 할당한다. 이 쉘 변수는 이후 스크립트에서 사용할 수 있다.

표시된 줄은 로컬 사전 파일의 이름을 묻고, 아무 것도 입력하지 않으면 현재 디렉터리에 있는 기본 사전 파일인 `dict` 를 사용한다. 샘플 실행에서는 캐리지 리턴만 입력했기 때문에, 변수 `localfile` 은 `dict` 로 설정된다.

*9* 이 스크립트를 처음 실행할 경우, 로컬 사전 파일이 없을 가능성이 높으며, 새로 생성해야 한다. `touch` 명령은 이를 위한 좋은 방법이다. 파일이 이미 존재한다면 접근 시간만 갱신되고(`ls -l`로 확인 가능), 존재하지 않으면 새로운 파일이 생성된다.

이 줄은 스크립트가 처음부터 제대로 작동하도록 만들기 위한 안정성 점검 차원에서 포함되었지만, 특히 큰 파일의 경우에는 로컬 사전을 수동으로 생성하는 것이 더욱 바람직하다. `spell` 프로그램은 문서에서 사용하는 많은 단어들을 오류로 표시하는 경향이 있다. `proof` 스크립트는 이러한 단어들을 로컬 사전에 추가하는 작업을 처리하지만, 이를 대화형으로 수행하면 시간이 많이 소요된다.

문서에 대한 기본 사전을 생성하는 좀 더 빠른 방법은 `spell` 의 출력을 사전 파일로 리디렉션한 다음, 실제 철자 오류는 제거하고 예외 목록만 남기도록 사전을 편집하는 것이다. 이후에는 `proof` 를 사용해서 오류를 수정한다면, 실제 오류가 아닌 단어에 계속해서 `n` 명령을 입력하는 번거로움은 피할 수 있다.

이 스크립트를 사용할 경우, 문서 초안에는 `proof` 대신 `spell` 을 실행해서 사전을 먼저 생성하는 것이 좋다. 이후의 `proof` 실행은 보다 간결하고 빠르게 진행될 것이다.

*10-14* 이 줄에서는 이전에 본 것과 유사하게 몇 가지 쉘 변수를 설정한다. 다음과 같다:

```sh
filelist="$*"
if [ -z "$filelist" ]; then
  echo "Usage: proof file ..."
  exit 1
fi
```

이 코드는 앞서 사용했던 “인자 수가 0보다 큰지 테스트” 와 거의 동일한 효과를 가진다. `filelist` 가 빈 문자열이라면, 인자가 지정되지 않은 것이므로 오류 메시지를 출력하고 쉘의 `exit` 명령을 사용해서 프로그램을 종료한다.

*15* 이 줄은 쉘에서 이전에 본 기능을 다시 보여주지만, 기억하는 데 시간이 걸릴 수도 있으므로 주목할 가치가 있다. 백틱(``` `` ```)으로 감싼 명령의 출력은 다른 명령의 인자 목록으로 대체될 수 있다. 여기서도 그런 일이 일어나고 있으며, `spell` 명령의 출력이 `for` 루프의 패턴 목록으로 재사용되고 있다.

*17-18* `spell` 은 여전히 발견한 모든 단어를 오류로 표시한다. 하지만 `for` 루프는 `grep` 을 사용해서 `spell` 이 생성한 단어 목록을 사전 내용과 비교한다. 사전에 없는 단어만 수정 대상으로 제출된다.

`grep` 에 제공된 패턴은 특수 패턴 매칭 문자 `^` 와 `$`(각각 줄의 시작과 끝)로 “고정(anchor)” 되어 있어서, 사전에서 전체 단어만 일치하도록 한다. 이러한 고정 작업이 없다면, 예를 들어 `ditroff` 라는 단어가 목록에 있을 경우 `trof` 같은 철자 오류를 발견하지 못하게 된다.

*20-25* 때로는 겉보기에는 철자 오류처럼 보여도 실제로는 문맥상 올바른 경우가 있다. 예를 들어, 샘플 실행에서는 `textp` 라는 단어가 마치 오류처럼 보였지만 실제로는 경로명의 일부였기 때문에 올바른 단어였다. 이에 따라 `proof` 는(다시 `grep` 을 사용해서) 오류가 포함된 각 줄을 사용자가 직접 보고나서 수정 여부를 결정할 수 있도록 처리한다.

덧붙이자면, 이 스크립트에는 한 가지 제한이 있다. 예제처럼 문자열이 여러 번 등장할 경우, 모두 수정하거나 모두 그대로 두어야 한다. 개별적으로 편집할 수 있는 기능은 없다.

*26-48* 오류로 제시된 단어를 수정하거나 그대로 둘 수 있다는 선택지가 제공된다. 스크립트는 각 단어가 어느 범주에 속하는지 추적해야 한다. 수정하지 않은 단어는 사전에 추가할 수도 있기 때문이다.

수정을 원한다면 직접 입력하면 된다. 이때 변수 `correction` 은 비어 있지 않게 되며(`test -n` 으로 검사), 이를 조건 테스트의 기준으로 사용할 수 있다. 수정 내용을 입력하면, `proof` 는 먼저 명령줄에 지정한 파일들 중 어떤 파일들이 수정 가능한지 확인한다. (`grep -l` 은 문자열이 발견된 파일 이름만을 변수 `hitlist` 에 저장한다.) 그런 다음, 수정은 이들 파일 각각에 적용된다.

*35* 안전을 위해, 스크립트는 먼저 수정 내용을 출력하고 실제 편집은 처리하지 않는다. (`-n` 옵션은 sed가 전체 파일을 표준 출력으로 출력하지 않고, `p` 명령으로 명시적으로 요청한 줄만 출력한다.) 이렇게 사용하면 sed는 `grep` 과 거의 같은 기능을 수행하지만, 동시에 편집도 수행한다.

*37-42* 사용자가 수정을 승인하면, sed가 다시 사용되어 실제 편집 작업을 수행한다. 이 부분은 스크립트에서 이미 본 적이 있을 것이다. 이 응용에서는 sed *표현식은 반드시 따옴표로 감싸는 것이 중요하다* 는 점을 기억하라.

*50-84* 이전 쉘 스크립트 부분을 이해했다면, 이 부분도 쉽게 해석할 수 있을 것이다. 여기서는 단어들을 로컬 사전에 추가한다. `tr` 명령은 예외 목록에 있는 각 단어 사이의 공백을 캐리지 리턴으로 변환한다. 그런 다음 `pr` 명령을 사용해서 다섯 개의 탭으로 구분된 열로 출력할 수 있다. 

이 프로그램의 이 부분은 꼭 공부해보길 바란다. UNIX 프로그램은 겉보기에는 단순하거나 명확한 기능이 없어 보일 수 있지만, 예상치 못한 방식으로 효과적으로 활용될 수 있다는 훌륭한 예시이다.
