* 1. sed.js

~JavaScript~ 로 컴파일된 GNU sed 스트림 편집기

다음 명령줄 옵션을 사용해서 호출할 수 있습니다:

- ~--version~ ::
실행 중인 sed의 버전과 저작권 고지를 출력한 후 종료합니다.

- ~--help~ ::
명령줄 옵션들을 간략히 요약한 사용법 메시지와 버그 보고 주소를 출력한 후 종료합니다.

- ~-n --quiet --silent~ ::
기본적으로 sed는 스크립트를 처리할 때마다 패턴 공간을 자동 출력합니다. 이 옵션들은 자동 출력을 비활성화하며, sed는 ~p~ 명령을 통해 명시적으로 지시받은 경우만 출력을 생성합니다.

- ~-e script --expression=script~ ::
/script/ 에 포함된 명령들을 입력 처리 중에 실행될 명령 집합에 추가합니다.

- ~--posix~ ::
GNU sed는 POSIX sed에 대한 몇 가지 확장 기능이 포함되어 있습니다. 이식성 있는 스크립트 작성을 단순화하기 위해, 이 옵션은 추가 명령어를 포함해서 이 설명서에 기술된 모든 확장 기능을 비활성화합니다. 대부분의 확장 기능은 POSIX에서 규정하는 구문 범위를 벗어난 sed 프로그램을 허용하지만, 일부(예: “버그 보고” 항목에 설명된 ~N~ 명령어의 동작)는 실제로 표준을 위반합니다. 후자의 유형에 해당하는 확장 기능만 비활성화하려면 /POSIXLY_CORRECT/ 변수를 비어 있지 않은 값으로 설정하면 됩니다.

- ~-r --regexp-extended~ ::
기본 정규 표현식(/BRE/) 대신 확장 정규 표현식(/ERE/)을 사용합니다. 확장 정규 표현식은 ~egrep~ 이 허용하는 표현식입니다. 일반적으로 백슬래시 사용 횟수가 적어 좀 더 명확할 수 있지만, 이는 GNU 확장 기능으로 스크립트는 이식성이 없습니다. ‘확장 정규 표현식’ 섹션을 참조하십시오.

명령행에서 ~-e --expression~ 옵션이 지정되지 않은 경우, 명령행에서 옵션이 아닌 첫 번째 인수를 실행할 스크립트로 간주합니다.


* 2. Programs

sed 프로그램은 하나 이상의 sed 명령어로 구성되며, 이 명령어들은 하나 이상의 ~-e --expression~ 옵션을 통해 전달되거나, 해당 옵션이 하나도 사용되지 않은 경우는 첫 번째 비-옵션 인수를 통해 전달됩니다.

스크립트 내의 명령어는 세미콜론(~;~)이나 줄바꿈(/ASCII 10/)으로 구분할 수 있습니다. 일부 명령어는 구문상의 이유로 명령어 구분자로 작용하는 세미콜론을 뒤에 붙일 수 없으므로, 줄바꿈으로 끝내거나 스크립트 맨 끝에 배치해야 합니다. 또한 명령어 앞에는 선택적으로 의미 없는 공백 문자를 붙일 수 있습니다.

각 sed 명령어는 선택적인 주소 또는 주소 범위와 그 뒤에 오는 한 글자의 명령어 이름 그리고 명령어에 특정한 추가 코드로 구성됩니다.

sed는 두 개의 데이터 버퍼를 유지합니다: “활성 패턴 공간” 과 “보조 홀드 공간” 입니다. 두 공간 모두 처음에는 비어 있습니다.

sed는 입력의 각 줄에 다음과 같은 실행 주기를 수행하며 동작합니다. 먼저, sed는 입력 스트림에서 한 줄을 읽고, 끝의 줄바꿈을 제거한 후 이를 패턴 공간에 저장합니다. 그런 다음 명령어가 실행됩니다. 각 명령어는 주소가 연관될 수 있습니다. 주소는 일종의 조건 코드이며, 명령어가 실행되기 전에 조건이 충족된 경우만 해당 명령어가 실행됩니다.

스크립트 끝에 도달하면, ~-n~ 옵션이 사용되지 않는 한, 패턴 공간의 내용은 출력 스트림으로 출력되며, 제거했던 끝의 개행 문자를 다시 추가합니다. 그런 다음 다음 입력 줄에 대한 다음 실행 주기가 시작됩니다.

~D~ 같은 특수 명령어를 사용하지 않는 한, 패턴 공간은 사이클 사이에 삭제됩니다. 반면 홀드 공간은 사이클 사이에도 데이터를 유지합니다(두 버퍼 간에 데이터를 이동하려면 ~h~, ~H~, ~x~, ~g~, ~G~ 명령어를 참조하십시오).



** 2.1. Selecting lines

sed 스크립트에서 주소(/addresses/)는 다음 형식 중 하나를 가질 수 있습니다:

- ~숫자~ ::
줄 번호를 지정하면 입력에서 해당 줄만 일치합니다.

- ~first~step~ ::
이 GNU 확장 기능은 /first/ 줄부터 시작해서 /step/ 간격으로 이어지는 모든 줄을 일치시킵니다. 특히, 현재 줄 번호가 ~first + (n * step)~ 과 같을 때, n 이 0 이상인 경우 해당 줄들이 선택됩니다. 따라서 홀수 줄을 선택하려면 ~1~2~ 를 사용하고, 두 번째 줄부터 시작해서 세 번째 줄마다 선택하려면 ~2~3~ 을, 열 번째 줄부터 시작해서 다섯 번째 줄마다 선택하려면 ~10~5~ 를 사용합니다. 또한 ~50~0~ 은 단순히 50 을 나타내는 다소 생소한 표현일 뿐입니다.

- ~$~ ::
이 주소는 입력의 마지막 줄과 일치합니다.

- ~/regexp/~ ::
정규 표현식 /regexp/ 와 일치하는 모든 줄을 선택합니다. /regexp/ 자체에 ~/~ 문자가 포함되면, 각 ~/~ 문자는 백슬래시(~\~)로 이스케이프 처리해야 합니다.

- ~\%regexp%~ ::
(~%~ 는 다른 단일 문자로 대체할 수 있습니다.) 이 역시 정규 표현식 /regexp/ 와 일치하지만, ~/~ 이외의 다른 구분자를 사용할 수 있게 해줍니다. 이는 특히 /regexp/ 자체에 슬래시가 많이 포함된 경우, 모든 ~/~ 문자에 번거로운 이스케이프 처리를 피할 수 있으므로 유용합니다. /regexp/ 자체에 구분자 문자가 포함되면, 각 구분자는 백슬래시(~\~)로 이스케이프 처리해야 합니다.

- ~/regexp/I \%regexp%I~ ::
정규식 일치에 사용되는 ~I~ 수정자는 대소문자를 구분하지 않고 정규식을 일치시키는 GNU 확장 기능입니다.

- ~/regexp/M \%regexp%M~ ::
정규식 일치에 사용되는 ~M~ 수식자는 GNU sed의 확장 기능으로, ~^~ 와 ~$~ 앵커는 (일반적인 동작에 더해) 각각 줄바꿈 뒤의 빈 문자열과 줄바꿈 앞의 빈 문자열과도 일치하도록 처리합니다. 버퍼의 시작이나 끝과 항상 일치하는 특수 문자 시퀀스(~\`~ 와 ~\'~)도 있습니다. 즉, ~M~ 은 다중 행(/multi-line/)을 의미합니다.

주소가 지정되지 않으면 모든 줄이 일치 대상으로 처리되며, 하나의 주소가 지정되면 해당 주소와 일치하는 줄만 일치 대상으로 처리됩니다.

주소 범위는 쉼표(~,~)로 구분된 두 개의 주소를 지정해서 정의할 수 있습니다. 주소 범위는 첫 번째 주소가 일치하는 위치부터 시작해서 두 번째 주소가 일치하는 위치까지(해당 위치 포함)의 줄과 일치합니다.

두 번째 주소가 정규식인 경우, 끝 부분 일치 확인은 첫 번째 주소와 일치하는 줄 바로 다음 줄부터 시작됩니다. 범위 일치는 항상 최소 두 줄을 포함합니다(물론 입력 스트림이 끝나는 경우는 예외입니다).

두 번째 주소가 첫 번째 주소와 일치하는 줄보다 작거나 같은 숫자인 경우, 한 줄만 일치합니다.

GNU sed는 몇 가지 특수한 주소 형식도 지원하며, 이 모든 것은 GNU 확장 기능입니다:

- ~0,/regexp/~ ::
~0,/regexp/~ 같이 주소 지정에서 줄 번호 ~0~ 을 사용할 수 있으며, 이 경우 sed는 입력 첫 번째 줄도 /regexp/ 와 일치하는지 확인합니다. 다시 말해, ~0,/regexp/~ 는 ~1,/regexp/~ 와 유사하지만, addr2가 입력의 첫 번째 줄과 일치할 경우 ~0,/regexp/~ 형식은 이를 범위의 끝으로 간주하는 반면, ~1,/regexp/~ 형식은 범위의 시작과 일치시켜 정규 표현식이 두 번째로 나타나는 위치까지 범위가 확장되도록 합니다.

이 경우만 “0 주소가 의미가 있다!” 는 점에 유의하십시오. 사실 0번 줄은 존재하지 않으며, 다른 방식으로 0 주소가 지정된 명령은 오류를 발생시킵니다.

- ~addr1,+N~ ::
addr1 과 addr1 다음의 N 줄을 일치시킵니다.

- ~addr1,~N~ ::
addr1 과 addr1 이후의 줄 중에서 입력 줄 번호가 N 의 배수인 다음 줄까지 일치하는 줄을 선택합니다.

주소 지정의 끝에 ~!~ 문자를 추가하면 일치 조건이 반전됩니다. 즉, 주소 범위 뒤에 ~!~ 문자가 오면 해당 주소 범위와 일치하지 않는 줄만 선택됩니다. 이는 단일 주소도 적용되며, 다소 역설적이지만 null 주소도 적용됩니다.


** 2.2. Regular Expression Syntax

sed 사용법을 익히려면 정규 표현식(줄여서 /regexp/)을 이해해야 합니다. 정규 표현식은 대상 문자열과 왼쪽에서 오른쪽으로 일치 여부를 확인하는 패턴입니다. 대부분의 문자는 일반 문자이며, 패턴 내에서 그 자체를 의미하며 대상 문자열의 해당 문자와 일치합니다. 간단한 예로, 다음 패턴

#+begin_example
The quick brown fox
#+end_example

는 대상 문자열 중 이 패턴과 완전 동일한 부분을 일치시킵니다. 정규 표현식이 강력한 점은 “패턴에 대안과 반복을 포함시킬 수 있다!” 는 데 있습니다. 이런 요소들은 패턴 내에서 특수 문자를 사용해서 인코딩되는데, 이 특수 문자들은 그 자체를 나타내는 것이 아니라 특정한 방식으로 해석됩니다. 

다음은 sed에서 사용되는 정규 표현식 구문에 대한 간략한 설명입니다.

- ~char~ ::
단일 일반 문자는 그 자체와 일치합니다.

- ~*~ ::
앞에 오는 정규 표현식(일반 문자, ~\~ 로 시작하는 특수 문자, 그룹화된 정규 표현식, 또는 대괄호 표현식이어야 함)이 0회 이상 연속되는 시퀀스와 일치합니다. GNU 확장 기능으로, 후치로 정규 표현식 뒤에도 ~*~ 를 붙일 수 있습니다. 예를 들어, ~a**~ 는 ~a*~ 와 동일합니다. POSIX 1003.1-2001 사양에 따르면 ~*~ 는 정규 표현식이나 하위 표현식 시작 부분에 나타날 때는 그 자체를 의미하지만, 많은 비-GNU 구현체는 이를 지원하지 않으므로 이식 가능한 스크립트는 이런 맥락에 대신 ~\*~ 를 사용해야 합니다.

- ~\+~ ::
~*~ 와 같지만, 하나 이상을 일치시킵니다. 이는 GNU 확장 기능입니다.

- ~\?~ ::
~*~ 와 같지만, 0개 또는 1개만 일치시킵니다. 이는 GNU 확장 기능입니다.

- ~\{i\}~ ::
~*~ 와 같지만, 정확히 i개의 시퀀스를 일치시킵니다(i 는 10진 정수이며, 이식성을 위해 0 부터 255 까지(0 과 255 포함)로 유지해야 합니다).

- ~\{i,j\}~ ::
i 부터 j 까지(i 와 j 포함)의 시퀀스 수를 일치시킵니다.

- ~\{i,\}~ ::
i 개 이상의 시퀀스와 일치합니다.

- ~\(regexp\)~ ::
내부 정규식을 전체로 묶습니다. 이는 다음 용도로 사용됩니다:
~\(abcd\)*~ 같은 후치 연산자를 적용합니다. 이 경우 ‘abcd’ 로 구성된 전체 시퀀스를 0개 이상 검색하는 반면, abcd* 는 ‘abc’ 뒤에 ‘d’ 가 0개 이상 반복되는 형태를 검색합니다. POSIX 1003.1-2001 사양에는 ~\(abcd\)*~ 에 대한 지원을 요구하지만, 많은 비-GNU 구현체는 이를 지원하지 않으므로 보편적으로 이식성이 보장되지 않습니다. 역참조(아래 참조)를 사용합니다.

- ~.~ ::
줄바꿈을 포함해서 임의의 문자와 일치합니다.

- ~^~ ::
패턴 공간의 시작 부분에 있는 빈 문자열과 일치합니다. 즉, 기호 뒤에 오는 내용은 패턴 공간의 시작 부분에 위치해야 합니다.

대부분의 스크립트에서 패턴 공간은 각 줄의 내용으로 초기화됩니다(‘sed의 작동 방식’ 참조). 따라서 ~^#include~ 를 ‘#include’ 가 줄 맨 앞에 오는 줄만 일치하는 것으로 생각하는 것은 유용하고 단순화된 방법입니다. 예를 들어, 앞에 공백이 있으면 일치는 실패합니다. 이런 단순화는 ~s~ 명령어 등으로 패턴 공간의 원래 내용이 수정되지 않는 한 유효합니다.

~^~ 는 정규식이나 하위 표현식 시작 부분(즉, ~\(~ 또는 ~\|~ 뒤)에서만 특수 문자로 작용합니다. 하지만 POSIX는 해당 맥락에서 ~^~ 를 일반 문자로 취급하는 구현도 허용하므로, 이식 가능한 스크립트는 하위 표현식 시작 부분에 ~^~ 를 사용하지 않는 것이 좋습니다.

- ~$~ ::
~^~ 와 동일하지만, 패턴 공간의 끝을 나타냅니다. ~$~ 역시 정규 표현식이나 하위 표현식의 끝(즉, ~\~ 또는 ~\|~ 앞)에서만 특수 문자로 작용하며, 하위 표현식의 끝에서 사용하는 것은 이식성이 보장되지 않습니다.

- ~[목록] [^목록]~ ::
목록에 포함된 임의의 단일 문자와 일치합니다. 예를 들어, ~[aeiou]~ 는 모든 모음과 일치합니다. 목록은 ~char1-char2~ 같은 순서가 포함될 수 있으며, 이는 char1 과 char2 사이의 모든 문자(두 문자 포함)와 일치합니다.

앞에 ~^~ 가 있으면 목록의 의미가 반전되어, 목록에 포함되지 않은 임의의 단일 문자와 일치합니다. 목록에 ~]~ 를 포함하려면 이를 첫 번째 문자(필요한 경우 ~^~ 다음)로 지정하고, ~-~ 를 포함하려면 첫 번째 또는 마지막 문자로 지정하며, ~^~ 자체를 포함하려면 첫 번째 문자 뒤에 배치하십시오.

~$, *, ., [, \~ 문자는 일반적으로 목록 내에서 특별한 의미를 가지지 않습니다. 예를 들어, ~[\*]~ 는 ‘~\~’ 또는 ‘~*~’ 중 하나와 일치하는데, 이는 여기서 ~\~ 가 특별한 의미를 가지지 않기 때문입니다. 그러나 ~[.ch.], [=a=], [:space:]~ 같은 문자열은 리스트 내에서 특수하며, 각각 정렬 기호, 동치 클래스, 문자 클래스를 나타냅니다. 따라서 ~[~ 뒤에 ~.~, ~=~ 또는 ~:~ 가 올 경우, 리스트 내에서 ~[~ 는 특수 문자로 간주됩니다. 또한, /POSIXLY_CORRECT/ 모드가 아닐 때, 리스트 내에서 ~\n~ 및 ~\t~ 같은 특수 이스케이프 문자가 인식됩니다.

- ~regexp1\|regexp2~ ::
/regexp1/ 또는 /regexp2/ 둘 중 하나와 일치합니다. 복잡한 대안 정규식을 사용하려면 괄호를 사용하십시오. 일치 과정에서 각 대안을 왼쪽에서 오른쪽으로 차례로 시도하며, 가장 먼저 일치하는 것이 사용됩니다. 이는 GNU 확장 기능입니다.

- ~regexp1regexp2~ ::
/regexp1/ 과 /regexp2/ 의 연결에 일치합니다. 이 연결 연산자는 ~\|, ^, $~ 보다 우선순위가 더 높지만, 다른 정규식 연산자보다 우선순위가 낮습니다.

- ~\digit~ ::
정규 표현식 내에서 digit번째 ~\(...\)~ 괄호로 묶인 부분 표현식과 일치합니다. 이를 “역참조” (/back reference/)라고 합니다. 부분 표현식은 ~\(~ 의 출현 횟수를 왼쪽에서 오른쪽으로 세어 암시적으로 번호가 매겨집니다.

- ~\n~ ::
줄바꿈 문자와 일치합니다.

- ~\char~ ::
/char/ 와 일치합니다. 여기서 /char/ 는 ~$, *, ., [, \,~ 또는 ~^~ 중 하나입니다. 포터블하게 해석된다고 가정할 수 있는 C 스타일의 백슬래시 시퀀스는 ~\n~ 과 ~\\~ 뿐이라는 점에 유의하십시오. 특히 ~\t~ 는 포터블하지 않으며, 대부분의 sed 구현에서 탭 문자가 아닌 ‘t’ 와 일치합니다.

정규 표현식 매칭은 탐욕적(/greedy/)으로 작동합니다. 즉, 왼쪽에서 오른쪽으로 매칭을 시도하며, 동일한 문자로 시작하는 두 개 이상의 매칭이 가능한 경우 가장 긴 것으로 선택합니다.

* Using the Hold Buffer

sed가 여러 줄을 고려한 편집 기능을 수행할 수 있게 해주는 요소 중 하나가 바로 “홀드 버퍼(/hold buffer/)” 입니다. 홀드 버퍼는 특정 명령어로 내용을 수정할 수 있는 임시 저장 공간입니다.

이런 추가 버퍼가 있기 때문에, 다른 줄을 편집하는 동안에도 줄을 저장했다가 필요에 따라 각 버퍼를 처리할 수 있습니다.

다음은 홀드 버퍼에 영향을 미치는 명령어입니다:

- ~h~ :: 
현재 패턴 버퍼(현재 일치되어 작업 중인 줄)를 홀드 버퍼로 복사합니다(이때 홀드 버퍼의 기존 내용은 지워집니다).

- ~H~ :: 
현재 패턴 버퍼를 현재 홀드 패턴의 끝에 줄바꿈(~\n~) 문자로 구분해서 추가합니다.

- ~g~ :: 
현재 홀드 버퍼를 현재 패턴 버퍼로 복사합니다. 이전 패턴 버퍼는 지워집니다.

- ~G~ :: 
현재 홀드 패턴을 현재 패턴 버퍼의 끝에 줄바꿈(~\n~) 문자로 구분해서 추가합니다.

- ~x~ :: 
현재 패턴 버퍼와 홀드 버퍼의 위치를 바꿉니다.

홀드 버퍼의 내용은 어떤 방식으로든 패턴 버퍼로 이동되기 전까지는 조작할 수 없습니다!!

GIST | 이 예제는 인접한 줄을 연결하는 방법을 보여주는 절차적인 예시입니다(사실 sed는 이 작업의 상당 부분을 대신 처리해 주는 내장 명령어가 있습니다. ~N~ 명령어는 현재 줄에 다음 줄을 추가합니다. 하지만 연습을 위해 일부러 어려운 방법으로 진행하겠습니다).

먼저 주목할 점은 “~-n~ 옵션이 자동 출력을 억제하는 데 사용된다!” 는 것입니다. 따라서 sed는 명시적으로 지시할 때만 출력합니다.

스크립트 첫 번째 부분은 ~1~2h~ 입니다. 앞부분은 주소 지정으로, 첫 번째 줄에 이어 그 이후의 모든 홀수 줄(즉, 1, 3, 5, 7… 줄)에 후속된 작업을 수행하라는 의미입니다. ~h~ 부분은 일치하는 줄을 홀드 버퍼로 복사하는 명령입니다.

명령 후반부는 좀 더 복잡합니다. 이 부분 역시 주소 지정으로 시작합니다. 이번에는 짝수 줄을 가리킵니다(첫 번째 명령과 반대입니다).

명령의 나머지 부분은 중괄호로 묶여 있습니다. 이는 나머지 명령들이 방금 지정한 주소를 상속받음을 의미합니다. 이 중괄호가 없다면 ~H~ 명령만 주소를 상속받고, 나머지 명령들은 모든 줄에서 실행될 것입니다.

~H~ 명령은 줄바꿈 문자와 그 뒤에 이어지는 현재 패턴 버퍼를 현재 홀드 패턴의 끝에 복사합니다.

이런 패턴(홀수 번호의 줄, 그 뒤에 줄바꿈 문자가 오고, 그 뒤에 짝수 번호의 줄이 오는 형태)은 ~g~ 명령어를 사용해서 패턴 버퍼로 다시 복사됩니다(이전 패턴 버퍼를 대체함).

다음으로, 줄바꿈 문자를 공백으로 바꾸고 ~p~ 명령어를 사용해서 해당 줄을 출력합니다.

#+begin_src
-n '1~2h;2~2{H;g;s/\n/ /;p}'

John Adams, 1797-1801
Thomas Jefferson, 1801-1809
James Madison, 1809-1817
James Monroe, 1817-1825

Thomas Jefferson, 1801-1809 James Madison, 1809-1817
#+end_src
