== 요약

이 글은 Windows(cmd.exe)에서 사용할 수 있는 스트림 에디터 `sed.js` 를 소개합니다. CUI의 텍스트 처리는 Unix 계열 OS(이하 Unix)에서 널리 이루어지며, 그 편의성은 잘 알려져 있습니다. 그러나 Windows는 GUI가 중시되기 때문에 CUI의 텍스트 처리는 일반적이라고 할 수 없으며, 표준 Windows는 그런 기능이 전혀 제공되지 않습니다footnote:[일단 PowerShell 이 존재하지만, 사용감은 Unix의 텍스트 처리와 크게 다르며, 이용 목적도 (아마도) 다릅니다.]. 

이런 상황에서 기술자에게 지급되는 PC는 범용성 측면에서 Windows가 선택되는 경우가 많으며, 또한 지급된 PC에 임의의 소프트웨어를 설치하는 것은 원칙적으로 금지되어 있습니다. 이 문제를 해결하기 위해 Windows 표준 기능만으로 작성 및 실행 가능한 텍스트 처리 명령어 sed.js 를 만들었습니다. 

sed.js 는 명령 프롬프트에서 sed.bat 를 통해 호출되어 작동하며, GNU sed와 거의 동등한 기능을 제공합니다. 이 글은 일반적인 sed 기능 확인과 sed.js 구현 개요, 그리고 현재 공개된 sed 스크립트를 실행한 결과에 대해 설명합니다.

소스 코드는 https://github.com/asterisk9101/wincmd/blob/master/scripts/sed.js[GitHub^]에 공개되어 있습니다. sed.js 실행 방법은 http://qiita.com/asterisk9101/items/7da60f8c8859d6e4dffe[별도의 글^]을 참조합니다.


== 서론

sed는 유닉스에서 대표적인 텍스트 처리 명령어입니다. sed는 입력 스트림(파일 또는 파이프라인을 통한 입력)을 변환해서 출력하는, 이른바 필터 역할을 합니다. 주요 특징은 정규 표현식을 지원해서 “다양한 입력에 대한 유연한 변환이 가능하다” 는 점을 들 수 있습니다. 또한 “sed 스크립트” 라고 불리는 스크립트 언어를 사용함으로써, 복잡한 변환 처리를 스크립트(파일)로 저장할 수 있습니다.

이런 편의성이 있는 반면, 기술자에게 지급되는 PC는 일반적으로 Windows이며, 표준 상태는 sed와 유사한 명령어가 존재하지 않습니다footnot:[PowerShell을 제외하면, 예전에 EDLIN 명령어가 있었지만, 64비트 OS는 사용할 수 없을 뿐만 아니라, 현재 OS에서 사용하려면 몇 가지 문제가 있었습니다.]. sed와 동등한 기능을 제공하는 소프트웨어가 몇 가지 존재footnote:[cygwin, mingw 등]하지만, 일반적인 기업에 지급된 PC는 임의의 소프트웨어를 설치하는 것이 금지되어 있습니다. 이런 현 상황에 대해 즉각적인 효과가 있으면서도 유효한 대처 방법은 알려져 있지 않습니다footnote:[있다면 알려주세요.]. 또한, Windows 7 이후의 OS는 PowerShell이 표준 스크립팅 환경으로 탑재되지만, 다음과 같은 점으로 인해 sed의 대체 수단으로 삼기에는 적절하지 않습니다.

* 범용적인 스크립팅 환경이기 때문에 텍스트 처리 코드가 장황해지기 쉽습니다.
* 기본 설정은 파일에 저장된 스크립트를 실행할 수 없습니다.

그래서 Windows의 표준 스크립팅 환경인 Windows Script Host(cscript.exe)에서 작동하는 텍스트 처리 명령어로 sed.js 를 만들었습니다. sed.js는 본질적으로 텍스트 파일이기 때문에, 별도의 소프트웨어를 설치하지 않고 생성부터 실행까지 가능합니다. sed.js는 GNU sed의 기능을 Windows 환경에서 재현하는 것을 목적으로 제작되었으며, Unix 계열의 ASCII 텍스트 파일과 Windows에서 생성된 텍스트 파일을 동일하게 처리할 수 있습니다footnote:[문자 코드는 ASCII 호환이어야 합니다. 멀티바이트 UTF-8 은 WSH에서 정상적으로 읽을 수 없습니다.].

이 글은 텍스트 처리 도구인 sed를 제작하면서 알게 된 점과, sed.js의 구현 세부 사항, sed 스크립트의 실행 검증, 향후 과제 등에 대해 설명합니다.


== sed의 특징

이 섹션은 일반적인 sed의 특징에 대해 확인해 보겠습니다.


== sed의 기본적인 동작

sed는 입력 스트림에서 한 줄을 읽어들인 후, “패턴 스페이스” 라고 불리는 영역에 저장합니다. 이때 줄바꿈은 생략됩니다. 그리고 패턴 스페이스에 저장된 문자열은 출력 스트림으로 전송됩니다. 이때 다시 줄바꿈이 추가됩니다. sed는 입력 스트림이 끝날 때까지 입력 스트림을 읽고, 패턴 스페이스에 저장한 뒤, 패턴 스페이스를 출력 스트림으로 전송하는 주기를 반복합니다.


== sed 명령어

sed는 여러 가지 명령어를 지정해서 동작을 제어할 수 있습니다. 가장 자주 사용되는 명령어는 `s` 입니다. `s` 는 아마 _substitute_ (치환)의 머리글자이며, 패턴 스페이스에 저장된 문자열을 치환합니다. 그 결과, 출력되는 문자열은 치환된 문자열입니다. 이 명령어는 입력되는 모든 행에 매번 적용됩니다. 잘 알려진 명령어를 크게 분류하면 다음과 같은 종류로 나눌 수 있습니다.

* 저장 영역을 조작하는 명령(h, H, g, G, x)
* 패턴 스페이스의 문자열을 가공하는 명령(c, s, y, d, D)
* 패턴 스페이스의 입력과 출력을 수행하는 명령(n, N, p, P)
* 패턴 스페이스의 문자열을 파일에 출력하는 명령(w, W)
* 기타 출력을 수행하는 명령(a, i, =, r, R)
* 명령을 그룹화하는 것({, })
* 명령의 실행 순서를 제어하는 것(b, t, T, q, Q)
* 주석(#)

앞서 언급한 `s` 등 몇몇 명령은 인수를 받을 수 있으며, 명령 뒤에 /regexp/replacement/ 같이 지정합니다. 인수의 구문은 명령에 따라 다르며, 최근 주류를 이루는 프로그래밍 언어와 비교하면 매우 원시적인 구문을 가지고 있습니다.


== 주소 지정

대부분의 명령어는 “주소” 라는 지정을 통해 실행 시점(명령어를 실행할 행)을 제어할 수 있습니다. sed는 행을 패턴 공간에 읽어들이면 주소를 평가하고, “주소가 나타내는 조건이 참일 때만 명령어를 실행” 합니다. 주소는 숫자를 사용해서 행 번호를 지정하거나, 정규 표현식과 일치하는 행을 지정할 수 있습니다. 또한, 숫자와 정규 표현식을 조합해서 범위로 지정하거나, 낱낱이 흩어진 행을 지정할 수 있습니다. 주소의 구문은 다음과 같습니다.

.syntax
----
<address>     := <number_addr>
              := <regexp_addr>
              := <step_addr>
              := <range_addr>
<number_addr> := [0-9]+
<regexp_addr> := ‘/’ <string> '/'
<step_addr>   := <number_addr> ‘~’ <number>
              := <regexp_addr> ‘~’ <number>
<range_addr>  := <number_addr> ‘,’ <number_addr>
              := <regex_addr> ‘,’ <regex_addr>
              := <step_addr> ‘,’ <number_addr>
              := etc
----

이 외에도 스트림의 끝을 나타내는 `$` 와 부정을 나타내는 `!` 가 있습니다.


== sed 스크립트

sed 명령어는 스크립트 형태로 연속 실행할 수 있습니다. sed 스크립트는 다음과 같은 문(_statement_)의 집합으로 구성됩니다.

.sed_script
----
<statement> := [<address>]<command>[<arguments>]
----

sed는 텍스트를 “행 단위로 처리” 하기 때문에, 해당 스크립트의 구문은 어떤 행(_address_)에 어떤 처리를 할 것인가(_command, arguments_)라는 형태를 취합니다. 이 중 `<address>` 는 생략 가능하며, 생략하면 입력된 모든 행에 `<command>` 와 `<arguments>` 로 지정된 처리를 수행합니다. `<arguments>` 는 `<command>` 에 따라 구문이 달라지며, 경우에 따라 생략 가능합니다.


== 명령 그룹화와 제어 명령

sed 명령은 여러 명령을 그룹화하는 것(`{, }`)과, 명령의 실행 순서를 제어하는 것(`:, b, t, T`, ...)이 있습니다. 이런 명령은 주로 스크립트를 작성할 때 사용됩니다.

그룹화된 명령은 `{` 앞에 지정된 주소가 참인 경우만 실행됩니다!

명령의 실행 순서를 제어하는 명령은 이른바 goto 문이며, `:` 으로 표시된 레이블 위치로 명령의 실행 위치를 이동시킵니다. 이 전환은 제한이 없어, 그룹화된 명령에서 빠져나오거나 반대로 그룹화된 명령 안으로 들어가는 것도 가능합니다.

다음 스크립트는 원래대로면 입력의 10번째 줄만 출력되야(`p` 명령어)하는데, 모든 줄에서 label 로 제어권이 이동하기(`b` 명령어) 때문에 모든 줄이 출력됩니다.

----
b label
10 {
   : label
   p
}
----


== 구현 개요

이 섹션은 sed.js를 어떻게 구현했는지에 대해 설명합니다.

sed.js는 일반적인 스크립트 언어 처리기와 마찬가지로, 스크립트를 해석해서 명령어 시퀀스를 구성하는 “컴파일러” 와, 명령어 시퀀스를 실행하는 “가상 머신” 으로 구성됩니다.


== 컴파일러

컴파일러는 주어진 sed 스크립트를 해석해서 명령어 시퀀스를 구성합니다. 일반적으로 컴파일러는 어휘 분석부와 구문 분석부로 나뉩니다. 그러나 sed 스크립트는 원시적인 구문을 가지기 때문에, 구문을 결정하기 전에 어휘를 분할하는 것이 어려웠습니다. 따라서 컴파일러는 어휘 분석과 구문 분석을 동시에 수행하는 함수로 구현했습니다footnote:[이로 인해 문법이 변경될 경우, 컴파일러 변경도 필요할 위험이 발생합니다. 하지만 sed는 이미 완성된 상태이므로 별 문제는 없을 것으로 보입니다.]. 이를 parser() 함수라고 합니다. parser() 함수의 간략화된 구현은 다음과 같습니다.

.sed.js
[source,js]
----
var text = sed_script;
var at = 0;
var ch = text.charAt(at);

function statements() {
    var head, stat;
    head = statement();
    stat = head;
    while(/* stat이 생성되는 한 계속됨 */){
        stat.next = statement();
        stat = stat.next;
    }
    return head;
}

function statement() {
    var addr = address();
    var cmd = command();
    return new Statement(addr, cmd);
}

function address() {
    var addr;
    switch(ch) {
    case “/”:       addr = new RegexAddr(/* 정규식을 파싱한 문자열 */); break;
    case /* 0-9 */: addr = new NumberAddr(/* 숫자를 파싱한 문자열 */); break;
    ...
    default: /* 주소 지정 없음 */ break;
    }
    return addr;
}

function command() {
    var cmd, name, args = [];
    name = ch;       // sed 명령어는 1글자로 표현됩니다
    switch(name) {
    case /* 명령어 */:
        args.push(/* name에 따른 인자 파싱 */)
        break;
    ...
    default: error();
    }
    return new Command(name, args);
}
----

맨 앞의 변수 text, at, ch 는 parser() 함수 전체에서 공유되며, 각각 sed 스크립트 전체를 나타내는 문자열, 분석 중인 위치, 분석 중인 한 글자를 저장합니다. 이어지는 4개의 함수는 인자 없이 호출되지만, 분석 위치를 공유하고 있기 때문에 sed 스크립트 전체를 순차적으로 분석해 나갈 수 있습니다.


== 명령열의 데이터 구조

parser() 함수는 sed 스크립트 전체를 스캔해서 명령열을 구성합니다. 명령열은 연결 리스트로 구현되며, 연결 리스트의 각 요소는 다음과 같은 데이터 구조로 정의되었습니다.

.연결 리스트 각 요소의 데이터 구조
----
statement
|- next       ... 다음 statement를 가리키는 포인터
|- address    ... address를 나타내는 객체
`- cmd        ... command를 나타내는 객체
   |- name    ... 명령어 이름을 나타내는 문자열
   `- args    ... arguments를 나타내는 배열
----

address 객체는 몇 가지 종류가 있습니다. 이들은 공통적으로 실행 중인 sed의 상태(sed_state)를 받아, address가 나타내는 조건에 부합하는지 판단하는 match 메서드를 가지고 있습니다. 후술할 가상 머신은 match 메서드의 판정에 따라 cmd를 실행할지 여부를 결정합니다.


== 가상 머신

sed 가상 머신(명령 평가기)은 컴파일러가 생성한 명령열을 실행하는 부분입니다. 가상 머신은 간단히 말해 다음과 같은 루프를 돌림으로써, 입력 행마다 명령열을 실행합니다.

.sed.js
[source,js]
----
while(!stream.AtEndOfStream)
    read()                 // 입력 행
    pc = stat_head;        // 명령어열(연결 리스트)의 첫 번째 항목
    while(pc){
        if (match()) {
            exec();
        }
        next();            // 다음 명령어를 읽어오는 함수
    }
    flush();
}
----

pc는 가상 머신이 다음에 실행할 명령(statement 객체)을 저장합니다. 가상 머신은 먼저 read() 를 통해 새로운 행을 패턴 스페이스에 읽어들이고, pc에 첫 번째 명령인 stat_head 를 설정합니다. 이어서 match() 함수를 통해 pc.addr 을 평가하고, 결과가 참인 경우만 exec() 함수를 실행합니다. exec() 함수는 pc.cmd.name 에 따라 적절한 함수에 pc를 전달하는 디스패처입니다. exec() 함수는 pc를 재설정하는 경우가 있으며, 라벨로 점프하는 명령어(`b, t, T`)는 pc의 재설정을 통해 구현됩니다.

특수한 명령어로 `{` 와 `}` 가 있습니다. 이 두 명령어 사이에 낀 명령어는 그룹화됩니다. 그룹화된 명령어는 `{` 에 부속된 주소와 일치해야만 실행됩니다. 예를 들어, 다음과 같은 sed 스크립트에서는 `i, p, a` 명령어가 그룹화되며, 공통 주소(1,10)를 따릅니다.

----
1,10{
    i text 삽입
    p
    a text 추가
}
----

이 기능을 구현하기 위해 가상 머신은 명령어 `{` 를 통해 다음 명령어인 pc.next 를 스택에 쌓았다가, pc.cmd.args[0] 을 pc에 설정합니다. 가상 머신은 pc.next 가 null 이 될 때까지 명령어를 실행하고, 마지막에 스택에서 pc.next 를 꺼내어 원래의 명령어열로 돌아갑니다.


== sed 동작 검증

sed.js가 제대로 구현되었는지 확인하기 위해, http://quruli.ivory.ne.jp/document/sed_4.1.2/sed-ja_4.html[인터넷에 공개된 sed 스크립트^]를 사용해서 동작을 검증했습니다. 검증 과정에서 스크립트를 수정해야 했습니다. 왜냐하면 sed.js의 정규 표현식이 “JScript 구현에 의존” 하기 때문입니다. 주요 수정 사항은 다음과 같습니다.

* `()` 를 `\` 로 이스케이프할 필요가 없어졌습니다.
* 전방 참조는 `\` 대신 `$` 를 사용해야 합니다.
* 줄바꿈 코드는 Windows 표준인 `\r\n` 을 사용합니다.

다음은 검증에 사용한 스크립트입니다. 다음 3개의 스크립트는 예상대로 동작했으며, sed.js에 일반적인 sed에 상응하는 기능이 올바르게 구현되어 있음을 확인할 수 있었습니다.


== 줄 중앙 정렬

다음 스크립트는 문자열을 너비 80자로 중앙 정렬합니다.

.centering.sed
[source,js]
----
# 버퍼에 80개의 공백을 넣습니다
1 {
  x
  s/^$/          /
  s/^.*$/$&$&$&$&$&$&$&$&/
  x
}

# 앞뒤 공백 제거
y/    / /
s/^ *//
s/ *$//

# 줄 끝에 줄바꿈과 공백 80개를 추가
G

# 처음 81자(80 + 줄바꿈)만 유지
s/^([\s\S]{81}).*$/$1/

# $2는 공백의 절반에 해당하며, 이 부분은 줄의 맨 앞으로 이동됩니다
s/^(.*)\r\n(.*)\2/$2$1$2/
----


== 숫자 증가시키기

다음 스크립트는 숫자만 포함된 줄의 값을 증가시킵니다.

.increment.sed
----
/[^0-9]/ d

# 행의 맨 앞에 있는 모든 9 를 _ 로 대체합니다(숫자 이외의 다른 문자를 사용할 수도 있습니다).
:d

s/9(_*)$/_$1/; td

# 마지막 자리수만 증가시킵니다. 첫 번째 줄은 숫자를 추가해야 할 경우 최상위 자릿수에 1을 더합니다.
# tn 명령어는 필수는 아니지만, 처리 속도를 높여줍니다
s/^(_*)$/1$1/; tn
s/8(_*)$/9$1/; tn
s/7(_*)$/8$1/; tn
s/6(_*)$/7$1/; tn
s/5(_*)$/6$1/; tn
s/4(_*)$/5$1/; tn
s/3(_*)$/4$1/; tn
s/2(_*)$/3$1/; tn
s/1(_*)$/2$1/; tn
s/0(_*)$/1$1/; tn
:n
y/_/0/
----


== 줄의 문자를 반전하기

문자열을 역순으로 표시합니다.

.reverse.sed
----
/../! b

# 한 줄을 반전합니다. 두 줄바꿈 사이에서 해당 줄을 감싸기 시작합니다.
s/^.*$/\
$&\
/

# 첫 번째 문자를 끝으로 이동합니다. 정규 표현식은 마커 사이에
# 0개 또는 1개의 문자가 있을 때까지 일치합니다.
tx
:x
s/(\r\n.)(.*)(.\r\n)/$3$2$1/
tx

# 줄바꿈 마커 제거
s/\r\n//g
----


== 마치며
이 글은 일반적인 sed 기능 확인과 sed.js 구현에 대해 소개했습니다. 또한, sed.js에서 수정한 기존 sed 스크립트를 실행해서 동작을 검증하고, 표준 Windows 환경에서 sed 기능을 재현할 수 있음을 보여주었습니다.

향후 과제는 몇 가지 미구현 명령어(r, R, l)의 구현과, 미지원 주소(n, ~m 등)의 구현, 정규 표현식의 개량이 있습니다footnote:[그리고, 이 기사가 마지막 부분에서 힘이 빠지는 느낌이라 글쓰기 실력을 키우고 싶습니다.]. 특히 정규 표현식의 경우, 기존 sed 스크립트를 재사용할 때 수정할 부분이 많아졌기 때문에, 재사용 시 수정 작업이 줄어들도록 개선하고 싶습니다.
