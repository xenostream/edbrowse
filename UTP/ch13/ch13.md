# Chapter 13 The awk Programming Language

프로그램이란 특정 언어의 구문으로 표현된 문제의 해결책입니다. sed를 사용해 복잡한 편집 스크립트를 작성하는 것에서 awk로 프로그램을 작성하는 것으로 넘어가는 것은 작은 한 걸음에 불과하지만, 많은
작성자들이 이 한 걸음을 내딛는 것을 두려워할 수 있습니다. 많은 사람들에게 ‘스크립트’라는 용어는 ‘프로그램’보다 부담감이 덜하지만, 편집
스크립트 역시 프로그램입니다.
각 프로그래밍 언어에는 다른 언어보다 특정 작업을 더 잘 수행할 수 있게 해주는 고유한 “스타일”이
있습니다. 누구나 참조 페이지를 훑어보며 언어의 구문을 빠르게 익힐 수는 있지만, 이 지식을 어떻게
적용해야 하는지 이해하기 위해서는 대개 해당 언어로 작성된 프로그램을 면밀히
살펴보는 과정이 필요합니다. 이런 의미에서 프로그래밍 언어는 단순히 또 다른 도구일 뿐이며,
사용법뿐만 아니라 언제, 왜 사용되는지까지 알아야 합니다.

하나 이상의 프로그래밍 언어를 배우는 것이 좋습니다. 우리는 이미 셸(shell), ex, sed를 위해 작성되고
이들 환경에서 실행되는 여러 가지 프로그램이나 스크립트를 살펴보았습니다. awk 프로그래밍 언어를
배워 나가다 보면, 유사점과 차이점을 발견하게 될 것입니다. 특히, awk
스크립트는 셸 스크립트와 모양이 다릅니다. awk 언어는 셸 프로그래밍 언어와 많은 기본 구문을
공유하지만, awk는 약간 다른 구문을 사용합니다. awk 프로그램의 기본
작동 방식은 sed와 크게 다르지 않습니다. 표준 입력을 한 줄씩 읽고, 패턴과 절차라는 두 부분으로 구성된
명령을 실행한 다음, 표준 출력에 결과를 기록하는 방식입니다.
더 중요한 점은, awk에는 특정 작업을 수행할 때 가장 적합한 도구로 만들어 주는 기능들이 있다는 것입니다. 프로그래밍
언어란 그 자체로, 적절한
도구가 존재하지 않았던 특정 종류의 문제를 해결하기 위해 작성된 프로그램입니다. awk 프로그램은 텍스트 처리 응용 프로그램, 특히
정보가 레코드와 필드로 구조화된 응용 프로그램을 위해 설계되었습니다. 다음 페이지에서 시연할
awk의 주요 기능은 다음과 같습니다:
• 정의 가능한 레코드 및 필드 구조
• 조건문 및 반복문
• 할당 연산자, 산술 연산자, 비교 연산자 및 논리 연산자
• 숫자 배열 및 결합 배열
• 서식이 지정된 출력 문
• 내장 함수

단일 기능을 간단히 비교해 보면, 프로그래밍 언어마다 얼마나 차이가 나는지 알 수 있습니다.
awk에서는 셸보다 산술 연산을 훨씬 쉽게 수행할 수 있습니다. 셸에서 x의 값을 1씩
증가시키려면 다음 명령어를 사용해야 합니다.
x=‘expr $x + 1‘
expr 명령어는 별도의 프로세스로 실행되어 인수의 값을 반환하는 UNIX 프로그램입니다.
반면 awk에서는 다음과 같이 작성하기만 하면 됩니다.
++x
이는 x = x + 1과 동일합니다. (이 형식은 awk에서도 사용할 수 있습니다.)



## Invoking awk

awk 프로그램 자체는 sed와 마찬가지로 입력 행에 대해 지정된 프로그램을 실행하는 프로그램입니다.
명령줄에서 또는 셸 스크립트 내에서 awk를 실행할 수 있습니다.
$ ]awk ’program’ files
입력은 하나 이상의 파일에서 한 줄씩 읽혀집니다. 셸의 간섭을 방지하기 위해 작은따옴표로 묶인
프로그램은 패턴과 절차 부분으로 구성됩니다. 패턴이 생략된 경우, 절차는
모든 입력 줄에 대해 수행됩니다:
$ awk ’{print}’ sample sample 파일의 모든 줄을 출력합니다
절차는 중괄호 안에 작성됩니다. 절차가 생략된 경우, 패턴과 일치하는 줄이 출력됩니다:
$ awk ’/programmer’s guide/’ sample sample 파일에서 패턴과 일치하는 줄을 출력합니다
awk 프로그램은 sed와 마찬가지로 0개, 1개 또는 2개의 패턴 주소를 지정할 수 있게 해줍니다. 정규
표현식은 슬래시(/) 한 쌍 안에 작성됩니다. awk에서는 패턴을 식(expression)으로 구성할 수도 있습니다.
식(정규 표현식과 혼동하지 않도록 ‘기본 식’이라고도 함)은 문자열이나
숫자 상수(예: red 또는 1), 변수(값이 문자열이거나 숫자인 경우), 또는 함수
(나중에 살펴보겠습니다)일 수 있습니다.
다음과 같이 패턴을 특정 절차와 연결할 수 있습니다.
/pattern1/ {
        procedure1
     }
/pattern2/ {
        procedure2
     }
{ procedure 3 }

sed와 마찬가지로, 특정 패턴과 일치하는 행만이 처리 대상이 되며, 한 행은
하나 이상의 패턴과 일치할 수 있습니다. 이 예제에서는 세 번째 처리가 모든 입력 행에 대해 수행됩니다. 일반적으로, 여러
줄로 구성된 awk 스크립트는 별도의 파일에 저장하고 -f 옵션을 사용하여 호출합니다:
$ awk -f awkscript sample



## Records and Fields

아마도 awk의 가장 중요한 특징은 입력의 각 줄을 필드로 나누는 점일 것입니다. 가장 간단한
경우, 각 필드는 공백으로 구분된 하나의 단어를 포함합니다. awk 프로그램을 사용하면 패턴이나
프로시저에서 입력 줄 내의 위치에 따라 이러한 필드를 참조할 수 있습니다. 기호 $0은
입력 줄 전체를 나타냅니다. $1, $2, ...는 입력 행 내의 위치에 따라 개별 필드를 가리킵니다.
파일 내의 약어 목록을 검색하는 awk 프로그램을 작성하여 이러한 기능 중 일부를 시연해 보겠습니다.
각 약어는 그 의미와 함께 나열되어 있습니다. 각 행의 첫 번째 필드를 출력하면
약어의 이름을 얻을 수 있습니다:
$ awk ’{print $1}’ sample
BASIC
CICS
COBOL
DBMS
GIGO
GIRL
약어를 지정하면 해당 설명을 얻을 수 있는 유용한 프로그램을 만들 수 있습니다.
grep과 똑같이 awk를 사용할 수도 있습니다:
$ awk ’/BASIC/’ sample
The awk Programming Language 311
BASIC 초보자를 위한 범용 기호 명령어 코드
하지만 이 프로그램을 개선하고 awk의 기능을 더 잘 활용하기 위해
다음 세 가지를 수행하고자 합니다:
1. 패턴 일치 검색 범위를 제한합니다.
2. 프로그램을 더 일반화하여 검색 대상인 특정 약어에
의존하지 않도록 합니다.
3. 설명만 출력합니다.


## Testing Fields

지정된 패턴은 줄의 어느 위치에서든 ‘BASIC’이라는 단어를 일치시킵니다. 즉, 설명에 사용된 ‘BASIC’과도
일치할 수 있습니다. 첫 번째 필드($1)가 패턴과 일치하는지 확인하려면 다음과 같이 작성합니다.
$1 == “BASIC”
기호 ==는 “같음”을 의미하는 비교 연산자로, 각 줄의 첫 번째 필드를
문자열 ‘BASIC’과 비교하는 데 사용됩니다. 또한 줄의 시작 부분에 있는 약어를 찾는 주어진 정규식을 사용하여 이 테스트를 구성할 수도 있습니다.
$1 ˜ /ˆBASIC/
패턴 일치 연산자 ˜는 표현식($1)이 정규식과 일치할 때 참으로 평가됩니다. 그
반대인 !˜는 표현식이 정규식과 일치하지 않을 때 참으로 평가됩니다.
이 두 예제는 매우 비슷해 보이지만, 결과물은 크게 다릅니다. 관계 연산자
==는 첫 번째 필드가 BASIC일 때 참으로 평가되지만, 첫 번째 필드가 BASIC,일 때는 거짓으로 평가됩니다(쉼표에 유의하십시오).
패턴 일치 연산자 ˜는 두 경우 모두를 찾아냅니다.
패턴 일치 연산은 정규 표현식(슬래시로 둘러싸인
문자열)에 대해 수행되어야 합니다. 다음 절에서 설명하듯이 셸 변수를 제외하고는
정규 표현식 내부에서 변수를 사용할 수 없습니다. 상수는 패턴 일치 연산자를 사용하여 평가할 수 없습니다.


## Passing Parameters from a Shell Script

우리 프로그램은 너무 구체적이고 입력해야 할 내용이 너무 많습니다. awk 스크립트를 파일로 저장한 다음
-f 옵션을 사용하여 호출할 수 있습니다. 또는 수행하는 기능에 따라 이름을 지정한 셸 스크립트 안에 이 명령을 넣을 수도 있습니다.
이 셸 스크립트는 명령줄에서 첫 번째 인자(약어 이름)를 읽어와
이를 awk에 매개변수로 전달할 수 있어야 합니다. 이 셸 스크립트의 이름을 awkronym으로 정하고,
acronyms라는 파일을 읽도록 설정하겠습니다. 다음은 awk 프로시저에 인수를 전달하는 가장 간단한 방법입니다:
$ cat awkronym
awk ’$1 == search’ search=$1 acronyms
awk 프로그램에 전달되는 매개변수는 프로그램 뒤에 지정됩니다. search 변수는
명령줄의 첫 번째 인수를 awk 프로그램에 전달하도록 설정되어 있습니다. 하지만 이 부분도 혼란스러울 수 있는데,
awk 프로그램 내부의 $1은 각 입력 행의 첫 번째 필드를 나타내는 반면, 셸에서 $1은
명령줄에서 제공된 첫 번째 인수를 나타내기 때문입니다. 이 버전의 프로그램이 작동하는 방식은 다음과 같습니다:
$ awkronym CICS
CICS Customer Information Control System
검색 문자열 BASIC을 변수(CICS 또는 BASIC 문자열로 설정 가능)로 대체함으로써,
상당히 일반화된 프로그램을 얻을 수 있습니다.

매개변수를 문자열로 테스트해야 했다는 점에 유의하십시오($1 == search). 이는 정규식 내부에서는
매개변수를 전달할 수 없기 때문입니다. 따라서 ‘‘$1 ˜ /search/’’ 또는 ‘‘$1 ˜
312 유닉스 텍스트 처리
search’’와 같은 표현은 구문 오류를 발생시킵니다.
부연 설명으로, 정규 표현식 내부에서도 작동하는 셸 변수를 awk 프로그램으로 가져오는 또 다른 방법을
살펴보겠습니다. 하지만 이 방법은 다소 복잡해 보입니다:
search=$1
awk ’$1 ˜ /’“$search”’/’ acronyms

이 프로그램은 이전 버전과 동일하게 작동합니다(인수가 정규 표현식 내부에서
평가된다는 점을 제외하면). 스크립트의 첫 번째 줄은 awk가 호출되기 전에 변수 할당을
수행한다는 점에 유의하십시오. awk 프로그램에서 셸 변수는 먼저 작은따옴표로, 그 다음 큰따옴표로 묶여 있습니다.
이러한 따옴표로 인해 awk가 정규식을 해석하기 전에 셸이 $search의 값을 정규식 내부에 삽입하게
됩니다. 따라서 awk는 셸 변수를 인식하지 못하고 이를 상수 문자열로 평가합니다.
정규식 내에 awk 변수를 넣을 수 있으면 좋겠다고 생각되는 상황이 종종 있을 것입니다. 이전 섹션에서 언급했듯이, 패턴 매칭을 통해 다양한
출현 형태를 검색할 수 있습니다. 예를 들어, 필드에는 우연히 포함된 구두점이 있을 수 있으며, 해당 구두점이
문자열에 포함되어 있지 않으면 고정된 문자열과 일치하지 않을 수 있습니다. 어쩌면 정규 표현식 내에서 awk 변수가 해석되도록 하는
문서화되지 않은 방법이 있을 수도 있고, 아니면 알아내야 할 복잡한
우회 방법이 있을지도 모릅니다.



## Changing the Field Separator

awk 프로그램은 필드와 레코드로 구성된 데이터를 처리하도록 설계되었습니다. 레코드는 일반적으로 하나의 입력 행으로,
하나 이상의 필드로 구성됩니다. 필드 구분자는 공백이나 탭이며, 레코드 구분자는
줄바꿈입니다. 예를 들어, 다음은 다섯 개의 필드로 구성된 하나의 레코드입니다:
CICS Customer Information Control System
세 번째 필드, 즉 $3은 “Information”이라는 문자열입니다. 이 프로그램에서는 설명을 하나의
필드로 출력할 수 있기를 원합니다. 단순히 print $2라고만 해서 전체 설명을 얻을 수는 없다는 것이
명백합니다. 하지만 바로 그 작업을
수행할 수 있기를 바랍니다.
이를 위해서는 공백이 아닌 다른 문자를 사용하여 필드를 구분하도록
입력 파일을 수정해야 합니다. 탭은 필드 구분자로 자주 사용됩니다. 첫 번째와 두 번째
필드 사이에 탭을 삽입해야 합니다:
$ cat acronyms
awk Aho, Weinstein & Kernighan
BASIC Beginner’s All-Purpose Symbolic Instruction Code
CICS Customer Information Control System
COBOL Common Business Orientated Language
DBMS Data Base Management System
GIGO Garbage In, Garbage Out
GIRL Generalized Information Retrieval Language

-F 옵션을 사용하여 명령줄에서 필드 구분자를 변경할 수 있습니다:
$ awk -F“|——|” ’$1 == search {print $2}’ search=$1 acronyms
|——|는 큰따옴표를 입력한 후 TAB 키를 누르고, 다시 큰따옴표를 입력하여 입력한다는 점에 유의하십시오. 이렇게 하면 탭 문자(예제에서는 |——|로 표시됨)가 유일한 필드 구분자로
사용되며, 공백은 더 이상 필드를 구분하는 역할을 하지 않습니다. 세 가지 개선 사항을 모두 구현했으니, 이제
프로그램이 어떻게 작동하는지 살펴보겠습니다:
$ awkronym GIGO
Garbage In, Garbage Out

NR 현재 레코드의 번호
OFS 출력 필드 구분자 (공백)
ORS 출력 레코드 구분자 (줄바꿈)
RS 레코드 구분자 (줄바꿈)
시스템 변수 FS는 awk에서 사용하는 필드 구분자를 정의합니다. FS는 프로그램 내부에서
설정할 수도 있고 명령줄에서 설정할 수도 있습니다.
일반적으로 필드 또는 레코드 구분자를 재정의하는 경우, 이는 BEGIN 프로시저의 일부로 수행됩니다.
BEGIN 프로시저를 사용하면 첫 번째 입력 행이 읽히기 전에 수행될 작업을 지정할 수 있습니다.
BEGIN { FS = “|——|” }
또한 END 프로시저를 정의하여 모든 입력이 읽힌 후에 수행될 작업을 지정할 수도 있습니다.
awk 명령어는 변수 NF를 현재 줄의 필드 수로 설정합니다. 임의의 텍스트 파일에서
다음 awk 명령어를 실행해 보세요:
$ awk ’{print $NF}’ test
현재 레코드에 필드가 다섯 개 있다면, NF는 5로 설정되며, $NF는 다섯 번째이자 마지막 필드를 가리킵니다.
조만간 이 변수를 효과적으로 활용하는 double이라는 프로그램을 살펴보겠습니다.


## Looping

awkronym 프로그램은 입력 파일의 구조를 재구성하고 필드 구분자를 재정의했기 때문에 두 번째 필드를 출력할 수 있습니다.
때로는 이러한 방법이 실용적이지 않을 수 있으며, 각 레코드에서 특정 수의 필드를 읽거나 출력하기 위해
다른 방법이 필요할 수도 있습니다. 필드 구분자가 공백이나 탭인 경우, 두 레코드는 각각 6개와 5개의 필드를
가지고 있을 것입니다.
BASIC: 초보자를 위한 다목적 기호 명령어 코드
CICS: 고객 정보 제어 시스템
레코드의 필드 수가 가변적인 것은 드문 일이 아닙니다. 첫 번째 필드를 제외한 나머지 모든 필드를 출력하려면, 우리 프로그램에는
남은 필드 수만큼 반복되는 루프가 필요합니다. 많은 awk 프로그램에서
루프는 흔히 사용되는 절차입니다.
while 문은 루프를 구성하는 데 사용할 수 있습니다. 예를 들어, 어떤 절차를
세 번 수행하려면, 루프 하단에서 변수를 증가시켜 루프를 몇 번 돌았는지 추적한 다음,
루프 상단에서 해당 변수가 3보다 큰지 확인합니다. 입력 행을 세 번 출력하는
예를 들어 보겠습니다.
{ i = 1
while (i <= 3) {
print
++i
}
}

하나 이상의 동작으로 구성된 절차를 기술하려면 루프 내부에 중괄호가 필요합니다. 이 프로그램에서는 세 가지
연산자가 사용됩니다. =는 변수 i에 값 1을 할당하고, <=는 i의 값을 상수 3과
비교하며, ++는 변수의 값을 1씩 증가시킵니다. while 문이 처음 실행될 때, i는
1입니다. 표현식 i <= 3이 참이므로, 해당 절차가 수행됩니다. 이 절차의 마지막
작업은 변수 i를 1 증가시키는 것입니다. 두 번째 루프가 끝난 후 i가 3으로
증가했기 때문에 while 표현식은 참이 됩니다. 그러나 세 번째 루프가 끝나면 i가 4로 증가하고, 이 표현식은
거짓으로 평가됩니다.
for 루프는 while 루프와 동일한 목적을 가지지만, 구문이 더 간결하여
기억하고 사용하기 쉽습니다. 앞서 본 while 문이 for 루프로 재구성된 모습은 다음과 같습니다:
for (i = 1; i <= 3; i++)
print
for 문은 괄호 안에 포함된 세 개의 표현식으로 구성됩니다. 첫 번째 표현식인 i = 1은
카운터 변수의 초기값을 설정합니다. 두 번째 표현식은 루프 시작 부분에서 검사되는 조건을
명시합니다. (while 문은 루프 끝 부분에서 조건을 검사했습니다.) 세 번째 표현식은
카운터를 증가시킵니다.

이제 해당 행의 나머지 필드를 순회하기 위해, 루프를 몇 번이나
실행해야 하는지 결정해야 합니다. 시스템 변수 NF에는 현재 입력 레코드의 필드 수가 저장되어 있습니다. 루프를 돌 때마다
카운터(i)를 NF와 비교하면, 모든 필드가
읽혀진 시점을 파악할 수 있습니다:
for (i = 1; i <= NF; i++)
각 필드($i)를 한 줄에 하나씩 출력하겠습니다. awk가 어떻게 작동하는지 보여주기 위해, 각 필드 앞에 레코드 번호와
필드 번호를 출력해 보겠습니다.
awk ’{ for (i = 1; i <= NF; i++)
print NR“:”i, $i } ’ $*
print 문은 NR, 콜론, i를 연결한다는 점에 유의하십시오. 쉼표는 출력 필드 구분자로 사용되며,
기본값은 공백입니다.

1:2 Aho,
1:3 Weinstein
1:4 &
1:5 Kernighan
2:1 BASIC
2:2 Beginner’s

2:5 Instruction

Symbolic은 두 번째 레코드의 네 번째 필드입니다. 샘플 파일이 acronyms라는 점에 주목할 수 있습니다. 이 파일은
첫 번째 필드와 두 번째 필드 사이에 탭 문자를 삽입한 파일입니다. 기본 필드 구분자를 변경하지 않았기 때문에,
awk는 탭이나 공백을 필드 구분자로 해석했습니다. 이를 통해 탭의 특수 값을 무시하는 프로그램을 작성할 수 있습니다.


### Conditional Statements

이제 예제를 수정하여, 인수가 주어지면 해당 인수가 나타나는 레코드와 필드
번호를 반환하도록 합시다.
기본적으로 각 필드를 검사하여 인수와 일치하는지 확인하고, 일치할 경우 해당
레코드와 필드 번호를 출력하고자 합니다. 이를 위해 또 다른 흐름 제어 구조인 if 문이 필요합니다. if
문은 식을 평가하여, 참이면 절차를 수행하고, 거짓이면 수행하지 않습니다.
다음 예제에서는 if 문을 사용하여 현재 필드가 인자와
일치하는지 확인합니다. 일치할 경우, 현재 레코드 번호와 필드 번호를 출력합니다.
awk ’{ for (i = 1; i <= NF; i++) {
if ($i == search) {
print NR“:”i
}
}
} ’ search=$1 acronyms
이 새로운 절차는 2:1이나 3:4를 출력하며, 그 자체로는 그다지 유용하지는 않지만, 어떤 레코드에서든
임의의 단일 필드를 추출하여 검사할 수 있음을 보여줍니다.
다음 프로그램인 double은 한 줄의 첫 번째 단어가
이전 줄의 마지막 단어와 중복되는지 확인합니다. 우리는 문서 교정 시 double을 사용하며, 이 프로그램은 놀라울 정도로 흔한 타이핑 실수를
포착해 줍니다.
awk ’
NF > 0 {
if ($1 == lastword) {
print NR “: double ” $1
}
lastword = $NF
}’ $1

입력의 첫 번째 줄이 읽혀질 때, 필드 수가 0보다 크면 if
문 내의 식이 평가됩니다. 변수 lastword가 설정되지 않았기 때문에, 이 식은 false로 평가됩니다. 마지막
작업에서는 $NF의 값을 변수 lastword에 할당합니다. ($NF는 마지막 필드를 가리키며, NF의 값은
마지막 필드의 번호입니다). 다음 입력 행이 읽히면, 첫 번째 단어가 lastword의 값과
비교됩니다. 둘이 같으면 메시지가 출력됩니다.
double sect1
15: double the
32: double a
이 버전의 double은 Kernighan과 Pike가 『The UNIX Programming
Environment』에서 소개한 프로그램을 기반으로 합니다. (Writer’s Workbench에는 이제 이 프로그램이 포함되어 있습니다.) Kernighan과 Pike의 프로그램은 또한
같은 줄에서 나란히 있는 중복 단어를 확인합니다. for 루프를 사용하고 현재 필드를 이전 필드와 비교하여
이 기능을 구현해 볼 수도 있습니다. Kernighan
과 Pike의 double의 또 다른 특징은 이 프로그램을 하나 이상의 파일에서 실행할 수 있다는 점입니다. 추가 파일을 처리하려면
셸 변수를 $1에서 $*로 변경할 수 있지만, NR이 출력하는 레코드 또는 줄 번호는
연속된 입력 줄에 해당합니다. 새 파일에서 입력을 읽기 전에 NR을 0으로 재설정하는
프로시저를 작성할 수 있겠습니까?


### Arrays

이 이중 프로그램은 변수에 데이터를 할당하여 데이터를 저장하는 방법을 보여줍니다. awk에서는 다른
여러 프로그래밍 언어와 달리, 프로그램에서 변수를 참조하기 전에 변수를 초기화할 필요가
없습니다. 앞의 프로그램에서는 lastword를 맨 위에서 평가했지만, 실제로는
프로그램의 맨 마지막에 이르러서야 값이 할당되었습니다. 이 awk 프로그램은 변수가 문자열로 참조되는지 숫자 값으로 참조되는지에 따라
빈 문자열 또는 0으로 설정하여 변수를 초기화했습니다.
배열은 항목이나 요소의 목록을 저장할 수 있는 변수입니다. 배열은
식당 메뉴와 유사합니다. 이 메뉴의 각 항목에는 번호가 매겨져 있습니다.
#1 참치 누들 캐서롤
#2 로스트 비프와 그레이비
#3 돼지고기 콩 요리
로스트 비프를 주문하는 한 가지 방법은 간단히 “2번”이라고 말하는 것입니다. 일반 변수를 사용한다면,
‘two’라는 변수를 정의하고 그 값으로 ‘로스트 비프와 그레이비’를 할당해야 했을 것입니다. 배열은
관련된 값들의 그룹을 참조하는 방법입니다. 이는 다음과 같이 작성할 수 있습니다:
menu[choice]
여기서 menu는 배열의 이름이고, choice는 배열 내의 항목을 참조하는 데 사용되는 인덱스입니다.
따라서 menu[1]은 참치 누들 캐서롤과 같습니다. awk에서는 배열의 크기를 선언할 필요가 없으며,
(참조하기 전에) 배열을 로드하기만 하면 됩니다. 세 가지 메뉴 선택 항목을 파일의 각기 다른 줄에
적어 놓았다면, 다음 문장을 사용하여 배열을 로드할 수 있습니다:
menu[NR] = $0

변수 NR(레코드 번호)은 배열의 인덱스로 사용됩니다. 각 입력 행은 배열의
다음 요소로 읽어집니다. 인덱스의 값(이 값을 설정하는 변수가 아닌)을 참조하여 개별 요소를 출력할 수 있습니다.
print menu[3]
이 문장은 배열의 세 번째 요소인 ‘pork and beans’를 출력합니다. 이 배열의 모든
요소를 참조하려면 for 루프의 특수한 형태를 사용할 수 있습니다. 구문은 다음과 같습니다.
for (element in array)
이 문장을 사용하면 배열을 순회하며 모든 요소를 출력할 수 있습니다.
for (choice in menu)
print menu[choice]
루프를 한 번 돌 때마다 변수 choice는 배열의 다음 요소로 설정됩니다. menu 배열은
요소의 인덱스로 숫자 첨자를 사용하는 배열의 예시입니다.
이제 배열을 사용하여 awkronym의 기능을 확장해 보겠습니다. 새로운 버전은
파일에서 약어를 읽어와 배열에 저장한 다음, 두 번째 파일을 읽어 약어를 검색할 것입니다.
기본적으로, 하나의 입력 파일을 읽어들이고 다른 파일에서 검색할 키워드를 정의하는 것입니다.
용어집에 있는 용어 목록을 읽어들이는 유사한 프로그램은 해당 단어가 챕터 내 어디에 나타나는지 보여줄 수 있습니다.
먼저 어떻게 작동하는지 살펴보겠습니다:
$ awkronym sect1

프로그램을 자세히 살펴보겠습니다.
awk ’ {
if ( FILENAME == “acronyms” ) {
acro_desc[NR] = $1
next
}
for ( name in acro_desc )
for (i = 1; i <= NF; i++)
if ($i == acro_desc[name] ) {
print $0
}
}’ acronyms $*
현재 파일 이름은 시스템 변수 FILENAME에 저장됩니다. 첫 번째 조건문 내의 절차는
acronyms 파일에서 입력을 받는 동안에만 수행됩니다. 다음 문은 파일에서 다음 입력 줄을 읽어
이 절차를 종료합니다. 따라서 다른 파일에서 입력을 받을 때까지 프로그램은 이
절차를 넘어 진행하지 않습니다.
첫 번째 절차의 목적은 각 약어($1)를 배열
acro_desc의 요소에 할당하는 것이며, 레코드 번호(NR)는 배열의 인덱스 역할을 합니다.
프로그램의 후반부에서는 배열의 각 요소를 모든
레코드의 각 필드와 비교하기 시작합니다. 이를 위해서는 두 개의 for 루프가 필요합니다. 하나는 각 입력 줄에 대해 배열을 순회하기 위한 것이고, 다른 하나는 배열에 있는 요소 수만큼 해당 줄의
각 필드를 읽기 위한 것입니다. if 문은
현재 필드와 배열의 현재 요소를 비교하며, 둘이 같으면 해당 줄을 출력합니다.

약어가 발견될 때마다 해당 줄이 출력됩니다. 테스트 예제에서는 한 줄에 두 개의
약어가 있었기 때문에, 그 한 줄이 중복되어 출력되었습니다. 이를 수정하려면 print
문 뒤에 next를 추가하면 됩니다.
awkronym을 수정하여 파일에서 약어를 검색할 뿐만 아니라,
약어와 함께 설명도 출력하도록 한다면 어떨까요? 줄이 BASIC을 가리키는 경우, 설명(Begin-
ner’s All-Purpose Symbolic Instruction Code)을 추가하고 싶습니다. 변경 여부와 관계없이
모든 줄을 출력하는 필터로 사용할 수 있는 프로그램을 설계할 수 있습니다. 이전 버전을 수정하려면, 단순히
print 문을 조건문 밖으로 옮기면 됩니다. 하지만, 그 외에도 반드시
수행해야 할 변경 사항이 있습니다. 다음은 새 버전의 첫 번째 부분입니다.
awk ’ {
if ( FILENAME == “acronyms” ) {
split ( $0, fields, “|——|” )
acro_desc[fields[1]] = fields[2]
next
}

약어에 포함된 레코드들은 탭을 필드 구분자로 사용합니다. 필드 구분자를 변경하는 대신,
split 함수(이 함수의 구문은 나중에 살펴보겠습니다)를 사용하여 ‘fields’라는 이름의 배열을 생성합니다. 이 배열은
약어의 이름과 설명이라는 두 개의 요소를 포함합니다. 그런 다음 이 숫자 배열을 사용하여
'acro_desc'라는 이름의 연관 배열을 생성합니다. 연관 배열을 사용하면 문자열을 배열 요소의
인덱스로 사용할 수 있습니다. 즉, 약어의 이름을 주면 해당
설명에 해당하는 요소를 찾을 수 있습니다. 따라서 'acro_desc[GIGO]'라는 표현은 'Garbage In, Garbage Out'에 접근합니다.
이제 프로그램의 후반부를 살펴보겠습니다:
for ( name in acro_desc )
for (i = 1 ; i <= NF; i++)
if ( $i == name) {
$i = $i “ (”acro_desc[name]“)”
}
print $0
이전 버전과 마찬가지로, 배열의 요소들과 각 레코드의 필드를 순회합니다.
이 섹션의 핵심은 현재 필드($i)가 배열의 인덱스(name)와 동일한지 확인하는
조건문입니다. 필드의 값과 인덱스가 같으면, 해당 필드와 배열 요소를
연결합니다. 또한, 설명을 괄호 안에 넣습니다.

왜 $i와 name을 비교하는지, 왜
acro_desc[name]과는 비교하지 않는지 분명해야 합니다. 후자는 요소를 가리키는 반면, 전자는 첨자, 즉
약어의 이름을 가리키기 때문입니다.
현재 필드($i)가 BASIC과 같고 배열(name)의 인덱스가 문자열 BASIC인 경우,
필드의 값은 다음과 같이 설정됩니다:
BASIC (Beginner’s All-Purpose Symbolic Instruction Code)
이 프로그램이 실용적이기 위해서는, 약어가 나타날 때마다 설명이 삽입되는 것이 아니라
처음 나타나는 약어에 대해서만 설명이 삽입되어야 합니다. (약어에 대한 설명을 삽입한 후에는 더 이상 그 설명이
필요하지 않습니다.) 해당 요소를 사용한 후 배열에서 재정의할 수 있습니다.
acro_desc[name] = name
이 경우, 단순히 요소를 인덱스와 동일하게 설정합니다. 따라서 acro_desc[BASIC]은
프로시저 시작 시점에 Beginner’s All-Purpose Symbolic Instruction Code와 같으며, 일치하는

경우에는 BASIC과 같아집니다. ‘(acro_desc[name] != name)’이라는 표현식을 사용하여 요소와 인덱스를 비교하는 테스트가 두 곳에서
이루어집니다. 첫 번째는 for 루프가 acro_desc에서 새로운
요소를 읽어온 후이며, 조건문은 이미 발견된 약어에 대해 다음 입력 레코드를
스캔하지 않도록 보장합니다. 두 번째 위치는 $i가 name과 일치하는지 확인하는 부분입니다. 이
검사를 통해 해당 줄에서 동일한 약어에 대해 중복 일치를 생성하지 않도록 보장합니다.
if ( $i == name && acro_desc[name] != name)

이 조건문은 복합 식을 평가합니다. &&(and) 부울 연산자는 복합 식이 참이 되려면 두 식이 모두 참이어야 한다는
조건을 나타냅니다.
예상할 수 있는 또 다른 문제는 80자를 초과하는 줄이 생성될 수 있다는 점입니다.
결국 설명 문장이 꽤 길기 때문입니다. 내장된 awk 함수인 length를 사용하여 문자열의
문자 수를 확인할 수 있습니다. 예를 들어, 현재 입력 레코드의 길이를 구하려면 다음과 같이 지정합니다.
length($0)
함수의 값은 변수에 할당하거나 식 안에 넣어 평가할 수 있습니다.
if ( length($0) > 70 ) {
if ( i > 2 )
$i = “\n” $i
if ( i+1 < NF )
$(i+1) = “\n” $(i+1)
}
현재 입력 레코드의 길이는 설명이 연결된 후에 계산됩니다. 길이가
70자보다 크면, 두 가지 조건을 통해 줄바꿈을 삽입할 위치를 확인합니다. 첫 번째 절차는
줄바꿈과 현재 필드를 연결합니다. 따라서 줄의 시작 부분 근처가 아닐 때(필드 값이 2보다 클 때)만
이 작업을 수행하고자 합니다. 두 번째 절차는 줄바꿈과 다음 필드
(i+1)을 연결하므로, 줄 끝 근처가 아닌지 확인합니다. 이러한 각 연산에서 줄바꿈은 필드보다
앞에 위치합니다. 줄바꿈을 필드 끝에 배치하면 다음 필드와 함께 공백으로 시작하는 새 줄이
출력될 수 있습니다.

줄 바꿈을 처리하는 또 다른 방법, 어쩌면 더 효율적인 방법은 length 함수를 사용하여
각 필드에 대한 값을 반환하는 것입니다. 이 값을 누적함으로써, 새로운 필드가 추가되어
합계가 특정 숫자를 초과할 때 줄 바꿈을 지정할 수 있습니다. 산술 연산에 대해서는 뒤에서 살펴보겠습니다.
다음은 awkronyms의 전체 버전입니다:

```
awk ’ {
if ( FILENAME == "acronyms" ) {
split ( $0, fields, "|——|" )
acro_desc[fields[1]]=fields[2]
next
}
for ( name in acro_desc )
if (acro_desc[name] != name)
for (i = 1; i <= NF; i++)
if ($i == name && acro_desc[name] != name) {
$i = $i " ("acro_desc[name]")"
acro_desc[name] = name
if (length ($0) > 70) {
if (i > 2)
$i = "\n" $i
if (i+1 < NF)
$(i+1) = "\n" $(i+1)
}
}
print $0
}’ acronyms $*
```

## awk Applications

셸 프로그램은 대화형으로 데이터를 수집하여 awk가 읽을 수 있는 형식으로 파일에 기록하는 데
매우 유용한 방법입니다. 이번에는 프로젝트 로그를 관리하기 위한 일련의 프로그램을 살펴보겠습니다. 셸
스크립트는 프로젝트 이름과 해당 프로젝트에 투입된 시간을 수집합니다. awk 프로그램은
각 프로젝트의 총 시간을 합산하여 보고서를 출력합니다.
‘day’ 파일은 정보를 수집하여 사용자의 홈 디렉토리에 있는 ‘daily’라는 파일에 추가하는 셸 스크립트입니다.

```
$ cat /usr/local/bin/day
case $# in
0) echo "Project: \c"; read proj; echo "Hours: \c"; read hrs;;
1) proj=$1; echo "Hours: \c"; read hrs;;
2) proj=$1; hrs=$2;;
esac
set ‘who am i‘; name=$1; month=$3; day=$4;
echo $name"\t"$month $day"\t"$hrs"\t"$proj>>$HOME/daily
```

이 case 문은 명령줄에 몇 개의 인수가 입력되었는지 확인합니다. 인수가
누락된 경우, 사용자에게 값을 입력하라는 메시지가 표시됩니다. 메시지 출력은 echo와
read라는 두 명령어를 통해 이루어집니다. echo 명령어는 사용자의 터미널에 메시지를 표시하며, \c는 메시지 끝의 캐리지 리턴을
억제합니다. read 명령어는 캐리지 리턴으로 종료되는 사용자 입력을 기다린 후,
그 값을 변수에 할당합니다. 따라서 case 문이 끝날 때쯤이면 proj와 hrs 변수가 정의됩니다.
set 명령어를 사용하면 명령어의 출력을 개별 인자($1, $2,
$3...)로 나눌 수 있습니다. set 내에서 who am i 명령어를 실행함으로써, 사용자의 이름과
당일 날짜를 자동으로 입력합니다. echo 명령어는 정보를 파일에 기록하는 데 사용됩니다. 탭으로 구분된 네 개의
필드가 있습니다. (Bourne 셸에서 이스케이프 시퀀스 \t는 탭을 생성합니다. 셸에 의해 백슬래시가 제거되지 않도록 하려면 따옴표를
사용해야 합니다).

다음은 주말이 끝날 무렵 한 사용자의 daily 파일에 포함된 내용입니다:

```
$ cat /usr/fred/daily
fred Aug 4 7 Course Development
fred Aug 5 4 Training class
fred Aug 5 4 Programmer’s Guide
fred Aug 6 2 Administrative
fred Aug 6 6 Text-processing book
fred Aug 7 4 Course Development
fred Aug 7 4 Text-processing book
fred Aug 8 4 Training class
fred Aug 8 3 Programmer’s Guide
```

이 파일에는 9개의 레코드가 있습니다. 보시다시피, 우리의 입력 프로그램은 사용자가 프로젝트 이름을
지정할 때 일관성을 강제하지 않습니다.
이 입력 데이터를 바탕으로, 해당 주의 총 근무 시간을 보고하고
프로젝트별 근무 시간 내역을 제공하는 awk 프로그램을 만들고자 합니다. 첫 번째 단계에서는 세 번째와 네 번째 필드만
읽어들이면 됩니다. 세 번째 필드의 값을 누적하여 총 근무 시간을 계산할 수 있습니다.
total += $3
+= 연산자는 두 가지 기능을 수행합니다. 즉, total의 현재 값에 $3을 더한 다음, 이
값을 total에 할당합니다. 이는 다음 문장과 동일합니다.
total = total + $3
연관 배열을 사용하여 프로젝트($4)별 시간($3)을 누적할 수 있습니다.
hours[$4] += $3
레코드가 읽힐 때마다 세 번째 필드의 값이 project[$4]의 누적 값에 더해집니다.
모든 입력 레코드가 읽힐 때까지는 아무것도 출력하지 않도록 합니다. END 프로시저는
누적된 결과를 출력합니다. 다음은 tot의 첫 번째 버전입니다:

```
awk ’
BEGIN { FS="|——|" }
{
total += $3
hours[$4] += $3
}
END {
for (project in hours)
print project, hours[project]
print
print "Total Hours:" , total
} ’ $HOME/daily
```

프로그램을 테스트해 봅시다:

```
$ tot
Course Development 11
Administrative 2
Programmer’s Guide 7
Training class 8
Text-processing book 10
Total Hours: 38
```

이 프로그램은 산술 연산 작업을 잘 수행하지만, 보고서의 형식이 정돈되지 않았습니다. 출력 필드 구분자(OFS)를 탭으로
변경하면 도움이 될 것입니다. 하지만 프로젝트 이름의 길이가 제각각이라서
프로젝트 소요 시간을 한 열에 정렬할 수 없습니다. awk 프로그램은 C 프로그래밍 언어에서 차용한
대체 출력 문인 printf를 제공합니다.



### Formatted Print Statements

printf 문은 두 부분으로 구성됩니다. 첫 번째는 형식 지정자를 설명하는 따옴표로 묶인 표현식이고,
두 번째는 변수 이름과 같은 인자들의 순서입니다. 두 가지 주요 형식 지정자는
문자열을 나타내는 %s와 십진수를 나타내는 %d입니다. (8진수, 16진수 및
비정수형 숫자를 위한 추가 지정자도 있습니다). 일반 print 문과 달리, printf는 자동으로
줄 바꿈을 추가하지 않습니다. 줄 바꿈은 \n으로 지정할 수 있습니다. 탭은 \t로 지정합니다.
문자열 및 십진수 형식 지정을 포함하는 간단한 printf 문은 다음과 같습니다.
printf “%s\t%d\n” , project, hours[project]
먼저 project가 출력되고, 그 다음 탭(\t), 소요 시간, 그리고 줄바꿈(\n)이 출력됩니다. 각 형식 지정자마다
해당하는 인수를 반드시 제공해야 합니다.
안타깝게도, 이러한 간단한 문장만으로는 서식 문제를 해결할 수 없습니다. 다음은 이 문장이 생성하는
출력 예시입니다:
Course Development 11
Administrative 2
Programmer’s Guide 7
탭이 항상 같은 위치에서 시작되도록 최소 필드 너비를 지정해야 합니다. printf 문에서는
이 지정을 % 기호와 변환 지정자 사이에 넣을 수 있습니다.
%-20s를 사용하면 값이 왼쪽 정렬되도록 최소 필드 너비를 20자로 지정할 수 있습니다. 마이너스 기호가
없으면 값이 오른쪽 정렬되는데, 이는 십진수 값의 경우 우리가 원하는 방식입니다.
END {
for (project in hours)
printf “%-20s\t%2d\n”, project, hours[project]
printf “\n\t총 시간:\t%2d\n”, total
}
“Total Hours”와 같은 리터럴은 형식 지정과 함께 첫 번째 부분에 배치된다는 점에 유의하십시오.
보고서를 출력할 때 END 프로시저를 사용하는 것과 마찬가지로, 보고서의 헤더를 출력하기 위해 BEGIN 프로시저를 포함할 수 있습니다:
BEGIN { FS="|——|"
printf “%20s%s\n\n”, “PROJECT ”, “ HOURS”
printf “%20s%s\n\n”, “PROJECT ”, “ HOURS”
}
이는 문자열을 처리하는 또 다른 방법을 보여줍니다. 다음과 같은 서식이 지정된 보고서가 표시됩니다:
PROJECT  HOURS
Course Development 11
Administrative  2
Programmer’s Guide 7
Training class 8
Text-processing book 10
Total Hours: 38


### Defensive Techniques

프로그램의 기본적인 작업을 완료한 후—이 시점에서 코드는 꽤 이해하기
쉬운 편입니다—이 핵심 부분을 일관성이 없는 입력 레코드를 포착하고 프로그램이 오류로
중단되는 것을 방지하도록 설계된 “방어적” 프로시저로 둘러싸는 것이 종종 좋은 방법입니다. 예를 들어, tot 프로그램에서는 각 입력
레코드에 대해 시간 수가 0보다 크고 프로젝트 설명이 null이 아닌지
확인하고 싶을 수 있습니다. 논리 연산자 &&를 사용하여 조건식을 작성할 수 있습니다.

$3 > 0 && $4 != “” {
procedure
}
이 프로시저가 실행되려면 두 조건이 모두 참이어야 합니다. 논리 연산자 &&는 두 조건이 모두 참일 때
그 표현식이 참임을 의미합니다.
방어적 기법을 도입하는 또 다른 측면은 오류 처리입니다. 다시 말해, 프로그램이 오류를 감지한 후
어떤 동작을 수행하기를 원합니까? 앞서 제시한 조건문은 프로시저가
실행되지 않을 경우 다음 입력 줄을 읽도록 설정되어 있습니다. 이 예제에서는 프로그램이 계속 진행되지만, 다른
경우에는 오류가 발생했을 때 프로그램이 오류 메시지를 출력하고 중단되기를 원할 수도 있습니다.

하지만 “프로” 프로그래머와 “아마추어” 프로그래머를 구분하는 것은 유용할 수 있습니다. 우리는
분명히 후자에 속하며, 항상 100% 사용자 오류에 대비한 프로그램을 작성해야 한다는 강박감을 느끼지는 않습니다.
첫째, 방어적 프로그래밍은 상당히 시간이 많이 걸리고 종종 지루하기 때문입니다. 둘째, 아마추어는
자신이 기대하는 대로 작동하는 프로그램을 자유롭게 작성할 수 있지만, 전문가는
특정 사용자를 위해 프로그램을 작성해야 하며 그들의 기대를 고려해야 합니다. 여러분이 작성하는 모든 프로그램의
가능한 용도와 사용자를 고려해 보십시오.


### awk and nroff/troff

awk 프로그램을 이용해 양식 보고서에 필요한 코드를 생성하는 것은 꽤 쉽습니다. 예를 들어, 우리는
tot 프로그램을 개선하여 troff 형식의 보고서를 생성하도록 했습니다:

```
awk ’ BEGIN { FS = "|——|"
print ".ce"
print ".B "
print "PROJECT ACTIVITY REPORT"
print ".R"
print ".sp 2"
}
NR == 1 {
begday = $2
}
$3 > 0 && $4 != "" {
hours[$4] += $3
total += $3
endday = $2
logname = $1
}
END {
printf "Writer: %s\n", logname
print ".sp"
printf "Period: %s to %s\n", begday, endday
print ".sp"
printf "%20s%s\n\n", "PROJECT ", " HOURS"
print ".sp"
print ".nf"
print ".na"
for (project in hours)
printf "%-20s\t%2d\n", project, hours[project]
print ".sp"
printf "Total Hours:\t %2d\n", total
print ".sp"
}’ $HOME/daily
```

이번 버전에서는 주 단위를 결정하기 위해 하나의 절차를 추가했습니다. 주의 시작일은
첫 번째 레코드(NR == 1)에서 가져옵니다. 마지막 레코드는 주의 마지막 날을 제공합니다.
보시다시피, awk는 print 문과 printf 문을 혼합하여 사용해도 문제없습니다. 일반 print
명령은 줄바꿈이 자동으로
삽입되기 때문에 서식 코드와 같은 리터럴을 지정하는 데 더 편리합니다. 이 프로그램은 표준 출력으로 기록하므로, 출력을 파이프를 통해
nroff/troff로 직접 전달할 수 있습니다.
awk를 사용하여 tbl 및 pic과 같은 다른 troff 전처리기용 입력을 생성할 수 있습니다.



### Multiline Records

이 섹션에서는 주문 추적용 프로그램 모음을 살펴보겠습니다. 우리는 소규모 우편 주문 출판 사업을 운영하기 위해 이
프로그램들을 개발했습니다. 이 프로그램들은 기술 문서 부서의 문서 추적에
쉽게 적용할 수 있습니다.
이번에도 데이터 입력을 위해 셸 프로그램인 `take.orders`를 사용했습니다. 이 프로그램은 두 가지
목적을 가지고 있습니다. 첫 번째는 나중에 메일링 리스트를 작성할 때 사용할 수 있도록 고객의 이름과 우편 주소를 입력하는 것입니다.
두 번째는 7개의 도서 제목을 표시하고, 사용자에게 도서 번호, 부수,
부당 가격을 입력하도록 요청하는 것입니다. 메일링 리스트와 고객 주문에 대해 수집된 데이터는 별도의
파일에 기록됩니다.

샬럿 스미스

이것들은 다중 행 레코드입니다. 즉, 줄 바꿈 문자가 필드 구분자로 사용됩니다. 빈 줄이 개별
레코드를 구분합니다. 대부분의 프로그램에서 이를 처리하려면 기본 필드 구분자와 레코드 구분자를
재정의해야 합니다. 필드 구분자는 줄 바꿈 문자로, 레코드 구분자는 null로 설정됩니다.
BEGIN { FS = “\n”; RS = “” }

복사 수량을 가격과 곱하는 간단한 프로그램을 작성해 봅시다. 각 레코드의 첫
두 줄은 고객 이름, 구매 주문 번호, 주문 날짜가 포함되어 있으므로 무시하고자 합니다.
제목이 명시된 줄만 읽어들일 것입니다. 이를 수행하는 방법에는 몇 가지가 있습니다. awk의 패턴
일치 기능을 이용하면, 해시(#)로 시작하는 줄을 선택하여 공백으로 구분된 필드를 가진 개별
레코드로 처리할 수 있습니다.
awk ’ /ˆ#/ {
amount = $2 * $3
printf “%s %6.2f\n”, $0, amount
next
}
{print}’ $*
메인 프로시저는 패턴과 일치하는 행에만 영향을 미칩니다. 이 프로시저는 두 번째 필드에 세 번째
필드를 곱하여 그 값을 amount 변수에 할당합니다. printf 변환자 %f는 부동 소수점 수를
출력하며, 6.2는 최소 필드 너비를 6, 정밀도를 2로 지정합니다. 정밀도는 소수점 오른쪽의
자리 수를 의미하며, %f의 기본값은 6입니다. 현재 레코드를 변수 amount의 값과 함께 출력합니다.
이 프로시저 내에서 한 줄이 출력되면, 다음 줄은 표준 입력에서 읽혀집니다. 패턴과
일치하지 않는 줄은 그냥 통과됩니다. addem이 어떻게 작동하는지 살펴보겠습니다:

이제 여러 줄로 구성된 레코드를 읽어들이고, 보고서를 위해 주문 정보를 집계하는 프로그램을 설계해 봅시다.
이 보고서는 각 도서 제목별 총 부수와 총 금액을 표시해야 합니다. 또한
주문된 모든 부수를 반영한 합계와 모든 주문의 합계도 표시해야 합니다.
각 레코드의 첫 두 필드에 있는 정보는 사용하지 않을 것임을 알고 있습니다. 하지만
각 레코드의 필드 수는 주문된 도서 제목의 수에 따라 달라집니다. 먼저,
입력 레코드에 필드가 최소 세 개 이상 있는지 확인합니다. 그런 다음 for 루프를 사용하여
세 번째 필드부터 시작하여 모든 필드를 읽어들입니다:
NF >= 3 {
for (i = 3; i <= NF; ++i)
데이터베이스 용어로 말하자면, 각 필드에는 값이 있으며 각 값은 다시 하위 값으로 나눌 수 있습니다. 즉,
여러 줄로 구성된 레코드에서 필드의 값이 한 줄로 이루어져 있다면, 하위 값은 해당 줄에 있는 단어들이 됩니다. 입력 레코드를 분할하는 데 사용되는 split 함수는
이미 살펴보았는데, 이제 이 함수를 사용하여
필드를 세분화하는 방법을 살펴보겠습니다. split 함수는 지정된 문자를 하위 값 구분자로 사용하여
어떤 문자열이든 배열에 담습니다.
split(string, array, separator)


기본 하위값 구분자는 공백입니다. split 함수는 배열에 로드된 요소의 개수를 반환합니다.
문자열은 리터럴(따옴표로 묶인)이거나 변수일 수 있습니다. 예를 들어, 잠시 주제를 벗어나
split 함수의 단독 사용 예를 살펴보겠습니다. 다음은 각 부분이 쉼표로 구분된
한 사람의 이름과 직함입니다:
title="George Travers, Research/Development, Alcuin Inc."
split을 사용하여 이 문자열을 분할하고 세 줄에 걸쳐 출력할 수 있습니다.
need = split (title, name, “,”)
print “.ne ”, need
for (part in name)
print name[part]
이 절차는 각 부분을 별도의 줄에 출력합니다. 배열의 요소 수(3)는
변수 need에 저장됩니다. 이 변수는 .ne 요청의 인수로 전달되며, 이는 troff가 첫 번째 줄을 출력하기 전에
페이지 하단에 최소 세 줄의 여유 공간이 있는지 확인하도록 지시합니다.
awk 프로그램에는 표 13-2에 표시된 대로 12개의 내장 함수가 있습니다. 이 중 4개는 코사인, 사인, 로그, 제곱근을 위한
특화된 산술 함수입니다. 나머지 함수들은 문자열을
조작합니다. (length 함수가 어떻게 작동하는지는 이미 살펴보았습니다.) 이 함수들의 구문은
부록 A를 참조하십시오.
보고서 생성기로 돌아가 보면, 각 필드를 하위 값으로 분할해야 합니다. 변수 $i는
현재 필드의 값을 배열 order의 요소로 세분화된 형태로 제공합니다.
sv = split ($i, order)
if (sv == 3) {
procedure
}

## Testing Programs

프로그램을 작성하는 과정에는 하나 이상의 테스트 케이스를 설계하는 작업이 포함됩니다. 보통 이는 샘플 입력
파일을 만드는 것을 의미합니다. 개발의 여러 단계에서 프로그램을 테스트하는 것이 좋습니다. 함수를 추가할 때마다
테스트를 수행하십시오. 예를 들어, 조건문 절차를 구현했다면, 식이 참일 때 해당 절차가 실행되는지
테스트하고, 거짓일 때는 어떤 일이 발생하는지 테스트하십시오. 프로그램 테스트는 구문이
올바른지, 그리고 문제가 해결되었는지 확인하는 과정을 포함합니다.
awk가 구문 오류를 발견하면 “bailing out”이라고 알려줍니다. 보통 오류와 관련된
줄 번호를 출력합니다. 구문 오류는 문자열을 따옴표로 묶는 것을 잊거나
중괄호로 절차를 닫는 것을 잊는 등 다양한 실수로 인해 발생할 수 있습니다. 때로는 여분의 공백 하나만
있는 사소한 실수 때문일 수도 있습니다. awk 프로그램의 오류 메시지는 도움이 되는 경우가 드물며, 오류를
찾아내기 위해서는 끈질긴 노력이 필요한 경우가 많습니다.
심지어 다음과 같은 끔찍한 선언과 같은 UNIX 시스템 오류 메시지가 표시될 수도 있습니다.
Segmentation fault-core dumped.
걱정하지 마세요. 프로그램이 완전히 실패했더라도, 지진이 일어나거나 시스템이 붕괴된 것은 아닙니다.
오류 발생 시점의 “코어” 메모리 이미지가 core라는 이름의 파일에 저장(덤프)됩니다. 숙련된
프로그래머는 디버깅 프로그램을 사용하여 이 이미지를 분석하고 메모리의 어느 부분에서 오류가
발생했는지 파악할 수 있습니다. 우리는 그냥 core 파일을 삭제하고 코드를 다시 검토하면 됩니다.
다시 한 번 말하지만, 프로그램에 구문을 추가할 때마다 각각을 확인하십시오. 프로그램이 커질 때까지 기다렸다가
오류가 발생하면, 오류를 찾는 데 어려움을 겪는 경우가 많습니다. 그뿐만 아니라, 무엇이 문제인지 찾으려고
하는 과정에서 문제가 없는 부분을 수정하는 등 불필요한 변경을 하게 될 가능성이 높습니다.
원래 해결하려 했던 문제를 제대로 해결했는지 확인하는 것은 훨씬 더 큰 문제입니다.
더 큰 규모의 샘플로 프로그램 테스트를 시작하면, 의심할 여지 없이 “예외” 즉, 버그라고도
불리는 문제들을 발견하게 될 것입니다. awkronym 프로그램을 테스트하던 중, 문장의 마지막 단어에
약어가 등장하는 예외를 발견했습니다. 문장을 끝내는 마침표 때문에 이 약어가 “발견”되지 않았던 것입니다.
즉, awk는 BASIC과 BASIC.이 같지 않다는 것을 발견한 것입니다. 검색 문자열을 정규 표현식으로 테스트할 수 있다면
이것은 문제가 되지 않겠지만, 우리는 배열 변수를 리터럴 문자열로 테스트해야만 합니다.
프로그래밍은 그 목적상 주로 실용적입니다. 특정 문제가
프로그램을 작성할 만한 가치가 있는지, 혹은 특정 예외 사항이 일반 프로그램을 수정하여
이를 반영할 만큼 중요한지 판단해야 합니다. 때로는 대규모 공개 프로그램은 물론 소규모 개인 프로그램에서도 버그가 단순히
프로그램의 알려진 동작의 일부가 되어, 사용자가 스스로 최선을 다해 대처해야 하는 경우가 있습니다. awkronym에서
발견된 버그는 꽤 흔한 문제이므로, 수정 사항을 구현할 필요가 있습니다.
awkronym 버그에 대한 수정 작업은 awk와 전혀 관련이 없습니다. awkronym 프로그램 실행 전에 sed 스크립트를
실행하여 구두점을 단어에서 분리합니다. 이 스크립트는 구두점을 가비지 문자가 포함된 필드로
변환합니다. 또 다른 스크립트가 awkronym의 출력을 처리하여 이러한 가비지
문자를 제거합니다. 아래 예제는 두 스크립트가 awkronym 프로그램의 시작과 끝을
감싸는 역할을 하는 방식을 보여줍니다.

```
sed ’s/\ (..*\)\([.,!;]\)/\1 @@@\2/g’ $* |
awk ’ {
program lines
}’ acronyms - |
sed ’s/ @@@\([.,!;]\)/\1/g’
```
