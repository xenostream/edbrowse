# Chapter 7 Advanced Editing

때로는 앞으로 나아가기 위해 뒤로 물러서야 할 때도 있습니다. 이 장은 라인 에디터의 작동 원리를 이해함으로써 텍스트 편집 기술을 어떻게 향상시킬 수 있는지 살펴보겠습니다. 그렇다고 해서 “전체 화면 편집 방식을 포기해야 한다” 는 뜻은 아닙니다. `vi` 편집기는 `ex` 라는 라인 편집기를 기반으로 만들어졌는데, `ex` 는 `ed` 라는 또 다른 라인 편집기의 개선된 버전입니다. 따라서 어떤 의미에서는 vi의 선조를 살펴보게 될 것입니다. 라인 편집기가 특정 문제를 해결하는 다양한 방법과, 그것이 전체 화면 편집기를 사용하는 우리에게 어떻게 적용되는지 살펴보겠습니다.

줄 편집기는 기본적으로 프린터였던 “종이 터미널” 에 사용하기 위해 등장했습니다. 이는 비디오 디스플레이 터미널이 등장하기 전의 일이었습니다. 프로그래머나 인내심이 대단한 사람은 프린터를 통해 대화형 방식으로 작업을 수행했습니다. 일반적으로 파일의 한 줄을 종이에 인쇄해서 확인한 다음, 해당 줄에만 영향을 미치는 명령을 입력하고, 편집된 줄을 다시 인쇄했습니다. 줄 편집기는 한 번에 한 줄씩 편집하는 이런 과정을 위해 설계되었습니다.

요즘은 종이 터미널에서 파일을 편집하는 사람이 거의 없지만, 여전히 줄 편집기를 선호하는 고집 센 사용자들도 있습니다. 무엇보다, 컴퓨터에 주는 부담이 매우 적기 때문입니다. 줄 편집기는 현재 표시된 줄만 보여주며, 화면 전체를 갱신하지 않습니다.

경우에 따라 줄 단위 편집기가 전체 화면 편집기보다 좀 더 간단하고 빠를 수 있습니다. 때로는 시스템의 반응이 너무 느려, 줄 단위 편집기로 전환하는 편이 작업할 때 덜 답답할 수 있습니다. 혹은 전체 화면 편집기로는 생산적으로 작업하기에 너무 느린 전송 속도로 작동하는 전화 접속 회선을 통해 원격으로 작업해야 하는 경우도 있을 수 있습니다. 이런 상황에서는 라인 편집기를 사용하는 것이 효율을 높이는 방법일 수 있습니다. 이를 통하면 컴퓨터가 명령에 응답할 때까지 기다리는 시간을 많이 줄일 수 있습니다.

하지만 사실, 화면 편집기에서 라인 편집기로 전환한 후에는 뭔가 부족함을 느낄 가능성이 높습니다. 그렇다고 해서 라인 편집기를 사용하지 않을 것이라는 이유만으로 이 장을 건너뛰어서는 안 됩니다. ex를 배우는 목적은 vi에서 할 수 있는 일을 확장하기 위함입니다.



## The ex Editor

ex 편집기는 자체적인 완전한 편집 명령어 세트를 갖춘 줄 단위 편집기입니다. vi를 사용하면 대부분의 편집 작업을 좀 더 간단하게 수행할 수 있지만, 파일의 여러 부분에 걸쳐 대규모 변경 작업을 처리할 때는 ex의 줄 단위 편집 방식이 장점입니다. ex를 사용하면 파일 간에 쉽게 이동할 수 있으며, 다양한 방법으로 한 파일에서 다른 파일로 텍스트를 옮길 수 있습니다. 텍스트를 줄 단위로 검색 및 교체하거나, 전체적으로 검색 및 교체할 수도 있습니다.

또한 일련의 편집 명령을 매크로로 저장해 두고, 키 한 번만 누르면 이를 실행할 수 있습니다. ex를 직접 호출했을 때 어떻게 작동하는지 살펴보면, 라인 에디터에 대한 ‘신비감’ 을 다소 덜어주고, 많은 ex 명령이 어떻게 작동하는지 좀 더 명확하게 이해할 수 있을 것입니다.

파일을 열고 몇 가지 ex 명령어를 사용해 봅시다. 파일에 ex를 호출하면 파일의 총 줄 수에 대한 메시지와 콜론(:) 명령 프롬프트가 표시됩니다. 예를 들어:

```
$ ex intro
"intro" 20 lines, 731 characters
:
```

ex 명령어를 입력해서 한 줄 이상을 출력하도록 명령하지 않는 한, 파일의 어떤 줄도 표시되지 않습니다. 

모든 ex 명령은 줄 주소(단순히 줄 번호일 수도 있음)와 명령어로 구성됩니다. 명령어는 캐리지 리턴을 입력해서 완료합니다. 줄 번호만 입력하는 것은 해당 줄에 대한 `print` 명령과 동일한 효과를 냅니다. 예를 들어, 프롬프트에 숫자 1 을 입력하면 파일의 첫 번째 줄이 표시됩니다:

```
:1
Sometimes, to advance,
:
```

두 줄 이상 인쇄하려면 줄 범위를 지정할 수 있습니다. 두 줄 번호를 쉼표로 구분해서 지정하며, 그 사이에 공백을 넣지 않아야 합니다:

```
:1,3
Sometimes, to advance,
you have to go backward.
Alcuin is a computer graphics tool
```

현재 행은 명령어의 영향을 가장 최근에 받은 행입니다. 예를 들어, ‘1,3’ 명령어를 실행하기 전에는 1행이 현재 행이었지만, 해당 명령어 실행 후에는 3행이 현재 행이 되었습니다. 이는 특수 기호인 점(.)으로 표시할 수 있습니다.

```
:.,+3
that lets you design and create hand-lettered, illuminated
manuscripts, such as were created in the Middle Ages.
```

앞서 입력한 명령을 실행하면 현재 줄을 시작으로 세 줄 더 출력됩니다. `+` 또는 `-` 는 현재 줄을 기준으로 양수 또는 음수의 오프셋을 지정합니다.

ex 편집기는 명령 모드와 삽입 모드가 있습니다. 파일에 텍스트를 입력하려면 `append` 명령을 입력해서 현재 줄 다음 줄에 텍스트를 삽입할 수 있습니다. `insert` 또는 `i` 명령은 현재 줄 바로 위 줄에 텍스트를 삽입합니다. 텍스트를 입력하고 완료되면, 빈 줄에 점(`.`)을 입력합니다:

```
:a
Monks, skilled in calligraphy,
labored to make copies of ancient
documents and preserve in a
library the works of many Greek and
Roman authors.
.
:
```

점(`.`)을 입력하면 삽입 모드가 종료되고 명령 모드로 돌아갑니다.

줄 편집기는 커서가 없으며, 텍스트 줄을 따라 특정 단어로 이동할 수 없습니다. 파일의 나머지 부분을 볼 수 없다는 점 외에도, 커서가 없다는 점(따라서 커서 이동 키도 없다는 점)은 아마도 적응하기 가장 어려운 부분일 것입니다. 줄 편집기를 사용한 후에는 vi의 `cw` 명령을 다시 사용하고 싶어질 것입니다.

단어를 변경하려면, 해당 단어가 포함된 줄로 이동한 다음, 편집기에 그 줄에서 어떤 단어를 변경할지 지정한 후, 대체할 단어를 입력해야 합니다. `substitute` 또는 `s` 명령을 사용하려면 이런 방식으로 생각해야 합니다. 이 명령을 사용하면 한 단어를 다른 단어로 대체할 수 있습니다.

첫 번째 줄의 마지막 단어를 tool 에서 environment 로 변경해 볼 수 있습니다:

```
:1
Alcuin is a computer graphics tool
:s/tool/environment/
Alcuin is a computer graphics environment
:
```

변경하려는 단어와 대체할 단어는 슬래시(`/`)로 구분됩니다. `substitute` 명령어를 실행하면 변경한 줄이 출력됩니다.

줄 편집기를 사용할 때 입력하는 명령어는 현재 줄에 적용됩니다. 따라서 첫 번째 줄이 현재 줄이 되도록 했습니다. 또한 다음 명령어를 사용해서 줄 번호를 지정함으로써 동일한 변경을 수행할 수도 있습니다:

```
:1s/environment/tool/
Alcuin is a computer graphics tool
```

줄 번호 범위 같은 주소를 지정하면, 이 명령은 사용자가 지정한 줄에 적용됩니다:

```
:1,20s/Alcuin/ALCUIN/
ALCUIN is named after an English scholar
```

치환이 이루어진 마지막 줄이 출력됩니다.

줄 편집기를 사용할 때는 어떤 줄(들)을 편집할지, 그리고 어떤 명령을 실행할지 편집기에 명시해야 한다는 점을 기억하십시오.

ex를 아는 것이 유용한 또 다른 이유는, vi에서 작업하다가 때때로 예기치 않게 “open 모드” 를 사용할 수도 있기 때문입니다. 예를 들어, vi에서 `Q` 를 누르면 ex 편집기로 전환됩니다. 콜론 프롬프트에서 `vi` 명령을 입력해서 vi 화면 편집기로 전환할 수 있습니다:

```
:vi
```

vi로 전환된 후에는 먼저 `:` (콜론)을 입력해서 원하는 ex 명령을 실행할 수 있습니다. 콜론은 화면 하단에 표시되며, 입력한 내용은 그곳에 에코(echo)됩니다. ex 명령을 입력하고 리턴(RETURN) 키를 누르면 명령이 실행됩니다.



## Using ex Commands in vi

일반적인 편집 작업을 수행하는 많은 ex 명령어는, 해당 작업을 좀 더 간단한 방식으로 처리하는 vi 명령어가 있습니다. 당연히, ex의 `delete` 명령어를 사용하는 대신 `dw` 나 `dd` 를 사용해서 단일 단어나 줄을 삭제할 것입니다. 하지만 여러 줄에 영향을 미치는 변경을 가할 때는 ex 명령어가 매우 유용하다는 것을 알게 될 것입니다. 이 명령어들을 사용하면 단 한 번의 명령으로 대량의 텍스트 블록을 수정할 수 있습니다.

다음은 이런 명령어 중 일부와 그 약어입니다. 기억하기 쉬운 쪽을 선택해서 전체 명령어 이름이나 약어를 사용할 수 있습니다.

명령어 | 약어 | 설명
--- | --- | ---
`delete` | `d` | 줄 삭제
`move` | `m` | 줄 이동
`copy` | `co` | 줄 복사
`substitute` | `s` | 한 문자열을 다른 문자열로 대체

`substitute` 명령어는 편집을 좀 더 쉽게 만들어 주는 ex 편집기의 능력을 가장 잘 보여주는 예입니다. 이 명령어를 사용하면 파일 내에서 특정 문자열이 나타나는 모든 위치에서 해당 문자열을 변경할 수 있습니다. 전역 대체 방식으로 편집을 수행하려면 패턴 매칭 또는 “정규 표현식” 사용법에 대한 충분한 지식은 물론, 이에 대한 확고한 자신감도 필요합니다. 다소 난해할 수 있지만, 전역 대체 방법을 익히는 것은 UNIX 텍스트 처리 환경에서 작업할 때 가장 보람찬 경험 중 하나일 수 있습니다.

그 밖의 ex 명령어들은 추가적인 편집 기능을 제공합니다. 실질적으로 볼 때, 이 명령어들은 vi의 필수적인 명령의 일부로 볼 수 있습니다. 이런 기능의 예로는 여러 파일을 편집하거나 UNIX 명령어를 실행하는 명령어들이 있습니다. 패턴 일치와 전역 치환에 대해 살펴본 후에 이 기능들을 자세히 알아보겠습니다.


## Write Locally, Edit Globally

때로는 문서를 반쯤 작성했거나 초안을 마무리할 무렵에, 특정 항목을 지칭하는 방식에 일관성이 없다는 것을 깨닫게 됩니다. 또는 설명서에서, 이름 그대로 부르던 어떤 제품의 명칭이 갑자기 바뀌는 경우도 있습니다(마케팅 때문이죠!). 이런 경우, 이미 작성한 내용을 여러 곳에서 되돌아가서 수정해야 하는 경우가 꽤 많습니다.

이런 변경을 수행하는 방법은 ex의 ‘찾기 및 바꾸기’ 명령을 사용하는 것입니다. 파일 내에서 특정 단어(또는 문자열)가 나타나는 모든 곳에서 이를 자동으로 바꿀 수 있습니다. Alcuin 을 ALCUIN 으로 바꿨을 때, `substitute` 명령을 사용한 예시를 이미 한 번 보셨을 것입니다.

```
:1,20s/Alcuin/ALCUIN/
```

검색 및 바꾸기 명령을 사용하는 것은 실제로 두 단계가 있습니다. 

- 첫 번째 단계는 검색이 이루어질 영역을 정의하는 것입니다. 검색 범위는 텍스트 블록만 포함하도록 국소적으로 지정하거나, 파일 전체를 포함하도록 전역적으로 지정할 수 있습니다. 

- 두 번째 단계는 `substitute` 명령을 사용해서 제거할 텍스트와 이를 대체할 텍스트를 지정하는 것입니다.

처음에는 검색 및 바꾸기 명령을 지정하는 구문이 배우기 어려워 보일 수 있습니다. 특히 패턴 매칭을 처리할 때는 더욱 그렇습니다. 하지만 이것은 매우 강력한 도구이며, 지루한 작업을 크게 줄여줄 수 있다는 점을 항상 명심하십시오. 게다가, 성공하면 스스로를 칭찬할 것이며, 주변 사람들은 여러분을 매우 영리한 사람으로 여길 것입니다.


### Searching Text Blocks

검색 범위를 정의하려면 ex에서 줄 주소 지정 방식이 어떻게 작동하는지 제대로 이해해야 합니다. 줄 주소는 단순히 ex 명령어가 어떤 줄이나 줄 범위에 적용될지를 나타냅니다. 줄 주소를 지정하지 않으면 명령어는 현재 줄에만 영향을 미칩니다. 이미 줄 번호를 지정해서 개별 줄을 지정할 수 있다는 사실은 잘 알고 계실 것입니다. 이제 살펴볼 내용은 파일 내의 텍스트 블록을 지정하는 다양한 방법입니다.

절대 행 번호나 상대 행 번호를 사용해서 행 범위를 정의할 수 있습니다. 텍스트 블록의 시작 행 번호와 블록의 끝 행 번호를 확인하십시오. vi에서는 `ˆG` (Ctrl+g)를 사용해서 현재 행 번호를 확인할 수 있습니다.

파일 내의 특정 위치를 지정하는 데 사용하는 특수 기호도 있습니다:

기호 | 설명
--- | ---
`.` | 현재 줄
`$` | 마지막 줄
`%` | 모든 줄 (`1,$` 와 동일)

다음은 `substitute` 명령어가 적용할 텍스트 블록을 정의하는 예시입니다:

적용 범위 | 설명
--- | ---
`:.,$s` | 현재 줄부터 파일 끝까지 검색
`:20,.s` | 20번째 줄부터 현재 줄까지 검색
`:.,.+20s` | 현재 줄부터 다음 20줄까지 검색
`:100,$s` | 100번째 줄부터 파일 끝까지 검색
`:%s` | 파일의 모든 줄 검색

이 예시에서 정의된 검색 범위 내에서, 대체 명령어는 하나의 문자열을 찾아 다른 문자열로 대체합니다.

또한 패턴 일치를 사용해서 텍스트 내의 특정 위치를 지정할 수도 있습니다. 패턴은 앞뒤에 슬래시로 구분됩니다.

적용 범위 | 설명
--- | ---
`/pattern1/,/pattern2/s` | pattern1 이 포함된 첫 번째 줄부터 pattern2 가 포함된 첫 번째 줄까지 검색합니다.
`:.,/pattern/s` | 현재 줄부터 pattern 이 포함된 줄까지 검색합니다.

이 작업은 단순히 패턴 앞의 텍스트가 아닌, 패턴이 포함된 줄 전체에 수행된다는 점을 유의해야 합니다.


### Search and Replace

한 문자열을 다른 문자열로 대체하는 데 사용되는 대체 명령어는 이미 살펴보았습니다. 슬래시는 기존 문자열과 새 문자열을 구분하는 구분자로 사용됩니다. `s` 명령어 앞에 주소를 붙여주면, 범위를 한 줄 이상으로 확장할 수 있습니다:

```
:1,20s/Alcuin/ALCUIN/
```

이 명령은 줄 주소와 결합되어 텍스트 블록 내의 모든 줄을 검색합니다. 하지만 각 줄에서 패턴이 나타나는 첫 번째 위치만 치환합니다. 예를 들어, 다음 줄에서 ‘roman’ 을 ‘Roman’ 으로 치환하는 치환 명령을 지정하면:

```
after the roman hand. In teaching the roman script
```

해당 단어가 나타나는 첫 번째 위치만 변경되고, 두 번째 위치는 변경되지 않습니다.

한 줄 내의 모든 발생 위치를 지정하려면 명령어 끝에 `g` 를 추가해야 합니다:

```
:s/roman/Roman/g
```

이 명령어는 현재 줄에서 roman 이 나타나는 모든 위치를 Roman 으로 변경합니다.

검색 및 바꾸기 기능을 사용하는 것은 문자열의 각 발생 위치를 찾아 개별적으로 바꾸는 것보다 훨씬 빠릅니다. 특히 철자가 서툰 분들에게는 다양한 용도로 활용할 수 있습니다.

지금까지는 한 단어를 다른 단어로 치환했습니다. 보통은 그렇게 간단하지 않습니다. 단어에 접두사나 접미사가 붙어서 치환을 어렵게 만들 수도 있습니다. 잠시 후, 패턴 매칭에 대해 살펴보겠습니다. 이를 통해 처리할 수 있는 작업의 범위가 훨씬 더 넓어질 것입니다. 하지만 먼저, 검색 및 치환을 파일 전체에 처리하도록 지정하는 방법을 알아보겠습니다.


### Confirming Substitutions

‘찾기 및 바꾸기’ 명령을 사용할 때 지나치게 조심스러워지는 것은 당연한 일입니다. 실제로 예상했던 결과와 다른 결과가 나오는 경우가 종종 있기 때문입니다. `u` 를 입력하면 어떤 ‘찾기 및 바꾸기’ 명령이든 실행 취소할 수 있습니다.

하지만 원치 않는 변경 사항을 되돌리기에는 이미 너무 늦은 후에야 알아차리는 경우도 있습니다. 편집한 파일을 보호하는 또 다른 방법은 치환을 수행하기 전에 `:w` 를 입력해서 파일을 저장하는 것입니다. 그러면 적어도 편집 내용을 저장하지 않고 파일을 종료한 뒤, 변경하기 이전 상태로 되돌릴 수 있습니다. 또한 `:e!` 를 사용해서 버퍼의 이전 버전을 불러올 수도 있습니다.

신중을 기하고 파일에서 무엇이 변경될지 정확히 파악하는 것이 가장 좋습니다. 검색 결과가 어떻게 나오는지 확인하고 각 치환이 적용되기 전에 확인하려면, 치환 명령어 끝에 `c` 를 추가하세요:

```
:1,30s/his/the/gc
```

그러면 해당 문자열이 발견된 줄 전체가 표시되고, 문자열 자체는 일련의 캐럿(`ˆˆˆ`)으로 표시됩니다.

```
copyists at his school
            ˆˆˆ
```

치환을 진행하려면 `y` 를 입력하고 RETURN 키를 눌러야 합니다. 변경하지 않으려면 RETURN 키만 누르면 됩니다.

```
this can be used for invitations, signs, and menus.
ˆˆˆ
```

vi 명령어인 `//` (마지막 검색 반복)과 `.` (마지막 명령 반복)을 조합하면, 파일을 일일이 훑어보면서 절대적인 전체 치환보다 판단이 필요한 반복적인 변경을 수행하는 데 유용하고(그리고 빠른) 방법이 됩니다.


### Global Search and Replace

줄 단위 주소 지정 기호를 살펴볼 때, 퍼센트 기호(`%`)를 소개했습니다. 이 기호를 `substitute` 명령과 함께 지정하면, 검색 및 바꾸기 명령이 파일의 모든 줄에 적용됩니다:

```
:%s/Alcuin/ALCUIN/g
```

이 명령은 모든 줄을 검색해서 한 줄에 나타나는 각 발생 항목을 모두 바꿉니다.

이를 수행하는 또 다른 방법이 있는데, 약간 더 복잡하지만 다른 장점이 있습니다. 패턴은 주소의 일부로 지정되며, 그 앞에 `g` 를 붙여 전역 검색임을 나타냅니다:

```
:g/Alcuin/s//ALCUIN/g
```

이 명령은 Alcuin 패턴이 포함된 모든 줄을 선택하고, 해당 패턴이 나타나는 모든 부분을 ALCUIN 으로 치환합니다. 검색 패턴이 변경하려는 단어와 동일하기 때문에, 치환 명령어에서 이를 반복 입력할 필요가 없습니다.

이 방법이 주는 추가적인 이점은 패턴을 검색한 후 다른 내용으로 치환할 수 있다는 점입니다. 이를 문맥에 민감한 치환이라고 합니다.

이 명령어의 핵심은 패턴을 전역적으로 검색하는 것입니다:

```
:g/pattern/
```

이를 치환합니다:

```
:g/pattern/s//
```

또는 해당 줄에서 다른 문자열을 치환합니다:

```
:g/pattern/s/string/
```

새로운 문자열로:

```
:g/pattern/s/string/new/
```

그리고 해당 줄에 나타나는 모든 발생 위치에 대해 이 작업을 수행합니다.

```
:g/pattern/s/string/new/g
```

예를 들어, 특수 키 이름 주위에 상자를 그리는데 `.BX` 매크로를 사용합니다. 매뉴얼에서 ESCAPE 키를 표시하려면 다음과 같이 입력합니다:

```
.BX Esc
```

Esc 를 ESC (대문자)로 변경해야 하지만, 본문에서 Escape 에 대한 참조는 변경하지 않는다고 가정해 봅시다. 다음 명령을 사용해서 변경할 수 있습니다:

```
:g/BX/s/Esc/ESC/
```

이 명령어는 다음과 같이 표현할 수도 있습니다. “BX가 나타나는 모든 부분을 전역적으로 검색하고, 해당 줄에서 ‘Esc’ 를 ‘ESC’ 로 대체하라!” 명령어 끝에 `g` 를 명시하지 않은 이유는 이 명령은 한 줄에 한 번 이상 나타날 것으로 예상하지 않았기 때문입니다.

사실, 이런 구문에 익숙해지기 어색하다는 점을 인정하면, 오히려 이 구문이 마음에 들 수도 있습니다.



## Pattern Matching

`grep` 도구에 익숙하다면 정규 표현식에 대해서도 어느 정도 알고 계실 것입니다. 전체 일괄 바꾸기를 수행할 때, 고정된 문자열뿐만 아니라 ‘정규 표현식’ 이라 불리는 단어 패턴도 검색할 수 있습니다.

문자열을 그대로 지정하면, 검색 결과에서 일치시키고 싶지 않은 다른 항목들도 나타날 수 있습니다. 파일에서 단어를 검색할 때의 문제는 한 단어가 여러 가지 다른 방식으로 사용될 수 있다는 점입니다. 정규 표현식을 사용하면 문맥에 맞는 단어 검색을 수행할 수 있습니다.

정규 표현식은 일반 문자와 여러 특수 문자를 결합해서 구성됩니다. 특수 문자와 사용법은 다음과 같습니다.[^1]

[^1]:  `\(` 와 `\)` 그리고 `\{n,m\}` 는 모든 버전의 vi에서 지원되지 않습니다. `\<, \>, \u, \U, \l, \L` 은 vi/ex만 지원되며, 정규 표현식을 사용하는 다른 프로그램에서는 지원되지 않습니다.


특수 문자 | 설명 
--- | ---
`.` | 줄바꿈을 제외한 임의의 단일 문자를 일치시킵니다.
`*` | 바로 앞에 오는 단일 문자(정규 표현식으로 지정된 문자 포함)가 0개를 포함해서 임의의 개수만큼 반복되는 것을 일치시킵니다. 예를 들어,
`.` | (점)은 임의의 문자를 의미하므로, `.*` 는 임의의 문자가 임의의 개수만큼 나오는 것을 일치시킵니다.
`[...]` | 대괄호로 묶인 문자 중 하나를 일치시킵니다. 예를 들어, `[AB]` 는 A 또는 B 중 하나를 일치시킵니다. 연속된 문자 범위는 범위의 첫 번째 문자와 마지막 문자를 하이픈으로 구분해서 지정할 수 있습니다. 예를 들어, `[A-Z]` 는 A부터 Z까지의 대문자를, `[0-9]` 는 0부터 9까지의 숫자를 일치시킵니다.
`\{n,m}\` | 바로 앞에 오는 단일 문자(정규 표현식으로 지정된 문자 포함)가 n~m 번 반복되는 범위를 일치시킵니다. n과 m은 0에서 256 사이의 정수이며, 일치시킬 반복 횟수를 지정합니다. `\{n\}` 은 정확히 n번의 출현을 일치시키고, `\{n,\}` 은 최소 n번의 출현을 일치시키며, `\{n,m\}` 은 n과 m 사이의 임의의 횟수만큼의 출현을 일치시킵니다. 예를 들어, `A\{2,3\}` 은 AA (AARDVARK 에서와 같이)나 AAA 와 일치하지만 단일 문자 A와는 일치하지 않습니다.
`ˆ` | 줄 시작 부분에서 다음 정규 표현식이 발견되어야 함을 나타냅니다.
`$` | 줄 끝 부분에서 앞서 언급된 정규 표현식이 발견되어야 함을 나타냅니다.
`\` | 뒤따르는 특수 문자를 일반 문자로 취급합니다. 예를 들어, `\.` 는 마침표를, `\*` 는 별표를 나타냅니다.
`\(` | `\(` 와 `\)` 로 묶인 패턴을 특수한 저장 공간에 저장합니다. 한 줄에 최대 9개의 패턴을 이 방법으로 저장할 수 있습니다. 이 패턴들은 `\1` 부터 `\9` 까지의 이스케이프 시퀀스를 사용해서 치환 과정에서 “재사용” 할 수 있습니다.
`\n` | `\(` 와 `\)` 로 이전에 저장된 n번째 패턴과 일치합니다. 여기서 n은 0에서 9 사이의 숫자이며, 이전에 저장된 패턴은 줄 왼쪽부터 순서대로 계산됩니다.
`\< \>` | 단어 시작 부분(`\<`) 또는 끝 부분(`\>`)에 있는 문자와 일치시킵니다. 표현식 `\<ac` 는 action 같이 ac로 시작하는 단어만 일치하며, react 같은 단어는 일치하지 않습니다.
`&` | 치환 문자열에서 사용될 때 전체 검색 패턴을 출력합니다.
`\u` | 치환 문자열의 첫 번째 문자를 대문자로 변환합니다.
`\U` | `:/Unix/\U&/` 같이 대체 문자열 전체를 대문자로 변환합니다.
`\l` | `:s/ Act/\l&/` 같이 대체 문자열의 첫 번째 문자를 소문자로 변환합니다.
`\L` | 대체 문자열 전체를 소문자로 변환합니다.

UNIX의 와일드카드 문자에 익숙하지 않다면, 이 특수 문자 목록은 아마 복잡해 보일 것입니다. 몇 가지 예시를 통해 좀 더 명확히 이해해 봅시다. 다음 예시는 빈 사각형 `(□)` 을 공백을 나타내는 데 사용합니다.

치환 작업에서 특수 문자를 어떻게 사용할 수 있는지 살펴보겠습니다. 긴 파일이 있고, 그 파일 전체에서 ‘ball’ 이라는 단어를 ‘balls’ 로 치환한다고 가정해 봅시다. 먼저 `:w` 를 사용해서 편집한 버퍼를 저장한 다음, 전역 치환을 시도해 봅니다.

```
:g/ball/s//balls/g
```

편집을 계속하다 보면 ‘ballsoon’, ‘globallsy’, ‘ballss’ 같은 단어들이 나타나는 것을 발견하게 됩니다. `:e!` 를 사용해서 마지막으로 저장한 버퍼로 돌아간 후, 이제 검색 범위를 제한하기 위해 ‘ball’ 뒤에 공백을 추가해서 지정해 봅니다.

```
:g/ball□/s//balls□/g
```

하지만 이 명령어는 ball., ball,, ball: 같은 발생 사례는 놓칩니다.

```
:g/\<ball\>/s//balls/g
```

검색 패턴을 `\<` 와 `\>` 로 감싸면, 뒤따르는 구두점 유무와 상관없이 패턴이 전체 단어와만 일치하도록 지정합니다. 따라서 'balls' 라는 단어가 이미 존재하는 경우는 일치하지 않습니다.

`\<` 와 `\>` 는 ex(그리고 vi)에서만 사용할 수 있으므로, 경우에 따라 좀 더 긴 형식을 사용해야 할 수도 있습니다:

```
:g/ball\([□,.;:!?]\)/s//balls\1/g
```

이 명령은 ‘ball’ 뒤에 공백(`□` 로 표시됨)이나 구두점 문자 중 하나(`, . ; : ! ?`)가 오는 부분을 찾아서 바꾸어 줍니다. 또한, 일치된 문자는 `\(` 와 `\)` 를 사용해서 저장되고, 오른쪽에서 `\1` 을 통해 복원됩니다. 구문이 복잡해 보일 수 있지만, 이 명령어 순서는 비슷한 대체 작업에서 수많은 수고를 덜어줄 수 있습니다.


### Search for General Classes of Words

특수 문자 `&` 는 치환 명령어의 치환 부분에서 일치된 패턴을 나타내는 데 사용됩니다. 이 문자는 비슷하지만 다른 단어와 구문을 검색하고 변경할 때 유용할 수 있습니다. 

예를 들어, 한 제조업체가 컴퓨터 모델명을 약간 변경하기로 결정해서 마케팅 브로셔를 수정할 경우가 있습니다. HX5000 모델은 HX6000 및 HX8500 모델과 함께 'Series HX5000' 으로 이름이 변경되었습니다. 다음은 `&` 문자를 사용해서 이를 수행하는 방법입니다.

```
:g/HX[568][05]00/s//Series &/g
```

이렇게 하면 HX8500 이 Series HX8500 으로 변경됩니다. `&` 문자는 전체 검색 패턴을 다시 불러와 여기에 내용을 추가할 때 유용합니다. 

검색 패턴의 일부만 캡처하려면 `\(` 와 `\)` 를 사용하며, 저장된 패턴은 `\1 ... \n` 을 사용해서 다시 불러와야 합니다.

예를 들어, 앞서 언급한 컴퓨터 제조사가 모델 번호에서 HX 를 삭제하고 그 번호 뒤에 Series 를 추가하기로 결정했다고 가정해 봅시다. 다음 명령을 사용해서 변경할 수 있습니다:

```
:g/\(Series\) HX\([568])[05]00\)/s//\2 \1/g
```

이 명령은 Series HX8500 을 8500 Series 로 치환합니다.

접두사 mgi, mgr, mga 로 시작하는 서브루틴 이름이 있다고 가정해 봅시다.

```
mgibox routine
mgrbox routine
mgabox routine
```

접두사를 유지하되 ‘box’ 를 ‘square’ 로 변경하려면, 다음 대체 명령어를 사용하면 됩니다:

```
:g/mg\([iar]\)box/s//mg\1square/
```

전역 대체 기능은 i, a, r 중 어떤 문자가 유지되는지 추적하므로, ‘box’ 만 ‘square’ 로 변경됩니다.

이는 다음 명령과 동일한 효과를 냅니다:

```
:g/mg[iar]box/s/box/square/g
```

결과는 다음과 같습니다:

```
mgisquare routine
mgrsquare routine
mgasquare routine
```


### Block Move by Patterns

특정 패턴으로 구분된 텍스트 블록을 편집할 수 있습니다. 예를 들어, 150페이지 분량의 참조 매뉴얼이 있다고 가정해 봅시다. 모든 참조 페이지는 동일한 방식으로 구성되어 있습니다. 즉, ‘SYNTAX’ 라는 제목의 단락이 있고, 그 다음에는 ‘DESCRIPTION’ 이, 그 다음에는 ‘PARAMETERS’ 가 이어집니다. 다음은 참조 페이지의 예시입니다:

```
.Rh 0 "Get status of named file" "STAT"
.Rh "SYNTAX"
.nf
integer*4 stat, retval
integer*4 status(11)
character*123 filename
...
retval = stat (filename, status)
.fi
.Rh "DESCRIPTION"
Writes the fields of a system data structure into the
status array. These fields contain (among other
things) information about the file’s location, access
privileges, owner, and time of last modification.
.Rh "PARAMETERS"
.IP "filename" 15n
A character string variable or constant containing
the UNIX pathname for the file whose status you want
to retrieve. You can give the...
```

이제 DESCRIPTION 을 SYNTAX 단락 위로 옮기기로 결정했다고 가정해 봅시다. 패턴 매칭을 이용하면, 단 한 번의 명령으로 150페이지 전체에 걸쳐 있는 텍스트 블록을 한 번에 이동할 수 있습니다!

```
:g/SYNTAX/,/DESCRIPTION/-1,mo/PARAMETERS/-1
```

이 명령은 ‘SYNTAX’ 라는 단어가 포함된 줄과 ‘DESCRIPTION’ 이라는 단어 바로 앞의 줄(`/DESCRIPTION/-1`) 사이에 있는 텍스트 블록을 ‘PARAMETERS’ 바로 앞의 줄로 이동시킵니다. 이와 같은 경우, 단 한 번의 명령으로 말 그대로 몇 시간의 작업 시간을 절약할 수 있습니다.


이는 다른 ex 명령어도 똑같이 적용됩니다. 예를 들어, 참조 장에 있는 모든 DESCRIPTION 단락을 삭제하려면 다음과 같이 입력하면 됩니다:

```
:g/DESCRIPTION/,/PARAMETERS/-1,d
```

이런 매우 강력한 변경 기능은 ex 편집기의 줄 주소 지정 구문에 내재되어 있었지만, 쉽게 알아차리기 어렵습니다. 따라서 복잡하고 반복적인 편집 작업에 직면할 때마다 시간을 내어 문제를 분석하고, 패턴 매칭 도구를 적용해서 작업을 수행할 수 있는지 확인해 보십시오.


### More Examples

패턴 매칭을 배우는 가장 좋은 방법은 예제를 통해 익히는 것이므로, 다음 섹션은 간략한 설명이 포함된 예제 목록을 제시합니다. 작동 원리를 이해할 수 있도록 구문을 주의 깊게 살펴보세요. 그러면 자신의 상황에 맞게 이를 적용할 수 있게 될 것입니다.

[1] 모든 빈 줄을 삭제합니다:

```
:g/ˆ$/d
```

여기서 매칭하는 대상은 줄 시작 부분과 끝 부분 사이에 아무것도 없는 경우입니다.

[2] RETURN 이라는 단어 주위에 troff 이탤릭 코드를 삽입합니다:

```
:g/RETURN/s//\\fIRETURN\\fR/g
```

troff 이탤릭 코드의 백슬래시(`\`)는 특수 문자로 해석되므로, 치환 시 두 개의 백슬래시(`\\`)가 필요하다는 점에 유의하십시오. (`\fI` 만 있으면 fI 로 해석되므로, `\fI` 를 얻으려면 `\\fI` 가 필요합니다).

[3] 파일 내 경로명 목록을 수정합니다:

```
:g/\/usr\/tim/s//\/usr\/linda/g
```

슬래시(전역 치환 시퀀스에서 구분자로 사용됨)는 패턴이나 치환 문자열의 일부일 때 백슬래시로 이스케이프 처리해야 합니다. `/` 를 얻으려면 `\/` 를 사용하십시오. 동일한 효과를 얻는 또 다른 방법은 패턴 구분자로 다른 문자를 사용하는 것입니다. 예를 들어, 앞서 언급한 치환을 다음과 같이 수행할 수도 있습니다:

```
:g:/usr/tim:s::/usr/linda:g
```

[4] 1~10행에서 모든 마침표를 세미콜론으로 변경합니다:

```
:1,10g/\./s//;/g
```

마침표는 특수 문자이므로 백슬래시로 이스케이프 처리해야 합니다.

[5] 목록에서 하이픈으로 구분된 모든 항목의 순서를 반대로 바꿉니다:

```
:g/\(.*\) - \(.*\)/s//\2 - \1/
```

이 명령어를 여러 항목에 적용하면 다음과 같은 결과가 나옵니다:

```
more - display files → display files - more
lp - print files → print files - lp
```

[6] 단어나 제목의 다양한 표기법을 통일합니다:

```
:g/ˆExample[□s:]/s//Examples:□/g
```

괄호 안에는 공백(예시는 □ 로 표시됨), 콜론, 문자 s 이렇게 세 개의 문자가 포함되어 있습니다. 따라서 이 명령은 줄 시작 부분에서 Example , Examples 또는 Example: 을 검색해서 Examples: 으로 치환합니다. (공백을 포함하지 않으면 Examples 가 Exampless: 으로 치환될 것입니다.) 이와 유사한 또 다른 예로, ‘help’ (또는 ‘Help’)라는 단어가 나타나는 모든 곳을 ‘HELP’ 로 변경해 보겠습니다:

```
:g/[Hh]elp/s//HELP/g
```

7. 하나 이상의 공백을 단일 공백으로 바꿉니다:

```
:g/□□*/s//□/g
```

별표(*)가 특수 문자로 어떻게 작동하는지 반드시 이해해야 합니다. 어떤 문자(또는 `.` 이나 `[a-z]` 같이 단일 문자와 일치하는 정규 표현식) 뒤에 오는 별표는 해당 문자의 0개 이상의 인스턴스와 일치합니다. 따라서 하나 이상의 공백(1개와 0개 이상)과 일치시키려면 두 개의 공백 뒤에 별표를 지정해야 합니다.

[8] 콜론 뒤에 오는 하나 이상의 공백을 두 개의 공백으로 바꿉니다:

```
:g/:□□*/s//:□□/g
```

[9] 마침표나 콜론 뒤에 오는 하나 이상의 공백을 두 개의 공백으로 바꿉니다:

```
:g/\([:.]\)□□*/s//\1□□/g
```

대괄호 안의 두 문자 중 어느 하나라도 일치시킬 수 있습니다. 이 문자는 괄호를 사용해서 저장된 후, 오른쪽에서 1로 복원됩니다. 마침표 같은 특수 문자는 대괄호 안에서 이스케이프 처리할 필요가 없다는 점에 유의하십시오.

[10] 줄의 맨 앞 공백을 모두 삭제합니다:

```
:g/ˆ□□*\(.*\)/s//\1/g
```

줄의 맨 앞에 있는 하나 이상의 공백을 검색하고, 줄의 나머지 부분을 저장한 뒤 맨 앞 공백을 제거한 상태로 다시 삽입합니다.

[11] 줄 끝의 공백을 모두 삭제합니다:

```
:g/□□*$/s///
```

[12] 문서 내 섹션 제목(예: 1.1 서론)에서 수동으로 매겨진 번호를 제거합니다:

```
:g/[1-9]\.[1-9]*\(.*\)/s//\1/g
```

대괄호(`[...]`)로 묶인 하이픈으로 구분된 문자 또는 숫자 쌍(예: [1-9])은 문자 범위를 지정합니다.

[13] 수동으로 번호가 매겨진 섹션 제목(예: 1.1, 1.2)을 troff 매크로(예: A급 제목의 경우 .Ah)로 변경합니다:

```
:g/ˆ[1-9]\.[1-9]/s//\.Ah/
```

[14] 매크로가 해석되지 않도록 보호해서 출력에 표시합니다. 매크로 앞에 `\&` 를 붙이면 troff가 매크로를 확장하지 못합니다. 이 명령은 매크로가 포함된 예제를 출력하기 위해 이 책 전체에서 자주 사용되었습니다. 치환 패턴에는 세 개의 백슬래시가 필요합니다. 두 개는 백슬래시를 출력하기 위함이고, 하나는 첫 번째 앰퍼샌드(`&`)가 문자 그대로 해석되도록 하기 위함입니다:

```
:g/ˆ\./s//\\\&&/
```


## Writing and Quitting Files

파일을 종료하고 파일 내용을 저장하는 vi 명령어 `ZZ` 를 배웠습니다. 하지만 일반적으로 ex 명령어를 사용해서 파일을 저장하고 종료하는 것이 좋습니다. 이 명령어들을 사용하면 좀 더 세밀하게 제어할 수 있기 때문입니다.

명령어 | 설명
--- | ---
`:w` | 버퍼의 내용을 파일에 저장하지만, 파일을 종료하지 않습니다. 편집 세션 도중 언제든지 `:w` 를 사용해서 시스템 오류나 중대한 편집 실수로 인한 손실을 방지할 수 있습니다.
`:q` | 파일을 종료하고 UNIX 프롬프트로 돌아갑니다.
`:wq` | 파일을 저장하고 종료합니다.

vi 편집기는 기존 파일과 버퍼에 있는 편집 내용을 보호합니다. 예를 들어, 버퍼 내용을 기존 파일에 쓰려고 하면, vi는 원본 파일이 삭제될 수 있으므로 경고를 표시합니다. 마찬가지로, 파일에 vi를 실행해서 편집을 마친 후 편집 내용을 저장하지 않고 종료하려고 하면, vi는 다음과 같은
오류 메시지를 표시합니다:

```
No write since last change.
```

이런 경고는 심각한 실수를 방지해 주지만, 때로는 어쨌든 명령을 진행할 때가 있습니다. 명령 뒤에 느낌표(`!`)를 붙이면 이런 경고를 무시할 수 있습니다:

```
:w! filename
:q!
```

`:q!` 명령은 세션에서 어떤 변경을 했든 상관없이 원본 파일에 영향을 주지 않고 종료할 수 있는 필수적인 편집 명령입니다. 버퍼의 내용은 버려집니다.


### Renaming the Buffer

`:w` 명령어를 사용하면 전체 버퍼(편집 중인 파일의 사본)를 새로운 파일 이름으로 저장할 수도 있습니다.

600줄로 구성된 ‘letter’ 라는 파일이 있다고 가정해 봅시다. 이 파일의 사본을 불러와 대대적인 편집을 진행했습니다. 이제 프로그램을 종료하면서 비교를 위해 ‘letter’ 의 이전 버전과 새로 편집한 내용 모두 저장하고 싶습니다. 버퍼 이름을 ‘letter.new’ 로 변경하려면 다음 명령어를 입력합니다:

```
:wq letter.new
```


### Saving Part of a File

편집 작업 중에는 때때로 파일의 일부만 별도의 새 파일로 저장할 때가 있습니다. 예를 들어, 여러 파일의 머리글로 사용하고 싶은 서식 코드와 텍스트를 입력해 둔 경우가 있을 수 있습니다.

‘ex’ 줄 지정 기능과 쓰기 명령어인 ‘w’ 를 함께 사용하면 파일의 일부를 저장할 수 있습니다. 예를 들어, ‘letter’ 파일에 있는 상태에서 ‘letter’ 의 일부를 ‘newfile’ 이라는 파일로 저장하려면 다음과 같이 입력하면 됩니다.

```
:230,$w newfile
```

이렇게 하면 230행부터 파일 끝까지가 newfile 에 저장됩니다. 또는:

```
:.,600w newfile
```

이렇게 하면 현재 행부터 600행까지가 newfile에 저장됩니다.


### Appending to a Saved File

`w` 명령어와 UNIX 리디렉션 및 추가 연산자(`>>`)를 함께 사용하면 버퍼의 내용을 기존 파일에 추가할 수 있습니다. 예를 들어:

```
:1,10w newfile
:340,$w>>newfile
```

기존 파일인 newfile 에는 1행부터 10행까지와, 340행부터 버퍼 끝까지의 내용이 포함됩니다.



## Reading In a File

때로는 시스템에 이미 입력된 텍스트나 데이터를 편집 중인 파일로 복사할 때가 있습니다. vi에서는 ex 명령어를 사용해서 다른 파일의 내용을 불러올 수 있습니다:

```
:read filename
```

또는:

```
:r filename
```

이렇게 하면 파일 내 커서 위치 바로 다음 줄에 filename 파일의 내용이 불러와집니다.

현재 letter 파일을 편집 중이며, `/work/alcuin/ch01` 이라는 다른 디렉터리에 있는 파일의 데이터를 불러오고 싶다고 가정해 봅시다. 새 데이터를 삽입할 줄 바로 위에 커서를 위치시킨 다음, 다음 명령을 입력합니다:

```
:r /work/alcuin/ch01
```

`/work/alcuin/ch01` 파일의 전체 내용이 커서 위치 바로 아래부터 시작해서 letter 파일에 읽어집니다.


## Executing UNIX Commands

vi에서 편집하는 동안에도 임의의 UNIX 명령어 결과를 표시하거나 읽어올 수 있습니다. 느낌표(`!`)를 사용하면 ex가 셸을 생성하고 그 뒤에 오는 내용을 UNIX 명령어로 인식하게 됩니다.

```
:!command
```

따라서 편집 중에 vi를 종료하지 않고 시간이나 날짜를 확인하려면 다음과 같이 입력하면 됩니다.

```
:!date
```

화면에 시간과 날짜가 표시됩니다. RETURN 키를 누르면 파일의 같은 위치에서 편집을 계속할 수 있습니다. 중간에 vi로 돌아가지 않고 여러 UNIX 명령을 연속으로 실행하려면, ex 명령을 사용해서 셸을 생성할 수 있습니다:

```
:sh
```

셸을 종료하고 vi로 돌아가려면 `ˆD` (Ctrl+d)를 누르십시오.

`:read` 명령을 UNIX 호출과 결합해서 UNIX 명령의 결과를 파일로 읽어올 수 있습니다. 아주 간단한 예로:

```
:r !date
```

이렇게 하면 시스템의 날짜 정보가 파일 텍스트로 읽어집니다.

파일을 편집 중인데, phone 이라는 파일에서 네 개의 전화번호를 알파벳 순서대로 읽어오고 싶다고 가정해 봅시다. phone 파일의 순서는 다음과 같습니다:

```
Willing, Sue 333-4444
Walsh, Linda 555-6666
Quercia, Valerie 777-8888
Dougherty, Nancy 999-0000
```

다음 명령어:

```
:r !sort phone
```

는 `sort` 필터를 거친 후의 phone 내용을 읽어옵니다:

```
Dougherty, Nancy 999-0000
Quercia, Valerie 777-8888
Walsh, Linda 555-6666
Willing, Sue 333-4444
```

파일을 편집하다가 같은 디렉토리에 있는 다른 파일의 텍스트를 삽입하고 싶지만, 해당 파일의 이름을 기억하지 못한다고 가정해 봅시다.

이 작업을 번거로운 방법으로 수행할 수도 있습니다. 즉, 현재 파일을 종료하고, `ls` 명령을 실행해서 올바른 파일 이름을 확인한 뒤, 다시 파일을 열고 해당 위치를 찾아야 합니다.

아니면 좀 더 적은 단계로 이 작업을 수행할 수도 있습니다. `:!ls` 명령을 입력하면 해당 디렉토리에 있는 파일 목록이 표시됩니다. 올바른 파일 이름을 확인한 후, RETURN 키를 눌러 편집을 계속하면 됩니다.

```
file1
file2
letter
newfile
```

다음 명령어:

```
:r newfile
```

는 새 파일을 읽어옵니다:

```
"newfile" 35 lines, 949 characters
```


### Filtering Text through a Command

또한 UNIX 명령어에 표준 입력으로 텍스트 블록을 내보낼 수도 있습니다. 이 명령어의 출력은 버퍼에 있는 텍스트 블록을 대체합니다. 명령어를 통해 텍스트를 필터링하는 작업은 ex나 vi에서 모두 수행할 수 있습니다. 두 방법의 주요 차이점은 ex에서는 텍스트 블록이 줄 주소로, vi에서는 텍스트 객체로 표시된다는 점입니다.

첫 번째 예제는 ex에서 이를 수행하는 방법을 보여줍니다. 앞서 예제에 나온 이름 목록이 phone 이라는 별도의 파일에 들어 있는 대신, 현재 파일의 96~99행에 이미 포함되어 있다고 가정해 봅시다.

변경하려는 행의 주소를 입력한 다음, 느낌표와 실행할 UNIX 명령줄을 입력하면 됩니다. 예를 들어, 다음 명령어:

```
:96,99!sort
```

는 96행부터 99행까지를 `sort` 필터를 통과시켜, 해당 행들을 `sort` 의 출력 결과로 대체합니다.

vi에서 이 시퀀스는 느낌표 뒤에 텍스트 블록을 나타내는 vi 객체를 입력하고, 그 뒤에 실행할 유닉스 명령줄을 입력해서 호출됩니다. 예를 들어:

```
!)command
```

는 다음 문장을 command 를 통해 처리합니다.

이 기능을 사용할 때 vi의 동작에는 몇 가지 특이한 점이 있습니다. 

- 첫째, 입력한 느낌표는 즉시 화면에 표시되지 않습니다. 영향을 받을 텍스트 객체를 나타내는 기호를 입력하면 화면 하단에 느낌표가 나타나지만, 객체를 참조하기 위해 입력한 기호는 표시되지 않습니다.

- 둘째, 한 줄 이상의 텍스트를 참조하는 객체(`G, {}, (), []`)만 사용할 수 있습니다. 숫자를 감탄 기호 앞이나 객체 앞에 붙이면 해당 효과를 반복할 수 있습니다. `w` 같은 객체는 한 줄을 초과할 만큼 충분히 지정되지 않는 한 작동하지 않습니다. 슬래시(`/`) 뒤에 패턴과 RETURN 을 지정할 수도 있으며, 이 경우 패턴까지의 텍스트가 명령어의 입력으로 사용됩니다.

- 셋째, 이 명령어 구문에서만 사용되는 특수 객체가 있습니다. 현재 줄은 두 번째 느낌표를 입력해서 지정할 수 있습니다:

```
!!command
```

전체 시퀀스나 텍스트 객체 앞에 숫자를 붙여 효과를 반복할 수 있습니다. 예를 들어, 이전 예제와 동일한 줄을 변경하려면 커서를 96번째 줄에 위치시킨 후 다음을 입력하면 됩니다:

```
4!!sort
```

또는:

```
!4!sort
```

또는, 파일 내의 특정 텍스트 부분을 소문자에서 대문자로 변경한다고 가정해 봅시다. `tr` 도구를 사용해서 해당 부분을 처리할 수 있습니다. 이 예제들에서 두 번째 문장은 명령어에 전달될 텍스트 블록입니다. 마지막 줄에는 UNIX 명령어를 입력하라는 안내로 느낌표가 표시됩니다:

![20261017_204720.jpg](images/20261017_204720.jpg)

UNIX 명령어를 입력하고 RETURN 키를 누르세요. 입력 내용이 출력 내용으로 대체됩니다.

![20261017_204759.jpg](images/20261017_204759.jpg)

이전 명령을 반복하려면 다음 구문을 사용합니다.

```
!block!
```

코딩된 문서의 일부를 nroff로 보내서 서식이 적용된 출력으로 대체하는 것이 때로는 유용합니다. 하지만 “원본” 입력 내용이 출력 내용으로 대체된다는 점을 기억하십시오.

예상한 출력 대신 오류 메시지가 전송되는 등 실수가 발생한 경우, 명령을 취소하고 해당 줄을 복원할 수 있습니다.



## Editing Multiple Files

ex 명령어를 사용하면 여러 파일을 편집할 수 있습니다. 여러 파일을 편집할 때의 장점은 속도입니다. 다른 사용자와 시스템을 공유할 때, 편집하려는 파일마다 vi를 종료했다가 다시 실행하는 데는 시간이 걸립니다. 동일한 편집 세션을 유지한 채 파일 간을 이동하면 접근 시간이 단축될 뿐만 아니라, 사용자가 정의한 약어와 명령어 순서를 저장하고 이름이 지정된 버퍼를 유지할 수 있어 한 파일에서 다른 파일로 텍스트를 복사할 수 있습니다.


### Invoking vi on Multiple Files

vi를 처음 실행할 때, 편집할 파일을 여러 개 지정해서 순차적으로 편집한 다음, ex 명령을 사용해서 파일 간을 이동할 수 있습니다. 다음 명령어:

```
$ vi file1 file2
```

는 file1 을 먼저 실행합니다. 첫 번째 파일 편집을 마친 후, ex 명령 `:w` 를 사용하면 file1 을 저장하고, `:n` 을 사용하면 다음 파일(file2)을 불러옵니다.

letter 와 note 라는 두 파일을 편집할 계획이라고 가정해 봅시다. 다음 명령을 입력해서 두 파일을 엽니다.

```
$ vi letter note
```

화면에 다음과 같은 메시지가 나타납니다.

```
Two files to edit
```

첫 번째로 지정한 파일인 letter 가 표시됩니다. letter 를 편집한 후, ex 명령 `:w` 를 사용해서 저장합니다. ex 명령 `:n` 을 사용해서 다음 파일인 note 를 불러온 다음 RETURN 키를 누릅니다. 편집을 마친 후 `:wq` 를 사용해서 편집 세션을 종료합니다.

한 번에 vi로 불러올 수 있는 파일 수에는 실질적인 제한이 없습니다. 셸의 모든 패턴 일치 문자를 사용할 수 있으며, 좀 더 복잡한 구문도 사용할 수 있습니다. 예를 들어, 프로그램을 작성하다가 getcursor 같은 함수 호출 이름을 변경한다고 가정해 봅시다. 다음 명령어:

```
$ vi ‘grep -l getcursor *‘
```

는 현재 디렉토리에서 ‘getcursor’ 라는 문자열을 포함하는 모든 파일에 대해 vi를 실행합니다. 다음 명령어:

```
$ grep -l
```

특정 문자열이 포함된 모든 파일의 이름을 출력합니다. 백쿼트(````)로 묶인 명령을 다른 명령의 인수로 사용하면, 셸은 백쿼트 안의 명령 출력을 첫 번째 명령의 인수 목록으로 사용합니다.

vi 편집기는 첫 번째 파일을 표시하기 전에 다음과 유사한 메시지를 출력합니다:

```
5 files to edit
```

모든 파일을 편집하지 않고 종료하려고 하면, vi는 다음과 같은 경고 메시지를 표시합니다:

```
4 more files to edit
```

모든 파일을 편집하지 않고 종료하려면 `:q!` 를 입력해야 합니다.


### Calling In New Files

편집 세션을 시작할 때 여러 파일을 한꺼번에 불러올 필요는 없습니다. vi에서는 언제든지 ex 명령어인 `:e` 를 사용해서 다른 파일로 전환할 수 있습니다. vi 내에서 다른 파일을 편집하려면, 먼저 현재 파일을 저장(`:w`)한 다음 다음 명령어를 입력합니다.

```
:e filename
```

예를 들어, ‘letter’ 파일을 편집 중인데 ‘note’ 파일을 편집한 후 다시 ‘letter’ 파일로 돌아가고 싶다고 가정해 봅시다. `w` 를 입력해서 letter 파일을 저장한 후 RETURN 키를 누릅니다. letter 파일이 저장되고 화면에는 그대로 남아 있습니다. 편집 내용이 저장되었으므로 이제 다른 파일로 전환할 수 있습니다. `:e` 를 입력해서 note 파일을 불러온 후 RETURN 키를 누릅니다.

vi 편집기는 한 번에 두 개의 파일 이름을 ‘현재 파일’ 과 ‘대체 파일’ 로 기억합니다. 이 파일들은 기호 `%` (현재 파일 이름)과 `#` (대체 파일 이름)을 사용해서 참조할 수 있습니다. `#` 기호는 특히 `:e` 명령과 함께 사용할 때 유용하며, 이를 통해 파일 간을 쉽게 오갈 수 있습니다. 방금의 예에서, `:e#` 명령을 입력하면 첫 번째 파일인 letter 로 돌아갈 수 있습니다.

현재 파일을 먼저 저장하지 않은 상태에서는, 명령어 뒤에 느낌표를 추가해서 강제로 지시하지 않는 한 vi에서 `:e` 나 `:n` 명령을 사용해서 파일을 전환할 수 없습니다!

예를 들어, note 파일을 약간 수정한 후 수정 내용을 버리고 letter 파일로 돌아가려면, `:e!#` 을 입력하면 됩니다. 다음 명령어:

```
e!
```

도 유용합니다. 이 명령어는 편집 내용을 취소하고 현재 파일의 마지막으로 저장된 버전으로 되돌립니다. 반면, `%` 기호는 주로 버퍼의 내용을 새 파일에 기록할 때 유용합니다. 예를 들어, 몇 페이지 앞서 우리는 다음 명령어를 사용해서 letter 파일의 두 번째 버전을 저장하는 방법을 보여드렸습니다:

```
:w letter.new
```

이 명령어는 다음과 같이 입력할 수도 있습니다:

```
:w %.new
```

## Word Abbreviation

종종 파일에서 동일한 긴 문구를 반복 입력해야 할 때가 있습니다. 약어를 정의해 두면, 삽입 모드에서 해당 약어를 입력할 때마다 vi가
자동으로 전체 텍스트로 확장해 줍니다. 약어를 정의하려면 `ab` 명령을 사용합니다:

```
:ab abbr phrase
```

여기서 abbr 는 지정된 문구의 약어입니다. 약어를 구성하는 문자열은 삽입 모드에서 전체 단어로 입력할 때만 확장되며, 단어 내부에서는 abbr 가 확장되지 않습니다.

‘letter’ 파일에서 자주 반복되는 문구(예: 발음하기 어려운 제품명이나 회사명)가 포함된 텍스트를 입력해야 한다고 가정해 봅시다. 다음 명령을 사용하면:

```
:ab IMRC International Materials Research Center
```

'International Materials Research Center' 가 약어인 IMRC 로 축약됩니다. 이제 삽입 모드에서 IMRC 를 입력하면:

```
i the IMRC
```

IMRC 는 전체 텍스트인 

```
the International Materials Research Center
```

로 확장됩니다.

약어를 선택할 때는 텍스트를 입력하는 동안 일반적으로 나타나지 않는 문자 조합을 선택하십시오.



## Saving Commands with map

편집하는 동안 특정 명령어를 자주 사용하거나, 때로는 매우 복잡한 명령어를 사용하기도 합니다. 키 입력 횟수를 줄이거나 처리 순서를 기억하는 데 소요되는 시간을 절약하기 위해, 해당 순서를 사용되지 않는 키에 할당할 수 있습니다.

`map` 명령어는 `ab` 명령어와 (매우) 유사하게 작동하지만, 삽입 모드 대신 명령 모드에서 매크로를 정의한다는 점이 다릅니다.

명령어 | 설명
--- | ---
`:map x sequence` | 문자 x를 편집 명령어 시퀀스로 정의합니다.
`:unmap x` | x에 정의된 시퀀스를 비활성화합니다.
`:map | 현재 매핑된 문자들을 나열합니다.

자신만의 매핑을 만들기 전에, 명령 모드에서 사용되지 않으며 사용자 정의 명령에 사용할 수 있는 키들을 알아야 합니다:

```
ˆA  g  K ˆK
ˆO  q ˆT  v
V  ˆW  ˆX  ˆZ
*  \  _ (밑줄)
```

터미널에 따라 특수 기능 키에 매핑 시퀀스를 할당할 수도 있습니다. 매핑을 사용하면 간단하거나 복잡한 명령 시퀀스를 만들 수 있습니다. 간단한 예로, 단어의 순서를 반대로 바꾸는 명령을 정의할 수 있습니다. vi에서 커서가 다음과 같이 the 의 t 문자에 위치했을 때:

```
you can the scroll page
```

삽입 순서는 다음과 같습니다. `dwelp` : 단어 삭제 - `dw`; 다음 단어의 끝으로 이동 - `e`; 오른쪽으로 한 칸 이동 - `l`; 삭제된 단어를 그 자리에 삽입 - `p` 이 순서를 다음과 같이 저장하면:

```
:map v dwelp
```

편집 세션 중 언제든지 v 키를 한 번만 누르면 두 단어의 순서를 바꿀 수 있습니다.

맵을 정의할 때 RETURN, ESC, TAB, BACKSPACE, DELETE 같은 특정 키를 맵 명령의 일부로 단순하게 입력할 수는 없다는 점에 유의하십시오. 이런 키 중 하나를 명령 시퀀스의 일부로 포함하려면 해당 키 앞에 `ˆV` 를 붙여야 합니다. `ˆV` 키 입력은 맵에서 `ˆ` 문자로 표시됩니다. `ˆV` 뒤에 오는 문자들도 예상대로 표시되지 않습니다. 예를 들어, 캐리지 리턴은 `ˆM` 으로, 이스케이프는 `ˆ[` 로, 탭은 `ˆI` 로 표시되는 식입니다.

`u` 명령어를 사용하면 어떤 매핑 시퀀스의 효과도 실행 취소할 수 있습니다. 다행히, 실행 취소 기능은 매핑 시퀀스를 실행하기 전의 파일 상태로 복원하며, 일련의 명령어를 마치 단일 vi 명령어인 것처럼 취급합니다.

`unmap` 을 사용해서 매핑된 키를 제거하지 않는 한, 파일을 전환하더라도 현재 세션이 지속되는 동안 해당 키의 특수 의미는 유효합니다. 따라서 여러 파일에서 동일한 편집 작업을 수행하는 편리한 방법이 될 수 있습니다.

모든 vi 및 ex 명령은 매핑 시퀀스에서 사용할 수 있지만, `p` 또는 `put` 명령은 동일한 매핑 내에서 복사해 둔 전체 줄을 대체하는 데 사용할 수 없다는 점은 예외입니다. 매핑 내에서 삭제된 줄을 복사한 다음 다시 붙여넣으려고 하면 다음과 같은 오류 메시지가 표시됩니다.

```
Cannot put inside global macro.
```

매핑 내에서 한 위치에서 다른 위치로 줄을 이동하려는 경우, 일반적으로 ex 편집기의 `copy` 또는 `co` 명령을 사용해서 이런 제한을 우회할 수 있습니다.


### Complex Mapping Example

다음과 같은 항목들이 포함된 용어집이 있다고 가정해 봅시다:

```
map - an ex command that allows you to associate
a complex command sequence with a single key.
```

이 용어집 목록을 nroff 형식으로 변환해서 다음과 같이 표시되도록 하고 싶습니다:

```
.IP “map” 10n
An ex command...
```

이를 수행하는 가장 좋은 방법은 항목 중 하나를 편집해서 명령어 순서를 기록해 두는 것입니다. 다음과 같이 진행하십시오:

1. 줄의 시작 부분에 들여쓰기 단락을 만드는 매크로를 삽입합니다.
2. ESC 키를 눌러 삽입 모드를 종료합니다.
3. 단어의 끝으로 이동해서 들여쓰기 크기를 추가합니다.
4. RETURN 키를 눌러 새 줄을 삽입합니다.
5. ESC를 눌러 삽입 모드를 종료합니다.
6. 하이픈을 제거하고 다음 단어를 대문자로 변경합니다.

이 작업을 몇 번 이상 반복한다면 꽤 번거로운 편집 작업일 것입니다! `:map` 을 사용하면 전체 명령어 순서를 저장해서 단 한 번의 키 입력으로 다시 실행할 수 있습니다.

```
:map z I.IP “ˆ[ea” 10nˆMˆ[3x□
```

`ˆ[` 시퀀스는 `ˆV` 를 입력한 뒤 ESC를 누르면 나타납니다. `ˆM` 시퀀스는 `ˆV RETURN` 을 입력하면 표시됩니다.

이제 z를 입력하면 일련의 편집 작업 전체가 수행됩니다. 속도가 느린 터미널에서는 편집 과정이 하나씩 진행되는 모습을 실제로 볼 수 있습니다. 속도가 빠른 터미널에서는 마치 마법처럼 순식간에 이루어지는 것처럼 보일 것입니다.

키 매핑을 처음 시도했을 때 실패하더라도 낙담하지 마세요. 매핑을 정의할 때 사소한 오류 하나만으로도 예상과 전혀 다른 결과가 나올 수 있습니다. `u` 를 입력해서 편집 내용을 실행 취소한 후 다시 시도해 보세요.

복잡한 매핑을 정의하는 가장 좋은 방법은 편집을 수동으로 수행하면서, 입력할 각 키 입력을 하나씩 기록해 두는 것임을 기억하세요.


### Mapping Keys for Insert Mode

일반적으로 매핑은 명령 모드에서만 적용됩니다. 어쨌든 삽입 모드에서는 키가 그 자체의 기능을 수행하므로, 명령으로 매핑되어서는 안 됩니다. 그러나 `map` 명령어에 느낌표(`!`)를 추가하면, 키의 일반적인 의미를 무시하고 삽입 모드에서도 매핑을 적용하도록 강제할 수 있습니다. 이 기능은 평소에는 사용하지 않는 특정 키에 문자열을 할당할 때 유용합니다. 

이 기능은 특히 프로그래밍 가능한 기능 키를 사용할 때 유용하며, 이에 대해서는 잠시 후에 살펴보겠습니다. 많은 터미널에는 프로그래밍 가능한 기능 키가 있습니다. 일반적으로 터미널의 특수 설정 모드를 사용해서 이런 키가 원하는 문자를 출력하도록 설정할 수 있습니다. 하지만 이 방법은 특정 터미널로만 제한될 뿐만 아니라, 해당 기능 키를 직접 설정하려는 프로그램의 동작을 제한할 수도 있습니다.

ex 편집기를 사용하면 다음 구문을 통해 번호별로 기능 키를 매핑할 수 있습니다.

```
:map #1 commands
```

(여기서 `#1` 은 기능 키 번호 1을 의미하며, 나머지 번호도 마찬가지입니다). 

(편집기가 termcap 또는 terminfo 데이터베이스에 있는 해당 터미널의 항목에 접근할 수 있고, 기능 키가 일반적으로 출력하는 이스케이프 시퀀스를 알고 있기 때문에 이런 매핑이 가능합니다).

다른 키와 마찬가지로, 매핑은 기본적으로 명령 모드에 적용되지만, `map!` 명령을 함께 사용하면 기능 키에 두 가지 별개의 값을 정의할 수 있습니다. 하나는 명령 모드에서, 다른 하나는 삽입 모드에서 사용하는 값입니다. 예를 들어, troff 사용자라면 기능 키에 글꼴 전환 코드를
할당할 수 있습니다. 예를 들면 다음과 같습니다.

```
:map #1 i\fIˆ[
:map! #1 \fI
```

명령 모드에 있을 때 첫 번째 기능 키를 누르면 삽입 모드로 전환되고, `\fI` 라는 세 글자를 입력한 후 명령 모드로 돌아갑니다. 이미 삽입 모드에 있는 경우, 이 키를 누르면 단순히 세 글자로 된 troff 코드가 입력됩니다.

참고: 터미널의 설정 모드에서 기능 키가 재정의된 경우, `#n` 구문이 작동하지 않을 수 있습니다. 이는 기능 키가 터미널 데이터베이스 항목에 설명된 대로 예상되는 제어 시퀀스나 이스케이프 시퀀스를 더 이상 출력하지 않기 때문입니다. 해당 터미널의 termcap 항목(또는 terminfo 소스)을 확인하고 기능 키에 대한 정의를 점검해야 합니다. 터미널의 기능키는 k0, k1, k2부터 k9 처음 10개의 기능 키를 설명합니다. 기능 l1, l2부터 l9, l0까지는 나머지 기능 키를 설명합니다. 터미널의 설정 모드를 사용해서, termcap 또는 terminfo 항목과 일치하도록 기능 키가 출력하는 제어 또는 이스케이프 시퀀스를 변경할 수 있습니다. (시퀀스에 `ˆM`, 즉 캐리지 리턴이 포함된 경우, RETURN 키가 아닌 `ˆM` 을 누릅니다.) 예를 들어, 기능 키 1을 매핑에 사용할 수 있게 하려면, 사용 중인 터미널에 대한 터미널 데이터베이스 항목에 `k1=ˆA@` 같은 k1 정의가 있어야 합니다. 또한, `ˆA@` 라는 정의는 해당 키를 누를 때 출력되는 내용과 일치해야 합니다. 기능 키가 어떤 출력을 생성하는지 테스트하려면, UNIX 프롬프트에서 해당 키를 누른 다음, 필요한 경우 RETURN 키를 누릅니다. 셸은 해당 키를 명령어로 실행하려다 실패한 후, 기능 키가 출력하는 문자열을 표시해야 합니다.


### @ Functions

이름이 지정된 버퍼는 매크로를 만드는 또 다른 방법을 제공합니다. 매크로란 몇 번의 키 입력만으로 반복할 수 있는 복잡한 명령어 시퀀스입니다.

텍스트에 명령줄(vi 시퀀스나 콜론(`:`)이 앞에 붙은 ex 명령어)을 입력한 다음, 이를 이름이 지정된 버퍼로 복사하거나 삭제하면, `@` 명령어를 사용해서 해당 버퍼의 내용을 실행할 수 있습니다. 이 기능은 맵 시퀀스와 동일한 방식으로 작동하지만, 콜론 프롬프트 대신 파일에 명령줄을 입력한다는 점이 다릅니다. 이는 명령어 시퀀스가 길거나 제대로 작동하기 위해 수정이 필요한 경우에 유용합니다. 간단하지만 그다지 유용하지는 않은 `@` 함수의 예를 살펴보겠습니다. 파일에서 다음 키 시퀀스를 입력합니다:

```
cw\fIgadfly\fRˆVESC
```

그러면 화면에 다음과 같이 표시됩니다:

```
cw\fIgadfly\fRˆ[
```

그런 다음 `"gdd` 를 입력해서 명령줄을 버퍼 "g 에 저장하십시오. 이제 커서를 단어의 시작 부분에 두고 `@g` 를 입력하면, 텍스트의 해당 단어가 gadfly 로 변경됩니다. `@` 는 vi 명령으로 해석되므로, `.` 명령을 입력하면 ex 명령이라 하더라도 전체 시퀀스가 반복됩니다. 

``@@`` 명령어는 마지막 `@` 명령어를 반복하며, `u` 또는 `U` 를 사용해서 `@` 의 효과를 실행 취소할 수 있습니다. `@` 기능은 매우 구체적인 명령어를 만들 수 있기 때문에 유용합니다. 특히 파일 간에 특정 편집 명령어를 만들 때 유용합니다. 명령어를 이름이 지정된 버퍼에 저장해 두면 편집하는 모든 파일에서 해당 명령어에 접근할 수 있기 때문입니다.
