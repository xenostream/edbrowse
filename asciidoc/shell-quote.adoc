가장 먼저 이해할 점은 ‘메타 문자’ 로 불리는 “특정 문자들이 특별한 의미를 지닌다!” 는 것입니다. 실제 의미는 메타 문자를 인식하는 프로그램에 따라 달라집니다. 일부 문자는 유닉스 셸에서만 특별한 의미를 가지며, 일부는 sed 나 grep 같은 유틸리티에서만 특별한 의미를 가집니다.

정규 표현식을 공부하기 전에, 셸을 사용해서 정규 표현식을 프로그램에 전달하는 방법을 이해하는 것이 중요합니다. 다시 말해, “이봐, 셸. 이 메타 문자들은 무시해. 이 메타문자들을 쉘이 아닌 유틸리티가 특별하게 처리해 주길 원해!” 라고 말하는 것과 같습니다. 이를 수행하는 기법을 ‘인용(_quoting_)’ 이라 합니다. 즉, 메타문자 주위에 따옴표를 붙여 쉘에게 (쉘의 관점에서 볼 때) 이 문자들이 특별한 의미가 아니라는 것을 알리는 것입니다. 문자를 인용하면, “쉘에게 그 문자를 그대로 두고 변경없이 유틸리티로 전달해 달라!” 고 요청하는 것입니다.

“$” 문자가 좋은 예입니다. 이 문자는 변수 이름의 시작일 수도 있고, 정규 표현식의 일부일 수도 있습니다. 정규 표현식을 사용한다면, 표현식 내의 문자가 메타문자인지 여부를 파악해야 하며, 셸에 의해 수정되지 않고 프로그램으로 전달되도록 해당 문자를 올바르게 따옴표로 묶는 방법을 알아야 합니다.

이 튜토리얼은 셸에 구애받지 않는 방식으로 작성했습니다. 즉, 여기서 설명하는 내용은 그토록 골칫거리인 C 셸을 포함해서 모든 주요 셸 종류에 적용됩니다. 다시 말해, 어떤 셸을 사용하든 상관없습니다. 모든 셸이 메타 문자를 인용하거나 이스케이프하는 세 가지 방법을 — 어느 정도는 — 이해하기 때문입니다. 몇 가지 까다로운 부분도 있지만, 나중에 각 셸을 다룰 때 언급하겠습니다.

다음은 Bourne 셸과 C 셸이 인식하는 메타문자 목록입니다. 이 표를 좀 더 완벽하게 만들기 위해 몇 가지 문자 조합도 포함시켰습니다. 이 표는 세부 사항이 많이 포함되지만, 완전한 것은 아닙니다. 솔직히 말해서, 당분간은 이 부분을 건너뛰셔도 됩니다. 단지 이 내용이 꽤 복잡할 수 있다는 점을 알아두셨으면 합니다. 그리고 어떤 문자가 특수 문자인지 확실하지 않다면, 만약을 대비해서 따옴표를 사용하는 것이 좋습니다.

중요한 것은 이런 특별한 의미를 지닌 문자들을 확실히 이해하는 것입니다. 또한 셸이 특수 문자를 올바르게 해석하는지 확인하는 방법도 설명해 드릴 테니, 이를 통해 문제의 원인을 정확히 파악할 수 있을 것입니다.

키보드에는 세 가지 다른 “따옴표” 가 있습니다. 그중 두 개는 영어에서 인용에 사용되는 기호를 사용하며, 때로는 작은 따옴표와 큰 따옴표라고 불립니다. 세 번째 따옴표는 백쿼트(좀 더 정확하게 백틱 또는 그레이브라고 함) 문자인 “`” 입니다. 이 문자는 작은 따옴표와 비슷하게 생겨서 쉘 스크립트에서 혼동하는 경우가 종종 있습니다. 처음 두 개는 유닉스에서 구문을 인용하는 데 사용됩니다. 백쿼트는 문자를 인용하는 데 사용하지 않습니다. 이 문자는 명령어 대체에 사용하며, 쉘이 그 사이에 있는 문자를 실행하고 그 결과를 해당 줄에 삽입합니다. 예:

[source,csh]
% echo the date is `date`

이 기회에, 최신 POSIX 셸은 백틱을 명령어 대체 용도로 더 이상 사용하지 않고, 이제 다음과 같은 형식을 사용한다는 점을 간단히 언급하겠습니다:

[source,csh]
% echo the date is $(date)

이에 대해서는 이 섹션에서 다루겠습니다.

다시 유닉스의 인용 기법으로 돌아가겠습니다.



== Using the echo command

가장 먼저 배울 것은 유닉스 셸에 내장된 “echo” 명령어입니다. 셸이 메타 문자를 어떻게 해석하는지 이해하려면, 명령어 앞에 “echo” 를 붙입니다. 예를 들어, 다음 명령어를 입력했을 때 어떤 일이 일어나는지 이해하려면

[source,csh]
% ls *

먼저 다음 명령어를 입력하시길 권합니다.

[source,csh]
% echo ls *

셸은 +“*”+ 문자를 인식하고 이를 특수 문자로 간주해서, “*” 를 현재 디렉터리의 파일 이름에 맞게 대체한 다음, 해당 인수를 사용해서 “ls” 명령을 호출합니다. “ls” 명령어는 “*” 문자를 전혀 인식하지 못합니다. 만약 디렉토리에 파일 이름에 “*” 가 포함된 파일이 있다면 어떻게 될까요? 그 파일만 나열하거나 삭제하려면 어떻게 할까요? 셸을 통과시키기 위해서는 “*” 를 따옴표로 묶어야 합니다.

사용할 수 있는 세 가지 따옴표 기법은 작은 따옴표, 큰 따옴표, 그리고 백슬래시입니다.


== Quoting a single character with the backslash

문자 앞에 백슬래시(“\”)를 붙이면 셸이 해당 문자를 해석하지 못하게 처리할 수 있습니다. 다음 명령어를 사용해서 파일을 나열할 수 있습니다:

[source,csh]
ls *\**

다음은 별표가 포함된 모든 파일을 삭제할 수 있는 셸 스크립트입니다:

[source,csh]
----
echo 이 스크립트는 이름에 별표가
echo 포함된 모든 파일을 제거합니다.
echo
echo 이 파일들을 정말로 삭제하시겠습니까\?
rm -i *\**
----

물음표(?) 앞에도 백슬래시가 필요한데, 이 역시 셸 메타문자이기 때문입니다. 백슬래시가 없으면 셸은 “files?” 패턴과 일치하는 모든 파일을 찾게 됩니다. 만약 “files1” 과 “files2” 파일이 있다면, 스크립트는 다음과 같이 출력할 것입니다.

[source,csh]
이 파일들을 정말로 삭제하시겠습니까? files1 files2

라는 결과가 출력될 것이며, 이는 의도한 바가 아닙니다! 이는 “확실하지 않을 때 따옴표를 사용하는 것이 더 낫다!” 는 또 다른 예시입니다. 저는 예제에서 항상 이렇게 하진 않습니다. 내부 작동 원리를 이해하는 것이 더 중요하기 때문입니다. 또한 때로는 세부 사항을 강조하기 위해 이 튜토리얼에서 의도적으로 잘못된 예제를 사용하기도 합니다.

백슬래시는 인용의 “가장 강력한” 방법입니다. 다른 모든 방법이 실패할 때 작동합니다. 가독성을 위해 텍스트를 두 줄 이상으로 나누고 싶지만, 프로그램에서 한 줄을 기대할 경우, 줄 이어쓰기 문자가 필요합니다. 줄의 마지막 문자로 백슬래시를 사용하면 됩니다:

[source,csh]
----
% echo This could be \
a very \
long line\!
This could be a very long line!
%
----

이렇게 하면 줄바꿈 문자가 이스케이프 처리되거나 따옴표로 묶이게 되어, 더 이상 특별한 의미를 가지지 않게 됩니다. 위의 예제는 느낌표 앞에 백슬래시를 추가했습니다. C 셸을 사용하는 경우, “!” 를 특수 문자로 처리하기 때문에 이 작업이 필요합니다. 다른 셸을 사용하는 경우는 필요하지 않을 수도 있습니다.


== Strong Quoting with the Single Quotes

여러 문자를 한 번에 인용할 때는 백슬래시를 여러 개 사용할 수 있습니다:

[source,csh]
% echo a\ \ \ \ \ \ \ b

(‘a' 와 'b’ 사이에 공백이 7개 있습니다.) 보기 흉하지만 작동은 합니다. 인용할 문자의 시작과 끝을 나타내기 위해 쌍따옴표를 사용하는 것이 더 쉽습니다:

[source,csh]
% echo 'a       b'

작은 따옴표 안에는 거의 모든 메타 문자를 포함할 수 있습니다:

[source,csh]
----
% echo ‘What the *heck* is a $ doing here???’
What the *heck* is a $ doing here???
----

위의 예제는 별표, 달러 기호, 물음표 같은 메타 문자를 사용했습니다. 텍스트를 그대로 처리할 때는 작은 따옴표를 사용해야 합니다. 참고 - C 셸을 사용하는 경우, “!” 문자들 앞에 백슬래시를 붙여야 할 수도 있습니다. 이는 그 문자의 양옆에 어떤 문자가 있는지에 따라 달라집니다. 공백으로 둘러싸여 있다면 백슬래시를 사용할 필요가 없습니다.


== Weak Quotes with the Double Quotes

때로는 “*” 나 “?” 같은 메타 문자는 확장하지 않으면서도 변수는 확장하고 명령어 대입을 수행하는, 좀 더 약한 형태의 인용이 필요할 때가 있습니다. 이는 큰따옴표를 사용해서 구현할 수 있습니다:

[source,csh]
----
% echo “홈 디렉터리가 $HOME입니까?”
홈 디렉터리가 /home/barnett입니까?
% echo “현재 디렉터리는 `pwd`입니다”
현재 디렉터리는 /home/barnett입니다
# 다음 예제는 C 셸과 Bourne 셸에서는 작동하지 않습니다
% echo “현재 디렉터리는 $(pwd)입니다”
현재 디렉터리는 /home/barnett입니다
----

단일 따옴표와 큰따옴표의 차이를 익히면 유용한 기술을 터득할 것입니다. 그리 어렵진 않습니다. 단일 따옴표가 큰따옴표보다 우선순위가 더 높습니다. 알겠나요? 좋습니다. 그리고 백슬래시가 그 중에도 가장 우선순위가 높습니다.


== Using quotes to include spaces and characters in filenames

파일 이름에 공백이나 특수 문자가 포함된 파일을 다루려면 따옴표를 사용할 수도 있습니다. 예를 들어, 이름에 공백이 포함된 파일을 만들려면 다음과 같이 할 수 있습니다.

[source,csh]
% cp /dev/null ‘a file with spaces in the name’

일반적으로 셸은 공백을 사용해서 각 인수의 끝을 구분합니다. 따옴표를 사용하면 이 동작이 변경되며, 위 예제는 인수가 두 개만 있습니다. 문자 앞에 백슬래시를 사용할 수도 있습니다. 아래 예제는 이름에 공백이 포함된 파일의 이름을 변경해서 공백을 밑줄로 바꿉니다:

[source,csh]
% mv a\ file a_file

같은 기법을 사용하면 파일 이름에 포함된 어떤 문자든 처리할 수 있습니다:

[source,csh]
% mv a 'a?'

최악의 경우, 파일명에 공백이 포함되면 인자로 사용하기 어려워집니다. 그 외의 문자들은 파일명에 사용하면 매우 위험할 수 있습니다.

한 가지 예로, 첫 번째 문자가 하이픈인 파일명이 있습니다. “-i” 이름의 파일을 삭제할 때, 다음 명령어는

[source,csh]
% rm “-i”

는 작동하지 않습니다. “rm” 명령어는 “-” 를 메타 문자로 해석해서 인수를 옵션으로 간주하기 때문입니다. 이를 해결하려면 유닉스 경로를 사용할 수 있으며, “.” 문자가 현재 디렉토리의 경로임을 알아야 합니다. 따라서 해결책은 다음과 같이 입력하는 것입니다:

[source,csh]
% rm “./-i”

파일 이름에 “?” 나 “*” 가 포함될 때도 문제가 발생합니다. “a?” 파일을 삭제하려면, 해당 파일 하나뿐만 아니라 다른 파일들도 함께 삭제될 수 있습니다. 메타 문자가 어떤 결과를 초래할지 확인하기 위해 “echo” 명령어를 사용하는 습관을 들이는 것을 강력히 권장합니다.


== Quotes within Quotes

두 가지 유형의 따옴표(백슬래시까지 포함하면 세 가지)가 있어 헷갈릴 수도 있지만, 실제로는 같은 문제를 해결할 수 있는 여러 가지 방법을 제공합니다. 한 종류의 따옴표를 다른 종류의 따옴표 안에 넣을 수도 있습니다. 작은 따옴표를 따옴표로 묶고 싶다면 큰 따옴표로 감쌉니다. 큰 따옴표를 따옴표로 묶고 싶다면 작은 따옴표를 사용합니다. 뭐, 직접 보여드리는 게 더 쉬울 것 같네요:

[source,csh]
----
% echo “그렇게 하지 마세요”
Don't do that
% echo ‘오늘의 명언은: “TGIF”’
오늘의 명언은: “TGIF”
%
----


== Finding out if your quotes are wrong

경우에 따라서는 확실하지 않을 때 백슬래시를 사용할 수도 있습니다. 반면, 어떤 경우는 백슬래시를 사용하면 의도하지 않은 결과가 나올 수도 있습니다. 인용 처리를 올바르게 하고 있는지 어떻게 확인할 수 있을까요? 정답은 셸을 사용하는 것입니다.

인용 처리를 확인하는 쉬운 방법은 명령어 앞에 “echo” 를 추가해서 어떤 일이 일어나는지 확인하거나, “ls” 명령어를 “echo” 명령어로 바꾸는 것입니다:

[source,csh]
----
echo scp gateway:\*.tar.Z .
ssh user@cruncher echo ls \*
ssh user@cruncher echo ‘ls *’
----

원격 시스템에서 파일 리디렉션을 수행하는 경우, echo 만으로는 충분하지 않습니다. 다음 명령어는

[source,csh]
ssh user@cruncher echo 'ls * >/tmp/file'

는 명령어 처리 결과를 터미널에 출력할 때, 그 결과를 파일로 보내버립니다. 따옴표를 중첩해서 사용해야 합니다:

[source,csh]
----
ssh user@cruncher “echo ‘ls * >/tmp/file’”
ssh user@cruncher ‘echo “ls * >/tmp/file”’
ssh user@cruncher “echo ‘cd newdir;ls * >>/tmp/file’”
----

셸 스크립트를 디버깅하면서 스크립트가 어떤 작업을 수행하는지 확인하려면, 스크립트 내의 중요한 줄 중 하나를 복제하고 복제본 중 하나 앞에 “echo” 를 삽입하면 됩니다. 스크립트에서 한두 번 정도 이렇게 처리하는 것은 그리 어렵지 않지만, 스크립트의 모든 줄을 지켜보고 싶은 경우도 있습니다. 이 경우, 셸에 현재 진행 상황을 보여달라고 요청하면 됩니다.


== The verbose and echo variables in the C shell

POSIX 및 Bourne 셸은 설정하면 변수 및 메타문자 확장의 복잡한 과정을 추적하는 데 도움되는 두 가지 변수가 있습니다. 다음 명령을 입력해서 스크립트를 실행할 때 POSIX 및 Bourne 셸 스크립트에 대한 변수 확장을 활성화할 수 있습니다.

[source,csh]
----
% sh -v script
% sh -x script
----

스크립트 내부에서 이 기능을 켜거나 끌 수 있습니다. 상세 출력 플래그를 켜려면 다음을 사용합니다.

[source,csh]
set -v

변수 에코를 켜려면 다음을 사용합니다.

[source,csh]
set -x

이 변수들을 끄려면 마이너스(-) 대신 플러스(+)를 사용합니다.

[source,csh]
----
set +x
set +v
----



== The Bourne Shell variables

C 셸은 설정하면 변수 및 메타문자 확장의 복잡한 과정을 추적하는 데 도움되는 두 가지 변수가 있습니다.

[source,csh]
set verbose

명령은 변수가 평가되기 전에 스크립트의 모든 줄을 출력합니다.

[source,csh]
set echo

명령은 변수와 메타문자가 대체된 후 각 줄을 표시합니다. 변수 처리를 중지하려면 set 대신 unset 을 사용합니다.

스크립트 첫 번째 줄에서 “-x” 옵션(_echo_)을 사용해서 이 변수들을 활성화하는 편리한 방법은 다음과 같습니다.

[source,csh]
#!/bin/csh -x

또는 “-v” 옵션(_verbose_)을 사용할 수도 있습니다:

[source,csh]
#!/bin/csh -v

위의 두 예제 모두, 스크립트 시작 시 .cshrc 파일이 읽힙니다. “-f” 옵션을 사용하면 이 파일을 건너뛸 수 있습니다. 원한다면 세 가지 옵션을 모두 조합할 수도 있습니다:

[source,csh]
#!/bin/csh -fxv

.cshrc 파일을 불러오고 이 변수들의 값을 추적하려면 “X” 와 “V” 변수를 대문자로 표기합니다. 이렇게 하면 .cshrc 파일이 읽히기 전에 추적이 활성화됩니다:

[source,csh]
#!/bin/csh -XV

verbose 또는 echo 변수를 활성화할 때 프로그램을 수정할 필요는 없습니다. 수정 권한이 없는 스크립트인 경우, 명령줄에서 다음 변수를 설정할 수 있습니다:

[source,csh]
% csh -x shell_script




== Including identical quotes within quotes

사람들이 겪는 문제 중 하나는 따옴표 안에 또 다른 따옴표를 포함시키는 것입니다. 많은 사람들이 다음 코드가 작동할 것이라고 기대합니다:

[source,csh]
----
echo “오늘의 단어는 \”TGIF\“입니다”
echo '내 말을 인용하지 마세요'
----

첫 번째 예제는 Bourne 셸은 작동하지만, C 셸은 작동하지 않습니다. 두 번째 예제는 두 셸 모두 작동하지 않습니다. 아마 많은 프로그래머 분들이 이런 점에 대해 혼란스러워하실 겁니다. 저도 그랬습니다. 일반적으로 문자열 시작 부분에 “문자열 시작” 을, 끝 부분에 “문자열 끝” 을 두어 문자열을 정의합니다. 이 둘 사이에 문자열이 들어갑니다. 간단하죠. 그리고 셸을 다룰 때는 이것이 어느 정도는 맞습니다. 대부분의 프로그래밍 언어와 달리, 따옴표는 치환을 켜거나 끄는 역할을 합니다. 문자열의 시작과 끝을 나타내는 데 사용되지 않습니다. 다음 따옴표 구성을 살펴봅니다:

[source,csh]
echo ‘a'b'c’

이것은 세 개의 단위로 나뉩니다. 첫 번째와 마지막은 따옴표로 묶여 있고, 가운데 부분은 그렇지 않습니다. 따옴표 처리와 치환이 이루어진 후, 이 세 단위가 결합됩니다. 가운데 부분은 따옴표로 묶지 않았기 때문에(즉, 메타 문자로 처리될 수 있음) 변수로 사용할 수 있습니다. 예를 들어, “b” 를 “$HOME” 으로 바꿀 수 있습니다:

[source,csh]
echo ‘a’$HOME'b'

이 기법은 셸 변수를 awk 스크립트에 전달하는 전형적인 방법입니다. 이를 보여주는 간단한 셸 스크립트가 있습니다. 중요한 내용이니 꼭 숙지하시기 바랍니다:

[source,bash]
----
#!/bin/sh
# 이 셸 스크립트는 필터 역할을 하지만,
# 한 열만 출력합니다.
# 해당 열의 값은 스크립트의
# 인자입니다.
#
# 작동 방식을 확인하려면 다음 줄의 주석 처리를 해제하세요.
#set -x
#
# 예시:
#       printcol 1
#       printcol 3
# 인수의 값은 $1입니다.
# 이제 까다로운 부분이 나옵니다 -
awk ‘{print $’$1'}'
# 보셨죠!
----

이 예시에서 셸은 awk 에 전달된 인수를 세 부분으로 나눕니다:

[%autowidth]
|===
|{print $   |인용
|$1         |평가
|}          |인용
|===

“set -x” 명령어의 주석 처리를 해제하고 다음 명령어로 스크립트를 실행할 수 있습니다.

[source,csh]
printcol 2 </etc/hosts

셸 스크립트의 인수는 2이므로 “$1” 이 평가되어 값 “2” 를 반환합니다. 이로 인해 awk 의 인수는 “print {$2}” 문자열이 되며, 두 번째 열이 출력됩니다.

이 기법은 두 종류의 따옴표 중 어느 것을 사용하든 “모든 셸에서 작동한다!” 는 점에 유의합니다.

따옴표 안에 또 다른 따옴표를 넣는 경우 이런 점을 반드시 이해해야 합니다. 사실, 따옴표 안에 따옴표를 넣는 것이 아니라, 여러 단위를 하나로 결합하거나 연결해서 하나의 인자로 만들려는 것입니다.

다시 말하겠습니다. 작은따옴표로 시작하는 인자 안에 작은따옴표를 포함시키려면, 작은따옴표가 시작하는 메커니즘을 비활성화하고 다른 따옴표 처리 방법을 사용해야 합니다. 기억하세요. 백슬래시는 모든 인용 기법 중에서 “가장 강력한 것!!” 입니다. 백슬래시를 사용하면 무엇이든 인용할 수 있습니다. 다음 예제는 세 가지 인용 부호 모두를 인용합니다:

[source,csh]
% echo \'\"\\

그 결과는 다음과 같습니다.

[source,csh]
'"\

언제든지 백슬래시를 사용해서 문자를 인용할 수 있습니다. 하지만 작은 따옴표 기법 내에서 “\'” 는 “인용 부호를 인용” 하지 않습니다. 이를 올바르게 처리하는 방법은 다음과 같습니다:

[source,csh]
----
% echo ‘Don’   \‘   't do that’
Don ' t do that
----

무슨 일이 일어나는지 쉽게 파악할 수 있도록 여백 몇 개를 추가했습니다. 여백을 제거한 버전은 다음과 같습니다:

[source,csh]
----
% echo ‘Don’\'‘t do that’
Don't do that
----

쉘 스크립트를 머릿속으로 분석할 때 따옴표를 제대로 맞추는 것만 기억합니다. 이 방법은 큰따옴표도 동일하게 적용됩니다:

[source,csh]
----
% echo “오늘의 명언은 ”\“TGIF\”
오늘의 명언은 “TGIF”
----

혹은 “TGIF”를 따옴표로 묶고 싶다면:

[source,csh]
----
% echo “오늘의 명언은 ”\“‘TGIF’\”
오늘의 명언은 “TGIF”입니다
----


== Quoting long lines

대부분의 유닉스 프로그램도 특수 문자를 이스케이프하기 위해 백슬래시를 사용합니다. 유닉스 유틸리티는 줄 끝의 백슬래시를 줄 이어쓰기 문자로 해석하는 것이 일반적입니다. 즉, 줄 끝 문자가 따옴표로 묶이거나 이스케이프되어 표준적인 의미가 적용되지 않게 됩니다.

줄 끝 표시자를 넘어 이어지는 줄을 따옴표로 묶을 때, Bourne 셸과 C 셸은 서로 다른 동작을 보입니다. C 셸은 마지막 문자가 백슬래시가 아닌 한, 따옴표를 줄 너머로 확장하지 않습니다:

[source,csh]
----
% echo "두 줄에 걸친 \
따옴표"
두 줄에 걸친
따옴표
----

반면 Bourne 셸은 따옴표가 줄 너머로 확장되는 것을 허용합니다:

[source,bash]
----
$ echo "두 줄에 걸친
> 따옴표"
A quote
on two lines
----

인용문이 닫히지 않았을 때 Bourne 셸이 “>” 를 프롬프트로 표시하는 점에 주목합니다. 어떤 동작이 올바른지는 여러분끼리 토론해 보시기 바랍니다. C 셸이 기본적으로 여러 줄에 걸친 따옴표 사용을 허용하지 않는 이유는 이해할 수 있습니다. 앞서 제시한 예시:

[source,csh]
echo ‘Don\'t do that’

C 셸을 사용할 경우 오류가 발생합니다. 하지만 Bourne 셸을 사용하면 “>” 프롬프트가 표시되며, 작은 따옴표를 입력할 때까지 이 상태가 지속됩니다. 이는 유닉스를 처음 접하는 사용자에게 혼란을 줄 수 있습니다.

awk 스크립트인 여러 줄로 된 인용문을 작성할 때는 Bourne 셸이 더 사용하기 편하다고 생각합니다:

[source,bash]
----
#!/bin/sh -x
# 이 스크립트는 첫 번째 인수로 지정된 그룹에
# 몇 명이 속해 있는지 계산합니다
grp=${1:?“인수가 누락되었습니다”}    # 그룹 ID 번호 가져오기
# 인수가 누락된 경우, 오류를 보고하고 종료합니다.
awk -F: '
# 여기부터 awk 스크립트 시작
BEGIN {
    # 시작하기 전에 총 인원을 0으로 설정
    #   total=0;
}
$3 ~ /^‘$grp’$/ {total++;}
END {
    # 파일 끝, 총 인원 출력
    printf(“Total: %d\n”, total);
}' </etc/passwd
----

이 예제는 awk 스크립트 중간에서 “$grp” 셸 변수를 사용합니다. 이는 셸 변수를 awk 스크립트에 전달하는 일반적인 방법입니다. 어떤 사람들은 문자열 내에서 동적 변수를 사용하기 위해 다른 기법을 선호하기도 합니다. 예를 들어, awk 는 또 다른 기법을 제공하지만, 이 기법은 다른 유틸리티도 작동하므로 이 기법을 이해하는 것이 좋습니다.



== HERE IS documents

셸이 지원하는 또 다른 유형의 인용문이 있습니다. 이를 ‘HERE IS 문서’ 라고 합니다. 표준 입력에서 무언가를 읽어야 하지만, 해당 입력을 제공하기 위해 파일을 생성하지 않을 때 사용됩니다. 셸 스크립트 내에서 동적 변수를 사용하는 또 다른 방법으로 이를 활용할 수 있습니다. 또한 셸 스크립트 내에서 파일을 생성하는 데도 사용됩니다. HERE IS 문서는 “<<” 문자에 이어 특수 단어를 붙여서 생성할 수 있습니다.

[source,csh]
----
% sort >file <<EndOfSort
zygote
abacus
EndOfSort
----

이 작업 중에 변수가 동적으로 평가되기 때문에 매우 유용합니다. 다음은 셸 스크립트에서 FTP를 사용해서 파일을 전송하는 방법입니다.

[source,bash]
----
#!/bin/sh
# 사용법:
#    ftpfile machine file
# set -x
SOURCE=$1
FILE=$2
BFILE=`basename $FILE`
ftp -n $SOURCE <<EndFTP
ascii
user anonymous $USER@`hostname`
get $FILE /tmp/$BFILE
EndFTP
----

보다시피 변수 및 명령어 대체가 이루어집니다. 따옴표로 묶인 텍스트를 그대로 유지하려면, 해당 단어의 이름 앞에 슬래시를 붙입니다:

[source,csh]
cat >file <<\FunkyStriNG


'FunkyStriNG' 문자열에 주목합니다. 이는 텍스트에 파일 이름을 종료하는 단어가 포함될 경우에 대비해서 추가된 것입니다. 제가 어떤 파일이든 특정 문자 조합을 넣을 가능성은 매우 희박합니다. C 셸은 해당 단어가 이스케이프 처리되기를 기대한다는 점에 유의해야 합니다. 즉, “\FunkyStriNG” 이어야 하는 반면, Bourne 셸은 그렇지 않습니다. Bourne 셸은 “FunkyStriNG” 을 기대합니다.


== When to quote?

보다시피, 따옴표 사용 문제는 혼란을 야기할 수 있습니다. 이쯤 되면 쉘이 여러분이 원하는 정확한 문자열을 인식하도록 처리하는 방법을 아셔야 할 것입니다. 다음에 정규 표현식을 다룰 때쯤이면, 여러분은 머리가 터질 것 같은 느낌없이 따옴표 사용법을 이해할 수 있을 것입니다.
