====

이 가이드는 AsciiDoc의 기본 사항을 다루는 것 외에도, 좀 더 일관성 있는 문서를 작성하고 글쓰기 생산성을 극대화하는 데 도움되는 일련의 규칙을 제안합니다.

그럼 `AsciiDoc` 을 자세히 알아보겠습니다!


== Writing in AsciiDoc

이 섹션의 목표는 여러분이 첫 번째 AsciiDoc 문서를 작성하는 방법을 알려드리는 것입니다. 나중에 되돌아보면, 이 방법이 정말 합리적이라는 데 동의하게 될 것입니다.

AsciiDoc과의 여정은 여러분이 즐겨 사용하는 텍스트 편집기에서 시작됩니다.


== It’s just text, mate.

AsciiDoc의 구문은 단순한 "일반 텍스트" 이므로, 어떤 텍스트 편집기를 사용하든 AsciiDoc 문서를 작성할 수 있습니다. Microsoft Word, OpenOffice Writer, Google Docs 같은 복잡한 워드 프로세서 프로그램은 필요하지 않습니다. 사실, 이런 프로그램들은 문서에 (눈에 보이지 않는) 불필요한 요소를 추가하고 변환 과정을 번거롭게 만들기 때문에 사용하지 않는 것이 좋습니다.

[NOTE]
====
어떤 텍스트 편집기라도 사용할 수 있는 것은 사실이지만, AsciiDoc 구문 강조 기능을 지원하는 편집기를 선택하는 것이 좋습니다. 색상은 텍스트에 대비를 주며 가독성을 높여줍니다. 또한 구문 강조 기능을 통해 인라인 요소나 블록 요소에 대한 구문을 올바르게 입력했는지 확인할 수 있습니다.
====

macOS에서 일반 텍스트를 편집하는 데 가장 널리 사용되는 프로그램은 `TextMate` 입니다. 리눅스는 `GEdit` 가 이와 비슷한 선택지입니다. 윈도우는 메모장이나 워드패드는 피하시기 바랍니다. 이 프로그램들이 생성하는 일반 텍스트는 크로스 플랫폼 호환성이 많이 떨어지기 때문입니다. 대신 `Notepad++` 같은 성능 좋은 텍스트 편집기를 선택합니다. 프로그래머이거나 혹은 내면에 괴짜 기질이 있는 작가라면 `Vim, Emacs, Sublime Text` 를 선호할 가능성이 높으며, 이 편집기들 모두 크로스 플랫폼으로 사용할 수 있습니다. 이 모든 편집기가 공통적으로 갖춘 핵심 기능은 바로 "AsciiDoc에 대한 구문 강조 표시" 입니다.

자신이 좋아하는 텍스트 편집기를 열고 AsciiDoc을 작성할 준비를 합니다!


== Content is king!

대부분의 문서는 단락 텍스트로 이루어져 있습니다. 그렇기 때문에 Asciidoctor은 단락을 지정하기 위한 특별한 마크업이나 속성이 필요하지 않습니다. 그냥 입력하면 됩니다.

Asciidoctor는 인접하거나 연속된 텍스트 줄은 하나의 단락을 형성합니다. 섹션 제목이나 표와 같은 다른 요소 뒤에 새 단락을 시작하려면 `RETURN` 키를 두 번 눌러 빈 줄을 삽입한 다음, 내용을 계속 입력하면 됩니다.

.AsciiDoc 문서의 두 단락
[source,asciidoc]
----
This journey begins one late Monday afternoon in Antwerp.
Our team desperately needs coffee, but none of us dare open the office door.

To leave means code dismemberment and certain death.
----

기본 (html5) 변환기와 스타일시트 (asciidoctor.css)를 사용하여 렌더링된 두 단락
======
[NOTE]
====
This journey begins one late Monday afternoon in Antwerp.
Our team desperately needs coffee, but none of us dare open the office door.

To leave means code dismemberment and certain death.
====
======

이제 이것만으로도 AsciiDoc으로 글을 작성할 수 있습니다!! 보시다시피, 마치 이메일을 쓰는 것과 같습니다.

파일 확장자를 `.adoc` 으로 지정해서 파일을 저장합니다.

[NOTE]
====
문서를 HTML, DocBook 또는 PDF로 변환하는 방법을 알고 싶다면, ‘문서 변환’ 섹션으로 건너뛰세요.
====


== Wrapped text and hard line breaks

Asciidoctor가 문서를 변환할 때 인접한 텍스트 줄들이 하나의 단락으로 합쳐지기 때문에, 단락 내 텍스트를 줄바꿈하거나 각 문장이나 구를 별도의 줄에 배치할 수 있습니다. 출력물에는 줄바꿈 표시가 나타나지 않습니다.

하지만 단락 내의 줄 바꿈을 그대로 유지하려면, 공백 뒤에 더하기 기호(`+`)를 사용하거나, 단락에 `hardbreaks` 옵션을 설정하면 됩니다. 이렇게 하면 각 줄 뒤에 눈에 보이는 줄 바꿈(예: `<br>`)이 생깁니다.

.공백 뒤에 더하기 기호(`+`)를 사용해서 줄 바꿈을 유지하는 경우
[source,asciidoc]
----
Rubies are red, +
Topazes are blue.
----

======
[NOTE]
====
Rubies are red, +
Topazes are blue.
====
======

.`hardbreaks` 옵션을 사용해서 줄바꿈을 유지함
[source,asciidoc]
----
[%hardbreaks]
Ruby is red.
Java is black.
----

======
[NOTE]
====
[%hardbreaks]
Ruby is red.
Java is black.
====
======

문서 전체에서 줄 바꿈을 유지하려면 문서 헤더에 `hardbreaks` 속성을 추가합니다.

.`hardbreaks` 속성을 사용해서 문서 전체에서 줄 바꿈이 유지됨
[source,asciidoc]
----
== Line Break Doc Title
:hardbreaks:

Rubies are red,
Topazes are blue.
----


== Admonitions

콘텐츠 흐름에서 분리해서 우선순위 라벨을 붙여 특정 문장에 주목을 끌고 싶은 경우가 있습니다. 이를 ‘주의 사항’ 이라고 합니다. 주의 사항의 표시 스타일은 할당된 라벨(즉, 값)에 따라 결정됩니다. Asciidoctor는 다섯 가지 주의 사항 스타일 라벨을 제공합니다:

* NOTE
* TIP
* IMPORTANT
* CAUTION
* WARNING

[IMPORTANT]
====
*주의(CAUTION) 대 경고(WARNING)* 

경고 유형을 선택할 때, “주의(CAUTION)” 와 “경고(WARNING)” 가 혼용되어 사용되기 때문에 두 용어를 혼동하기 쉽습니다. 다음은 이 둘을 구별하는 데 도움되는 간단한 규칙입니다.

* `CAUTION` 은 독자에게 신중하게 행동할 것(즉, 주의를 기울일 것)을 권고할 때 사용합니다.
* `WARNING` (경고)은 독자에게 존재하는 위험, 피해 또는 결과를 알릴 때 사용합니다.

자세한 분석은 https://www.differencebetween.com/difference-between-caution-and-vs-warning/ 을 참조합니다.
====

특정 단락에 주목을 끌고 싶다면, 해당 단락의 첫 줄에 사용하려는 레이블을 적습니다. 레이블은 대문자로 시작해야 하며, 그 뒤에 콜론(`:`)을 붙여야 합니다.

.경고 문단의 구문
[source,asciidoc]
----
WARNING: Wolpertingers are known to nest in server racks. ① ② 
Enter at your own risk.
----

① 라벨은 대문자로 작성해야 하며, 바로 뒤에 콜론(`:`)이 와야 합니다. +
② 단락 첫 줄과 라벨 사이에는 공백 하나만 넣습니다.

결과: 훈계 조항

======
[NOTE]
====
WARNING: Wolpertingers are known to nest in server racks.   
Enter at your own risk.
====
======

주의 문단은 콜아웃 상자로 표시되며, 여백 부분에 ‘주의’ 라벨 또는 이에 해당하는 아이콘이 표시됩니다. 아이콘은 문서의 `icons` 속성을 설정해서 활성화할 수 있습니다.

IMPORTANT: Admonitions can also encapsulate any block content, which we’ll cover later.



== Mild punctuation, strong impact

말할 때 특정 단어나 구를 강조하듯이, 글에서도 구두점을 사용해서 강조할 수 있습니다. AsciiDoc에서 이런 표기 방식을 ‘인용문’ 이라 부릅니다.


== Quoted text

예를 들어, 이메일에서 단어를 별표로 묶어 그 단어를 “강조할” 수 있습니다.

[source,asciidoc]
----
I can't believe it, we *won*!
----

예상했지만, 별표(*)를 사용하면 텍스트가 굵게 표시됩니다. 거의 그 감정이 느껴질 정도입니다. 이것이 인용(즉, 서식이 적용된) 텍스트의 한 예입니다.

NOTE: 여기서 “인용” 이라는 용어는 강조나 특별한 의미를 부여하기 위해 텍스트를 둘러싸는 모든 기호를 포괄하는 의미로 널리 사용됩니다.

다음은 AsciiDoc이 인식하는 인용 텍스트의 형태입니다:

.굵게, 기울임꼴, 고정폭 서식 구문
[source,asciidoc]
----
bold *constrained* & **un**constrained

italic _constrained_ & __un__constrained

bold italic *_constrained_* & **__un__**constrained

monospace `constrained` & ``un``constrained

monospace bold `*constrained*` & ``**un**``constrained

monospace italic `_constrained_` & ``__un__``constrained

monospace bold italic `*_constrained_*` & ``**__un__**``constrained
----

단어 경계가 아닌 다른 위치에서 텍스트를 인용(예: 강조)할 때는 구두점을 두 번 사용해야 합니다.

결과: 굵은 글씨, 기울임체, 고정폭 글꼴

======
[NOTE]
====
bold *constrained* & **un**constrained

italic _constrained_ & __un__constrained

bold italic *_constrained_* & **__un__**constrained

monospace `constrained` & ``un``constrained

monospace bold `*constrained*` & ``**un**``constrained

monospace italic `_constrained_` & ``__un__``constrained

monospace bold italic `*_constrained_*` & ``**__un__**``constrained
====
======

인용된 텍스트 앞에는 속성 목록을 붙일 수 있습니다. 첫 번째 위치 기반 속성은 역할로 간주됩니다. 이 역할을 사용해서 텍스트에 사용자 정의 스타일을 적용할 수 있습니다. 예를 들어:

[source,asciidoc]
----
Type the word [.userinput]#asciidoc# into the search bar.
----

HTML로 변환할 때, “asciidoc” 단어는 `<span>` 태그로 감싸지며, role 속성은 해당 요소의 CSS 클래스로 사용됩니다:

[source,html]
----
<span class="userinput">asciidoc</span>
----

CSS를 사용해서 텍스트에 스타일을 적용할 수 있습니다.

이런 대체가 항상 이루어지기를 원하지 않을 수도 있습니다. 그런 경우는 마크업을 사용해서 텍스트를 이스케이프 처리해야 합니다.



== Preventing substitution

원하지 않는 곳에서 인용문 처리가 발생하는 경우, 백슬래시나 패스스루 매크로를 사용해서 이를 방지할 수 있습니다.

Asciidoctor는 치환을 방지하기 위한 여러 가지 방법을 제공합니다.

*백슬래시 이스케이프* +
구두점이 서식 마크업으로 해석되는 것을 방지하려면, 해당 구두점 앞에 백슬래시(\)를 붙입니다. 서식 구두점이 두 개의 문자로 시작하는 경우(예: __), 그 앞에 백슬래시 두 개(\\)를 붙여야 합니다. 이 방법은 문자 및 속성 참조가 대체되는 것을 방지할 때도 사용할 수 있습니다. 문서가 처리될 때 백슬래시는 제거되므로 출력 결과에 표시되지 않습니다.

[source,asciidoc]
----
\*Stars* will appear as *Stars*, not as bold text.

\&sect; will appear as an entity, not the &sect; symbol.

\\__func__ will appear as __func__, not as emphasized text.

\{two-semicolons} will appear {two-semicolons}, not resolved as ;;.
----

Asciidoctor는 여러 형태의 패스스루 매크로를 지원합니다.

*인라인 pass 매크로* +
콘텐츠를 그대로 전달할 때 사용할 수 있는 `pass` 라는 이름의 인라인 매크로입니다. 선택적인 대체 항목 집합을 지원합니다.

[source,asciidoc]
----
pass:[content like #{variable} passed directly to the output] followed by normal content.

content with only select substitutions applied: pass:c,a[__<{email}>__]
----

*단일 및 이중 플러스* +
텍스트 서식이 적용되지 않도록 하는 특수 구문입니다. 출력 형식을 준수하기 위해 특수 문자만 이스케이프 처리하며, 명시적 치환은 지원하지 않습니다.

*삼중 플러스* +
통과 콘텐츠를 지정하는 특수 구문입니다. 어떤 치환도 적용하지 않으며(인라인 pass 매크로와 동일), 명시적 치환을 지원하지 않습니다.

*이중 달러 (사용 중단됨)* +
패스스루 콘텐츠를 지정하기 위한 더 이상 사용되지 않는 특수 구문입니다. 트리플 플러스와 마찬가지로 어떤 대체도 적용하지 않으며, 명시적 대체도 지원하지 않습니다.

CAUTION: Asciidoctor는 블록 패스 매크로를 구현하지 않습니다. 대신, 패스 블록을 사용해야 합니다.


== Inline pass macro and explicit substitutions

특정 구문을 치환 대상에서 제외하고 특수 문자의 이스케이프를 비활성화하려면, 해당 구문을 inline pass 매크로로 감쌉니다. 예를 들어, AsciiDoc에서 HTML을 생성할 때 텍스트에 밑줄을 적용하는 한 가지 방법은 다음과 같습니다:

[source,asciidoc]
----
The text pass:[<u>underline me</u>] is underlined.
----

======
[NOTE]
====
The text pass:[<u>underline me</u>] is underlined.
====
======

애드혹(Ad-Hoc) 인용문 대체 기능을 활성화하려면, 매크로 값을 `subs` 에 할당하고 인라인 패스 매크로를 사용합니다.
