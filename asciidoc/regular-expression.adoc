== What is a Regular Expression?

정규 표현식은 특정 패턴을 지정하는 문자 집합입니다. “정규(_regular_)” 라는 용어는 식이섬유가 풍부한 식단과는 아무런 관련이 없습니다. 이 용어는 문법과 형식 언어를 설명하는 데 사용되는 용어에서 유래했습니다.

정규 표현식은 특정 패턴을 포함하는 텍스트의 특정 줄을 검색할 때 사용됩니다. 대부분의 UNIX 유틸리티는 ASCII 파일을 한 줄씩 처리합니다. 정규 표현식은 한 줄 내에서 패턴을 검색하며, 한 줄에서 시작해서 다른 줄에서 끝나는 패턴은 검색하지 않습니다.

특정 단어나 문자열을 검색하는 것은 간단합니다. 거의 모든 컴퓨터 시스템의 편집기에서 이 기능을 지원합니다. 정규 표현식은 좀 더 강력하고 유연합니다. 특정 길이의 단어를 검색할 수도 있습니다. 모음이 4개 이상이고 “s” 로 끝나는 단어를 검색할 수도 있습니다. 숫자, 구두점 등 무엇이든 정규 표현식을 사용하면 찾을 수 있습니다. 사용 중인 프로그램이 해당 패턴을 찾았을 때 어떤 동작을 하는지는 또 다른 문제입니다. 어떤 프로그램은 단순히 패턴을 검색할 뿐이고, 다른 프로그램은 패턴이 포함된 줄을 출력하기도 합니다. 편집기의 경우 해당 문자열을 새로운 패턴으로 대체할 수도 있습니다. 이는 모두 유틸리티에 따라 다릅니다.

정규 표현식은 셸에서 사용하는 파일 일치 패턴과 매우 비슷하기 때문에 사람들을 혼란스럽게 합니다. 심지어 작동 방식도 거의 비슷합니다. 대괄호는 비슷하고, 별표(*)는 정규 표현식의 별표와 비슷하게 작동하지만 완전히 동일하진 않습니다. 특히, Bourne 셸, C 셸, find, cpio 는 정규 표현식이 아닌 파일 이름 일치 패턴을 사용합니다.

“셸 메타문자는 셸이 인수를 프로그램에 전달하기 전에 확장된다” 는 점을 기억합니다. 이런 확장을 방지하려면, 셸에서 옵션으로 전달할 때 정규 표현식 내의 특수 문자를 따옴표로 묶어야 합니다. 지난 튜토리얼에서 이 주제를 다뤘기 때문에, 이미 이를 수행하는 방법을 알고 계실 것입니다.


== The Structure of a Regular Expression

정규 표현식은 세 가지 중요한 구성 요소가 있습니다. “앵커” 는 텍스트 줄 내에서 패턴의 위치를 지정하는 데 사용됩니다. “문자 집합” 은 단일 위치에서 하나 이상의 문자와 일치시킵니다. “수정자” 는 앞의 문자 집합이 몇 번 반복되는지를 지정합니다. 이 세 가지 구성 요소를 모두 보여주는 간단한 예로는 정규 표현식 “^#*” 이 있습니다. 위쪽 화살표는 줄의 시작을 나타내는 앵커입니다. 문자 “#” 은 단일 문자 “#” 과 일치하는 간단한 문자 집합입니다. 별표(*)는 수정자입니다. 정규 표현식에서 이 수정자는 앞의 문자 집합이 “0회를 포함해서 임의의 횟수만큼 나타날 수 있음” 을 나타냅니다. 곧 보겠지만, 이 정규 표현식은 아무런 용도가 없습니다.

정규 표현식은 “기본” 정규 표현식과 “확장” 정규 표현식, 두 가지 유형이 있습니다. awk 나 egrep 같은 일부 유틸리티는 확장 정규식을 사용합니다. 대부분은 “기본” 정규식을 사용합니다. 이제부터 “정규식” 이라 언급할 때는 두 유형 모두의 기능을 의미합니다.

== The Anchor Characters: ^ and $

대부분의 유닉스 텍스트 처리 기능은 줄 단위로 작동합니다. 여러 줄에 걸쳐 있는 패턴을 검색하는 것은 쉽지 않습니다. 왜냐하면 줄 끝 문자는 검색 대상 텍스트 블록에 포함되지 않기 때문입니다. 이 문자는 구분자 역할을 합니다. 정규 표현식은 구분자 사이의 텍스트를 검사합니다. 패턴의 시작이나 끝 부분에 해당하는 내용을 검색하려면 앵커를 사용해야 합니다. 문자 “^” 는 시작 앵커이고, 문자 “$” 는 끝 앵커입니다. 정규 표현식 “^A” 는 대문자 A로 시작하는 모든 줄과 일치합니다. 표현식 “A$” 는 대문자 A로 끝나는 모든 줄과 일치합니다. 앵커 문자가 패턴의 적절한 끝 위치에 사용되지 않으면 더 이상 앵커 역할을 하지 않습니다. 즉, “^” 는 정규 표현식의 첫 번째 문자인 경우만 앵커가 됩니다. “$” 는 마지막 문자인 경우만 앵커 역할을 합니다. “$1” 표현식은 앵커가 없으며, “1^” 역시 마찬가지입니다. 줄의 시작 부분에 있는 “^” 나 줄의 끝 부분에 있는 “$” 와 일치시켜야 하는 경우, 백슬래시를 사용해서 특수 문자를 이스케이프 처리해야 합니다. 요약하면 다음과 같습니다:

[%autowidth]
|===
|패턴   |일치 조건

|^A     |줄의 시작 부분에 있는 “A”
|A$     |줄의 끝 부분에 있는 “A”
|A^     |줄의 어느 위치나 있는 “A^”
|$A     |줄의 어느 위치나 있는 “$A”
|^^     |줄의 시작 부분에 있는 “^”
|$$     |줄의 끝 부분에 있는 “$”
|===

줄의 시작이나 끝을 나타내는 표시로 “^” 와 “$” 를 사용하는 것은 다른 유틸리티도 따르는 “관례” 입니다. vi 편집기는 이 두 문자를 줄의 시작이나 끝으로 이동하는 명령어로 사용합니다. C 셸은 “!^” 를 사용해서 이전 줄의 첫 번째 인수를 지정하고, “!$” 는 이전 줄의 마지막 인수를 나타냅니다.

이는 일관성을 유지하기 위해 다른 유틸리티들도 따르는 관례 중 하나입니다. 예를 들어, ed 나 sed 를 사용할 때 “$” 는 파일의 마지막 줄을 가리킬 수 있습니다. cat -e 명령어는 줄 끝을 “$” 로 표시합니다. 다른 프로그램도 이와 같은 표기를 볼 수 있습니다.


== Matching a character with a character set

가장 간단한 문자 집합은 하나의 문자입니다. 정규 표현식 “the” 는 “t”, ‘h’, “e” 세 개의 문자 집합이 포함되어 있습니다. 이 표현식은 내부에 “the” 문자열이 포함된 모든 줄과 일치합니다. 이 경우 “other” 단어도 일치하게 됩니다. 이를 방지하려면 패턴 앞뒤에 공백을 넣어 “ the ” 같이 작성합니다. 이 문자열을 앵커와 결합할 수도 있습니다. 패턴 “^From: ” 는 발신자를 식별하는 메일 메시지의 줄과 일치합니다. 이 패턴을 grep 과 함께 사용하면 수신함의 모든 주소를 출력할 수 있습니다:

----
grep ‘^From: ’ /usr/spool/mail/$USER
----

일부 문자는 정규 표현식에서 특별한 의미를 가집니다. 이런 문자를 검색하려면 백슬래시로 이스케이프 처리해야 합니다.


== Match any character with .

문자 “.” 은 이런 특수 메타 문자 중 하나입니다. 이 문자는 단독으로 사용될 때 줄바꿈 문자를 제외한 모든 문자와 일치합니다. 단일 문자로 구성된 줄과 일치하는 패턴은 다음과 같습니다.

----
^.$
----


== Specifying a Range of Characters with [...]

특정 문자를 일치시키려면, 대괄호를 사용해서 검색하려는 정확한 문자를 지정할 수 있습니다. 숫자가 정확히 하나 포함된 모든 텍스트 줄과 일치하는 패턴은 다음과 같습니다.

----
^[0123456789]$
----

이 방식은 다소 번거롭습니다. 두 문자 사이에 하이픈을 사용해서 범위를 지정할 수 있습니다:

----
^[0-9]$
----

명시적인 문자와 문자 범위를 함께 사용할 수 있습니다. 다음 패턴은 알파벳, 숫자 또는 밑줄(_) 중 하나인 단일 문자와 일치합니다:

----
[A-Za-z0-9_]
----

문자 집합은 서로 나란히 배치해서 결합할 수 있습니다. 다음과 같은 조건을 모두 충족하는 단어를 검색하려면

----
대문자 “T” 로 시작하는 단어
줄의 첫 번째 단어인 단어
두 번째 글자가 소문자인 단어
정확히 세 글자로 구성된 단어, 그리고
세 번째 글자가 모음인 단어
----

정규 표현식은 “^T[a-z][aeiou] ” 가 됩니다.


== Exceptions in a character set

대괄호([...]) 안에 있는 문자를 제외한 모든 문자를 검색하려면, “[” 바로 뒤에 “^” 를 첫 번째 문자로 넣으면 됩니다. 모음을 제외한 모든 문자를 일치시키려면 “[^aeiou]” 패턴을 사용합니다.

앵커로 간주될 수 없는 위치의 앵커와 마찬가지로, “[” 바로 뒤에 “]” 와 “-” 가 오더라도 특별한 의미를 가지지 않습니다. 다음은 몇 가지 예시입니다:

[%autowidth]
|===
|정규 표현식     |일치 대상

|[]              |“[]” 문자
|[0]             |“0” 문자
|[0-9]           |임의의 숫자
|[^0-9]          |숫자 이외의 임의의 문자
|[-0-9]          |임의의 숫자 또는 “-”
|[0-9-]          |임의의 숫자 또는 “-”
|[^-0-9]         |숫자 또는 “-”를 제외한 임의의 문자
|[]0-9]          |임의의 숫자 또는 “]”
|[0-9]]          |“]”가 뒤따르는 임의의 숫자
|[0-9-z]         |임의의 숫자 또는 “9” 와 “z” 사이의 임의의 문자.
|[0-9\-a\]]      |임의의 숫자, 또는 “-”, ‘a’ 또는 “]”
|===


== Repeating character sets with *

정규 표현식의 세 번째 부분은 수정자입니다. 이는 앞의 문자 집합이 몇 번이나 나타날 것으로 예상되는지를 지정하는 데 사용됩니다. 특수 문자 “*” 는 0개 이상의 복사본과 일치합니다. 즉, 정규 표현식 “0*” 는 0개 이상의 0 과 일치하고, 표현식 “[0-9]*” 는 0개 이상의 숫자와 일치합니다.

이것이 바로 “^#*” 패턴이 쓸모없는 이유입니다. 이 패턴은 줄의 시작 부분에 있는 “#” 의 개수가 0 개를 포함해서 얼마든지 일치시키기 때문입니다. 따라서 모든 줄은 0 개 이상의 “#” 으로 시작하므로, 이 패턴은 모든 줄과 일치하게 됩니다.

언뜻 보면 카운트를 0 부터 시작하는 것이 어리석게 보일 수도 있습니다. 하지만 그렇지 않습니다. 알 수 없는 개수의 문자를 찾는 것은 매우 중요합니다. 줄의 시작 부분에 숫자가 있는지, 그 앞에 공백이 있을 수도 있고 없을 수도 있는 경우를 생각해 봅니다. 줄의 시작 부분에 0 개 이상의 공백을 일치시키려면 “^ *” 를 사용하면 됩니다. 하나 이상 일치시켜야 한다면, 해당 문자 집합을 반복하면 됩니다. 즉, “[0-9]*” 는 0 개 이상의 숫자와 일치하고, “[0-9][0-9]*” 는 하나 이상의 숫자와 일치합니다.


== Matching a specific number of sets with \{ and \}

최소 문자 집합 수를 지정하려면 위의 기법을 계속 사용할 수 있습니다. “*” 수식자를 사용해서 최대 집합 수를 지정할 수는 없습니다. 반복 횟수의 최소값과 최대값을 지정하는 데 사용할 수 있는 특별한 패턴이 있습니다. 이는 “\{” 와 “\}” 사이에 두 개의 숫자를 넣는 방식으로 이루어집니다. 백슬래시는 별도로 설명할 필요가 있습니다. 일반적으로 백슬래시는 문자의 특수 의미를 무효화합니다. 마침표는 “\.” 로, 별표는 “\*” 로 일치됩니다.

“<”, “>”, “{”, “}”, “(”, “)” 또는 숫자 앞에 백슬래시를 붙이면, 백슬래시는 해당 문자의 특수 의미를 활성화합니다. 이는 정규 표현식의 발전 과정에서 이런 특수 기능이 나중에 추가되었기 때문입니다. “{” 의 의미를 변경했다면 기존 표현식이 작동하지 않을 것입니다. 이는 1년 동안 COBOL 프로그램을 작성하는 강제 노동을 선고받을 만한 끔찍한 범죄입니다. 대신 백슬래시를 추가함으로써 기존 프로그램을 깨뜨리지 않고 기능을 확장했습니다. 비-대칭성을 불평하기보단 이를 진화로 받아들이기 바랍니다.

“\{” 가 여러분을 혼란스럽게 하려는 음모가 아니라는 점을 납득시켰으니, 이제 예제를 살펴보겠습니다. 소문자 4, 5, 6, 7 또는 8자를 일치시키는 정규 표현식은 다음과 같습니다.

----
[a-z]\{4,8\}
----

0 에서 255 사이의 숫자를 사용할 수 있습니다. 두 번째 숫자는 생략할 수 있으며, 이 경우 상한이 제거됩니다. 쉼표와 두 번째 숫자를 모두 생략하면, 패턴은 첫 번째 숫자로 지정된 횟수만큼 정확히 반복되야 합니다.

“*” 나 “\{1,5\}” 같은 수정자는 “문자 집합 뒤에 올 때만 수정자 역할을 한다!” 는 점을 기억해야 합니다. 패턴 맨 앞에 위치할 경우 수정자로 작용하지 않습니다. 다음은 예시와 예외 사항 목록입니다:

[%autowidth]
|===
|정규 표현식     |일치 조건

|_               |
|*               |별표가 포함된 모든 줄
|\*              |별표가 포함된 모든 줄
|\\              |백슬래시가 포함된 모든 줄
|^*              |별표로 시작하는 모든 줄
|^A*             |모든 줄
|^A\*            |“A*” 로 시작하는 모든 줄
|^AA*            |“A” 하나로 시작하는 모든 줄
|^AA*B           |“A” 가 하나 이상 있고 그 뒤에 “B” 가 오는 모든 줄
|^A\{4,8\}B      |“A” 가 4, 5, 6, 7 또는 8개 있고 그 뒤에 “B” 가 오는 모든 줄
|^A\{4,\}B       |4개 이상의 “A” 로 시작하고 그 뒤에 “B” 가 오는 모든 줄
|^A\{4\}B        |“AAAAB” 로 시작하는 모든 줄
|\{4,8\}         |“{4,8}” 이 포함된 모든 줄
|A{4,8}          |“A{4,8}” 이 포함된 모든 줄
|===


== Matching words with \< and \>

단어를 검색하는 것은 겉보기만큼 간단하지 않습니다. 문자열 “the” 는 “other” 단어와도 일치합니다. 글자 앞뒤에 공백을 넣고 “ the ” 같은 정규식을 사용할 수 있습니다. 하지만 이 방법은 줄의 시작이나 끝 부분에 있는 단어는 일치하지 않습니다. 또한 단어 뒤에 구두점이 있는 경우도 일치하지 않습니다.

간단한 해결책이 있습니다. “\<” 와 “\>” 문자는 “^” 및 “$” 앵커와 유사하게, 문자 위치를 차지하지 않습니다. 이 문자들은 표현식 양쪽 끝을 “고정” 해서 단어 경계에서만 일치하도록 합니다. “the” 단어를 검색하는 패턴은 “\<[tT]he\>” 가 됩니다. ‘t’ 앞의 문자는 줄 바꿈 문자이거나, 알파벳, 숫자, 밑줄(_)을 제외한 어떤 문자라도 되어야 합니다. “e” 뒤의 문자도 숫자, 알파벳, 밑줄(_)을 제외한 다른 문자여야 하며, 줄 끝 문자일 수도 있습니다.


== Backreferences - Remembering patterns with \(, \) and \1

특별한 메커니즘이 필요한 또 다른 패턴은 반복되는 단어를 검색하는 것입니다. “[a-z][a-z]” 표현은 임의의 소문자 두 글자와 일치합니다. 만약 서로 인접한 동일한 글자 두 개가 포함된 줄을 검색하려면, 위의 패턴만으로는 도움이 되지 않습니다. 찾은 내용을 기억했다가 동일한 패턴이 다시 나타나는지 확인할 수 있는 방법이 필요합니다. “\(” 와 “\)” 를 사용해서 패턴의 일부를 표시할 수 있습니다. “\” 뒤에 한 자리 숫자를 붙이면 기억해 둔 패턴을 다시 불러올 수 있습니다. 따라서 두 개의 동일한 문자를 검색하려면 “\([a-z]\)\1” 을 사용하면 됩니다. 총 9개의 서로 다른 패턴을 기억해 둘 수 있습니다. “\(” 가 나타날 때마다 새로운 패턴이 시작됩니다. 5글자 팔린드롬(예: “radar”)과 일치하는 정규 표현식은 다음과 같습니다.

----
\([a-z]\)\([a-z]\)[a-z]\2\1
----


== Potential Problems

이것으로 기본 정규 표현식에 대한 설명을 마칩니다. 확장 표현식이 제공하는 기능을 다루기 전에, 두 가지 잠재적인 문제점을 언급하고 싶습니다.

“\<” 와 “\>” 문자는 vi 편집기에서 처음 도입되었습니다. 당시 다른 프로그램들은 이런 기능을 지원하지 않았습니다. 또한 “\{min,max\}” 수정자는 새로운 것으로, 초기 유틸리티들은 이 기능이 없었습니다. 이로 인해 정규 표현식을 처음 접하는 사용자들은 각 유틸리티마다 서로 다른 규칙을 따르는 것처럼 보여서 어려움을 겪곤 했습니다. Sun은 자사의 모든 프로그램에 최신 정규 표현식 라이브러리를 적용해서, 이제 모든 프로그램이 동일한 기능을 갖도록 했습니다. 다른 벤더의 시스템에서 이런 새로운 기능을 사용하면, 예상과 다르게 작동할 수 있습니다.

또 다른 혼란의 소지가 될 수 있는 점은 패턴 일치 범위의 문제입니다. 정규 표현식은 가능한 가장 긴 패턴과 일치합니다. 즉, 정규 표현식

----
A.*B
----

는 “AAB” 뿐만 아니라 “AAAABBBBABCCCCBBBAAAB” 도 일치합니다. grep 을 사용할 때는 이로 인해 큰 문제가 발생하지 않습니다. 정규 표현식에서 실수가 있더라도 원하는 것보다 더 많은 줄이 일치할 뿐이기 때문입니다. 하지만 sed를 사용할 때 패턴이 지나치게 확장되면, 의도한 것보다 더 많은 내용을 삭제할 수도 있습니다.


== Extended Regular Expressions

확장 정규식을 사용하는 프로그램은 두 가지가 있습니다: egrep 과 awk 입니다. 이런 확장을 적용하면, 백슬래시가 앞에 붙은 특수 문자들, 즉 “\{”, “\}”, “\<”, “\>”, “\(”, “\)” 및 “\digit” 은 더 이상 특별한 의미를 가지지 않게 됩니다. 여기는 아주 타당한 이유가 있는데, 긴장감을 높이기 위해 설명은 잠시 미루겠습니다.

문자 “?” 는 앞에 온 문자 집합이 0 번 또는 1 번 나타나는 것과 일치하고, 문자 “+” 는 해당 문자 집합이 한 번 이상 나타나는 것과 일치합니다. 확장 정규 표현식은 \{ 와 \} 를 사용할 수 없지만, 만약 사용할 수 있다면 “?” 는 “\{0,1\}” 과 같고, “+” 는 “\{1,\}” 과 같다고 생각할 수 있습니다.

이쯤 되면, 확장 정규 표현식을 왜 사용하는지 의문이 들 것입니다. 두 가지 약어를 제외하면 장점은 없고 단점만 많기 때문입니다. 따라서 예시를 통해 살펴보는 것이 도움될 것입니다.

확장 정규 표현식에서 중요한 세 가지 문자는 “(”, “|”, “)” 입니다. 이 세 가지를 함께 사용하면 여러 패턴 중 하나를 선택해서 일치시킬 수 있습니다. 예를 들어, egrep 을 사용해서 수신 메일의 모든 From: 및 Subject: 줄을 출력할 수 있습니다:

----
egrep ‘^(From|Subject): ’ /usr/spool/mail/$USER
----
    
“From:” 또는 “Subject:” 로 시작하는 모든 줄이 출력됩니다. 기본 정규 표현식만으로는 이를 처리할 쉬운 방법이 없습니다. “^[FS][ru][ob][mj]e*c*t*: ” 를 사용할 수는 있겠지만, “Sromeet:” 로 시작하는 줄이 없기를 바랄 수밖에 없습니다. 확장 정규 표현식은 “\<” 및 “\>” 문자가 없습니다. 대신 선택 기법을 사용해서 이를 보완할 수 있습니다. 문장의 시작, 중간, 끝 또는 줄 끝에서 “the” 라는 단어를 일치시키는 작업은 다음 확장 정규 표현식을 사용해서 수행할 수 있습니다.

----
(^| )the([^a-z]|$)
----

단어 앞에는 공백이나 줄 시작 중 하나가 올 수 있습니다. 단어 뒤에는 소문자 이외의 문자가 와야하거나, 그렇지 않으면 줄 끝이어야 합니다. 확장 정규 표현식의 또 다른 장점은 “(...)” 그룹화 뒤에 “*”, “+”, “?” 수정자를 사용할 수 있다는 점입니다. 다음은 “a simple problem”, “an easy problem” 은 물론 “a problem” 도 일치합니다.

----
egrep “a[n]? (simple |easy )?problem” data
----

“simple” 과 “easy” 뒤의 공백에 유의합니다.

“확장 정규 표현식에서 백슬래시 문자가 작동하지 않는 이유를 설명하겠다” 고 약속했었죠. 글쎄요, 어쩌면 “\{...\}” 와 “\<...\>” 를 확장 정규 표현식에 추가할 수도 있었을 겁니다. 이 두 가지는 정규 표현식 계열에 가장 최근에 추가된 요소들입니다. 추가할 수는 있겠지만, 이 문자들은 추가하고 “\(...\)” 는 추가하지 않으면 사람들이 헷갈릴 수도 있습니다. 그리고 현재의 사용법을 변경하지 않고는 확장 정규 표현식에 그 기능을 추가할 방법이 없습니다. 그 이유를 아시겠습니까? 아주 간단합니다. 만약 “(” 가 특별한 의미를 가진다면, “\(” 는 일반 문자여야 합니다. 이는 “(” 가 일반 문자고 “\(” 가 특별한 의미를 갖는 기본 정규 표현식과 정반대입니다. 괄호 사용법이 호환되지 않으므로, 어떤 변경이라도 기존 프로그램을 작동하지 않게 만들 수 있습니다.

만약 확장 표현식이 “( ..|...)” 를 일반 문자로 사용하고, “\(...\|...\)” 를 대체 패턴을 지정하는 데 사용한다면, 모든 기능을 갖춘 단일 정규 표현식 집합을 가질 수 있습니다. 참고로, 이것이 바로 GNU emacs가 취하는 방식입니다.

나머지는 무작위 메모입니다.

[%autowidth]
|===
|정규 표현식    |클래스     |유형        |의미

|_              |           |            |
|.              |모두       |문자 집합   |단일 문자 (줄바꿈 제외)
|^              |모두       |앵커        |줄의 시작
|$              |모두       |앵커        |줄의 끝
|[...]          |모두       |문자 집합   |문자 범위
|*              |전체       |수정자      |0회 이상 반복
|\<             |기본       |앵커        |단어 시작
|\>             |기본       |앵커        |단어 끝
|\(..\)         |기본       |역참조      |패턴 기억
|\1..\9         |기본       |참조        |패턴 불러오기

|_              |           |            |
|\(...\|...\)   |EMACS      |앵커        |변형을 나타냄
|\w             |EMACS      |문자 집합   |단어 내의 문자와 일치
|\W             |EMACS      |문자 집합   |\w의 반대

== POSIX character sets

POSIX는 문자 집합을 검색하는 데 있어 좀 더 최신이고 이식성이 뛰어난 방법을 추가했습니다. [a-zA-Z] 를 사용하는 대신 'a-zA-Z' 를 [:alpha:] 로 대체하거나, 좀 더 완벽하게 하려면 [a-zA-Z] 를 [[:alpha:]] 로 대체할 수 있습니다. 이 방법의 장점은 “국제 문자 집합도 일치한다!” 는 점입니다. 기존 방식과 새로운 POSIX 방식을 혼합해서 사용할 수 있습니다. 예를 들어,

----
grep ‘[1-9[:alpha:]]’
----

다음은 전체 목록입니다.

[%autowidth]
|===
|문자 그룹     |의미

|[:alnum:]     |영숫자
|[:cntrl:]     |제어 문자
|[:lower:]     |소문자
|[:space:]     |공백
|[:alpha:]     |알파벳
|[:digit:]     |숫자
|[:print:]     |인쇄 가능한 문자
|[:upper:] 	   |대문자
|[:blank:]     |공백, 탭 등
|[:graph:]     |인쇄 가능하고 가시적인 문자
|[:punct:]     |구두점
|[:xdigit:]    |확장 숫자
|===

일부 사람들은 [[:alpha:]] 를 표기법으로 사용하지만, 바깥쪽의 '[...]' 가 “문자 집합을 지정한다!” 는 점에 유의합니다.

|\B       |앵커          |(단어 경계가 아닌) 위치를 일치시킴
|\A       |앵커          |문자열의 시작 부분에서만 일치시킴
|\Z       |앵커          |문자열 끝(EOS) 또는 줄바꿈 전에서만 일치시킴
|\z       |앵커          |문자열의 끝에서만 일치시킴
|\G       |앵커          |이전 m//g가 중단된 위치에서만 일치시킴
|===

PERL 확장형 다중 행 정규 표현식의 예시

[source,perl]
----
m{ \(
      (	  # Start group
       [^()]+ # anything but '(' or ')'
      |   # or
        \( [^()]* \)
      )+  # end group
   \)
}x
----
