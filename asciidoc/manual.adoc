== asciidoc이란?

`AsciiDoc` 은 주로 기술 문서를 작성하기 위해 설계된 경량 시맨틱 마크업 언어입니다. 이 언어를 사용하면 간결하고 사람이 읽기 쉬운 일반 텍스트 형식으로 인코딩된 콘텐츠만으로 다양한 시각적 효과가 풍부한 출력 형식을 생성할 수 있습니다.

AsciiDoc 구문은 텍스트를 마크업하고 구조화하기 위해 잘 정립된 일반 텍스트 관례를 기반으로 처리하므로
매우 직관적입니다. AsciiDoc에 익숙치 않은 사람이라도 구문 요소들을 보기만 해도 그 목적을 대략 짐작할 수 있을 것입니다. 이는 구문 요소들이 그 의미와 외관이 일치하도록 신중하게 선택되었기 때문입니다(이는 기술 업계에서 오랫동안 채택해 온 관행입니다).

AsciiDoc 프로세서는 AsciiDoc 소스 문서를 구문 분석하고 이해한 후, 구문 분석된 문서 구조를 HTML, PDF, EPUB3, 매뉴얼 페이지, DocBook 같은 하나 이상의 출력 형식으로 변환할 수 있습니다. AsciiDoc 언어는 이를 통해 생성되는 출력 형식과 밀접하게 연결되어 있지 않습니다. 다양한 출력 형식을 생성할 수 있는 능력은 AsciiDoc의 주요 장점 중 하나입니다. 이런 기능 덕분에 정적 사이트 생성기, 도움말 텍스트, 도서 출판, IDE, Git 도구 및 서비스, CI/CD 시스템, 그리고 기타 새로운 용도에서 활용될 수 있습니다.

AsciiDoc은 편리한 작성 방식과 기술 문서 작성 및 출판의 엄격한 요구 사항 사이의 격차를 해소합니다. AsciiDoc은 읽기나 쓰기에는 텍스트 편집기만 필요하므로, 시작하기 위한 진입 장벽이 낮습니다.


== About this documentation

현재 여러분은 Asciidoctor에 구현된 AsciiDoc 언어에 대한 사용자용 문서를 읽고 계십니다. 이 문서는 AsciiDoc 콘텐츠를 처리하기 위해 Asciidoctor를 설정하고 사용하는 방법에 대해서는 다루지 않습니다. 해당 문서는 이 웹사이트의 Asciidoctor 섹션에서 확인하실 수 있습니다.

이 문서는 Eclipse의 AsciiDoc 언어 프로젝트에 대한 초기 기여물로 제출되었습니다. 해당 프로젝트는 이 문서를 바탕으로 AsciiDoc 언어 사양 초안을 작성할 예정입니다. 또한 이 문서는 AsciiDoc 언어 사용자 가이드 초안으로도 활용될 것이며, 이 가이드 역시 해당 프로젝트에서 관리할 예정입니다.

AsciiDoc 언어 사양의 첫 번째 버전이 승인될 때까지는 AsciiDoc이 Asciidoctor 구현체에 의해 정의됩니다. 이 언어에 대한 다른 공식적인 정의는 없습니다.

AsciiDoc 언어 프로젝트가 AsciiDoc 언어에 대한 자체 문서를 게시하기 시작할 때까지 AsciiDoc 관련 문서는 이 사이트에 계속 게시될 것입니다.

그때까지, 시작해 봅시다!



== Introduction

=== Document Structure

이 페이지는 AsciiDoc 문서의 전반적인 구조에 대해 알아보겠습니다. 이 단계는 구문의 세부 사항에 대해 너무 신경 쓰지 마시기 바랍니다. 그 내용은 이 문서 뒷부분에서 자세히 다룰 예정입니다. 지금은 AsciiDoc 문서가 무엇으로 구성되는지 대략적인 감을 잡는 데 집중해 봅시다.


==== Documents

AsciiDoc은 정형화된 묶음 구조나 프롤로그가 없는 일반 텍스트 작성 형식입니다. AsciiDoc 문서는 단 한 문장(혹은 엄밀히 말해 단 한 글자)만으로 구성될 수도 있습니다.

아래 예시는 유효한 AsciiDoc 문서입니다. 이 문서에는 단 한 문장으로 구성된 단 하나의 단락이 포함되어 있습니다.

 This is a basic AsciiDoc document.

물론, 한 문장보다 더 많은 내용을 담을 수도 있습니다! 여기서 강조하고 싶은 점은 시작하는 것이 간단하다는 것입니다.

AsciiDoc 문서는 줄 단위로 쌓여 있는 일련의 블록들로 구성됩니다. 이 블록들은 일반적으로 빈 줄 하나로 서로 간격을 두고 배치됩니다. (비록 이런 빈 줄이 항상 필요한 것은 아니지만, 가독성을 위해 사용하는 것을 권장합니다.)

앞서 본 문서를 한 단락에서 두 단락으로 확장하려면, 두 단락 사이에 빈 줄 하나를 삽입하면 됩니다: 

[source]
----
This is a basic AsciiDoc document.
 
This document contains two paragraphs.
----

AsciiDoc 문서는 문서 헤더로 시작할 수 있습니다. 문서 헤더는 선택 사항이지만, 문서 제목을 지정할 수 있을 뿐만 아니라 문서 전체에 적용되는 구성 설정과 문서 속성 형태의 재사용 가능한 텍스트를 정의할 수 있기 때문에 흔히 사용됩니다.

[source,asciidoc]
----
= Document Title
Author Name
:reproducible:

This is a basic AsciiDoc document by {author}.

This document contains two paragraphs.
It also has a header that specifies the document title and some attibutes.
----

거의 모든 블록 조합은 유효한 AsciiDoc 문서를 구성합니다(단, 문서 유형에 따라 정해진 몇 가지 구조적 요구 사항이 있습니다). 문서의 규모는 한 문장부터 여러 부로 구성된 책에 이르기까지 다양할 수 있습니다.


==== Lines

줄은 AsciiDoc에서 중요한 구성 요소입니다. 줄은 양쪽이 줄바꿈 문자나 문서의 경계로 구분된 텍스트로 정의됩니다. 구문의 여러 요소는 반드시 한 줄 전체를 차지해야 합니다. 이것이 바로 AsciiDoc을 ‘줄 중심 언어’ 라고 부르는 이유입니다.

예를 들어, 섹션 제목은 반드시 한 줄을 단독으로 차지해야 합니다. 속성 항목, 블록 제목, 블록 속성 목록, 블록 매크로, 목록 항목, 블록 구분자 등도 마찬가지입니다.

.예제 1. 한 줄을 차지해야 하는 섹션 제목의 예

[source,asciidoc]
----
== Section Title
----

.예 2. 속성 항목의 예시. 이 항목 역시 최소 한 줄을 차지해야 합니다.

 :name: value

.예 3. 두 줄에 걸쳐 있는 속성 항목의 예

 :name: value \
 more value

속성 항목은 다른 줄로 이어지도록 명시적으로 이어서 써야 한다는 점에 유의하십시오.

빈 줄도 중요한 의미를 가질 수 있습니다. 예를 들어, 헤더와 본문은 하나의 빈 줄로 구분됩니다. 앞서 두 단락으로 구성된 예제에서 보셨듯이, 많은 블록들도 빈 줄로 구분됩니다.

반면, 단락 내용 내의 줄들은 별다른 의미를 가지지 않습니다. AsciiDoc 구문을 학습할 때 이런 점들을 염두에 두시기 바랍니다.


==== Blocks

AsciiDoc 문서의 블록은 문서의 구조를 구성합니다. 일부 블록은 다른 블록을 포함할 수 있으므로, 문서 구조는 본질적으로 계층적(즉, 트리 구조)입니다. 예를 들어, 자동 목차를 활성화하면 이런 섹션 구조를 확인할 수 있습니다. 블록의 예로는 단락, 섹션, 목록, 구분된 블록, 표, 블록 매크로 등이 있습니다.

블록은 대개 다른 블록과 빈 줄 하나로 구분되므로(항상 필요한 것은 아니지만) 쉽게 식별할 수 있습니다. 블록은 항상 새 줄에서 시작하고, 줄 끝에서 끝나며, 왼쪽 여백에 정렬됩니다.

모든 블록에는 하나 이상의 블록 메타데이터 줄이 포함될 수 있습니다. 이 메타데이터는 블록 속성, 블록 앵커 또는 블록 제목 형태를 띨 수 있습니다. 이런 메타데이터 줄은 블록 자체 바로 위, 인접한 위치에 있어야 합니다.

섹션, 비-버바팀(non-verbatim)으로 구분된 블록, 그리고 AsciiDoc 테이블 셀에는 다른 블록이 포함될 수 있습니다. 블록이 계층 구조를 형성한다는 사실에도 불구하고, 중첩된 블록조차 왼쪽 여백에서 시작합니다. 블록이 왼쪽 여백에서 시작하도록 요구함으로써, 들여쓰기 수준을 추적하고 관리해야 하는 번거로움을 피할 수 있습니다. 또한 이는 콘텐츠의 재사용성을 높여줍니다.


==== Text and inline elements

마커, 구분자 및 메타데이터 줄로 둘러싸인 부분이 바로 텍스트입니다. 텍스트는 문서의 핵심이며, AsciiDoc 구문이 텍스트에 넉넉한 공간을 할애하는 이유이기도 합니다. 텍스트는 주로 블록(예: 단락)의 줄, 블록 제목(예: 섹션 제목) 및 목록 항목에서 발견되지만, 그 외에도 존재할 수 있는 다른 위치들이 있습니다.

텍스트는 치환의 대상이 됩니다. 치환은 마크업을 텍스트 서식으로 해석하고, 매크로를 텍스트나 비-텍스트 요소로 대체하며, 속성 참조를 확장하고, 그 밖의 다양한 텍스트 치환 작업을 수행합니다.

별도로 지정되지 않는 한, 일반 텍스트는 모든 대체 처리를 거칩니다. Verbatim 텍스트는 소스에서 보이는 그대로 출력에 표시될 수 있도록 최소한의 대체 처리만 적용됩니다. 또한 텍스트를 수정 없이(즉, 원본 그대로) 출력으로 전달하기 위해 모든 대체 처리를 비활성화할 수도 있습니다. 텍스트의 구문 분석은 결국 인라인 요소와 다른 형태의 변환이 혼합된 형태가 됩니다.


==== Encodings and AsciiDoc files

AsciiDoc 파일은 `.adoc` 파일 확장자를 가진 텍스트 파일입니다(예: _document.adoc_). 대부분의 AsciiDoc 프로세서는 파일 내 텍스트가 UTF-8 인코딩을 사용한다고 가정합니다. UTF-16 인코딩은 파일 시작 부분에 BOM이 있는 경우만 지원됩니다.

AsciiDoc 프로세서는 문자열(즉, 문자 시퀀스) 형태의 AsciiDoc도 처리할 수 있습니다. 하지만 대부분의 경우 AsciiDoc 문서를 파일로 저장할 것입니다.


=== Key Concepts

이 페이지는 AsciiDoc을 배우는 과정에서 접하게 될 몇 가지 개념과 용어를 소개합니다. 각 개념은 이 문서의 뒷부분에서 자세히 다룰 예정입니다. 이 페이지를 통해 관련 용어에 익숙해지는 데 활용해 보시기 바랍니다.


==== Document

문서는 AsciiDoc에서 최상위 블록 요소를 나타냅니다. 문서는 선택 사항인 문서 헤더와, a) 선택 사항인 서문이 앞에 붙은 하나 이상의 섹션, 또는 b) 최상위 블록만으로 구성된 순서로 이루어집니다.

문서는 문서 헤더를 사용해서 구성할 수 있습니다. 헤더는 그 자체로는 블록이 아니지만, 문서 제목이나 문서 속성 같은 메타데이터를 문서에 제공합니다.


==== Elements

요소는 문서 내에서 식별 가능하고, 참조 가능하며, 조합 가능한 콘텐츠 단위입니다. AsciiDoc 문서는 단순히 그 안에 포함된 모든 요소의 조합에 불과합니다.

요소는 유형의 계층 구조를 이루며, 한 요소가 특정 요소군의 특화된 형태일 수 있습니다. 예를 들어, 사이드바 블록은 블록 요소이므로 모든 블록 요소의 특성을 공유할 뿐만 아니라, 자체적인 특성도 일부 추가합니다.

요소에는 문서 자체, 섹션, 블록, 블록 매크로, 줄바꿈, 인라인 구문 및 매크로 등이 포함됩니다.

블록 요소는 다른 블록 요소의 위나 아래에 (줄 단위로) 수직으로 쌓입니다. 블록 요소는 일반적으로 단순히 ‘블록’ 이라 불립니다. 블록은 문서의 주요 트리 구조를 형성합니다.

인라인 요소는 블록 요소 내부 또는 그 속성 중 하나(예: 블록 제목)에 포함된 콘텐츠 구간입니다. 인라인 요소에는 서식이 적용된 텍스트(이탤릭체, 굵은체 등), 인라인 매크로, 요소 참조 등이 포함됩니다. 이런 요소들 사이의 빈 공간을 채우는 것은 대체되지 않은 텍스트입니다. 인라인 요소는 트리 구조보다 대체에 더 중점을 두기 때문에 블록 요소보다 구조화가 덜 되어 있습니다.

==== Attributes

속성은 AsciiDoc 언어에서 메타데이터를 저장하고 공개하는 데 사용되는 이름-값의 쌍입니다. 속성을 사용하면 구문을 조정하고, 동작을 제어하며, 스타일을 사용자 정의하고, 통합 기능을 활성화하거나 구성하거나, 인라인 대체 콘텐츠를 저장할 수 있습니다. 속성은 AsciiDoc을 다른 경량 마크업 언어와 확실히 차별화하는 요소입니다.

속성은 사실 추상적인 용어입니다. 속성은 문서 속성과 요소 속성이라는 두 가지 구체적인 분류로 나뉩니다.


===== Document attributes

문서 속성은 이름에서 알 수 있듯이 문서와 직접적으로 연관되어 있습니다. 이 속성은 실행 시 문서에 대한 정보를 내보내고, 프로세서의 동작을 제어하며, 재사용 가능한 값이나 구문을 저장하는 데 사용됩니다. 따라서 문서 속성은 프로세서와의 일종의 양방향 통신 채널 역할을 합니다.

문서 속성은 속성 참조를 사용해서 콘텐츠 내에서 참조할 수 있습니다(속성 대체가 활성화된 곳이라면 어디에서나). 문서 속성은 문서 내의 속성 항목(일반적으로 문서 헤더)을 통해 정의하거나, API 또는 CLI를 통해 정의할 수 있습니다. 모든 문서 속성을 수정할 수 있는 것은 아닙니다.


===== Element attributes

요소 속성은 블록이나 인라인 요소 같은 특정 요소에 대한 메타데이터입니다. 이들은 속성 목록에 정의되며 해당 요소에만 적용됩니다. 속성 목록의 위치는 요소에 따라 다릅니다. 속성 이름은 문자열(즉, 명명된 속성)이거나 암시적인 숫자 인덱스(즉, 이름이 없는 위치 기반 속성)일 수 있습니다.

문서 속성과 달리, 요소 속성은 문서 모델 상에서 콘텐츠 내에서 직접 참조할 수 없습니다. 즉, 속성 참조를 사용해서 해결할 수 없습니다. 요소 속성은 역할 적용이나 이미지의 너비 설정 같이 요소의 동작을 보강하거나 구성하는 역할을 합니다. 요소 속성은 요소의 속성 목록이나 블록 제목 줄 같은 사용 가능한 약식 표기법을 사용해서 정의됩니다.


==== Macros

이 문서를 읽다 보면 ‘매크로’ 라는 용어가 자주 등장하는 것을 보게 될 것입니다. 매크로는 비-텍스트 요소를 나타내거나, 제공된 메타데이터를 사용해서 텍스트로 확장되는 구문을 의미합니다. 이 용어의 의미에 대해 더 자세히 알아보려면 ‘매크로’ 항목을 참조합니다.

다음은 블록 매크로의 예시입니다:

 image::sunset.jpg[Sunset]
 
다음은 인라인 매크로의 예시입니다:

 Click the button with the image:star.png[Star] to favorite the project.

매크로는 함수와 비슷하다고 생각할 수 있습니다. 매크로 구문은 이름, 때로는 생략될 수 있는 대상(target), 그리고 대괄호로 묶인 0개 이상의 요소 속성으로 구성된 속성 목록의 형식을 따릅니다.

매크로는 블록 매크로와 인라인 매크로, 두 가지 유형이 있습니다. 블록 매크로는 이름과 대상이 두 개의 콜론(`::`)으로 구분되며, 반드시 별도의 줄에 위치해야 합니다. 인라인 매크로의 경우, 이름과 대상은 콜론(`:`) 하나로 구분되며, 텍스트나 다른 인라인 요소와 나란히 배치될 수 있습니다. 블록 매크로는 항상 구문 분석되는 반면, 인라인 매크로는 매크로 대체가 활성화된 위치에서만 구문 분석됩니다.


==== Preprocessor direct

AsciiDoc은 블록 매크로와 비슷해 보이지만, 실제로는 다른 구문이 하나 더 있습니다. 바로 전처리기 지시문입니다.

전처리기 지시문은 파서로 전달되는 줄을 제어하는 기능입니다. 조건부 전처리기 지시문은 속성의 유무(ifdef, ifndef)나 다른 임의의 조건(ifeval)에 따라 포함되거나 제외될 줄을 설정할 수 있습니다. 인클루드 지시어는 다른 문서에서 가져온 추가 줄을 문서에 삽입할 수 있습니다.

전처리기 지시어는 블록 매크로와 공통된 특징을 가지고 있습니다. 블록 매크로와 마찬가지로, 전처리기 지시어는 반드시 단독 줄에 위치해야 합니다. 전처리기 지시어는 문서 속성에 접근할 수 있지만, 그 외에는 주변 문맥을 인식하지 못합니다. 이는 단지 줄 단위로 처리하는 기능일 뿐입니다. 블록 매크로와 마찬가지로, 인클루드 지시어도 요소 속성을 지정할 수 있지만, 이런 속성은 전처리 작업 자체에만 적용됩니다.
