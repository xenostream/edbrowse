# Chapter 0: Introduction

이 점에 대해 아주 분명히 말씀드리겠습니다. `ed(1)` 는 표준 유닉스 텍스트 편집기입니다. 유닉스의 공동 창시자인 데니스 리치(*Dennis Ritchie*)가 그렇게 선언했습니다. <ruby>유리 텔레타이프<rt>glass teletype</rt></ruby>를 사용하지 않고도 완전한 운영 체제를 작성할 수 있는 사람에게 누가 감히 이의를 제기할 수 있겠습니까? [^1]

많은 젊은 시스템 관리자들은 순진하게도 깃발을 휘날리며 `ex`, `vi` 심지어 도저히 감당할 수 없을 정도로 부풀려진 `nvi` 같은 과장되고, 지나치게 복잡하며, 과도하게 설계된 텍스트 편집기를 옹호합니다. 일부는 `vim` 이나 `Emacs` 처럼 일반 사용자를 위해 만들어진 복잡하고 난해한 편집기에 몰두할 정도로 방향을 잃기도 합니다. 

이런 행보는 끔찍한 시스템 관리 능력뿐만 아니라 도덕적 기백의 결여를 의미합니다. 시스템 관리자로서 여러분은 자신이 무엇을 입력했는지 기억하고, 머릿속에서 작업 맥락을 파악하며, 깊고 개인적인 차원에서 기계와 진정으로 소통할 수 있을 만큼의 두뇌 능력을 갖추어야 합니다.

대부분의 유닉스 호스트는 데이터베이스 지원이나 웹 페이지 제공 같은 실제 업무를 수행하기 위해 존재합니다. 시스템의 메모리, 프로세서, 디스크 I/O 사양을 결정할 때, 여러분은 이러한 작업을 실행하는 데 필요한 하드웨어의 양을 고려했을 겁니다. 그 이상으로 할당된 시스템 자원은 비정상적인 피크 부하를 지원하기 위한 것이지, 한심할 정도로 과도하게 설계된 텍스트 편집기를 위한 것이 아닙니다. 화려한 편집기를 실행하기 위해 여분의 킬로바이트—혹은 더 나쁘게는 메가바이트—를 낭비한다면, 호스트의 자원을 훔치는 것입니다.

`vim` 같은 것에 의존하는 시스템 관리자들? 그들은 시스템에 적극적으로 해를 끼칩니다. 그들을 믿지 마십시오.

[^1]: 아시다시피, 유리 텔레타이프 말이에요. 아이들이 계속 "모니터" 라고 부르는 그 장난감 말이에요. 사실 우리 모두 모니터가 오디오 제작에 쓰이는 참조용 스피커라는 건 다 알고 있지만요...

일반 사용자는 `ed` 를 사용할 줄 모른다고 해서 부끄러워할 필요는 없습니다. 저는 네이비 씰이 될 자격이 없습니다. 해변에 누워서 짖는 그런 종류의 물개조차 될 자격이 없죠. 괜찮습니다. 세상에는 컴퓨터가 넘쳐납니다. ed가 주는 순수한 위대함을 감당할 수 없다면, 그 친근한 '클릭 한 번으로' 작동하는 시스템 중 하나를 사용하세요. 그 시스템들은 바로 당신을 위해 존재합니다. 다만 키보드가 없는 태블릿 컴퓨터를 추천합니다. 밝고 다채로운 아이콘들이 배울 의지가 없는 사람들에게는 매우 유용하기 때문이죠.

ed(1)를 사용하는 것이 시스템 관리의 정점이라기보다는, 최소한의 필수 요건일 뿐입니다. 이 컴퓨터를 관리하려면 적어도 이 정도의 역량은 갖춰야 합니다. 이 책을 읽고 계신다면, 여러분이 엘리트 대열에 합류하고 싶기 때문일 겁니다. 정보 기술 분야의 네이비 씰(Navy SEALs) 대원 중 한 명으로 이름을 올리고 싶으실 테니까요.

여러분은 "모니터" 같은 화려한 장난감이 필요한 가짜들이 아니라, 진정한 시스템 관리자가 되고 싶은 겁니다. 네, 저도 모니터를 가지고 있지만, 그건 이 빈약한 현대식 노트북에 라인 프린터가 내장되어 있지 않기 때문일 뿐입니다. 진정한 시스템 관리자는 일할 수 있을 뿐만 아니라, 오로지 자신의 재치와 라인 프린터만으로 진정으로 빛을 발합니다. 우리와 함께할 자격이 있음을 입증하는 분이라면 누구든 환영합니다.

이 책은 "표준 ed" 를 다룹니다. 많은 운영 체제 개발자들은 ed에 추가 기능을 더하고 싶은 유혹을 참지 못합니다. 결국, ex와 vi의 비극도 그렇게 일어난 것이니까요. 이러한 개발자들이 ed 같은 중대한 프로젝트의 일원이 되고자 하는 욕구는 충분히 이해할 수 있지만, ed는 이미 기능이 완성된 상태입니다. 이 책에서는 리눅스의 x 및 y 명령어나 FreeBSD의 암호화 지원과 같은 OS별 확장 기능은 다루지 않을 것입니다.[^2]

[^2]: ed에 왜 암호화 기능을 추가해야 하나요? 그건 crypt(1) 이 하는 일입니다.

하지만 한 가지 경고해 드릴게요. 일부 시스템 관리자들은 이 책을 반대합니다. 그들은 최고의 시스템 관리자가 운영 체제 소스 코드를 연구하거나, 최악의 경우 매뉴얼 페이지를 읽으면서 배운다고 진심으로 믿고 있습니다. 하지만 그들 중 상당수는 자신의 젊은 시절을 잊고 있습니다. 컴퓨터를 혼자서 배울 수는 없습니다. 아무리 현명한 유닉스 관리자라도 멘토가 있었으니까요.

검색 엔진 알고리즘이 허술하게 짜여진 HOWTO를 샅샅이 뒤져 권위있는 문서인 양 내세우는 이 암울한 시대에, 차세대 시스템 관리자들을 양성하는 일은 우리 직업이 마주한 가장 중요한 과제 중 하나입니다. 저는 제 퇴직 자금을 저장하고 있는 서버가, ex(1)의 난해함에 허우적대는 소위 시스템 관리자들에게 맡겨지기를 원치 않습니다. 이 책을 곁에 두고 ed(1) 소스 코드를 연구하되, 저명한 브라이언 커니건(Brian Kernighan)과 데니스 리치(Dennis Ritchie)가 저술한 1978년판 『C 프로그래밍 언어(The C Programming Language)』 같은
훌륭한 C 언어 참고서와의 병행 학습을 권장합니다. 그들이 출력 장치로 라인 프린터만을 사용해서 완전한 운영 체제를 작성할 수 있었다면, 여러분도 자신의 사소한 작업 정도는 충분히 처리할 수 있을 겁니다.

자신의 한계를 뛰어넘어 제대로 된 시스템 관리자가 되려는 시도를 비하하는 사람은 오직 멍청이 뿐입니다. 안타깝게도 사회적 편견 때문에, 이 책을 소장하고 있다는 사실을 소중한 비밀로 간직하더라도 당신을 탓할 수는 없습니다. 필요하다면, 가장 가까운 Gopher 사이트에서 갈색 종이 봉투로 보호용 책 커버를 만드는 방법을 알아볼 수 있습니다. 진정한 시스템 관리자는 컴퓨터가 어떻게 작동하는지 이해합니다. 우리는 오랫동안 찾아 헤매던 "What You See Is What You Get" (WYSIWYG) 편집기가 마케팅 부서가 지어낸 해로운 거짓말에 불과하단 것을 잘 알고 있습니다. 우리는 .txt 로 끝나는 파일이 반드시 텍스트 파일은 아니며, 사실 텍스트 파일은 어떤 이름이든 가질 수 있다는 사실을 뼈속 깊이 잘 알고 있습니다. 이러한 속임수를 초월하는 것은 진정한 시스템 관리자 경지에 도달하기 위한 필수적인 단계입니다. 표준 유닉스 편집기는 텍스트를 조작하는 도구 그 이상도 이하도 아니라고 솔직하게 인정합니다. 그리고 그 도구는 정말 훌륭합니다.




# Chapter 1: Ed Essentials

본질적으로 ed(1) 는 텍스트 편집기입니다. 하지만 이 프로그램은 컴퓨터에 모니터가 없던 시절에 개발되었습니다. 당시 컴퓨터는 테이프나 프린터에 데이터를 출력할 수 있었습니다. 다만 그 당시 프린터들은 한 번에 종이 한 장 전체를 낭비하듯 출력하지는 않았습니다. 티커 테이프 기계나 타자기와 마찬가지로, 이 줄 단위 프린터들은 한 번에 한 줄씩만 출력했습니다.

시스템 관리자는 명령어를 입력하고, 필요한 경우만 결과를 출력했습니다. 혹은, 여러분이 원한다면, 생각이 끊어질 때마다 삐걱거리는 프린터 소리가 들리는 범위 내의 모든 사람에게 알려주기도 했습니다. 진정한
시스템 관리자는 업무에 집중하고 맥락을 기억할 수 있습니다.

ed는 줄 단위 편집기입니다!프린터로 출력되는 것처럼 텍스트 줄 단위로 작동합니다. 만약 운이 나빠서 그 신기한 "모니터" 라는 것을 써야 한다면, ed는 그 모니터에도 완벽하게 작동할 겁니다.

이제 몇 가지 기본적인 작업 즉, 프로그램 시작, 모드 확인, 저장, 종료 등을 통해 ed를 살펴보기 시작하겠습니다.

## Starting Ed

'ed' 와 편집하려는 파일 이름을 입력해서 ed(1)를 실행합니다.

여기서는 제가 가장 좋아하는 시인 루이스 캐롤의 '재버워키' 가 담긴 텍스트 파일을 편집해 보겠습니다.

```
$ ed jabberwocky.poem
963
```

숫자 963 은 시 어디에도 나타나지 않습니다!! 왜 여기에 있는 걸까요?

파일을 편집할 때, ed는 파일 전체를 메모리 버퍼로 읽어옵니다. 메모리에 있는 다른 모든 것과 마찬가지로 버퍼는 시스템이 종료되거나 프로그램이 종료되면 모두 사라집니다. 파일을 편집할 때, 여러분은 버퍼에 있는 사본을 변경하는 것입니다. 어느 시점에서 버퍼의 내용을 원본 파일에 덮어쓸 수도 있는데 이를 "변경 사항 저장" 이라고도 합니다. 버퍼의 내용을 다른 파일이나 새 파일에 쓸 수도 있습니다. 이처럼 ed를 시작하면 버퍼에서 읽어 들인 바이트 수를 알려줍니다. 실제 소프트웨어는 필요한 만큼만 메모리를 사용한다는 점을 기억하세요.

그렇다면 텍스트는 어디에 있을까요? 이것이 바로 여러분의 파일입니다. 그 안에 무엇이 들어있는지 이미 잘 알고 계시지 않나요? 파일을 열 때마다 자동으로 인쇄되는 종이를 몇 줄로 인해 낭비하고 싶진 않으시겠죠? 다음 번에는 파일을 편집기로 불러오기 전에 `head(1)` 명령을 사용해서 파일 내용을 살짝 확인하거나 이전 인쇄물을 뒤져 해당 파일을 찾아보시기 바랍니다.

## Commands and Modes

ed는 명령어 기반 프로그램으로 좀 더 멋지게 표현하면 텍스트 편집용 셸입니다. ed 명령 프롬프트에서 명령어를 입력합니다. 지금 <kbd>Enter</kbd> 키를 눌러 직접 시도합니다.

```
↵
?
```

ed는 단 하나의 오류 메시지를 가지는데 바로 물음표 문자 하나입니다. 이는 "무슨 뜻인지 모르겠습니다!" 라는 의미입니다. 오류 메시지가 나타나면 입력한 명령을 잘 살펴보고 무엇이 잘못된지 파악합니다. 현재 `ENTER` 는 유효한 ed 명령어가 아닙니다. 모든 ed 명령어는 문자, 숫자 그리고 표준 키보드 기호로 구성됩니다. [^3]

[^3]: 물론 Ed는 UTF-8 을 지원합니다. 이모지를 처리할 순 있지만 그렇게 하면 nano 를 사용하는 것만큼이나 여러분의 불멸의 영혼을 위태롭게 만듭니다.

`h` 명령어는 ed에게 마지막 오류에 대한 설명을 요청합니다. 상세 오류 메시지 표시가 꺼진 상태에서 `ENTER` 를 다시 입력한 다음 `h` 로 오류 설명을 확인합니다.

```
?
h
invalid address
```

이제 모든 것이 완벽하게 명확해졌나요? 아마 그렇지 않겠지만 주소(*address*)는 10장에서 다룰 예정입니다.

잉크 예산에 제한이 없다면 상세 오류 메시지를 활성화할 수 있습니다. `H` (대문자)를 단독 입력해서 상세 오류 메시지를 켜거나 끕니다.

```
H
Invalid address
```

Ed는 사용자의 명령을 프린터로 전송합니다. 이제 다시 `ENTER` 키를 누릅니다.

```
↵
?
invalid address
```

기본적으로 상세 오류 메시지를 켜두면 종이도 낭비되고 읽는 시간도 낭비되지만 우리 모두는 무엇을 잘못했는지 알아내려고 명령어를 오랫동안 뚫어지게 쳐다본 경험이 한 번쯤 있을 것입니다. 누구나 배울 때는 도움이 필요합니다.

유용하게 사용할 수 있는 또 다른 명령은 명령 프롬프트를 켜고 끄는 것입니다. ed의 명령 프롬프트는 별표(`*`) 하나입니다. 이 기능은 예전 출력물을 검토하면서 자신의 명령을 확인해야 할 때나, 비디오 터미널이 장착된 고급 시스템을 사용할 때 유용합니다. `P` (대문자)를 입력해서 명령 프롬프트를 켜거나 끕니다.

```
P
```

비디오 터미널을 사용할 경우 명령 프롬프트는 곧바로 표시됩니다. 프린터 사용자는 다음 명령을 입력할 줄에 명령 프롬프트가 나타납니다.

ed 명령은 하나씩 입력합니다. 정규 표현식(101장) 같은 일부 명령은 매우 복잡하고 수많은 문자를 포함할 수도 있지만 각 명령은 별도의 줄에 입력해야 합니다.

여기선 자세한 오류 메시지와 명령 프롬프트를 동시에 켜보겠습니다.

```
HP
?
```

또 ed를 혼란스럽게 만들었습니다. 자세한 내용을 확인합니다.

```
h
invalid command suffix
```

ed는 제가 `H` 명령어를 사용하면서 `P` 접미사를 추가한 것으로 감지합니다. ed 명령어의 접미사는 명령줄 인자와 유사하며 명령어를 수정하는 역할을 합니다. `H` 명령어는 `P` 를 접미사로 허용하지 않으므로 ed는 오류 메시지를 뱉어내면서 여러분을 무능하다고 선언합니다. 

대신, 각 명령어를 따로 입력합니다.

```
$ ed jabberwocky.poem
963
H
P
*
```

이제 자세한 오류 메시지와 명령 프롬프트가 표시됩니다. 여러분은 지금 막 ed를 배우는 단계이므로 이 책에 나오는 예제 중 상당수는 자세한 오류 메시지와 명령 프롬프트를 표시한 후 실행합니다. 잉크를 낭비하는 셈이지만 여러분에겐 그럴 가치가 충분합니다.

`q` 명령으로 ed를 종료합니다.

```
*q
```

`-p` 옵션으로 ed를 시작할 때 대체 프롬프트를 설정합니다.

```
ed -p# jabberwocky
```

특히 `-p` 와 프롬프트 사이에 공백을 넣은 경우 프롬프트를 따옴표로 묶어야 할 수도 있습니다. 그렇지 않으면 `*` 나 `>`  같이 셸에서 특별한 의미를 갖는 문자로 인해 문제가 발생할 수 있습니다. 이해를 돕기 위해 `ed -p * jabberwocky.poem` 을 실행하고 어떤 결과가 나오는지 확인합니다. 그렇지 않다면 프롬프트를 항상 따옴표로 묶습니다.

```
$ ed -p '>' jabberwocky.poem
963
>
```

모든 명령은 명령 모드에서 실행됩니다. 따라서 텍스트를 추가하려면 입력 모드로 전환해야 합니다.


##  Switching Modes

명령 모드는 텍스트 편집기 명령을 실행할 때 사용되는 반면, 입력 모드는 파일에 텍스트를 추가할 수 있게 해줍니다. 여기서는 빈 파일인 *todo* 를 엽니다. 이 파일은 현재 존재하지 않으므로 다음과 같이 오류 메세지를 표시합니다.

```
$ ed todo
todo: No such file or directory
```

Ed는 삽입 모드로 진입하는 세 가지 방법, 즉 추가(`a`), 현재 줄 앞에 삽입(`i`), 현재 줄 변경(`c`) 명령을 지원합니다. 변경 명령은 10장에서 다루겠습니다.

`a` 명령어로 추가(입력) 모드로 들어갑니다. 추가 모드는 커서를 현재 줄 바로 다음의 새 줄에 위치시킵니다. 현재 이 파일은 비어 있으므로 커서는 파일 끝으로 이동합니다. 입력하는 모든 내용은 파일에 그대로 추가됩니다. 

`Enter` 키를 눌러 다음 줄로 이동합니다. 여기서는 오늘의 할 일 목록을 이 파일 끝에 추가해 보겠습니다.

```
*a
식료품 사기
자본주의 억제하기
쥐 우리 청소하기
```

이 모든 것을 해낼 수 있다면 오늘은 좋은 날이 될 것입니다. 

삽입 모드와 추가 모드를 종료하고 명령 모드로 돌아가려면 한 줄에 마침표만 입력합니다.

```
.
```

`i` 명령어를 사용하면 현재 줄 앞에 텍스트를 삽입할 수 있습니다. 이를 위해서는 현재 줄을 선택해야 하는데 이에 대해서는 10장에서 다루겠습니다. 마찬가지로, `c` 명령어로 기존 줄을 선택하고 내용을 변경할 수도 있습니다.

명령을 입력하는 도중 실수를 했다면 `CTRL-C` 를 누르면 명령은 중단되고 명령 모드 프롬프트로 돌아갑니다.

이제 버퍼에 할 일 목록이 들어 있습니다. 이를 디스크에 저장하는 것이 좋을 것입니다.


## Saving and Exiting

`w` 명령어로 버퍼를 파일에 기록합니다. (다른 파일에 저장하는 방법은 100장에서 다루겠습니다.) ed는 기록(저장)한 바이트 수를 표시합니다. 저장이 끝나면 `q` 명령어로 ed를 종료합니다. 

할 일 목록을 만드는 전체 ed 편집 세션은 다음과 같습니다.

```
$ ed todo
0
P
*a
식료품 사기
자본주의 억제하기
쥐 우리 청소하기
.
*w
67
*q
```

일반적으로 명령어는 결합할 수 없지만 쓰기 명령어와 종료 명령어는 결합할 수 있습니다.

```
*wq
```

종료하기 전에 실수로 파일을 저장하지 않으면 ed는 경고를 표시합니다.

```
*q
?
```

무슨 오류 메시지인지 확인합니다.

```
*h
warning: file modified
```

네, 파일을 저장하지 않았습니다. `q` 명령어를 한 번 더 입력하면 변경 내용을 버리고 저장하지 않은 채로 종료합니다. `Q` 를 사용하면 저장하지 않고 즉시 종료할 수 있습니다.

이제 줄 주소 지정 기능을 살펴보겠습니다.



# Chapter 10: Addresses

ed에서 "주소" 란 버퍼 내의 줄 번호를 의미합니다. 사용자가 입력하는 명령은 주소에 영향을 미칩니다. "delete address" 나 "insert after address 5" 같은 많은 명령이 주소 단위로 효과를 발휘합니다. ed에는 기본 위치인 '현재 주소' (*current line*)라는 개념이 있습니다. ed에 "현재 5번째 줄에서 작업 중" 이라 지정한 다음, 파일 내의 위치를 변경하거나, 내용을 추가하거나, 다른 방식으로 수정할 수 있습니다. ed는 주소를 적극적으로 활용합니다. 주소를 선택하고 설정하는 것은 ed를 사용하는 데 있어 매우 중요한 부분입니다.

캐롤의 시 `재버워키(*Jabberwocky*)` 가 담긴 파일을 예로 들어 주소를 시연해 보겠습니다. 대부분의 독자분들은 품위가 있고 가치있는 분들이시니 이 시를 잘 알고 계실 뿐만 아니라 외우기도 하셨으리라 확신하지만, 인문학 교육이 끔찍할 정도로 부족한 분들을 위해 부록 A에 시의 전문을 실었습니다. 

이 시는 단락 사이의 빈 줄을 포함해서 총 34 줄로 이루어져 있으므로 34개의 주소를 포함하고 있습니다. 몇몇 ed 명령어(전부는 아님)는 "주소 1 이전" 을 의미하는 "주소 0" 을 받아들일 수 있습니다.

많은 ed 명령어는 영향받을 주소들을 명령어 앞에 입력할 것으로 기대합니다. `4d` 나 `3,5c` 같은 명령어는 "이 줄들에 이 명령어를 실행하라!" 는 의미입니다. 이렇게 하면 가장 중요한 맥락을 취약한 뇌에서 가능한 한 빨리 컴퓨터로 옮겨 놓을 수 있습니다. 줄을 삭제한다는 것은 잘 알지만 머릿속에선 구체적인 줄들을 잊어버리기 쉬우므로 해당 줄들을 즉시 지정하는 것이 가장 좋습니다.

주소 하나만 있으면 "단일 주소를 의미" 합니다. 쉼표로 구분된 두 개의 밤위 주소는 시작 주소와 끝 주소를 나타내며 해당 주소와 그 사이의 모든 내용을 포함합니다.

주소를 설정하면 ed는 해당 줄을 항상 출력합니다!! 이 섹션의 이해를 돕기 위해 저는 ed를 시작할 때 `P` 및 `H` 명령어를 설정했습니다.


## Setting Your Address

파일을 처음 열면 현재 주소는 파일의 마지막 줄로 설정됩니다. `p` 명령어로 현재 주소의 내용을 프린터로(혹은, 좀 더 세련된 분이라면 모니터로) 출력합니다.

```
*p
And the mome raths outgrabe.
```

네, 이것은 'Jabberwocky' 의 마지막 줄입니다. 특수 기호 `$` 는 항상 파일의 마지막 줄을 가리킵니다. 주소를 줄 번호로 설정하려면 해당 번호를 입력합니다. 저는 『재버워키』 의 6번 줄을 보고 싶습니다.

```
*6
"Beware the Jabberwock, my son!
```

주소를 변경하면 ed는 자동으로 해당 주소의 줄을 출력합니다.

`+` 명령어로 주소를 한 줄씩 이동합니다.

```
*+
The jaws that bite, the claws that catch!
*+
Beware the Jubjub bird, and shun
*+
The frumious Bandersnatch!"
```
여러 줄을 건너뛰려면 `+` 명령어와 건너뛸 줄 수를 입력합니다. 이 부분은 연의 마지막 줄이며 뒤에 오는 빈 줄을 건너뛰고 싶으므로[^4] 다음을 입력해서 두 줄을 건너뜁니다.

[^4]: 파일에 "빈 줄이 있다!" 는 사실을 기억하는 것은 ed(1)을 제대로 활용하려면 반드시 해야할 일 중 하나입니다.

```
*+2
He took his vorpal sword in hand;
```
`–` 또는 `^` 명령어로 버퍼를 뒤로 이동합니다. (GNU ed는 무례하게 `^` 명령어를 제거해서 `-` 명령어만 남았습니다.) 숫자를 추가하면 그만큼의 줄 수만큼 뒤로 이동합니다.

```
*-
```

이전 줄은 현재 빈 줄입니다—하지만 이미 알고 있었죠. 그래서 앞으로 건너뛴 것입니다. 주소를 한 칸 더 뒤로 이동합니다.

```
*-
The frumious Bandersnatch!"
```

밴더스내치는 정말 기막힌 존재입니다.


## Finding Your Address

등호 명령어(`=`)는 주소를 출력합니다. 기본값은 버퍼의 마지막 주소입니다.

```
*=
34
```

이 버퍼의 길이는 총 34줄입니다.

마침표(`.`)는 "현재 주소" 를 나타냅니다. 현재 주소를 확인하려면 마침표와 등호를 입력합니다.

```
*.=
9
```

현재 주소는 9로 파일의 9번째 줄에 있습니다.

주소 `$` 는 파일의 마지막 줄을 나타냅니다. 이 기호는 주로 파일 끝으로 이동할 때 사용하지만 등호 명령어와 결합해서 파일의 줄 수를 명시적으로 나열할 수 있습니다.

```
*$=
34
*$
```

제 기억이 맞았습니다. 이 파일은 34줄입니다. 그리고 이제 파일 끝으로 이동했습니다.


## Address Ranges

Ed는 쉼표(`,`)와 세미콜론(`;`) 두 가지 주소 기호를 통해 여러 줄에 동시에 작업을 수행할 수 있습니다. 퍼센트(`%`) 문자는 파일 전체를 나타냅니다. 

쉼표는 그 자체로는 아무런 동작도 처리하지 않습니다. 즉, 현재 주소를 "파일 전체" 로 설정할 수는 없지만 다른 명령과 결합하면 파일 전체에 한 번에 작업을 수행할 수 있습니다. 여기서는 쉼표를 `p` 명령과 결합해서 파일 전체를 출력합니다.

```
*,p
'Twas brillig, and the slithy toves
Did gyre and gimble in the wabe:
All mimsy were the borogoves,
And the mome raths outgrabe.
"Beware the Jabberwock, my son!
The jaws that bite, the claws that catch!
Beware the Jubjub bird, and shun
The frumious Bandersnatch!"
…
```

이렇게 하면 종이를 엄청나게 낭비할 뿐만 아니라 라인 프린터 소리가 들리는 범위 내의 모든 사람이 당신이 복사본을 찾기 위해 롤 앞부분을 일일이 뒤져보는 게 너무 귀찮거나, 나무를 싫어한다는 사실을 알게 될 것입니다.

세미콜론은 `.,$` 와 마찬가지로 파일 끝을 가리키는 현재 주소를 나타냅니다. 파일의 마지막 9줄, 즉 시의 두 연을 표시한다고 가정합니다. 파일 길이는 총 34줄로 26번 줄부터 34번 줄까지 필요합니다. 현재 주소를 26으로 설정하고 나머지 파일을 프린터로 전송합니다.

```
*26
"And hast thou slain the Jabberwock?
*;p
"And hast thou slain the Jabberwock?
  Come to my arms, my beamish boy!
O frabjous day! Callooh! Callay!"
  He chortled in his joy.
'Twas brillig, and the slithy toves
  Did gyre and gimble in the wabe:
All mimsy were the borogoves,
  And the mome raths outgrabe.
```

네, 26번째 줄을 두 번 출력합니다! 하지만 이 모든 내용을 출력한 걸 보니 분명 나무를 싫어하시는 분이시군요.(tree-hater) 그러니 이건 오히려 당신 목적에 부합하는 셈이죠.

단일 주소를 주소 범위로 변경하면 현재 주소는 주소 범위의 마지막 주소로 설정됩니다.


## Relative Addresses

상대 주소로 줄에 접근할 수도 있습니다. "상대 주소" 란 현재 주소에서 앞뒤로 특정 줄 수만큼 떨어진 위치를 가리키며 더하기(`+`) 또는 빼기(`-`) 기호로 표시합니다. 이렇게 처리하는 여러 가지 타당한 이유가 있습니다.

```
*30
```

주소를 설정하니 ed가 내용을 보여줍니다—네 빈 줄입니다. 지금 시에서 정확히 어디에 있을까요?

```
*-2,+2p
O frabjous day! Callooh! Callay!"
  He chortled in his joy.

'Twas brillig, and the slithy toves
  Did gyre and gimble in the wabe:
```

아, 거기였군요. 네, `28,32p` 같은 명령어를 사용해도 동일한 결과를 얻을 수 있습니다.

상대 주소는 ed가 제공하는 수많은 사용자 친화적인 편리한 기능 중 하나일 뿐입니다.

마이너스나 플러스 기호 하나만 단독으로 사용하면 '1' 을 의미합니다. 따라서 `-p` 는 "이전 줄을 출력하라!" 는 뜻이며, `-+,+p` 는 현재 주소 양쪽에서 한 줄씩의 문맥을 출력합니다.


## Scrolling

스크롤 기능은 ed가 "모니터" 에 의존하는 사람들에게 도움을 주기 위해 어쩔 수 없이 제공하는 기능입니다. `z` 명령어는 ed에게 다음 주소부터 터미널이 허용하는 한도까지 스크롤(페이지 출력)하도록 지시합니다.

표준 터미널은 한 번에 24줄을 표시할 수 있습니다. 스크롤이 어떻게 작동하는지 살펴보겠습니다. Jabberwocky의 맨 위에서 시작합니다.

```
*1
'Twas brillig, and the slithy toves
```

Ed는 지정한 주소의 줄을 항상 출력합니다!! 이제 `z` 로 스크롤합니다.

```
*z
  Did gyre and gimble in the wabe:
All mimsy were the borogoves,
  And the mome raths outgrabe.
…
```

Ed는 2번째 줄부터 시작합니다. 이미 1번 줄을 봤고 방금 읽은 내용은 분명 기억하실 테니까요, 그렇죠? 출력은 터미널을 가득 채울 때까지 즉, 24줄에 걸쳐 계속됩니다.

```
He left it dead, and with its head
  He went galumphing back.
*
```

버퍼를 좀 더 보고 싶으신가요? `z` 키를 다시 누릅니다.

특정 줄부터 스크롤을 시작하려면 `z` 앞에 해당 줄의 주소를 입력합니다. 예를 들어, 1번째 줄부터 스크롤을 시작할 수 있습니다.

```
*1z
'Twas brillig, and the slithy toves
  Did gyre and gimble in the wabe:
…
```

줄 수를 줄여서 스크롤하려면 `z` 뒤에 표시할 줄 수를 입력합니다. 여기서는 '재버워키' 시의 세 번째 연을 스크롤합니다. 각 연은 4줄로 이루어져 있으며 그 뒤에 빈 줄 하나가 있습니다. 11번부터 14번까지의 주소, 즉 11번과 11번 다음의 세 개 주소를 표시합니다.

```
*11z3
He took his vorpal sword in hand;
  Long time the manxome foe he sought—
So rested he by the Tumtum tree
```

3절, 액자에 넣기 딱 좋네요!

`z` 명령어는 현재 위치를 마지막으로 표시한 줄로 변경(설정)합니다.


## Displaying Addresses

매우 긴 파일로 작업할 때는 각 줄의 주소가 표시된 마스터 사본을 인쇄하는 것이 유용할 수 있습니다. `n` 명령을 사용하면 각 줄 앞에 해당 줄의 주소를 표시합니다. `n` 명령을 사용할 때 명령어 앞에 쉼표로 구분해서 원하는 시작 주소와 종료 주소를 지정하면 선택한 줄만 이 명령을 적용할 수 있습니다.

```
*11,14n
11      He took his vorpal sword in hand;
12        Long time the manxome foe he sought—
13      So rested he by the Tumtum tree
14        And stood awhile in thought.
```

Ed의 현재 주소는 마지막으로 표시된 주소, 즉 여기서는 14번이 됩니다. 또는 파일 전체를 번호 순서대로 모두 출력할 수도 있습니다.

```
*,n
1       'Twas brillig, and the slithy toves
2         Did gyre and gimble in the wabe:
3       All mimsy were the borogoves,
4         And the mome raths outgrabe.
5
…
```

파일 정리를 마친 후에 이 작업을 진행합니다. 그렇지 않으면 아까운 종이를 낭비하게 됩니다.


## Viewing Trailing Space

텍스트 파일을 다룰 때 성가신 점 중 하나는 "공백 하나가 파일을 엉망으로 만들 수도 있다!" 는 것입니다. 텍스트 중간의 불필요한 공백이 있는 것은 쉽게 알아차릴 수 있지만 줄 끝의 불필요한 공백은 까다롭습니다. 어차피 프린터 헤드가 공백을 표현하려고 줄 끝을 지나치게 넘어가는지 지켜봐야 하는 상황은 피하고 싶을 테니까요. 

`n` 이나 `p` 뒤에 `l` 접미사를 사용하면 각 줄 끝에 `$` 기호를 넣을 수 있습니다. 여기서는 제 할 일 목록이 담긴 파일의 실제 공백을 확인하고 있습니다.

```
*,nl
1 목욕하기 $
2 비누로$
```

1행 끝에 불필요한 공백이 하나 있습니다.


## Bookmarks

긴 파일을 스크롤한다는 것은 특히 줄을 추가하거나 삭제할 때 번거로울 수 있습니다. Ed는 북마크로 파일 내의 특정 위치로 쉽게 이동할 수 있습니다. 북마크는 하나의 소문자로 이름이 지정되며 해당 문자를 사용해서 북마크 위치로 이동할 수 있습니다.

'Jabberwocky' 의 각 절 시작 부분에 북마크를 설정한다고 가정합니다. 북마크에 번호를 매길 순 없지만 7개의 절을 각각 a, b, c... g까지 명명할 수 있습니다. `k` 명령어로 북마크를 지정합니다.

```
*1
'Twas brillig, and the slithy toves
*ka
*6
"Beware the Jabberwock, my son!
*kb
…
```

5줄마다 북마크를 생성합니다. 북마크로 이동하려면 작은 따옴표와 북마크 문자를 사용합니다.

```
*'b
"Beware the Jabberwock, my son!
```

이제 파일을 자유롭게 넘나들 수 있 있으니 버퍼를 뒤섞어 보겠습니다.



# Chapter 11: Text Editing

Ed는 텍스트 파일을 수정하는 데 필요한 모든 기능이 포함되어 있습니다. 

간단한 예로 할 일 목록을 손보겠습니다. 줄을 삽입하거나, 줄을 합치거나, 텍스트 순서를 바꾸는 등 온갖 메뉴나 설정을 신경쓰지 않고 일상을 편안하게 이어갈 수 있습니다.


## Changing Lines

텍스트 편집기의 핵심 기능 중 하나는 기존 텍스트를 수정하는 것입니다. ed에서 이 작업은 편집할 줄을 (주소를 지정해서) 선택한 다음 내용을 변경하는 것을 의미합니다.

다음은 저의 할 일 목록입니다.

```
ed todo
67
H
P
*,p
식료품 사기
자본주의 억제하기
쥐 우리 청소하기
```

두 번째 줄은 틀렸습니다. 이 줄을 수정해야 하고 두 번째 줄과 세 번째 줄 사이에 새로운 항목을 추가해야 합니다. 

주소를 2번째 줄로 설정합니다.

```
*2
자본주의 억제하기
```

ed는 지정한 주소를 항상 출력합니다!! 네, 바로 제가 원하던 줄입니다. 변경(`c`) 명령으로 삽입 모드로 들어갑니다. 일반 삽입과 달리  `c` 명령은 기존 줄을 덮어씁니다.

```
*c
```

새로운 두 줄을 입력하고 `ENTER` 키를 누른 다음 또 다른 줄을 추가합니다. 줄에 마침표만 남긴 상태로 삽입 모드를 종료합니다.

```
자본주의 말살하기
사방에 무지개 조랑말
.
```

만약 제 ed 사용 실력에 완전한 믿음이 없다면 버퍼를 다시 확인합니다.

```
*,p
식료품 사기
자본주의 말살하기
사방에 무지개 조랑말
쥐 우리 청소하기
```

네, 맞습니다. 이제 `wq` 명령어로 할 일 목록을 저장합니다.


## Inserting Amidst the File

*append* (`a`) 명령어는 현재 주소 뒤에 줄을 추가합니다. *insert before* (`i`) 명령어는 현재 주소 앞에 새 줄을 삽입합니다. 어느 것을 사용할까요? 여러분이 달성하려는 바에 맞는 명령어를 사용하면 됩니다. 지금은 파일 맨 앞에 두 줄을 삽입하므로 주소를 1로 설정하고 `i` 명령어로 해당 주소 앞에 새 줄을 삽입합니다. `1` 명령어를 입력한 다음 `i` 를 입력할 수도 있지만, `i` 명령어에 주소를 함께 지정하는 것이 좀 더 간단합니다.

```
*1i
단두대에 투자하기
개인 섬으로 도망치기
.
```

이제 할 일 목록에는 여섯 가지 항목이 있습니다.

```
*,p
단두대에 투자하기
개인 섬으로 도망치기
식료품 사기
자본주의 말살하기
사방에 무지개 조랑말
쥐 우리 청소하기
```


## Moving Text

저는 할 일 목록을 위에서 아래로 처리합니다. 즉, 처리 순서가 중요하다는 뜻입니다. 아침에 차를 마시고 정신이 맑아지면, 개인 섬으로 도망친 뒤에는 식료품을 살 수 없다는 사실을 깨달을 겁니다. 음식을 챙겨가야만 합니다. 하지만 제가 '식료품 사기' 보다 먼저 '개인 섬으로 도망치기' 를 추가한 건 확실한 것 같습니다.

```
*1,3n
1       단두대에 투자하기
2       개인 섬으로 도망치기
3       식료품 사기
```

네, 제가 실수했네요. 새로운 항목을 1번 줄 앞에 삽입하는 대신, 1번 줄 뒤에 추가했어야 합니다. 다행히 ed는 `m` (이동)명령어가 있습니다. *move* 명령어는 명령어 앞뒤 주소를 모두 사용합니다!! 이동할 주소는 명령어 앞, 즉 왼쪽에 지정합니다. 해당 줄들은 오른쪽 주소 뒤, 즉 `m` 명령어 뒤에 삽입됩니다. 오른쪽 주소로 `0` 을 사용하면 해당 줄들을 파일 맨 위에 배치할 수 있습니다.

```
*3m1
```

3번 항목(식료품 사기)이 이제 1번 항목(단두대에 투자하기) 뒤에 표시되야 합니다. 다른데서 실수한 건 없나요? 전 숫자를 좋아하니까 주소 목록으로 보겠습니다.

```
*,n
1       단두대에 투자하기
2       식료품 사기
3       개인 섬으로 도망치기
4       자본주의 말살하기
5       사방에 무지개 조랑말
6       쥐 우리 청소하기
```

아니, 잠깐만요. 더러운 쥐들과 여행할 순 없지만, 우리 청소를 하기 전에 식료품을 사야합니다. 따라서 6번 항목을 2번 항목 뒤로 옮깁니다.

```
*6m2
*,n
1       단두대에 투자하기
2       식료품 사기
3       쥐 우리 청소하기
4       개인 섬으로 도망치기
5       자본주의 말살하기
6       사방에 무지개 조랑말
```

여전히 문제가 있습니다. 저는 저 자신을 잘 알기 때문입니다. 일명 "이 신기한 웹 장치로 이리저리 만지작거리는 것" 은 지루한 집안일보다 훨씬 더 재미있습니다. 2번과 3번 항목을 목록 맨 위로 옮겨야겠습니다. 1번 항목보다 앞선 위치로 목적지 주소로 0을 사용합니다.

```
*2,3m0
*,n
1       식료품 사기
2       쥐 우리 청소하기
3       단두대에 투자하기
4       개인 섬으로 도망치기
5       자본주의 말살하기
6       사방에 무지개 조랑말
```

네, 훨씬 더 낫습니다.

줄을 뒤쪽의 다른 줄 뒤로 옮길 때, ed는 명령을 실행한 시점의 현재 줄 번호를 사용합니다. 즉, 1번 줄을 12번 줄 뒤로 옮기면 모든 줄은 한 줄씩 위로 이동합니다. 맞습니다. 1번 줄이 12번 줄이 되는 것이지, 줄 번호를 재귀적으로 다시 매기는 것이 아닙니다.

이후의 이동 명령은 새로운 주소를 사용합니다. 여러 개의 이동 명령을 사용할 때는 이런 계산량을 줄이기 위해 버퍼 끝 부분부터 작업을 시작합니다.


## Deleting Lines

이건 꽤 야심찬 목록입니다. 오늘 내로 이 모든 걸 처리할 수 있을까요? 현실적으로 생각하면 일단 컴퓨터에서 이리저리 만지작거리기 시작하면 하루종일 이 편안한 의자에서 일어나지 못할 것임을 알고 있습니다. 따라서 프린터 앞에서 편안하게 쉬게 만들만한 항목들은 모두 없애는 게 최선입니다. 

`d` 명령어로 주소를 삭제합니다. 여기서는 3번째 줄을 삭제합니다.

```
*3d
```

줄 이동과 마찬가지로 쉼표로 구분해서 여러 줄을 지정할 수 있습니다. 버퍼에는 새로운 3번째 줄이 생겼습니다. 

파일의 서로 다른 부분에서 여러 줄을 삭제할 때는 끝부분부터 시작해서 거꾸로 진행하는 것이 좋습니다. 주소를 삭제하면 그 이후의 모든 줄의 주소가 한 칸씩 위로 이동합니다. 거꾸로 진행하면 번호를 다시 매기는 데 낭비되는 정신적인 노력을 줄일 수 있습니다.


## Undo

저도 다른 사람들과 마찬가지로 게으름을 피우곤 합니다. 할 일이 있을 때, 컴퓨터에서 일어나야 한다는 자제력을 기르도록 해야겠습니다. 방금 삭제한 항목을 다시 목록에 추가해야 합니다. 

`u` 명령어로 마지막 작업을 취소할 수 있습니다.

```
*u
```

Ed는 한 단계의 취소 기능만 있습니다. 이 기능은 취소 명령을 포함해서 가장 최근에 실행한 명령에 적용됩니다. 다시 실행하려면 취소한 작업을 다시 취소합니다. 즉, `u` 를 세 번 누르면 취소된 취소 작업을 되돌릴 수 있습니다. 이 줄을 삭제하고 다시 삽입하는 작업을 무한 반복할 수 있지만, 취소 기능은 줄 재배열을 되돌릴만큼 멀리까지 거슬러 올라가진 않습니다. 그 작업은 한 번 이상의 명령을 거슬러 올라가야 하기 때문입니다.

여러 줄에 영향을 미치는 정규식 연산(101장 참조)도 단일 명령으로 간주합니다. 이런 변경 사항들은 전체적으로 취소하거나 다시 실행해야 합니다.


## Inserting Text from Files

저는 매일 아침에 특정한 작업을 수행합니다. 편의를 위해 해당 항목들을 담은 별도의 파일을 만들었습니다. `r` 명령어로 다른 파일에서 내용을 읽어올 수 있습니다. 여기서는 *usualtodo* 파일을 읽어 주소 0 뒤에 넣겠습니다. 이 파일은 버퍼 맨 앞에 추가됩니다.

```
*0r usualtodo
24
```

21바이트를 읽었습니다. 이제 할일 목록은 어떻게 보일까요?

```
*,n
1       비누로
2       목욕하기
3       식료품 사기
4       쥐 우리 청소하기
5       단두대에 투자하기
6       개인 섬으로 도망치기
7       자본주의 말살하기
8       사방에 무지개 조랑말
```

훨씬 낫네요.


##  Joining Lines

잠깐만요, 할일 목록이 엉망입니다. 처음 두 항목은 하나로 합쳐져야 합니다. 혹시 ex(1) 같은 부피 큰 편집기를 만지작거리는 초보자가 제 파일에 캐리지 리턴을 삽입한 건가요? 책임있는 녀석은 나중에 처단하겠지만, 지금은 일단 `j` 명령어로 해당 줄들을 합쳐야 합니다. 합쳐친 주소들은 버퍼에서 삭제되고 그 내용 전체를 포함한 단일 줄로 대체됩니다.

`j` 명령어는 `n` 과 유사한 주소 지정 구문을 사용합니다. 줄들을 합치기 전에 합치려는 줄 번호를 다시 한 번 확인하는 것이 도움됩니다. 왜냐하면 줄을 합치는 것이 분리하는 것보다 훨씬 더 쉽습니다.

```
*1,2n
1       비누로
2       목욕하기
```

네, 이 줄들이 맞습니다. 이 줄들을 하나의 줄로 병합하고 결과를 다시 확인합니다.

```
*1,2j
*1,2n
1       비누로 목욕하기
2       식료품 사기
```

훨씬 낫습니다. Ed의 현재 주소는 병합된 줄의 주소로 변경됩니다. 이 경우는 1입니다.

10장에서 봤듯이 앞선 줄 끝엔 공백 하나가 있었습니다. 그 공백이 없었다면 단어들이 서로 붙어 있었을 것입니다. 누락된 공백을 수정하려면 해당 줄을 변경해야 합니다.

줄을 다시 나누려면 제110장에서 다루는 치환 명령어를 사용해야 합니다.


## Copying Lines

오늘은 정말 긴 하루가 될 것 같습니다. 하루가 끝나면 분명 목욕을 해야할 것 같습니다. 더 큰 문제는 애완용 쥐들이 외딴 섬으로 끌려간 뒤 분개할 거라는 점입니다. 그들의 우리를 청소해야 합니다. 하지만 할 일 목록 끝에 이 항목들을 일일이 수고스럽게 다시 입력하기보단 `t` (*transfer*) 명령어로 복사하겠습니다. 

복사하려는 주소(또는 주소 범위)를 명령어 앞에, 대상 위치를 뒤에 넣으면 됩니다. `t` 명령어는 마지막으로 복사한 줄의 주소를 현재 주소로 설정합니다.

방금 처음 두 줄을 합쳐서 파일의 주소를 다시 지정했으니 주소를 다시 확인합니다.

```
*1,3n
1       비누로 목욕하기
2       식료품 사기
3       쥐 우리 청소하기
```

좋습니다. 1번, 3번 항목을 목록 맨 아래로 복사해야 합니다. 제대로 씻고 잠자리에 들고 싶어서 "쥐 우리 청소하기" (주소 3)를 파일 맨 끝으로 복사합니다.

```
*3t$
```

이제 주소 1을 파일 끝으로 복사해서 목욕을 청소 이후에 배치할 수 있습니다.

```
*1t$
```

결과가 어떻게 나왔나요?

```
*,n
1       비누로 목욕하기
2       식료품 사기
3       쥐 우리 청소하기
4       단두대에 투자하기
5       개인 섬으로 도망치기
6       자본주의 말살하기
7       사방에 무지개 조랑말
8       쥐 우리 청소하기
9       비누로 목욕하기
```

할 일 목록을 모두 다 끝냈어요. 세상을 정복하는 일을 마치면 적어도 몸은 깨끗해지겠네요.

제가 주소를 버퍼 끝으로 복사했지만 여러분은 어디나 넣을 수 있습니다. 흥미로운 방법 중 하나는 마침표(`.`)로 현재 주소 바로 뒤에 해당 줄을 복사하는 것입니다. 이렇게 하면 줄은 두 개로 복제되고 현재 주소는 두 번째 복사본에 설정된 상태로 남습니다. 110장에서 보겠지만 원본을 건드리지 않고 복제된 줄에 작업을 수행할 수 있습니다.


## Appending Lines to Another File

`W` (대문자)명령어를 사용하면 버퍼에 있는 주소를 다른 파일에 추가할 수 있습니다. 포함할 줄들을 명령어 앞에 배치하고 추가할 파일 이름을 맨 뒤에 적습니다.

누구라도 할 일 목록의 모든 일을 끝내진 못합니다. 여기서는 끝내지 못한 일들을 내일 할 일 목록 맨 끝에 복사합니다.

```
*5,9W tomorrow-todo
133
```

내일은 좀 더 생산적인 하루가 되기를 바랍니다.

할 일 목록을 관리하는 정도는 간단한 편집과 재배열만으로 충분합니다. 하지만 때로는 텍스트 편집기가 운영 체제와 상호 작용할 수도 있습니다. 이에 대해서는 다음에서 다루겠습니다.



# Chapter 100: File Management and Shell Escapes

기존 파일을 여는 것도 좋지만 새 파일을 만들려면 어떻게 해야 할까요? 아니면 한 파일을 편집하다가 다른 파일로 전환할 때는요? 혹은 명령어의 출력 결과를 파일로 저장하고 싶을 수도 있겠죠? Ed를 사용하면 이 모든 작업은 물론 그 이상의 기능도 수행할 수 있습니다.

먼저 파일 조작부터 살펴본 다음 명령어에 대해 알아보겠습니다.


## The Empty Buffer

지금까지는 기존 파일을 편집하는 방식으로 ed를 사용했습니다. 하지만 파일을 지정하지 않고 ed를 단독 실행할 수 있습니다.

```
$ ed
H
P
*
```

이 경우 ed는 빈 버퍼를 제공합니다. 이제 빈 공간을 채워보겠습니다.

```
*i
?
invalid address
```

무슨 문제일까요? (gnu ed 버전에선 문제가 발생하지 않습니다)

삽입(`i`) 명령어는 현재 주소 바로 앞에 한 줄을 삽입한다는 점을 기억합니다. 지금은 빈 버퍼이므로 현재 주소는 무엇일까요? 추측할 수도 있겠지만 ed에게 직접 물어보면 알려줄 것입니다.

```
*.=
0
```

주소는 모두 양수입니다. 이 파일에는 앞에 새로운 항목을 삽입할만한 내용이 없습니다. 하지만 뒤에 추가할 수 있습니다. 이제 텍스트 몇 줄을 만들겠습니다.

```
*a
once upon a midnight dreary
while i pondered weak and weary
.
```

이제 텍스트가 생겼으니 파일을 저장합니다.

```
*w
?
no current filename
```

이건 또 무슨 새로운 지옥인가요?


## The Default Filename

ed는 사용자가 별도로 지정하지 않는 한, 현재 어떤 파일을 편집하는지 알지 못합니다. ed는 사용자가 버퍼 내용을 파일로 저장하길 원한다고 무턱대고 가정하지도 않습니다. 어쩌면 이 버퍼는 보안상 민감한 내용일 수도 있으며 전적으로 메모리에만 남아 있어야 할 수도 있기 때문입니다. 

기존 파일을 편집할 때, ed는 사용자가 변경 사항을 동일한 파일에 저장하길 원한다고 가정하지만 "기본 파일 이름" 을 변경해서 다른 파일에 기록할 수도 있도록 허용합니다. 기본 파일명은 ed가 버퍼를 쓰는 파일의 이름입니다. 파일을 열면 예상대로 기본 파일명은 해당 파일의 이름으로 지정됩니다. 하지만 파일명을 지정하지 않고 ed를 단독 실행하면 기본 파일명은 비어 있습니다. 

`f` 명령으로 파일명을 설정합니다. 여기서는 잘못 입력한 시가 담긴 버퍼를 가져와 파일 이름을 지정하고 저장합니다.

```
*f raven.poem
raven.poem
*wq
60
```

이 시를 좀 더 잘못 입력하고 싶을 때는 이 파일로 열어 번거로움을 덜 수 있습니다. 

`w` 명령어에 파일 이름을 지정하면 기본 파일 이름을 설정할 수 있습니다.

```
ed
H
P
*w empty
0
```

기본 파일 이름을 사용하면 버퍼를 다른 파일 이름으로 저장할 수 있습니다. 기능이 제한된 텍스트 편집기들은 이를 "다른 이름으로 저장" 기능으로 구현합니다. 

예를 들어, '재버워키' 의 서식을 정리한다고 가정합니다. 이 과정에서 텍스트가 어떻게든 손상되거나 원본보다 보기 흉한 결과물이 나올 가능성이 높으므로 파일의 복사본으로 작업하고 싶습니다. 

이제 기본 파일 이름을 변경하고 저장합니다.

```
*f jabberwocky-hackedup.poem
jabberwocky-hackedup.poem
*w
963
```

이로써 원본 파일을 손상시키지 않고 사본으로 마음대로 수정할 수 있습니다. 

Ed는 사용자가 시스템에 어떤 파일이 이미 존재하는지 알고 있다고 가정합니다. `w` 로 기존 파일에 쓰면 해당 파일의 내용은 덮어쓰여집니다. 파일 내용을 덮어쓰지 않고 끝에 내용을 추가하려면 `W` (대문자)를 사용합니다.


## Switching Files

왜? 다른 파일을 편집하려고 ed를 종료할까요? `e` (편집)명령어로 현재 작업 중인 파일을 전환합니다.

예를 들어, *Jabberwocky* 시의 서식을 보기 좋게 만들기 위해 수정하던 중, 할 일 목록에 항목을 추가한다고 가정합니다. 

`e` 명령어와 원하는 파일 이름으로 파일을 전환합니다.

```
*e todo
?
warning: file modified
```

Ed는 원본 파일을 변경했지만 "변경 내용을 저장하지 않았다!" 고 경고합니다. `w` 로 변경 내용을 파일에 저장하거나, `e` 를 연속 두 번 입력해서 "네, 버퍼를 버리고 새 파일을 열겠습니다!" 라고 지정해야 합니다. 여기서는 버퍼를 버리겠습니다.

```
*e todo
223
*a
Jabberwocky 서식 수정하기
.
*w
255
```

수정된 버퍼를 버리려는 숙련된 시스템 관리자는 확인 단계를 건너뛰기 위해 `E` (대문자)를 사용합니다.

```
*E todo
255
```

이제 할 일 목록이 업데이트되었습니다.


## Saving Part of the Buffer

현재 파일의 일부를 다른 파일에 저장할 수 있습니다. 이 경우 *write* (`w`) 명령에 주소(또는 범위)와 파일 이름을 지정합니다.

현재 할 일 목록 파일이 열려 있습니다. 평소 매일 아침 맨 처음 작성하는 일일 할 일 항목 템플릿이 들어 있는 파일이 손상되었습니다. 할 일 목록의 첫 번째 항목을 해당 파일로 보내서 손상된 버전을 수정된 버전으로 덮어쓰고 싶습니다. 

주소를 지정하고, `w` 명령어를 입력한 뒤 파일 이름을 지정합니다.

```
*1w usualtodo
23
```

이렇게 하면 주소 1, 즉 첫 번째 줄이 *usualtodo* 파일에 기록됩니다. 저장한 크기는 23바이트입니다.

또는, 제가 'Jabberwocky' 를 편집하고 있다고 가정합니다. 두 번째 절을 별도의 파일에 저장하고 싶습니다. 주소 6부터 9까지가 두 번째 절을 포함하고 있습니다. 

해당 주소 범위, *write* 명령어 그리고 파일 이름을 지정합니다.

```
*6,9w verse2.poem
139
```

시의 2절에 해당하는 139바이트가 *verse2.poem* 파일에 기록됩니다. 이처럼 버퍼의 일부를 파일에 기록해도 현재 주소는 변경되지 않습니다.


## Shell Escapes

운영 체제에서 IP 주소나 파일 이름 등 다양한 정보를 가져올 때가 있습니다. 세부 사항을 확인하기 위해 편집기를 잠시 떠났다가 다시 편집기를 실행해서 현재 위치로 돌아오는 것은 성가실 뿐만 아니라 비효율적입니다. 바로 이때 셸 이스케이프가 유용합니다.

셸 이스케이프는 ed 외부에서 단일 쉘 명령을 실행하고 출력 결과를 표시한 다음 다시 편집기로 돌아옵니다. 이렇게 하면 명령어의 출력이 표시됩니다. ed는 느낌표(`!`)로 셸 이스케이프를 실행합니다.

현재 호스트에 대한 시스템 관리 문서를 작성하는데 IP 주소를 알아야 한다고 가정합니다. 모든 가상 인터페이스가 아니라 em0만 확인하고 싶습니다. `ifconfig(8)` 로 해당 정보를 얻습니다. [^5]

[^5]: 진정한 Unix에는 `ifconfig` 와 `ed` 편집기가 기본으로 포함되어 있습니다.

```
*! ifconfig em0
em0: flags=8843<UP,BROADCAST,RUNNING,SIMPLEX,MULTICAST> mtu 1500
lladdr 08:00:27:03:eb:10
index 1 priority 0 llprio 3
groups: egress
media: Ethernet autoselect (1000baseT full-duplex)
status: active
inet 203.0.113.209 netmask 0xffffff00 broadcast 203.0.113.255
```

이 호스트의 IP 주소는 203.0.113.209입니다. 이제 문서에서 이 IP 주소를 참조할 수 있습니다.

때로는 셸 명령을 재실행할 때가 있습니다. ed는 마지막으로 실행한 셸 명령을 기억하므로 `!!` 명령으로 재실행할 수 있습니다.

```
* !!
ifconfig em0
em0: flags=8843<UP,BROADCAST,RUNNING,SIMPLEX,MULTICAST> mtu 1500
...
```

혹시 잊어버렸을 경우를 대비해서 명령어를 다시 표시합니다. 

때로는 명령어의 출력 결과를 파일로 읽어올 때가 있습니다. `r` 명령어는 다른 파일을 현재 버퍼로 읽어들이는 것과 마찬가지로 셸 이스케이프의 출력 결과를 파일로 읽어들이는 데 사용할 수 있습니다.

```
*r !ifconfig em0
267
```

267바이트가 읽어졌습니다. 파일 내용을 확인해 보면 명령어의 출력이 표시된 것을 볼 수 있습니다.

```
*,n
1 em0: flags=8843<UP,BROADCAST,RUNNING,SIMPLEX,MULTICAST> mtu 1500
2 lladdr 08:00:27:03:eb:10
3 index 1 priority 0 llprio 3
…
```

Ed는 일반적으로 쉘 이스케이프에서 나온 출력을 버퍼의 끝에 추가합니다. 출력을 다른 곳에 넣으려면 명령어 앞에 삽입할 주소를 지정합니다. 

다음과 같은 두 줄이 들어있는 파일을 가정합니다.

```
This is ifconfig
That was ifconfig
```

이 두 줄 사이, 즉 주소 1 뒤에 `ifconfig` 출력 결과를 삽입하고 싶습니다.

```
*1r !ifconfig em0
267
```

확신이 서지 않으면 항상 버퍼를 확인합니다.

```
*,p
This is ifconfig
em0: flags=8843<UP,BROADCAST,RUNNING,SIMPLEX,MULTICAST> mtu 1500
…
That was ifconfig
```

네, 올바른 위치에 있습니다.


## Send to a Program

셸 이스케이프로 결과를 읽는 것도 좋지만 외부 프로그램의 표준 입력으로 내보낼 수도 있습니다. 이렇게 하면 버퍼 전체나 일부를 다른 프로그램에 전달할 수 있습니다. 예를 들어, 현재 파일에 단어가 몇 개나 있는지 세고 일일 단어 작성 목표를 달성했는지 확인할 수 있습니다. 

`ed(1)` 가 표준 텍스트 편집기인 것처럼 `wc(1)` 는 표준 텍스트 카운팅 도구입니다. 버퍼를 셸 이스케이프로 출력합니다.

```
*w !wc
       34       166       963
963
```

이 파일은 전체 34줄, 166단어, 963글자가 있습니다. 마지막 줄은 ed에서 출력한 것으로 몇 바이트를 썼는지 나타냅니다. 물론 이 값은 `wc(1)` 가 보고한 문자 수와 일치합니다.

오늘은 166단어라니? 서둘러 글을 써야겠네요!


## Starting with an Escape

아마 이 다음에 만들고 편집할 파일은 셸 명령의 출력 결과로 시작할 수도 있습니다. 작업 내용을 저장하고, ed를 종료한 뒤, ed를 재실행하고, 셸 명령을 실행할 수도 있습니다. 이 방법도 문제없지만 우아하지 않습니다.

`e` 명령어로 셸 이스케이프의 출력 결과로 미리 채워진 새 버퍼를 생성할 수 있습니다. 하지만 이 경우 기본 파일 이름이 변경되지 않습니다. 따라서 `f` 명령어로 파일 이름을 지정하거나, `w` 명령어와 파일 이름을 입력해서 버퍼를 저장할 새 파일을 설정해야 합니다.

```
*e !ifconfig
1049
*f ifconfig-full.txt
ifconfig-full.txt
*w
1049
```

첫 번째 명령어는 셸 이스케이프 `ifconfig` 를 실행하고 출력 결과를 읽어옵니다. 두 번째 명령어인 `f` 는 기본 파일 이름을 `ifconfig-full.txt` 로 설정합니다. 마지막으로 `w` 는 파일을 새로운 파일 이름으로 저장합니다.

`e` 명령어를 사용하지 않으려면 ed를 시작할 때 셸 이스케이프를 직접 사용할 수 있습니다. 복잡한 명령어는 따옴표로 묶어야 합니다.

```
$ ed !'ifconfig em0'
```

이제 원하는대로 파일을 마음껏 다룰 수 있습니다. 이제부터 정규 표현식으로 ed의 강력한 기능을 최대한 활용하겠습니다.



# Chapter 101: Regular Expressions and Searches

정규 표현식(`regex`)은 텍스트 패턴을 정의하는 문자열입니다. 일반적으로 텍스트 문자열과 일치하도록 만들어진 텍스트 문자열(패턴)을 말합니다. Ed는 버퍼에서 정규 표현식과 일치하는 텍스트를 검색해서 사용자에게 해당 부분을 표시하거나 패턴과 일치하는 모든 부분에 변환 작업을 수행할 수 있습니다.

정규 표현식은 검색과 텍스트 교체에 주로 사용됩니다. ed의 정규 표현식은 POSIX 같은 후대의 정규 표현식에 많은 영감을 주었습니다. 하지만 창시자인 ed는 POSIX의 불필요한 기능까지 지원할 필요를 느끼지 않습니다. 요즘 ed의 정규 표현식을 "기본 정규 표현식" (BRE)이라 부릅니다. 

다른 정규식 버전에 의해 부풀려진 불순한 ed 버전도 찾아볼 수 있지만 다시 말하지만 그런 것들은 정신력이 약한 사람들을 위한 것이며 관심가질 가치가 없습니다. 평판과 달리, 정규식을 본다해서 치유할 수 없는 광기에 빠지는 것은 아닙니다—여러분이 생각하는 그것은 "확장" 정규식입니다.

ed의 놀라운 검색 및 대체 기능을 사용하기 전에 우선 정규식을 만드는 방법을 이해해야 합니다.


## Regular Expression Format

일반적으로 (항상 그런 것은 아니지만) 정규 표현식은 슬래시 문자 사이에 위치합니다. Ed 문서에선 `re` 를 정규 표현식을 뚯하는 예로 사용하며 이는 `/re/` 로 표시합니다. 슬래시 사이에는 문자, 와일드카드, 문자 클래스, 이스케이프 처리된 문자 및 수정자(명령어)가 나타납니다.

단일 문자는 그 자체와 일치합니다. 만약, "t", "h", "e" 라는 글자를 순서대로 일치시키려면 `/the/` 같은 정규식을 사용합니다.

와일드카드는 점(`.`) 문자로 사용합니다. 이는 어떤 문자든 모두 일치시킵니다.

문자 클래스는 대괄호(`[]`)로 표시됩니다. 문자 클래스는 표현식에 나타날 수 있는 일련의 문자를 정의합니다. 이에 대해서는 이 장 후반부 "문자 클래스" 에서 자세히 다룰 것입니다.

에스케이프 문자를 사용하면 정규 표현식에서 특수한 목적을 가진 문자를 포함할 수 있습니다. 가장 대표적인 예는 정규 표현식에 슬래시 문자를 포함할 때입니다. 슬래시는 정규 표현식의 경계를 구분하는 데 사용하므로 `///` 같은 형식은 사용할 수 없습니다. 백슬래시(`\`)를 에스케이프 문자로 사용해서 해당 문자가 표현식의 특수 문자가 아닌 문자 그대로 처리되어야 함을 ed에게 알려야 합니다. 

에스케이프 처리된 백슬래시는 `\/` 같이 보이며 슬래시를 일치시키는 (정규) 표현식은 `/\//` 입니다. 마침표를 검색하려면 `\.` 을 사용하고, 대괄호는 `\[` 또는 `\]` 를 사용합니다. 

이처럼 에스케이프 문자를 사용하면 일반 문자를 특수 문자로 변환할 수 있는데 예를 들어 문자 카운트에 사용하는 중괄호나 역참조에 필요한 괄호 등이 있습니다.

어떤 것을 언제 사용할까요? 소스 코드를 읽어보면 모든 것이 완벽히 이해되겠지만 지금은 단지 고개를 끄덕이고 미소를 지으며 예제를 그대로 따라갑니다.

수정자(명령어)는 정규 표현식이 해석되는 방식을 변경합니다. 접미사는 가장 흔한 정규 표현식의 수정자로 마지막 슬래시 뒤에 위치합니다. 수정자 중 상당수는 명령어와 정확히 동일합니다. 예를 들어, `p` 는 정규 표현식에 일치하는 결과를 출력하고, `n` 은 일치하는 결과를 출력하고 줄 번호를 추가합니다.

이제 매우 인위적인 몇 가지 예제로 정규 표현식이 어떻게 작동하는지 살펴보겠습니다.


## Searching in Ed

문서에 특정 단어를 사용한 건 알지만 정확히 어딘지 기억나지 않는 경우가 너무 자주 있습니다. 파일 전체를 인쇄할 필요는 없습니다. ed를 사용하면 정규 표현식으로 단어를 검색할 수 있습니다. 

다음과 같은 단어 목록을 만듭니다—비슷한 단어도 많고, 그렇지 않은 단어도 있으며, 쉽게 설명할 수 있도록 주소(줄 번호)와 함께 표기했습니다.

```
*,n
1 the
2 their
3 then
4 Them
5 there
6 they're
7 thereafter
8 2
9 3weasels
10 4 theremin
11 /the/
12 pet rats
13 [pedicular]
14 hamster5
```

정규식이 포함된 슬래시(`/`) 쌍을 입력하면 ed는 정규 표현식과 일치하는 텍스트가 포함된 다음 줄(`.+1`)을 검색합니다.

예제는 매우 인위적이라고 미리 말씀드렸습니다. 이제 정규 표현식 `/the/` 를 검색합니다.

```
*/the/
the
*.=
1
*
```

버퍼 첫 번째 줄이 일치합니다. 검색 명령을 실행하면 현재 주소는 일치한 줄로 설정됩니다. 동일한 정규식을 앞으로 검색하려면 이중 슬래시를 입력합니다.

```
*//
their
```

좋습니다, 2번 줄입니다. 계속해서 주소를 물어볼 수도 있고 검색 명령어 뒤에 (수정자)명령어를 추가할 수도 있습니다. 줄 번호를 추가하는 `n` 명령어를 기억하시나요? 이 명령어는 수정자로 작동합니다.

```
*//n
3 then
*//n
5 there
```

잠깐만요—4번 줄은 어떻게 된건가요? 파일을 보니 "Them" 단어에 "the" 가 포함되어 있습니다. 일치해야 하지 않나요? 아니요, 절대 일치하지 않습니다. "Them" 은 대문자로 시작합니다. 정규 표현식은 문자 그대로의 소문자 'the' 만 (정확히) 일치시킵니다. 대소문자를 구분하지 않는 검색을 수행하려면 문자 클래스를 사용해야 합니다.

하지만 버퍼를 이렇게 한 줄씩 훑어보는 건 매우 지루합니다. 검색어 앞에 `g` 명령어를 사용해서 정규 표현식을 버퍼 전체 범위에서 전역적으로 검색합니다. 정규식은 `g` 바로 뒤에 입력합니다. 모든 일치 항목을 출력하려면 수정자로 `p` 를 끝에 추가합니다.

여기서는 "re" 라는 문자열, 즉 정규식 `/re/` 를 전체 버퍼에서 검색하고 결과를 출력합니다.

```
*g/re/p
there
they're
thereafter
4 theremin
```

`p` (수정자)명령어는 검색 명령의 기본 동작으로 생략할 수 있습니다. 별도로 지정하지 않는 한 검색 결과는 자동 출력됩니다. 하지만 이 예제가 새로 등장한 `grep(1)` 명령어가 어디서 유래한지 설명하지 못하겠죠? 

만약 "re" 를 검색하면서 줄 번호를 함께 출력하려면 `p` 대신 `n` 수정자를 사용합니다.

```
*g/re/n
5 there
6 they're
7 thereafter
10 4 theremin
```

네, 사실 `grep` 은 줄 번호를 출력하는 옵션이 있습니다. 하지만 이미 ed에 편리하게 내장되어 있는데 굳이 옵션을 찾아볼 필요가 있나요? [^6]

[^6]: 유닉스에 정말 필요한 것은 `gren(1)` 명령어입니다. 왜냐하면 `grep(1)` 이 외로워 하니까요.

`g` 전역 검색을 수행하면 커서 위치(현재 주소)는 마지막 일치 위치로 설정됩니다.

명령어 앞에 주소(또는 범위)를 입력해서 버퍼의 일부를 전역 검색합니다.

```
*1,10g/re/n
```

현재 주소에서 뒤로 검색하려면 정규식 주위에 슬래시 대신 물음표 문자를 사용합니다.

```
*10
4 theremin
*?re?n
7 thereafter
```

이전 일치 항목은 주소 7에 위치합니다. 현재 위치에서 뒤로 검색을 반복하려면 물음표 두 개를 입력합니다.

```
*??n
6 they're
```

`//` 및 `??` 검색 명령은 모두 가장 최근 정규식을 참조(기억)하므로, 현재 검색 결과를 기준으로 앞뒤로 이동할 수 있습니다.


## Running Commands on Searches

일치한 줄을 출력하는 명령이 검색 명령으로 처리할 수 있는 유일한 명령은 아닙니다. 검색 명령(`g`, `G`, `v` 또는 `V`) 이외의 어떤 명령이든 검색 결과에 적용할 수 있습니다.

간단한 예로 일치한 줄을 삭제합니다. `d` 명령어는 현재 (주소)위치를 삭제합니다. 여기서는 "re" 문자열과 일치하는 모든 줄을 제거합니다.

```
*g/re/d
```

버퍼의 내용이 줄어들었습니다. 집에서 따라하신다면 다음 예제를 보기 전에 이 작업을 `u` 명령으로 실행 취소합니다!!

정규 표현식과 일치하는 줄을 버퍼의 끝으로 이동한다고 가정합니다. 파일 끝을 의미하는 `$` 기호를 목적지 주소로 지정해서 `m` 명령어를 사용합니다.

```
*g/re/m$
```

이 명령어를 실행하면 어떤 결과가 나올까요?

```
*,n
1 the
2 their
3 then
4 Them
5 2
6 3weasels
7 /the/
8 pet rats
9 [pedicular]
10 hamster5
11 there
12 they're
13 thereafter
14 4 theremin
```

Ed는 버퍼를 훑어가면서 일치하는 부분을 찾을 때마다 해당 줄을 파일 끝으로 이동시켰습니다. 이렇게 하면 버퍼의 줄 순서가 자동으로 재조정됩니다! 이와 같은 간단한 정규 표현식을 사용할 때는 별것 아닌 것처럼 보이지만 복잡한 정규 표현식을 만들 때는 이 방법이 유용하단 것을 잘 알게됩니다.

이제 일치하는 모든 내용을 파일 시작 부분으로 옮긴다고 가정합니다. 명령어는 대상 위치만 다를 뿐이지만 결과는 다르게 나타납니다. (`u` 명령으로 이전 상태로 복구합니다)

```
*g/re/m0
*,n
1 4 theremin
2 thereafter
3 they're
4 there
5 the
6 their
7 then
8 Them
9 2
10 3weasels
11 /the/
14 hamster5
```

정규 표현식과 일치하는 단어들은 파일 맨 위에 있지만 순서가 뒤바뀝니다. 11행이 1행이 되고 10행은 2행이 되며 이런 식으로 이어집니다. 전역 검색을 수행할 때 ed는 각 행을 순서대로 처리합니다. 정규 표현식과 일치하는 행은 주소 0으로 이동합니다. 5행이 일치하므로 주소 0으로 이동합니다. 그 다음 6행이 일치하므로 역시 주소 0으로 이동합니다. 줄을 스택—아니, 버퍼—의 맨 위로 한 번에 하나씩 이동시키면 이렇게 순서가 뒤바뀝니다. 줄을 `$` 이외의 주소, 예를 들어 파일 중간 주소로 이동시킬 때도 이와 같은 현상이 발생합니다.

이런 순서 반전을 피하려면 정규 표현식을 사용하는 대화형 편집 작업이 필요합니다.


## Interactive Searching

때로는 일치하는 모든 줄에 작업을 다르게 수행할 때가 있습니다. 각 줄마다 검색한 다음, 명령 실행을 강요하는 대신 ed는 일치 항목이 나올 때마다 일시 정지한 후 별도의 명령을 실행할 기회를 제공합니다. 

`G` (대문자)명령으로 ed가 일치 항목이 나올 때마다 일시 정지하도록 지시할 수 있습니다.

```
*G/re/n
5 there
```

`Enter` 키로 계속 진행하거나 명령어를 입력할 수 있습니다. 이 경우 `m` 명령어로 줄을 주소 0, 즉 파일 맨 앞으로 이동시킵니다.

```
m0
```

ed는 다음 일치 항목을 표시합니다. 모든 항목을 파일 맨 앞 주소로 이동시킵니다.

```
6 they're
m1
7 thereafter
m2
10 4 theremin
m3
```

검색이 끝나면 ed는 현재 주소와 해당 주소의 내용물을 표시합니다.

```
4 4 theremin
*
```

여기서 무엇을 처리 했을까요? 모든 일치 항목을 버퍼 맨 앞으로 이동시켰지만 원래 배치 순서는 그대로 유지했습니다!!

```
*,n
1 there
2 they're
3 thereafter
4 4 theremin
5 the
6 their
7 then
8 Them
9 2
10 3weasels
11 /the/
12 pet rats
13 [pedicular]
14 hamster5
```

이런 종류의 작업을 실수해도 ed는 전역 검색을 단일 작업으로 간주합니다. 따라서 `u` 키로 복잡한 대화형 검색 작업도 되돌릴 수 있습니다.


## Inverted Matches

정규 표현식과 일치하지 않는 모든 항목을 검색하려면 `v` 명령어를 사용합니다. 여기서는 "the" 와 일치하지 않는 모든 항목의 줄 번호를 표시합니다.

```
*v/the/n
4 Them
8 2
9 3weasels
12 pet rats
13 [pedicular]
14 hamster5
```

다시 말해, "Them" 은 "the" 와 일치하지 않습니다! 검색 명령은 대소문자를 구분합니다!!

일치하지 않는 각 줄을 대화식으로 편집하려면 `V` 명령을 사용합니다. 이 기능은 `G` 명령을 사용한 대화식 편집과 정확히 동일하게 작동합니다.


## Character Classes

문자열을 검색 일치시키는 기능만으로 충분하지만 그 정도는 아무리 평범한 WYSIWYG 텍스트 편집기도 처리할 수 있습니다. 정규 표현식이 강력한 이유는 일치시킬 텍스트의 유형을 정의할 수 있는 능력에 있습니다.

영숫자 문자열을 일치시키고 싶으신가요? 정규 표현식으로 가능합니다. 숫자 3부터 5까지 포함된 모든 줄을 찾아내고 싶으신가요? 문제없습니다. 이런 기능들과 그 외의 모든 기능은 문자 클래스 기반으로 처리합니다.

문자 클래스는 대괄호 안에 포함된 일치 대상 문자 목록입니다. 문자 클래스 `[Tt]` 는 소문자 또는 대문자 T 중 하나와 일치하고, `[Hh]` 는 H 의 두 가지 형태 중 하나와 일치합니다. 문자 클래스가 한 번 등장하면 정규 표현식 내의 단일 문자와 일치합니다. 문자 클래스로 대소문자를 구분하지 않는 검색을 수행할 수 있습니다.

```
*g/[Tt][Hh][Ee]/n
1 the
2 their
3 then
4 Them
…
```

단순히 `/the/` 로 검색할 때와 달리 이 검색은 4번 줄 맨 앞에 대문자 T 가 있는 경우도 잘 찾아냅니다.

하이픈으로 문자 범위를 나열할 수 있습니다. 문자 클래스 `[a-z]` 는 모든 소문자를 일치시키고, `[A-Z]` 는 대문자를, `[0-9]` 는 모든 숫자를 일치시킵니다. 

문자 클래스에 여러 범위를 포함할 수 있습니다(예: `[a-zA-Z0-9]`). 하이픈 문자를 포함하는 문자 클래스가 필요하면 하이픈 문자를 맨 앞에 배치합니다. 문자 클래스 `[-/[]]` 는 하이픈, 슬래시 그리고 대괄호 중 하나를 일치시키는 반면, `[/-[]]` 는 `/` 부터 `[` 까지의 문자와 `]` 를 무엇으로 정의하든 모두 일치시킵니다.

범위엔 원하는 어떤 문자든 포함할 수 있습니다. 소문자 a부터 d까지와 u부터 z까지의 문자가 포함된 줄을 일치시킨다면 문자 클래스는 `[a-du-z]` 가 됩니다.

```
*g/[a-du-z]/n
6 they're
7 thereafter
9 3weasels
12 pet rats
13 [pedicular]
14 gelato5
```

이런 문자 클래스로 원하는 내용을 보다 정확히 좁혀내고, 앵커로 원하는 위치를 지정할 수 있습니다.


## Anchors

앵커는 정규식을 줄의 특정 위치로 고정합니다. 이를 통해 "줄 시작에 숫자가 있는 줄" 이나 "Z로 끝나는 줄" 같은 검색을 수행할 수 있습니다. 캐럿(`^`)은 정규식을 줄 맨 앞으로 고정하고, 달러 기호(`$`)는 줄 끝으로 고정합니다. 

여기서는 문자 "t" 로 시작하는 모든 줄을 검색합니다.

```
*g/^t/n
1 the
2 their
3 then
5 there
6 they're
7 thereafter
```

마찬가지로, 숫자로 끝나는 모든 줄을 검색할 수 있습니다.

```
*g/[0-9]$/n
8 2
14 hamster5
```

이처럼 앵커를 사용하면 검색 범위를 좁힐 수 있습니다.


## Inverted Classes

반전 (문자) 클래스는 해당 클래스에 나열한 문자를 제외한 모든 문자가 포함됩니다. 반전 클래스의 첫 번째 문자는 **반드시** 캐럿(`^`)이라야 합니다. 예를 들어, `[^w]` 같은 반전 클래스는 "소문자 w 를 제외한 모든 문자" 를 의미합니다.

반전 (문자) 클래스 기반으로 검색하면 금세 복잡해집니다. 반전 클래스를 사용하려면 클래스를 짧고 간단하게 구성해야 합니다. 특정 문자 클래스가 포함되지 않은 모든 것을 검색하려면 `v` 또는 `V` 반전 전역 검색 명령을 사용하는 것이 훨씬 더 좋습니다. 

다음은 대문자가 포함된 모든 것을 제외합니다.

```
*v/[A-Z]/n
```

반전 클래스는 복잡한 정규 표현식에서 가장 유용합니다. 예를 들어, 문자 "e" 가 포함된 모든 것을 일치시키고 싶지만, 그 뒤에 오는 문자가 "t" 가 아닌 경우만 일치시킨다고 가정합니다.

```
*g/e[^t]/n
2 their
3 Them
4 then
…
```

주의깊게 살펴보셨다면 첫 번째 줄의 the 가 빠진 것을 눈치채셨을 것입니다. 여기는 문자 e가 포함되지만 그 뒤에 t 문자가 오지 않습니다. 왜 이 결과엔 나타나지 않을까요? 정규 표현식은 문자 "e" 뒤에 "t" 를 제외한 어떤 문자가 오는 것을 찾도록 정의되어 있습니다. the 의 "e" 뒤에 아무런 문자도 없기 때문에 일치하지 않는 것입니다.

반전 클래스와 앵커에서 캐럿 차이에 유의합니다. 반전 클래스는 대괄호 안에서 캐럿을 사용하는 반면, 앵커는 대괄호 바깥에 위치합니다. 이를 통해 "t" 이외의 문자로 시작하는 모든 줄을 나열하는 것 같은 검색을 수행할 수 있습니다.

```
*g/^[^t]/n
4 Them
8 2
9 3weasels
10 4 theremin
11 /the/
12 pet rats
13 [pedicular]
14 hamster5
```

하지만 `v/^t/n` 명령어를 사용하는 편이 좀 더 나을 수 있습니다.

정규 표현식은 까다롭습니다. 반전 클래스는 두 배 더 까다롭습니다. 가능하면 피하는 것이 좋습니다.


## Multiple Matches and Wildcards

때로는 특정 문자를 하나 이상 일치시키거나, 심지어 0개 이상 일치시킬 때가 있습니다. Ed는 이를 위한 연산자를 제공합니다.

```

H
P
*a
the
their
then
Them
there
they're
thereafter
2
3weasels
4 theremin
/the/
pet rats
[pedicular]
hamster5
thee
theee
theeeeee
theeeeeen
.
wq
133
```

중괄호(`{m,n}`)로 특정 문자를 정해진 횟수만큼 정확히 일치시킬 수 있습니다. 일치시키려는 문자 바로 뒤에 횟수를 표기하면 됩니다. `e{2}` 같은 정규 표현식은 ed에게 "e" 문자를 연속으로 두 번 일치시키도록 지시합니다. (ee 같은 정규 표현식을 사용할 수도 있지만, 그러면 앞으로 살펴볼 좀 더 복잡한 정규 표현식을 구성할 수 없게 됩니다.) 

일반적으로 ed는 정규 표현식의 중괄호를 일반 문자로 취급합니다. 중괄호를 이스케이프 처리하면 ed가 이를 특수 문자로 취급하도록 지시합니다. 하지만 표현식이 좀 복잡해집니다.

```
*g/e\{2\}/n
15 thee
16 theee
17 theeeeee
18 theeeeeen
```

네 개의 일치 항목이 나옵니다. 잠깐만요—16, 17, 18행은 연속된 'e' 가 두 개보다 훨씬 더 많이 나옵니다. 무슨 일이 일어난 걸까요? 이는 단지 ed가 여러분보다 세부 사항에 좀 더 민감하단 것을 보여주는 예시일 뿐입니다. 16행은 'e' 가 두 쌍 연속으로 나타나며 가운데 'e' 는 두 쌍이 공유하고 있습니다. 17행과 18행은 'e' 쌍이 세 개 연속으로 나타나며 공유된 'e' 까지 포함하면 좀 더 많은 수가 됩니다.

특정 문자의 집합을 일치시키려면 신중하게 고려해야 합니다. 정확히 무엇을 일치시키고 싶은가요? 두 글자, 정확히 두 글자를 일치시키고, 그 뒤에 "e" 가 아닌 다른 문자가 오도록 하고 싶습니다. 

e 문자를 제외한 문자 클래스를 사용합니다.

```
*g/e\{2\}[^e]/n
18 theeeeeen
```

확실히 'e' 가 두 번 연속 나온 뒤에 'e' 가 아닌 문자가 하나 따라오는 경우입니다.

혹은 'e' 가 아닌 문자가 나온 뒤에 'e' 가 두 번 연속 나오고 그 'e' 두 개를 줄 끝에 붙인다고 가정합니다.

```
*g/[^e]e\{2\}$/n
15 thee
```

동일한 문자가 연속으로 나오는 부분을 일치시키려면 신중하게 생각해야 합니다.

기본 정규 표현식을 사용하면 일정 범위의 문자를 일치시킬 수 있습니다. 예를 들어, 연속된 'e' 두 개에서 다섯 개를 일치시키려면 다음과 같이 표현합니다. 하한, 쉼표, 상한으로 표현하는데 예를 들어, `e{2,5}` 와 같습니다. 실제 ed 명령어는 중괄호를 이스케이프 처리해야 합니다.

```
*g/e\{2,5\}/n
15 thee
16 theee
17 theeeeee
18 theeeeeen
```

이는 'e' 가 연속으로 두 개 있는 것을 찾는 경우와 동일한 문제가 발생합니다. 원하는 결과를 얻으려면 이 정규 표현식에 또 다른 조건을 추가해야 합니다.

```
*g/e\{2,5\}$/n
15 thee
16 theee
17 theeeeee
```

언뜻 보기엔 괜찮아 보이지만 자세히 세어보면 17번 줄에 'e' 가 6개 나열됨을 알 수 있습니다. 'not-e' 클래스로 그 앞에 경계를 설정해야 합니다.

```
*g/[^e]e\{2,5\}$/n
15 thee
16 theee
```

주어진 개수 이상의 문자가 포함된 모든 것을 일치시키려면 `{2,}` 같이 쉼표 뒤에 상한을 지정하지 않습니다.

```
*g/e\{2,\}/p
thee
theee
theeeeee
theeeeeen
```

어떤 경우는 특정 문자가 0개 이상 포함되길 원할 때가 있습니다. "0개 이상" 을 나타내려면 별표(`*`)를 사용합니다. 복잡한 표현으로 만들려면 모든 문자를 나타내는 와일드카드 `.` 문자와 결합합니다.

```
*g/.*/n
1 the
2 their
…
```

네, 이 표현식은 파일의 모든 줄과 일치합니다. 꽤 쓸모없죠?

와일드카드와 별표는 단독으로 사용하면 유용하지 않지만 다른 문자, 문자 클래스, 앵커와 결합하면 매우 강력해집니다. 예를 들어, 문자로 시작하지만 숫자로 끝나는 모든 줄을 찾는다고 가정합니다. 

줄 앞에 있는 문자를 찾기 위해 `^[a-zA-Z]` 정규식을 사용했습니다. `[0-9]$` 정규식은 줄 끝의 숫자를 문제없이 찾아줍니다. 하지만 이 둘을 결합하면 좀 까다로워집니다… 중간에 다른 문자가 포함되도록 허용하기 전까진 말입니다.

```
*g/^[a-zA-Z].*[0-9]$/n
14 hamster5
```

이렇게 하면 중간에 무엇이 있든, 문자열 길이가 어떻든 상관없이 지정할 수 있습니다. 문자로 시작하고 숫자로 끝나는 경우라면 모두 일치합니다. 마침표(`.`)는 0개 이상의 문자를 나타내고, 별표(`*`)는 어떤 문자든 일치시키므로 그 외의 문자는 0개 이상 허용한 것입니다. 이를 통해 "a1" 같은 매우 짧은 문자열도 일치시키면서 좀 더 긴 문자열을 제외하지 않을 수 있습니다.

별표 문자는 쉘 프로그래밍에 익숙한 사람들에겐 직관적이지 않은 결과를 초래할 수 있습니다. `*g/ther*/n` 같은 정규 표현식이 "ther" 로 시작하는 단어를 표시할 것이라 예상할 수 있지만 이는 틀린 생각입니다.

```
*g/ther*/n
1 the
2 their
3 then
…
```

별표(`*`)는 표현식 끝부분의 "r" 문자를 0개 이상 일치시킵니다. 문자열 "the" 는 "r" 문자가 0개 있으므로 일치합니다!! 만약 "r" 문자를 1개 이상 일치시키려면 `rr*` 같은 정규식을 사용합니다.


## Commands and Searches

검색 및 정규 표현식의 강력한 기능 중 하나는 "검색한 후 검색 결과에 명령을 실행할 수 있다!" 는 점입니다. 정규 표현식과 일치하는 모든 줄을 복제한다고 가정합니다. 

이 작업은 파일을 변경하므로 먼저 일반 검색 명령으로 정규 표현식이 예상한 내용과 일치하는지 확인합니다.

```
*g/there/n
5 there
7 thereafter
10 4 theremin
```

정확합니다. 이제 `t` 명령어로 해당 줄을 복사하되 목적지 주소로 `.`—즉, 현재 줄—을 지정합니다. 이렇게 하면 복사된 내용은 현재 줄 바로 뒤에 삽입됩니다. [^8] `n` 명령어로 변경된 줄을 출력합니다.

[^8]: Ed는 《스타 트렉》 에 나오는 원시적인 AI가 아닙니다. 재귀나 역설로 그의 머리를 터뜨릴 순 없습니다. Ed는 각 줄을 딱 한 번만 복제한 뒤 다음으로 넘어가기 때문입니다.

```
*g/there/t. n
6 there
9 thereafter
13 4 theremin
```

줄 번호를 확인합니다. 일치하는 줄들이 새로운 줄에 복제되었습니다.

# Chapter 110: Substitution

정규 표현식을 사용하면 일치하는 줄을 검색하고 조작할 수 있는 반면, ed는 동일한 정규 표현식을 기반으로 텍스트를 변경할 수 있게 해줍니다. 정규 표현식 기반의 치환 기능은 다른 텍스트 편집기들이 꿈도 꾸지 못할만큼 엄청나게 강력한 검색 및 치환 기능입니다. 

서툰 정규 표현식은 버퍼를 엉망으로 만들 수도 있지만, 연습을 통해 텍스트를 빠르고 쉽게 변환할 수 있게 됩니다. 저는 수십 년 동안 정규 표현식을 사용하며—음, 함께 일하며—고생해 왔습니다. 오늘날도 저는 정규 표현식을 사용해서 검색한 뒤, 그 정규 표현식을 기반으로 치환을 수행합니다. 정규 표현식은 미묘하고 쉽게 오작동을 일으킵니다. 항상 먼저 테스트해 보세요. 제대로 작동한다고 생각들더라도, 변환되지 않은 데이터 사본은 꼭 보관해 둡니다.

치환하려면 `s` 명령어를 사용하고, 그 뒤에 정규 표현식과 새로운 텍스트를 입력하세요. 각 항목은 슬래시로 구분하세요.

```
s/정규식/새 텍스트/
```

간단한 치환부터 시작해 보겠습니다. 하지만 이를 위해선 먼저 간단한 검색부터 진행해야 합니다. 101장에서 사용한 것과 동일한 단어 목록을 사용해서, "there" 가 나오는 모든 부분을 "then" 으로 바꾼다고 가정해 봅시다. 

먼저, 정규 표현식을 사용해서 검색해 보고, 예상한 결과가 제대로 나오는지 확인하세요.

```
*g/there/n
5 there
7 thereafter
10 4 theremin
```

세 개의 일치 항목이 있습니다. 검색 결과의 마지막 일치 항목이 (현재) 주소로 설정되므로, 파일 맨 위로 돌아가서 치환을 시도해 봅시다.

```
*1
the
*s/there/then/
?
no match
```

오류인가요? 하지만 방금 전 검색에서는 버퍼에 일치하는 문자열이 분명 있었는데!

"ed는 한 줄씩 처리한다!" 는 점을 항상 기억하세요. 1행은 정규식과 일치하지 않으므로 오류가 발생합니다. 치환을 수행하려면 (수동 또는 자동) 검색을 사용해야 합니다. 치환을 사용하면 프로그래밍 방식으로 오류를 수정할 수 있습니다.

단어 목록에 있는 항목 중 하나를 살펴보겠습니다.

```
*18
theeeeeen
```

"Theeeeeen" 은 정상 단어가 아닙니다. 누군가 "then" 을 입력할 때 e 키가 분명히 걸렸던 것이 분명합니다. 치환을 사용해서 이를 수정할 수 있습니다. 여기서는 e가 두 개 이상 연속된 모든 문자열을 하나의 e로 바꿉니다.

```
*s/e\{2,\}/e/
```

이제 해당 줄을 확인해 보세요.

```
*18
then
```

결과를 출력한다는 것을 미리 알았다면, 치환 명령어 끝에 `p` 명령어를 추가할 수도 있었을 것입니다. 치환 명령어 끝에서 작동하는
몇 가지 특정 명령어는 나중에 다루겠습니다.

```
*s/e\{2,\}/e/p
```

이 모든 중괄호를 이스케이프 처리하는 것이 어렵다면, 치환을 반복하는 좀 더 간단한 방법을 선택할 수도 있습니다. `s` 명령어는
이전 치환을 반복합니다.

```
*s/ee/e/p
theeeeen
*s
theeeen
*s
theeen
*s
theen
*s
then
*s
?
no match
```

이 치환이 단 하나의 일치 항목만 영향을 미친다는 것을 눈치채셨을 수도 있습니다.

다음과 같은 줄을 생각해 보세요.

```
*19
wXXhXXaXXtXX XXisXX this?XX
```

저 XX 부분들이 어떻게 거기에 들어갔는지 모르지만, 제거해야 합니다. 다음 문자열 중 하나를 빈 문자열로 치환할 수 있습니다.

```
*s/XX//p
whXXaXXtXX XXisXX this?XX
```

치환 엔진은 사용자가 요구하는 최소한의 작업만 수행합니다. [^9] w와 h 사이에 있는 첫 번째 XX를 찾아내어 제거합니다. 인자로 숫자를 지정해서 어떤 일치 항목을 제거할지 지정할 수도 있습니다. 여기서는 일곱 번째 XX를 빈 문자열로 치환합니다.

[^9]: 그런 면에서 대체 선수들은 의심스러울 정도로 인간적입니다.

```
*s/XX//7p
wXXhXXaXXtXX XXisXX this?
```

기존 줄에 약간의 수정을 가하는 것은 유용합니다. 이런 치환의 문제는 "숫자를 세어야 한다!" 는 점입니다. 또한 이로 인해 치환을 반복하는 것이 덜 유용해집니다. 마지막 치환을 반복하려면 `s` 키를 다시 누르세요.

```
*s/XX//p
whXXaXXtXX XXisXX this?XX
*s
whaXXtXX XXisXX this?XX
…
*s
what is this?
```
`s` 뒤에 숫자를 추가하면 해당 줄에서 특정 일치 항목만 치환을 반복할 수 있습니다.

`g` (전역) 수정자를 사용하면 모든 일치 항목을 제거하는 것이 훨씬 더 간단합니다. 이 수정자는 ed에게 현재 줄에서 발견되는 모든 일치 항목에 치환을 수행하도록 지시합니다. 또한 결과를 출력하기 위해 `p` 수정자도 추가하겠습니다.

```
*s/XX//gp
what is this?
```

문제가 해결되었습니다.


## Combining Searches and Substitution
바꾸고 싶은 텍스트가 포함된 줄을 일일이 찾아야 한다면 ed를 사용하는 즐거움이 반감될 것입니다. 기분을 망치지 않도록, ed는 검색과 치환을 결합할 수 있습니다. 검색 뒤에 치환 명령을 지정해서 "이것과 일치하면 이 치환을 수행하라!" 고 지시하면 됩니다.

이 예제는 "there" 라는 단어를 찾아 "then" 으로 치환합니다. 검색은 꽤 간단합니다: `g/there/` 

셸과 마찬가지로 백슬래시 문자는 "다음 줄로 이어짐" 을 의미합니다. 그런 다음 원하는 치환 내용을 지정합니다.

```
*g/there/ \
s/there/then/
test there
thereafter
4 theremin
```

Ed는 검색 조건에 맞는 줄들을 출력합니다. 하지만 이제 그 줄들을 한 번 살펴보세요.

```
*5p
then
*7p
thenafter
*10p
4 thenmin
```

치환 성공! Ed는 이 검색과 치환이 결합된 작업(혹은 요즘 젊은이들이 말하듯, '검색 및 바꾸기')을 하나의 명령으로 간주하므로, `u` 를 사용해서 역순으로 실행 취소할 수 있습니다. 이 예제는 좀 어이없는 예제라서 저는 그렇게 했습니다. 

하지만 스크립트에서 사용자 로그인 스크립트를 업데이트하거나, 마이그레이션된 서버로 연결되는 링크를 수정하거나, 그 밖의 지루한 작업을
처리하는 데 이 방법을 사용할 수 있습니다. 111장에서 몇 가지 예제를 살펴보겠습니다.

이 작업을 두 줄로 나누는 백슬래시는 필요하지 않습니다. 모든 내용을 한 줄에 넣으면, ed는 검색어와 일치하는 줄을 표시하지 않습니다.

```
*g/there/ s/there/then/
*
```

하나의 명령어에 여러 개의 치환을 포함할 수 있지만, 각 치환은 백슬래시로 구분해서 별도의 줄에 작성해야 합니다.

```
*g/there/ s/there/then/\
s/t/T/n
5 Then
7 Thenafter
10 4 Thenmin
```

이 명령어는 "there" 를 "then" 으로 바꾸고 각 줄의 첫 번째 T를 대문자로 변경합니다.

치환식 내부에 겉보기에 별 관련 없는 정규식을 사용할 수는 있지만, 하나의 치환이 실패하면 그 이후 모든 치환이 중단됩니다!! 치환을 신중하게 구성하십시오.

복잡한 형식을 살펴보았으니, 이제 약간 단순화해 보겠습니다.

검색 대상인 정규 표현식에 치환을 수행하려면, `%` 주소를 사용해서 사용 가능한 모든 줄에 치환을 수행할 수 있습니다.

```
*%s/there/Then/
```

단, 이는 위에서 살펴본 좀 더 복잡한 치환과 정확히 동일하지 않습니다. 5번째 줄는 "then" 대신 "test" 의 첫 글자를 대문자로 변경합니다. 전체 버전이 훨씬 더 유연하므로, 그 부분에 집중해 보겠습니다.


## Subexpressions and Backreferences
부분 표현식은 정규 표현식의 일부입니다. 부분 표현식을 사용해서 한 줄을 "관심 대상 앞의 모든 내용, 관심 대상, 그리고 그 뒤의 모든 내용" 같이 여러 부분으로 나눌 수 있습니다. 부분 표현식은 `([a-zA-Z0-9])` 같이 괄호로 표시됩니다. 중괄호와 마찬가지로, ed에게 괄호를 부표현식으로 사용함을 알리려면 백슬래시로 괄호를 이스케이프 처리해야 합니다. 그렇지 않으면 ed는 괄호 문자를 문자 그대로 해석합니다. 하지만 부분 표현식을 소개하는 이 글에서는 이해를 돕기 위해 백슬래시 표기를 생략하겠습니다.

ed가 전체 줄을 기억하도록 처리하려면, 부분 표현식이 원하는 문자열을 포함하는 전체 줄과 일치해야 합니다. 여기서 마침표와 와일드카드가 유용하게 쓰입니다. `/the/` 는 "the" 라는 문자열이 포함된 줄과 일치하지만, 전체 줄을 기억하려면 `/.*the.*/` 를 사용해야 합니다.—즉, 0개 이상의 무언가(우리가 실제로 원하는 부분), 그리고 0개 이상의 무언가를 포함해야 합니다. 정규식을 괄호로 묶어 ed가 이를 부분표현식으로 기억하도록 하세요: `/(.*the.*)/`

역참조는 부분 표현식이 일치시킨 리터럴 텍스트를 참조할 수 있게 해줍니다. 검색 시에도 역참조를 사용할 수 있지만, 대부분은 치환에서 사용합니다. 

ed는 부분 표현식을 정의한 순서대로 기억합니다. 첫 번째 부분 표현식은 역참조1, 두 번째는 역참조2, 그 다음은 역참조3 같은 순서입니다. 역참조는 백슬래시와 번호(예: \1, \2 등)를 사용해서 지정합니다.

예제 정규식 `/(.*the.*)/` 는 ed에게 하나의 부분 표현식을 기억하도록 지시합니다. 따라서 역참조는 `\1` 하나 뿐입니다.

부분 표현식과 역참조를 어떻게 사용할 수 있을까요? 열고 닫는 따옴표가 모두 포함된 모든 줄을 검색할 수 있습니다. 사람은 일관성이 없다는 것이 잘 알려져 있으므로, 해당 문자열에는 작은따옴표나 큰따옴표 중 하나가 사용될 수 있습니다. 저는 두 종류의 따옴표를 모두 포함하는 문자 클래스 `['"]` 을 정의합니다. 이 클래스를 괄호 안에 넣어 부분 표현식으로 선언합니다: `(['"])` 그 뒤에는 부분 표현식과 일치하는 문자가 다시 나타날 때까지 임의의 개수의 문자가 올 수 있습니다: `.*` 부분 표현식에서 찾은 문자가 바로 첫 번째 역참조, 즉 `\1` 입니다. 이 모든 것을 정규식 `(['"]).*\1` 에 결합합니다. 이 정규식을 검색 명령에서 사용하려면, ed에게 이것이 하위(부분) 표현식임을 알리기 위해 괄호를 백슬래시로 이스케이프 처리해야 합니다: `\(['"]\).*\1`  

`g` 명령을 사용해서 이 정규식과 일치하는 줄을 출력합니다.

```
*g/\(['"]\).*\1/
"bleeeeep"
unconscious 'people'
```

역참조는 치환과 함께 사용됩니다. 여기서는 "the" 가 포함된 모든 줄 앞에 "HIT-." 라는 문자열을 추가하려고 합니다. 이해를 돕기 위해
결과를 출력하는 `p` 명령어를 추가했습니다. `g` 명령어를 사용해서 정규식 `/the/` 와 일치하는 줄을 대상으로 지정하므로, 해당 정규식이 포함된 줄에서만 치환이 이루어집니다. 실제 치환에서는 하위 표현식을 사용해서 전체 줄을 캡처한 다음, 역참조를 통해 캡처된 문자열을 정규 표현식 내에 삽입합니다.

```
*g/the/\
s/\(.*\)/HIT-\1/p
the
HIT-the
their
HIT-their
…
```

첫 번째 줄은 대상 정규식을 기준으로 검색을 수행해서 "the" 가 포함된 줄을 선택합니다. 명령어가 두 줄로 나뉘어 있으므로 ed는
일치하는 줄을 출력합니다!! 두 번째 줄은 치환을 수행하며, 문자열 "HIT-" 를 추가한 다음, 첫 번째이자 유일한 부분 표현식을 불러오기 위해 `\1` 역참조를 추가합니다. 

치환 후 결과를 출력해서 변경 전후를 보여주기 위해 끝에 `p` 를 추가했습니다. 일치하는 각 문자열에는 원하는 접두사가 붙어 있습니다. "the" 에 대소문자를 구분하지 않는 일치를 원하고, 일치한 내용을 기억할 뿐만 아니라, 그 내용을 "일치 전, 일치 부분, 일치 후" 로 세 부분으로 나누고 싶다고 가정해 봅시다.

각 부분에는 별도의 괄호가 필요하므로, 다음과 같은 형태가 됩니다.

```
/(.*)([tT][hH][eE])(.*)/ .
```

이 정규식에는 세 개의 하위 표현식이 있으므로, 이를 `\1`, `\2`, `\3` 으로 역참조합니다.

이 기능을 어떻게 사용할 수 있을까요? 아마도 일치하는 부분 주위에 "HERE->" 와 "<-HERE" 를 넣고 싶을 수도 있습니다. [^10] 

[^10]: 이를 전통적으로 "정규식 디버깅" 이라 부릅니다.

치환을 수행하려면 첫 번째 부분 표현식을 가져온 다음, "HERE->" 를 추가하고, 두 번째 부분 표현식을 가져온 뒤 "<-HERE" 를 추가한 다음, 마지막 부분 표현식을 추가해야 합니다.

첫 번째 줄인 검색 조건은 대소문자를 구분하지 않는 "the" 와 일치하는 줄만 치환이 적용되도록 합니다. 두 번째 줄은 부분 표현식을 사용하는 정규식을 통해 해당 줄을 여러 조각으로 분할한 다음, 역참조를 사용해서 치환을 수행함으로써 줄을 다시 결합합니다. 이를 사용하려면
모든 괄호를 백슬래시로 이스케이프 처리해야 하는데, 이것이 바로 제가 정규식을 작성할 때 백슬래시를 생략한 이유입니다.

```
*g/[tT][hH][eE]/\
s/\(.*\)\([tT][hH][eE]\)\(.*\)/\1HERE->\2<-HERE\3/p
the
HERE->the<-HERE
their
HERE->the<-HEREir
then
HERE->the<-HEREn
Them
HERE->The<-HEREm
…
```

이제 각 줄에서 정규 표현식이 어디에 일치했는지와 나머지 줄 내용을 확인할 수 있습니다.

이 특정 치환은 `%` 연산자를 사용해서 단순화할 수 있으며, 그 결과 다음과 같습니다:

```
% s/\(.*\)\([tT][hH][eE]\)\(.*\)/\1HERE->\2<-HERE\3/p 
```

하지만 이 방법으로는 단일 검색에서 여러 번의 치환을 수행할 수 없습니다.



## Multiple Substitutions
정규식 검색을 사용해서 치환 대상을 지정했지만, 그렇다고 해서 치환 시 반드시 그 정규식을 사용해야 하는 것은 아닙니다. Ed를 사용하면 검색 후 여러 치환을 연이어 수행할 수 있어, 단일 명령어로 복잡한 데이터 변환을 수행할 수 있습니다.

잠시 101장으로 돌아가 보겠습니다. 그곳에서 우리는 'e' 가 2개에서 5개까지 연속으로 포함된 문자열을 일치시키려고 시도했었습니다. 이 작업은 사실 까다로운데, 정규 표현식은 한 줄에서 여러 항목과 일치시킬 수 있기 때문입니다. 결국 'e' 가 6개 연속으로 나열된 문자열은 'e' 3개씩으로 구성된 두 그룹에 불과하니까요. 하지만 현실적으로
그 데이터를 어떤 식으로든 변환하기 위해 그런 검색을 수행할 것입니다. 검색 후 치환을 연쇄적으로 적용하면 sed(1) 같은 신생 도구에 의존하는 단점없이도 무수히 많은 변환 작업을 수행할 수 있습니다.

가끔 손상된 데이터가 포함된 텍스트 파일이 있습니다. 단어에는 'e' 가 연속으로 두 개 이하이거나, 5개 이상이어야 합니다. 단어에 'e' 가 연속으로 3개, 4개, 또는 5개 포함된 경우, 해당 문자열은 'e' 두 개로 치환되어야 합니다. 'e' 가 연속으로 1개, 2개, 또는 6개 이상인 경우에는 그대로 두어야 합니다.

이를 위해서는 정규 표현식을 신중하게 고려해야 합니다. 제한된 범위의 문자로 구성된 문자열을 식별하려면 관심 대상 문자의 양쪽에 무엇이 있는지 파악해야 합니다. 기본적으로 세 가지 경우가 있습니다: 해당 문자가 단어의 시작이나 끝에 있을 수도 있고, 가운데에 있을 수도 있습니다. 이 세 가지 경우 모두에 대한 정규식과 치환 규칙이 필요합니다. 다시 말하지만, 정규식을 설명하는 동안 명확성을 위해 백슬래시 이스케이프 기호는 생략하겠습니다. 이 기호들은 ed 명령줄에 입력할 것입니다.

첫 번째 경우, 즉 'e' 문자열이 줄 끝에 있는 경우는 'e' 가 아닌 문자 클래스(`[^e]`)를 사용해서 'e' 문자열의 시작 부분을 식별합니다. 그런 다음 'e' 가 3개에서 5개까지 나오는 경우에 대한 정규식인 `e{3,5}` 를 추가합니다. 정규식을 `$` 를 사용해서 줄 끝 부분에 고정합니다. 그러면 다음과 같은 치환 정규식이 `[^e]e{3,5}$` 가 됩니다. 이 부분을 'e' 가 아닌 문자 클래스가 일치하는 내용에 'e' 두 개를 더한 것으로 치환하고자 합니다. 'e 가 아닌 문자' 클래스가 일치한 내용을 기억하려면 부분 표현식이 필요하므로, `[^e]` 주위에 괄호를 추가해서 `([^e])e{3,5}$` 를 만듭니다. 이 복잡한 표현식을 역참조와 'e' 두 개, 즉 `\1ee` 로 치환합니다. 최종 치환 문장은 다음과 같습니다. `s/([^e])e{3,5}$/\1ee/`

'e' 가 연속된 문자열이 줄의 맨 앞에 있다면, 기본적으로 줄 끝 정규식을 반대로 적용하면 됩니다. 캐럿(`^`)을 사용해서 정규식을 줄 맨 앞에 고정합니다. 캐럿 바로 뒤에 3개에서 5개 사이의 'e' 를 나타내는 `e{3,5}` 정규식을 추가하고, 부분 표현식에서 'e' 가 아닌 클래스(`[^e]`)를 사용합니다. 그러면 `^e{3,5}([^e])` 라는 정규 표현식이 만들어집니다. 이를 'e' 두 개와 'e' 가 아닌 문자열을 일치시킨 하위 표현식의 결과로, 즉 `ee\1` 로 치환하고자 합니다. 최종 치환 문장은 `s/^e{3,5}([^e])/ee\1/` 와 같습니다.

줄 중간에 'e' 문자열이 있으면 앞뒤의 두 정규식에서 각각 요소가 빼앗기게 됩니다. 따라서 'e' 문자열 앞뒤에 'e' 가 아닌 문자를 위한 부분 표현식을 두고, 중간에는 3~5개의 'e' 가 위치하도록 해야 합니다. 그 결과 `([^e])e{3,5}([^e])` 가 됩니다. 두 개의 하위 표현식이 있으므로 치환 시 두 개의 역참조가 필요하며, 즉 `\1ee\2` 가 됩니다. 최종 치환 문장은 `s/([^e])e{3,5}([^e])/\1ee\2/` 와 같습니다.

이 치환들을 검색 명령과 함께 실행합니다. 이 치환들은 5자보다 긴 'e' 문자열에는 영향을 미치지 않으므로, 'e' 가 3개 이상 포함된 모든 패턴(`e{3,}`)에 대해 실행할 수 있습니다. 결합된 검색 및 치환 명령은 대략 다음과 같이 보일 것입니다—다시 한 번, 명확성을 위해 백슬래시 이스케이프는 생략했습니다.

```
g/e{3,}/ \
s/([^e])e{3,5}$/\1ee/p\
s/^e{3,5}([^e])/ee\1/p\
s/([^e])e{3,5}([^e])/\1ee\2/p
```

각 치환에 `p` (출력)명령을 추가해서, 각 줄에서 어떤 치환이 어떤 변화를 일으키는지 확인할 수 있도록 했습니다. 이는 전형적인 printf 스타일의 디버깅 방식입니다. 초기 검색어와 첫 번째 정규식을 구분하기 위해 백슬래시를 사용했기 때문에, ed는 일치하는 용어를 출력합니다. 따라서 각 일치 항목마다 네 줄의 출력이 생성됩니다: 원본 줄, 앞에 e 를 삽입한 대체 후의 줄, 뒤에 e 를 삽입한 대체 후의 줄, 그리고 가운데에 e 를 삽입한 대체 후의 줄입니다.

이제 백슬래시 이스케이프를 추가하고 명령을 실행하면 다음과 매우 유사한 출력이 생성됩니다.

```
* g/e\{3,\}/ \
s/\([^e]\)e\{3,5\}$/\1ee/p\
s/^e\{3,5\}\([^e]\)/ee\1/p\
s/\([^e]\)e\{3,5\}\([^e]\)/\1ee\2/p
theee
thee
thee
thee
```

첫 번째 일치 항목은 끝에 'e' 가 세 개 있습니다. 첫 번째 치환이 이를 포착해서 줄여줍니다.

```
theeeeee
theeeeee
theeeeee
theeeeee
```

검색 결과 'e' 가 여섯 개 연속으로 나오는 단어가 발견되었습니다. 어떤 치환 정규식도 이에 일치하지 않기 때문에, 이 단어는 무사히 빠져나갑니다.

```
eeeeek!!!
eeeeek!!!
eek!!!
eek!!!
```

여기 'e' 가 다섯 개로 시작하는 줄이 있습니다. 이 단어는 두 번째 치환에 걸려 삭제됩니다.

```
bleeeeep
bleeeeep
bleeeeep
bleep
```

정말 긴 욕설 문자열이 아닌 이상, 'e' 두 개면 무언가를 비프음으로 처리하기에 충분합니다. 마지막 치환 정규식이 이를 포착해서 잘라냅니다.

이 모든 것이 아주 잘 작동하다가, 누군가 여러분의 정규 표현식에 'e' 가 3개에서 5개만 포함된 줄이라는 특별한 경우가 포함되지 않았다고 지적할 때까지는 말이죠. 여러분은 다른 도구를 사용할 때와 똑같이 이 치환 문을 추가하고 명령을 다시 실행할 겁니다. 우리 모두에게 이런 순간은 늘 있기 마련입니다. 이와 같은 복잡한 다중 정규 표현식 치환을 수행하려면, 111장에서 다룬 것 같이 스크립트에서 처리하는 것이 가장 좋습니다.



## Underlining via Substitution
지금까지 보여드린 예제들 모두 꽤 간단했습니다. 이제 이것을 활용해서 좀 더 실질적인 것을 만들어 보겠습니다. 치환 기능과 일반 텍스트를 사용해서 정규 표현식이 포함된 모든 줄에 밑줄을 그어보겠습니다. [^11] 네, 일반 텍스트는 밑줄 기능을 지원하지 않지만, 어쨌든 이를 구현해 볼 것입니다. 마치 예전에 진짜 시스템 관리자들이 그랬던 방식 그대로 말이죠.

[^11]: 원시 시대의 시스템 관리자조차 관리층으로부터 보기 좋은 보고서를 요구받았기 때문입니다.

간단한 정규 표현식 "the" 부터 시작해서 이 작업을 점진적으로 개발해 보겠습니다. 작동하는 개념 증명이 완성되면 이를 확장할 것입니다.

```
ed words2
H
P
*a
the
but then
their
Them
4 theremin
thebadgerthe
thee
.
*wq
53
```

파일에는 다음과 같은 줄들이 많이 포함되어 있습니다(주소가 표시된 상태로).

```
1       the
2       but then
3       their
4       Them
5       4 theremin
6       thebadgerthe
7       thee
```

먼저 정규 표현식과 일치하는 줄을 복제해서, 원본 위치에 그대로 복사합니다.

```
*g/the/t.
```

이렇게 하면 중복된 줄이 많이 포함된 버퍼가 생성됩니다.

```
1 the
2 the
3 but then
4 but then
5 their
6 their
…
```

`t` (전송 또는 복사) 명령은 주소를 복사된 줄의 주소로 설정한다는 점을 기억하세요. 이 검색이 일치하는 항목을 찾을 때마다, ed는 주소를 복사된 줄로 설정합니다. 복사 작업 직후에 치환을 수행하면, 치환은 현재 줄, 즉 복사된 줄에만 적용됩니다. 정규 표현식과 일치하는 줄에 밑줄을 그으려면, 일치하는 줄의 모든 문자를 등호로 변환하세요.

```
*g/the/t. \
s/./=/g
*,n
1 the
2 ===
3 but then
4 =====
5 their
6 ====
7 Them
8 there
9 =====
```

"the" 와 일치하는 줄에는 톰슨과 리치가 의도한 대로 적절한 ASCII 밑줄이 표시되고, 일치하지 않는 줄에는 표시되지 않습니다.


## Partial Underlining
밑줄을 그리는 것은 유용하지만, 어쩌면 줄 전체에 밑줄을 그리는 것은 원치 않을 수도 있습니다. 아마도 정규 표현식과 일치하는 부분에만 밑줄을 그을 수도 있겠죠. 그렇게 하는 것도 그리 어렵지 않습니다. 먼저 밑줄 명령어를 살펴본 다음 이를 수정해 보겠습니다.

복사한 줄을 공백이 될 부분과 밑줄이 될 부분으로 나눌 필요가 있습니다. 이 문제를 처리하는 방법은 여러 가지가 있지만, 제가 사용하는 방법은 치환 도중에 줄바꿈 문자를 사용해서 줄을 나누는 것입니다. 남아있는 백슬래시가 중요하기 때문에 명확성을 위해 이스케이프 백슬래시는 제거했습니다.

```
s/(.*)(the).*/x\1\
\2/
```

이 치환의 정규식 부분에는 두 개의 하위 표현식이 포함되어 있습니다. 하나는 원하는 정규식 `(.*)` 앞에 오는 모든 부분이고, 두 번째는 정규식 자체인 `(the)` 입니다. 정규식에는 나머지 모든 부분을 나타내는 세 번째 부분인 `.*`  가 있습니다. 세 번째 부분은 하위 표현식이 아니므로, ed는 이를 기억하지 않습니다. (엄밀히 말하면 세 번째 부분은 필요하지 않지만, 며칠 또는 몇 년 후에 코드를 읽을 때 "이 뒤에 무언가 있을 수도 있다" 고 명시적으로 표기하는 편이 좀 더 편리하다고 생각합니다.)

이제 치환 부분을 살펴보겠습니다. 검색어가 가장 먼저 나타나면, 첫 번째 역참조는 빈 값이 됩니다. 이 명령어의 뒤쪽 부분은 이 자리에 무언가 있다고 가정하므로, 어떤 경우든 줄 맨 앞에 'x' 문자를 넣습니다. 첫 번째 부분에 대한 역참조가 있고 줄 바꿈으로 넘어갑니다. 이 줄바꿈은 "명령이 다음 줄에서 계속된다" 는 의미가 아니라, 대신 치환 내용에 삽입됩니다. Ed는 줄바꿈이 치환 내용(치환 문자열) 한 가운데에 나타나기 때문에 이런 차이를 구분할 수 있습니다. 현재 이 줄을 두 줄로 나누고 있는 것입니다.

다음 줄에서, 두 번째 역참조는 검색한 텍스트를 가져옵니다. 앞서 검색한 내용과 결합되면, 버퍼는 다음과 같이 됩니다.

```
1 the
2 x
3 the
4 but then
5 xbut
6 then
…
```

정규 표현식과 일치하는 모든 내용은 세 줄씩 그룹으로 나뉩니다. 각 그룹의 첫 번째 줄은 원본 줄입니다. 두 번째 줄은 정규 표현식 일치 부분 앞의 모든 내용을 복사한 것으로, 앞에 "x" 문자가 붙어 있습니다. 세 번째 줄은 정규 표현식과 일치하는 문자열입니다. 정규 표현식 일치 부분 뒤의 내용은 모두 제거됩니다.

첫 번째 3줄 그룹에서, 2번째 줄에는 정규식 일치 부분 앞에 아무것도 없기 때문에 "x" 문자만 포함되어 있습니다. 3번째 줄에는 정규식에 일치한 문자열이 포함되어 있습니다. 두 번째 3줄 그룹(4~6번째 줄)에서 5번째 줄은 정규식 일치 부분 앞에 있던 내용을 "x" 문자가 앞에 붙은 형태로 보여줍니다. 6번째 줄은 정규식에 일치한 부분을 보여줍니다.

각 치환 작업이 끝날 때마다, 주소는 세 줄 중 마지막 줄로 설정됩니다. 이것이 바로 정규식과 일치하는 잘려나간 텍스트 부분입니다. 매우 간단한 치환 명령어 `s/./=/g` 를 사용해서 해당 문자들을 하나씩 등호로 변환합니다. 첫 번째 일치 항목뿐만 아니라 모든 일치 항목이 등호로 변환하려면 끝에 `g` 명령어를 추가해야 합니다.

이렇게 하면 텍스트가 다음과 같이 변환됩니다.

```
1 the
2 x
3 ===
4 but then
5 xbut
6 ===
…
```

여기에 등호 밑줄이 생겼지만, 용어 바로 아래에 위치하도록 적절한 공백이 필요합니다. 그래서 각 3줄 그룹의 두 번째 줄인 "정규식 앞 부분" 을 따로 저장해 둔 것입니다. 상대 주소 지정(선두의 마이너스 기호)을 사용해서 이전 줄에 치환을 수행하고, 모든 문자를 공백으로 대체합니다. 예를 들어: `-s/./ /g` 한 줄을 처리하면 (현재) 주소가 해당 줄로 변경됩니다. 그러면 다음과 같은 줄이 생성됩니다.

```
1 the
2
3 ===
4 but then
5
6 ===
…
```

각 3줄 그룹의 두 번째 줄은 비어있는 것처럼 보이지만, 실제로는 공백이 포함되어 있습니다. 모든 줄에는 자리 표시자로 사용된 "x" 문자로 인해 적어도 하나의 공백이
있습니다. 이는 서식을 망가뜨릴 수 있는 불필요한 문자이므로, `s/^ //\` 를 사용해서 이를 제거합니다. 눈에 띄는 차이는 없겠지만, 이제 다음 명령이 정상적으로 작동할 것입니다.

`j` (join)명령어는 기본적으로 다음 줄을 현재 줄 끝에 연결합니다. 공백 문자는 등호 밑줄이 일직선으로 정렬되도록 만드는 간격을 제공합니다.

자, 이제 모두 함께 해 봅시다! 각 괄호와 중괄호 앞에 필요한 백슬래시 이스케이프 문자를 추가하면, 각 줄의 "the" 에 밑줄을 그을 수 있습니다.

```
* g/the/t.\
s/\(.*\)\(the\).*/x\1\
\2/\
s/./=/g\
-s/./ /g\
s/^ //\
j
*,p
the
===
but then
    ===
their
===
Them
4 theremin
  ===
thebadgerthe
         ===
thee
===
```

보셨나요? 마이크로소프트 워드는 ed에 비할 바가 아닙니다. 전혀요.


## Shortcuts and Alternates
ed는 사용자가 모든 것을 일일이 자세히 설명해 줄 필요가 없을만큼 똑똑합니다. 검색 형식을 살펴보겠습니다.

```
g/regex/commands
```

마지막 슬래시는 정규식과 명령어를 구분하기 위해 있습니다. 추가 명령을 실행하지 않는다면, 마지막 슬래시는 불필요합니다. 생략해도 됩니다.

```
*g/hams
hamster5
```

최신(1980년대 중반 이후) 버전의 ed는 `g` 명령조차 필요하지 않습니다. 슬래시만 있어도 검색이 실행됩니다.

```
*/\[.*icu
[pedicular]
```

마찬가지로, 치환 명령의 마지막 슬래시는 치환을 뒤따르는 명령과 구분해 줍니다. 뒤따르는 명령이 없다면, 마지막 슬래시를 생략해도 됩니다.

```
*s/vim/ed
ed
```

`s/regex//` 처럼 정규식을 빈 문자열로 치환하려면, 명령을 좀 더 짧게 줄일 수 있습니다. Ed는 `s` 명령을 사용했기 때문에 치환을 하려는 것임을 알아챕니다. 정규식은 지정했지만 치환 내용은 지정하지 않았으므로, Ed가 자동으로 처리해 줍니다. 이를 통해 문서에서 불필요한 단어를 쉽게 제거할 수 있습니다.

```
*s/emacs
```

검색 및 치환 작업에는 정말 놀라울 정도로 많은 백슬래시가 사용됩니다. 슬래시를 찾는 정규식을 작성하면, 그 모양이 티라노사우루스의 턱처럼 보이기 시작합니다. Ed는 대체 구분 기호를 지원함으로써 이 문제를 완화합니다. `s` 또는 `g` 명령을 사용할 때, 그 다음에 나오는 문자가 슬래시 대신 사용됩니다. 여기서는 슬래시를 검색하고 싶으므로, 문자 "m" 을 대체 구분 기호로 사용합니다.

```
*gm/
/the/
```

대체 구분 기호는 치환 작업에서도 작동합니다. 여기서는 "@" 를 구분 기호로 사용합니다.

```
*s@nano@heresy
```

다음으로 "m" 을 구분 기호로 사용해서 현재 줄의 첫 번째 "h" 를 삭제합니다.

```
*smh
```

명령을 짧게 만드는 것이 유닉스 방식입니다. 대체 구분자를 사용하면 명령을 좀 더 짧게 만들 수 있습니다.

이제 ed를 대화형으로 사용하는 방법을 잘 이해하셨을 것입니다. 하지만 마무리하기 전에, 스크립트를 통해 ed 명령을 재사용하는 방법을 살펴보겠습니다.




# Chapter 111: Scripting
스크립팅은 시스템 관리에 있어 절대적으로 필수적인 요소입니다. 스크립트에서 ed를 사용하면 특정 작업을 단순화할 뿐만 아니라, 주변의 소위 '시스템 관리자' 라고 자칭하는 하급자들보다 도덕적으로 우월함을 입증할 수 있습니다.

지난 장에서 다룬, 각 줄의 정규 표현식에 밑줄을 그리는 명령을 생각해 보세요. 이 변환을 수행할 때마다 매번 그 모든 내용을 직접 입력하고 싶지는 않겠죠? 재사용이 가능하고 수정할 수 있는 스크립트가 훨씬 더 낫습니다.

스크립팅의 핵심은 ed가 명령어 기반 줄 편집기라는 점을 기억하는 것입니다. 하찮은 편집기들과 달리, ed는 표준 입력에서 명령을 받아들입니다! ed는 사람이 입력한 것과 스크립트가 입력한 것을 구분할 필요가 없습니다. ed 스크립트 내에 주석을 포함할 수는 없지만, 스크립트로 작성된 ed를 실행하는 방법은 매우 다양합니다.


## The Ed Command File
ed를 사용해서 스크립트를 작성하는 가장 쉬운 방법은 실행할 모든 ed 명령어를 포함한 파일을 만든 다음, 다음과 같이 실행하는 것입니다.

```
$ ed textfile < ed-commands.ed
```

명령어 파일에는 실행하려는 ed 명령어만 포함됩니다.

다른 스크립팅 방법을 배울 때와 마찬가지로, 간단하게 시작하세요. 정규 표현식과 일치하는 모든 줄을 복제하는 스크립트를 만들어 보겠습니다. 편집기를 열고
함께 따라 해 보세요.

```
$ ed dup.ed
dup.ed: No such file or directory
P
*H
cannot open input file
*a
g/the/t.
,p
Q
.
*wq
14
$
```

ed 세션을 열고 프롬프트와 상세한 오류 메시지를 활성화합니다. ed는 파일이 존재하지 않는 것을 신경쓰지 않지만, 상세한 오류 메시지를 활성화하면 기존 오류를 알려줍니다. 그런 다음 버퍼에 내용을 추가합니다. 스크립트의 첫 번째 명령어는 지난 장에서 가져온 친숙한 `g/the/t.` 입니다.

검색 및 복사가 완료되면 `,p` 명령어가 파일을 처음부터 끝까지 출력합니다.

스크립트 파일의 마지막 명령어는 `Q` 로, 저장하지 않고 즉시 종료합니다.

점(`.`)을 입력하면 편집 세션의 명령줄로 돌아가고, `wq` 를 입력해서 저장하고 종료할 수 있습니다.

```
$ ed textfile < dup.ed
179
the
the
pony
their
their
…
```

출력의 첫 번째 줄은 텍스트 파일의 바이트 수로, 마치 텍스트 파일을 대화형으로 편집하는 것과 같습니다. 그런 다음 버퍼의 각 줄을 확인할 수 있으므로, 명령 파일이 예상대로 작동하는지 확인할 수 있습니다.

결과가 만족스럽다면, 처리된 파일을 저장하도록 명령 파일을 수정하십시오.

```
$ ed dup.ed
14
P
*H
*,n
1 g/the/t.
2 ,p
3 Q
```

필요한 변경 사항을 고려해 봅시다. 3행에서 더이상 무조건 종료하지 말고, 파일을 저장한 후 종료해야 합니다. 또한 변환 결과를 확인할 필요는 없으므로 2행을
삭제할 수 있습니다. 줄 번호가 이전 출력 결과와 가능한 한 일관성을 유지할 수 있도록 맨 아래부터 편집을 시작하세요.

```
*3s/Q/wq
wq

```

이렇게 하면 `Q` 명령어가 `wq` 로 대체됩니다. Ed는 수정된 줄을 표시합니다. `c` (변경) 명령어를 사용할 수도 있었지만, 정규 표현식 연습을 조금 해보는 것은 결코 나쁠 것이 없습니다. 이제 2번째 줄을 삭제하고, 저장한 후 종료하세요.

```
*2d
*wq
12
```

이제 스크립트가 무엇을 표시하는지 확인해 봅시다.

```
$ ed textfile < dup.ed
179
266
$
```

Ed는 176바이트를 읽고 266바이트를 썼습니다. 텍스트 파일이 변경되었습니다—그리고 무엇보다, ed로 편집할 때는 실수로 화살표 키를 누르는 바람에 변환을 수행한 명령이 엉망이 될 가능성이 전혀 없습니다. 변경한 것은 저장 루틴 뿐입니다.

읽고 쓴 바이트 수를 숨기려면, ed의 `-s` 옵션을 사용하세요.

좀 더 복잡한 것을 원하시나요? 110장에서 했던 것처럼, 한 줄에서 정규 표현식의 마지막 일치 항목을 밑줄로 표시하는 명령 파일은 지난 장의 명령과 명령 스크립트에 필요한 명령 사이에 사소한 차이점이 하나 있습니다. 그 차이점을 찾아보세요.

```
g/the/t.\
s/\(.*\)\(the\).*/x\1\
\2/\
s/./=/g\
-s/./ /g\
s/^ //\
j
wq
```

차이점이 무엇일까요? 스크립트는 작업 내용을 자동으로 저장해야 하므로, `wq` 명령어를 추가했습니다.

일상적인 작업에 ed를 사용하면 소위 "비주얼" 편집기에서만 발생할 수 있는 수많은 오류를 방지할 수 있습니다.


## Ed in Shell Scripts
명령 파일은 일회성 작업에는 괜찮지만, 때로는 ed를 좀 더 복잡한 워크플로에 통합할 때가 있습니다. 명령 파일을 호출하는 셸 스크립트를 작성할 수도 있겠지만, 해당 명령들을 스크립트에 직접 통합하지 않을 이유가 없습니다.

워드프레스를 실행 중인 웹사이트가 아주 많다고 가정해 봅시다. (여러분이 콘텐츠를 그렇게 부적절한 방식으로 제공하진 않겠지만, 대부분의 고객은 유즈넷(Usenet) 같은 건전하고 우아한 기술을 다루지 못할 가능성이 높습니다.) 모든 사이트에 워드펜스(Wordfence) 같은 애플리케이션 방화벽을 배포해야 합니다. Wordfence를 설치하려면 각 사이트의 `.htaccess` 파일을 수정해야 합니다. 오류가 발생하기 쉬운 수동 편집을 수없이 반복할 수도 있지만, ed를 사용해서 체계적이고 안정적으로 해당 편집 작업을 수행할 수도 있습니다.

먼저, 스크립트가 수정할 모든 파일을 찾도록 합니다.

```
#!/bin/sh

for x in /var/www/*/.htaccess
do
```

이제 `echo` 문을 사용해서 ed 명령어를 입력합니다. 확실히 하기 위해 1행 앞에 새 내용을 삽입하기 전에 줄바꿈을 설정했습니다.

```
echo "1
i
# Wordfence WAF
<Files ".user.ini">
<IfModule mod_authz_core.c>
       Require all denied
</IfModule>
<IfModule !mod_authz_core.c>
       Order deny,allow
       Deny from all
</IfModule>
</Files>
# END Wordfence WAF
.
w
q" | ed $x
done
```

마지막 단계에서 대상 파일에 ed 명령을 호출하고, `echo` 문장의 내용을 명령에 전달합니다. 그게 다입니다. 끝났습니다!

만약 `cat(1)` 과 `echo(1)` 의 불필요한 사용을 비난하는 것만이 삶의 유일한 이유인 까다로운 사람들을 두려워한다면, 대신 "here" 문서를 사용할 수도 있습니다. 하지만 적어도 `EOE (End of Ed)` 마커는 사용하세요.

```
ed $x <<EOE
1
i
# Wordfence WAF
<Files ".user.ini">
<IfModule mod_authz_core.c>
Require all denied
</IfModule>
<IfModule !mod_authz_core.c>
Order deny,allow
Deny from all
</IfModule>
</Files>
# END Wordfence WAF
.
w
q
EOE
```

여기까지 읽으셨다면, 이제 소위 시스템 관리자라 자칭하는 대부분의 사람들보다 ed에 대해 좀 더 많이 알고 계실 겁니다. ed를 연습하세요. 실력을 키워가세요. 그리고 다음에 면접에서 화면을 공유하며 실력을 보여줘야 할 때, 초반부터 당신의 우위를 확립하세요. ed를 사용해서요.
