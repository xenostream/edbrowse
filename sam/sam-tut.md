A tutorial for the sam command language

---
[Rob Pike]

**Abstract**

> `sam` 은 정규 표현식을 폭넓게 활용하는 명령어를 갖춘 대화형 텍스트 편집기입니다.  
> 이 언어의 구문은 `ed(1)` 와 유사하지만, 세부 사항은 흥미롭게도 조금 다릅니다.  
> 이 튜토리얼에서 “명령어” 를 소개하지만, 화면 및 마우스 인터페이스는 다루지 않습니다.  
> ‘Ninth Edition Blit’ 소프트웨어에 익숙치 않은 분들께 죄송하지만,  
> 이 수준은 `sam` 이 `mux(9)` 와 매우 유사하므로 sam의 마우스 언어는 쉽게 익힐 수 있을 것으로 가정합니다.  
>  
> `sam` 명령어는 두 가지 환경에서 동일하게 적용됩니다.  
> - 하나는 일반 터미널에서 sam을 실행할 때(`sam -d` 명령어 사용),
> - 다른 하나는 다운로드한 sam 명령 창에서 즉, 비트맵 디스플레이와 마우스를 사용하는 경우입니다.


# Introduction

이 튜토리얼은 Blits 및 비트맵 디스플레이를 갖춘 일부 컴퓨터에서 실행되는 대화형 텍스트 편집기인 `sam` 의 명령어를 설명합니다. 대부분의 편집 작업은 마우스 기반 편집 기능만으로 충분하며, 이 기능들은 사용하기도 쉽고 배우기도 간편합니다.

그러나 전체 변경을 수행할 때는 명령어가 좀 더 유용할 때가 많습니다. 변경을 수행하는 `ed` 명령어와 달리, sam 명령어는 복잡하거나 반복적인 편집 작업에 주로 사용되는 경향이 있습니다. 이런 다소 복잡한 용도에서 sam과 다른 텍스트 편집기 간의 차이가 가장 뚜렷하게 드러납니다.

sam의 명령어는 `sed` 나 `awk` 같은 프로그램을 포함한 다른 편집기들에서 매끄럽게 처리하지 못하는 일부 작업을 쉽게 수행할 수 있으므로, 이 튜토리얼은 부분적으로 sam의 텍스트 조작 방식을 배우는 클래스 역할을 합니다. 따라서 아래 예제들은 sam에서 “마우스 사용법을 최악의 경우라도 쉽게 익힐 수 있다” 고 가정하고, 전적으로 명령어에만 집중합니다. 사실, sam은 `-d` 플래그를 지정해서 마우스 없이(다운로드 없이) 실행할 수 있으며, 이 튜토리얼은 바로 이런 사용 방식에 대해 다룹니다. 이 모드의 명령어도 동일합니다.

> [!NOTE]
> **유닉스 전문가분들께 드리는 말씀**: sam은 구문상 ed와 유사하지만, 설계와 세부적인 의미론 면에서는 근본적으로, 그리고 의도적으로 다릅니다. ed에 대한 지식을 바탕으로 *substitute* 명령어가 어떻게 작동할지 예측할 수 있겠지만, sam의 작동 원리에 대한 이해를 바탕으로 예측해야만 정답을 맞힐 수 있습니다. 특히 관용구 표현에 대해서는 각별히 주의해야 합니다. 관용구는 언어의 기묘한 구석에서 형성되며, 신뢰할 수 없는 특이점에 의존합니다. ed의 관용구는 sam에서 전혀 작동하지 않습니다. `1,$s/a/b/` 는 파일 전체에서 한 번의 치환만 수행할 뿐, 줄마다 치환하지 않습니다. sam만의 고유한 관용구가 있습니다. 이 튜토리얼의 목적 중 하나는 이런 관용구를 공개하고, sam을 능숙하게 다루는 것이 교묘한 요령이 아닌 학습의 문제로 만드는 것입니다.

이 튜토리얼은 정규 표현식에 대한 이해를 전제로 하지만, 좀 더 전통적인 유닉스 편집기에 대한 경험이 있다면 도움이 될 수 있습니다. ed에 익숙한 독자들을 돕기 위해, 대괄호 `[...]` 안에 ed와 sam 간의 차이점 몇 가지를 지적해 두었습니다. 이런 주석은 차이점을 이해하고 싶은 경우만 읽으시기 바랍니다. 이 강의는 sam에 관한 것이지, sam과 ed의 비교에 관한 것이 아닙니다. 또 다른 표기 규칙은 출력 결과는 이 글꼴로 표시되고, 사용자가 입력한 내용은 *기울임체로 표시된다* 는 점입니다.

> [!TIP]
> **용어 설명**: sam은 현재 편집 중인 텍스트의 복사본을 보관합니다. 이 사본을 ‘파일’ 이라 부릅니다. 혼동을 피하기 위해, 디스크에 영구적으로 저장된 것은 ‘유닉스 파일’ 이라 칭하겠습니다.



# Text

시작하려면 연습할 텍스트가 필요합니다. 어떤 텍스트든 상관없습니다. 제임스 고슬링의 Emacs 매뉴얼의 내용을 사용하겠습니다:

```
$ sam -d
a
This manual is organized in a rather haphazard manner. The first
several sections were written hastily in an attempt to provide a
general introduction to the commands in Emacs and to try to show
the method in the madness that is the Emacs command structure.
.
```

`sam -d` 를 실행하면 sam이 시작됩니다. `a` (*append*)명령어는 마침표만 단독 포함된 줄이 나올 때까지의 텍스트를 추가하고, "현재 텍스트"(`dot` 이라 함)를 입력한 내용, 즉 `a` 명령과 마침표 사이의 모든 내용으로 설정합니다. [ed를 사용하면 dot은 마지막 줄로 설정됩니다.] 

`p` (*print*)명령어는 현재 텍스트(`dot`)를 출력합니다:

```
p
This manual is organized in a rather haphazard manner. The first
several sections were written hastily in an attempt to provide a
general introduction to the commands in Emacs and to try to show
the method in the madness that is the Emacs command structure.
```

[다시 말하지만, ed는 마지막 줄만 출력할 것입니다.] 

`a` 명령어는 점(현재 텍스트) 뒤에 텍스트를 추가하고, `i` (*insert*)명령어는 `a` 명령과 비슷하지만 점 앞에 텍스트를 추가합니다.

```
i
Introduction
.
p
Introduction
```

현재 텍스트를 변경(대체)하는 `c` (*change*)명령어와 텍스트를 삭제하는 `d` (*delete*)명령어도 있는데, 이에 대한 예시는 아래에 나와 있습니다.

전체 텍스트를 살펴보려면 출력할 텍스트 범위를 지정해야 합니다. 지금 당장은 “`0,$` 는 파일 전체를 지정한다” 는 점만 알면 충분합니다. [ed 사용자는 `1,$` 를 입력할텐데, 실제 같은 의미지만, 아래 내용을 참고합니다.]

```
0,$p
Introduction
This manual is organized in a rather haphazard manner. The first
several sections were written hastily in an attempt to provide a
general introduction to the commands in Emacs and to try to show
the method in the madness that is the Emacs command structure.
```

아래에서 설명할 `w` (*write*)명령어를 제외하고, `p` 명령어를 포함한 “모든 명령어는 커서(`dot`)를 터치한 텍스트로 설정” 합니다. 따라서 `a` 와 `i` 명령어는 커서를 새로 앱력한 텍스트로, `p` 명령어는 출력한 텍스트로 설정하는 방식입니다. 마찬가지로, `w` 명령어를 제외한 “모든 명령어는 기본적으로 현재 텍스트를 대상으로 작동합니다!” [기본적으로 일부 명령어(예: `g`)만 전체 파일 대상으로 처리하는 ed와 다릅니다].

`dot` (현재 텍스트 또는 점)을 임의로 설정할 수 있기 전까지는 흥미로운 내용이 나오지 않을 것입니다. 이는 파일의 특정 부분을 지정하는 ‘주소’ (*address*)를 통해 이루어집니다. 예를 들어, 주소 1 은 dot을 파일 첫 번째 줄로 설정합니다.

```
1p
Introduction
c
Preamble
.
```

여기서 사용한 `c` 명령어는 별도로 dot을 지정할 필요가 없고, 처음 `p` 명령어로 인해 dot을 첫 번째 줄에 그대로 두었습니다. 

따라서 첫 번째 줄을 삭제하는 것은 매우 쉽습니다. 마지막 명령어로 인해 dot을 첫 번째 줄로 설정했습니다:

```
d
1p
This manual is organized in a rather haphazard manner. The first
```

(파일 변경 사항을 반영해서 내부 줄 번호가 변경됩니다.)

`/text/` 패턴 주소는 dot 뒤에 text 가 처음 나타나는 위치로 dot으로 설정합니다. [ed는 text 가 포함된 첫 번째 줄로 설정합니다.] 

만약 text 가 발견되지 않으면, 검색은 파일 시작 부분에서 다시 시작되고 dot까지 계속됩니다.(wrap around)

```
/Emacs/p
Emacs
```

타이포그래피로 제대로 표현하긴 어렵지만, 위의 예시는 Emacs 뒤에 줄바꿈이 나타나지 않습니다. 출력된 텍스트는 정확히 ‘Emacs’ 문자열 뿐입니다. (또한 마지막 `p` 명령어는 생략해도 됩니다. 이는 “기본 명령어” 이기 때문입니다. 하지만 다운로드 모드로 실행한 sam의 경우, 기본 동작은 텍스트를 선택하고 강조 표시하며, 필요한 경우 파일 창으로 이동해서 텍스트가 화면에 보이도록 처리하는 것입니다. 따라서 /Emacs/ 는 화면에 해당 텍스트가 다음에 나타나는 위치를 의미합니다.)

예를 들어 “haphazard 단어를 thoughtless 로 바꾼다” 고 가정합니다. 여기서 필효한 것은 또 다른 `c` 명령어지만, 지금까지 텍스트를 삽입할 때 사용한 방법은 줄바꿈이 직접 포함되었습니다.(엔터키로 줄바꿈) 이런 줄바꿈 없이 텍스트에 포함하는 구문은 슬래시 문자로 감싸는 것입니다(이는 텍스트 검색 구문과 동일하지만, 어떤 원리로 작용하는지는 문맥으로 명확히 알 수 있을 것입니다).

텍스트는 `c`(또는 `a`, `i`) 명령어 바로 뒤에 와야 합니다. 이를 고려하면 변경을 쉽게 수행할 수 있습니다:

```
/haphazard/c/thoughtless/
1p
This manual is organized in a rather thoughtless manner. The first
```

[텍스트가 한 줄보다 짧더라도 `c` 명령어로 변경할 수 있습니다.]

이런 방식으로 명령어에 텍스트를 직접 입력하는 것이 여러 줄로 구성된 구문보다 훨씬 더 흔하게 사용된다는 것을 잘 알게될 것입니다. 텍스트에 슬래시 / 자체를 포함시키려면, 그 앞에 백슬래시 `\` 문자를 붙이고, 백슬래시 자체를 보호하려면 백슬래시를 한 번 더 사용하면 됩니다.

```
/Emacs/c/Emacs\\360/
4p
general introduction to the commands in Emacs\360 and to try to show
```

다음과 같은 방법으로 적용할 수도 있습니다.

```
/Emacs/a/\\360/
```

이쯤에서 `u` (*undo*)명령어를 소개하겠습니다. 이 명령어는 마지막으로 실행한 명령을 (실행) 취소합니다. `u` 를 한 번 더 입력하면 직전 명령이 취소되며, 이와 같은 방식으로 계속 실행 취소할 수 있습니다.

```
u
4p
general introduction to the commands in Emacs and to try to show
u
3p
This manual is organized in a rather haphazard manner. The first
```

되돌리기 명령어는 뒤로만 갈 수 있으며, 이전 `u` 명령어를 되돌릴 방법은 없습니다.



# Addresses

지금까지 주소의 가장 간단한 형태를 살펴봤지만, 좀 더 깊이 들어가기 전에 배워야 할 내용이 있습니다.

주소는 파일 내의 특정 영역, 즉 “부분 문자열을 지정” 하므로 해당 영역의 시작점과 끝점을 정의해야 합니다. 따라서 주소 13 은 13번째 줄 시작부터 13번째 줄 끝까지를 지정하며, /Emacs/ 는 ‘Emacs’ 단어의 시작부터 끝까지를 지정합니다.

주소는 쉼표로 결합할 수 있습니다:

```
13,15
```

13행부터 15행까지 선택합니다. 쉼표 연산자의 정의는 왼쪽 주소 시작 부분(13행의 시작)부터 오른쪽 주소 끝 부분(15행의 끝)까지 선택하는 것입니다.

몇 가지 특별한 주소는 유용하게 쓰입니다: 

- `.` (마침표)는 현재 텍스트를 나타내고, 
- `0` (0행)은 파일 시작 부분의 빈 문자열을 선택하며, 
- `$` 는 파일 끝 부분의 빈 문자열을 선택합니다 [파일 마지막 행이 아닙니다!] 

따라서,

```
0,13
```

주소는 파일 시작 부분부터 13번째 줄 끝 부분까지 선택하고,

```
.,$
```

주소는 현재 텍스트(`dot`)의 시작 부분부터 파일 끝 부분까지 선택하며,

```
0,$
```

주소는 “파일 전체” 를 선택합니다. [즉, 파일 내의 모든 줄이 아니라 파일 전체를 포함하는 단일 문자열입니다.]

이것들 모두 “절대 주소” 로, 파일 내의 특정 위치를 가리킵니다. 

sam은 dot 값에 따라 결정되는 “상대 주소” 도 있으며, 이미 한 가지 형태를 살펴봤습니다: /Emacs/ 는 dot 기준으로 앞(방향)으로 검색해서 Emacs 가 처음 나타나는 위치를 찾습니다. 어떤 Emacs 가 발견될는 dot 값에 따라 달라집니다. 

만약 dot 앞(방향)의 첫 번째 Emacs 를 찾는다면 어떻게 해야 할까요? 패턴 앞에 마이너스 기호를 붙이면 됩니다. 이렇게 하면 검색 방향이 반대로 바뀝니다:

```
-/Emacs/
```

사실, 앞(방향)으로 검색하는 완전한 구문은

```
+/Emacs/
```

지만, 플러스 기호는 "기본값" 으로 거의 사용하지 않습니다. 

이해를 돕기 위해 이를 포함한 완전한 예제를 보여드리겠습니다:

```
0+/Emacs/
```

는 파일에서 Emacs 가 처음 나타나는 위치를 선택합니다. 이를 “0번째 줄로 이동한 다음, 앞(방향)으로 ‘Emacs’ 를 검색하라!” 고 해석하면 됩니다.

여기서 ‘+’ 는 “선택 사항” 으로, `0/Emacs/` 으로 쓸 수 있습니다. 마찬가지로,

```
$-/Emacs/
```

는 파일에서 Emacs 가 마지막으로 나타나는 위치를 찾으므로,

```
0/Emacs/,$-/Emacs/
```

는 첫 번째 Emacs 부터 마지막 Emacs 까지(두 개 모두 포함)의 텍스트를 선택합니다. 

좀 더 흥미로운 예로는:

```
/Emacs/+/Emacs/
```

(시작 부분에 묵시적인 `.+` 주소가 있습니다)는 점 뒤에 오는 두 번째 Emacs 를 선택합니다.

또한 줄 번호는 상대적일 수 있습니다.

```
-2
```

는 바로 앞의 두 번째 줄을 선택하고,

```
+5
```

는 바로 뒤의 다섯 번째 줄을 선택합니다(여기서 더하기 기호는 **필수** 입니다).

주소는 한 줄 이상 선택할 수 있으므로(dot도 한 줄 이상일 수 있으므로), ‘앞’ 과 ‘뒤’ 에 대한 정의가 필요합니다. “‘앞’ 은 dot 시작 지점 이전” 을 의미하고, “‘뒤’ 는 dot 끝 지점 이후” 를 의미합니다.

예를 들어, 파일에 A*AA*A 가 포함되어 있고, 점(dot)이 가운데 두 개의 AA (기울어진 문자)로 설정된 경우, `-/A/` 는 점을 첫 번째 A에, `+/A/` 는 점을 마지막 A에 설정합니다. 특이한 상황(예: 파일에서 해당 텍스트가 현재 텍스트인 경우 등)을 제외하고, 검색으로 선택된 텍스트는 점과 분리됩니다.

길이에 상관없이 dot을 포함하는 troff -ms 단락을 선택하려면:

```
-/.PP/,/.PP/-1
```

주소를 사용합니다. 이 명령은 단락을 시작하는 .PP 는 포함하고, 단락을 끝내는 .PP 는 제외합니다.

상대 주소를 입력할 때의 기본은 1 이므로, 위의 명령을 좀 더 간단히 다음과 같이 작성할 수 있습니다:

```
-/.PP/,/.PP/-
```

주소 `+1-1` 또는 이에 상응하는 `+-` 주소는 무엇을 의미할까요? 아무런 효과도 없는 것처럼 보이지만, "dot이 반드시 완전한 한 줄의 텍스트일 필요는 없다!" 는 점을 떠올려 봅니다. 따라서 `+1` 은 현재 텍스트의 끝 다음 줄을 선택하고, `-1` 은 시작 전의 줄을 선택합니다. 따라서 `+1-1` 은 점(.)의 끝 다음 줄 바로 앞의 줄, 즉 점(`.`)의 끝을 포함하는 “전체 줄을 선택” 합니다. 이 구문을 사용해서 선택 범위를 확장해서 전체 줄을 포함시킬 수 있습니다.

예를 들어, 파일 첫 번째 줄에 Emacs 가 포함되면:

```
0/Emacs/+-p
general introduction to the commands in Emacs and to try to show
```

여기서 사용한 `+-` 주소는 **sam의 관용구** 입니다.



# Loops

앞서 Emacs 가 등장하는 한 곳만 Emacs\360 으로 변경했지만, 편집기 이름이 실제로 바뀌는 경우라면 한 번의 명령으로 해당 이름이 등장하는 모든 부분을 변경하는 것은 매우 유용할 것입니다. sam은 바로 이런 작업을 위한 `x` (*extract*) 명령을 제공합니다. 구문은 `x/패턴/명령` 형식입니다. 선택된 텍스트에서 패턴이 나타나는 각 위치마다, `x` 명령어는 dot에 해당 위치를 설정하고 지정한 명령을 실행합니다.

예를 들어, Emacs 를 vi 로 변경하려면,

```
0,$x/Emacs/c/vi/
0,$p
This manual is organized in a rather haphazard manner. The first
several sections were written hastily in an attempt to provide a
general introduction to the commands in vi and to try to show
the method in the madness that is the vi command structure.
```

이 명령은 현재 텍스트(`0,$` — 파일 전체)를 텍스트 인수(Emacs)가 나타나는 부분들로 세분화한 다음, 점(.)을 해당 텍스트로 설정하고 뒤따르는 명령어(`c/vi/`)를 실행하는 방식으로 작동합니다. 이 예제는 다음과 같이 해석할 수 있습니다.

“파일에서 ‘Emacs’ 가 나타나는 모든 부분을 찾고, 각 부분마다 현재 텍스트를 해당 부분으로 설정하고 `c/vi/` 명령을 실행해서, 현재 텍스트를 vi 로 대체한다!” [이 명령은 ed의 `g` 명령과 다소 유사합니다. 유일한 차이점은 아래에 설명하겠지만, 기본 주소는 언제나 그렇듯이 전체 파일이 아닌 ‘.’ 임을 유의합니다.]

`x` 명령으로 몇 번의 변경을 일으키든지 상관없이, 단 한 번의 `u` 명령으로 `x` 명령을 실행 취소할 수 있습니다!!

```
u
0,$p
This manual is organized in a rather haphazard manner. The first
several sections were written hastily in an attempt to provide a
general introduction to the commands in Emacs and to try to show
the method in the madness that is the Emacs command structure.
```

물론, `x` 명령어에 사용할 수 있는 명령은 `c` 명령어 뿐만이 아닙니다. `a` 명령어를 사용하면 Emacs 에 독점 표시를 넣을 수 있습니다:

```
0,$x/Emacs/a/{TM}/
/Emacs/+-p
```

Emacs{TM} 은 명령어에 대한 일반적인 소개이자 다음 명령을 보여주기 위한 시도입니다. [ed의 `g/Emacs/s//&{TM}/p` 같이 변경 사항이 발생하는 즉시 확인할 방법은 없습니다. 아래 ‘다중 변경’ 섹션을 참조합니다.]

`p` 명령어는 `x` 명령어로 호출할 때도 유용하겠지만, 의도한 바를 정확히 표현해야 한다는 점에 주의해야 합니다.

```
0,$x/Emacs/p
EmacsEmacs
```

`x` 명령어는 슬래시 안의 텍스트를 dot에 할당하므로, 이처럼 해당 텍스트만 출력하는 것은 별다른 정보를 제공하지 못합니다. 하지만 `x` 명령어로 실행하는 명령어에는 주소를 포함할 수 있습니다.

예를 들어, Emacs 가 포함된 모든 줄을 출력하려면 단순히 `+-` 관용구를 사용하면 됩니다:

```
0,$x/Emacs/+-p
general introduction to the commands in Emacs{TM} and to try to show
the method in the madness that is the Emacs{TM} command structure.
```

마지막으로, 또 다른 `x` 명령어를 사용해서 파일 상태를 이전으로 복원하고, 편리한 약어도 활용하겠습니다. 

주소에 쉼표가 포함되면 왼쪽 부분은 기본적으로 0 으로, 오른쪽 부분은 기본적으로 $ 로 가정하므로, 입력하기 쉬운 주소인 `,` 는 "파일 전체" 를 의미합니다:

```
,x/Emacs/ /{TM}/d
,p
This manual is organized in a rather haphazard manner. The first
several sections were written hastily in an attempt to provide a
general introduction to the commands in Emacs and to try to show
the method in the madness that is the Emacs command structure.
```

이 `x` 명령어가 무엇을 처리하는지 주목합니다: Emacs 가 나타날 때마다 그 뒤에 오는 {TM} 을 찾아서 삭제합니다.

sam에서 주소나 `x` 명령어로 검색할 때 사용하는 ‘텍스트’ 는 단순한 텍스트가 아니라 "정규 표현식" 입니다. 유닉스는 정규 표현식에 대한 몇 가지 서로 다른 해석 방식이 있습니다. sam이 사용하는 형식은 `regexp(6)` 으로, 그룹화를 위한 괄호 `(...)` 와 문자열을 병렬로 일치시키기 위한 ‘또는’ 연산자인 `|` 를 포함합니다. 또한 sam은 `\n` 을 줄바꿈 문자로 인식합니다. `a` 및 `c` 명령어에 사용되는 대체 텍스트는 여전히 일반 텍스트지만, `\n` 시퀀스는 그 맥락에서도 줄바꿈을 의미합니다.

다음은 예시입니다. 문서의 줄 간격을 두 배로 늘린다고 가정합니다. 즉, 모든 줄바꿈을 줄바꿈 두개로 바꾸는 작업입니다.

다음 명령어들 모두 이 작업을 수행합니다:

```
,x/\n/ a/\n/
,x/\n/ c/\n\n/
,x/$/ a/\n/
,x/ˆ/ i/\n/
```

마지막 예제는 줄 앞 부분에 줄바꿈을 삽입하기 때문에 처리 형식이 다릅니다. 다른 예제들은 줄바꿈을 뒤 부분에 삽입합니다. 또한 처음 두 예제는 줄바꿈을 직접 조작합니다. [ed가 처리할 수 없는 부분입니다]; 마지막 두 예제는 정규 표현식을 사용합니다: `$` 는 줄 끝의 빈 문자열, `ˆ` 는 줄 시작의 빈 문자열을 의미합니다.

위의 해결책 모두 잠재적인 단점이 있습니다. 이미 빈 줄(즉, 연속된 두 개의 줄바꿈)이 있는 경우, 훨씬 더 길게(연속된 네 개의 줄바꿈) 만들어 버립니다. 좀 더 나은 방법은 모든 줄바꿈 그룹을 하나씩 늘리는 것입니다:

```
,x/\n+/ a/\n/
```

정규식 연산자 `+` 는 ‘하나 이상’ 을 의미합니다. `\n+` 는 `\n\n*` 과 동일합니다. 따라서 이 예제는 모든 줄바꿈 시퀀스 끝에 줄바꿈을 추가합니다.

좀 더 흔한 예로 텍스트 블록을 탭 정지 위치만큼 들여쓰는 것입니다. 다음 예제 모두 정상 작동하지만, 첫 번째 예제가 가장 깔끔합니다(슬래시 안의 빈 텍스트는 탭을 의미합니다):

```
,x/ˆ/a/ /
,x/ˆ/c/ /
,x/.*\n/i/  /
```

마지막 예제는 `.*\n` 패턴(사실 관용구)을 사용해서 줄을 일치시킵니다. `.*` 는 줄바꿈 문자가 아닌 문자로 구성된 가능한 가장 긴 문자열과 일치합니다.

앞 예제에서 추가한 탭을 제거하는 것도 쉽습니다:

```
,x/ˆ /d
```

이 예제들은 주소(전체 파일)를 지정했지만, 실제로 이런 명령은 주소 지정없이 실행하고, 마우스로 텍스트를 선택해서 설정된 점(.)의 값으로 사용하는 경우가 더 많습니다.


# Conditionals

`x` 명령어는 반복 구조입니다. 정규 표현식과 일치하는 항목이 있을 때마다, 해당 항목을 추출(dot에 할당)하고 명령어를 실행합니다. sam에는 조건문인 `g` (*guard*) 명령어도 있습니다. `g/패턴/명령어` 는 dot에 해당 패턴과 일치하는 항목이 포함되어 있을 경우, dot의 값을 변경하지 않고 명령어를 실행합니다. 그 반대인 `v` (*reverse*)는 dot에 해당 패턴과 일치하는 항목이 포함되어 있지 않을 경우 명령어를 실행합니다. (문자 `g` 와 `v` 는 역사적으로 유래된 것으로, 기억을 돕는 특별한 의미는 없습니다. `g` 를 ‘가드(guard)’ 로 생각해도 좋습니다.) [ed 사용자는 위의 정의를 매우 주의 깊게 읽어야 합니다. sam의 `g` 명령어는 ed의 `g` 명령어와 근본적으로 다릅니다!]

다음은 `x` 명령어와 `g` 명령어의 차이점을 보여주는 예시입니다:

```
,x/Emacs/c/vi/
```

는 파일 내의 ‘Emacs’ 라는 단어가 나오는 모든 곳을 ‘vi’ 로 변경하지만,

```
,g/Emacs/c/vi/
```

는 파일 내 어디든 ‘Emacs’ 라는 단어가 (하나라도) 있으면 파일 전체를 ‘vi’ 로 변경합니다!!

이 두 명령어 중 어느 것도 단독으로는 특별히 흥미롭지 않지만, `x` 명령어와 결합하거나 서로 결합할 때 유용합니다.


# Composition

`x` 명령어를 이해하는 한 가지 방법은, 선택 영역(dot의 값)이 주어지면 이 명령어가 관심 있는 하위 선택 영역(dot의 값 내부의 영역)을 차례로 탐색한다고 보는 것입니다. 다시 말해, 텍스트의 일부를 가져와서 이를 좀 더 작은 조각들로 잘라내는 것입니다. 하지만 이렇게 잘라내는 텍스트는 이미 이전 `x` 명령어로 잘라낸 부분일 수도 있고, `g` 명령어로 선택된 부분일 수도 있습니다.

`x` 명령어의 가장 흥미로운 특징은 특정 작업을 수행하기 위해 "일련의 명령어를 정의할 수 있다!" 는 점입니다.[^1]

[^1]: 쉘 파이프라인과 명백한 유사성은 부분적으로만 타당합니다. 개별 sam 명령어들 모두 동일한 텍스트를 처리하고 있으며, 달라지는 것은 텍스트가 어떻게 분할되느냐 하는 점 뿐이기 때문입니다.

간단한 예로, Emacs 가 나오는 모든 부분을 emacs 로 바꾸는 경우를 들 수 있습니다. 물론

```
,x/Emacs/ c/emacs/
```

도 작동하겠지만, `x` 명령어를 사용하면 Emacs 라는 단어 대부분을 다시 입력하는 수고를 덜 수 있습니다:

```
,x/Emacs/ x/E/ c/e/
```

(한 줄에 있는 명령어들을 구분하기 위해 공백을 사용하면 가독성이 높아집니다!)

이 명령어가 처리하는 일은 Emacs(`,x/Emacs/`)가 나타나는 모든 곳을 찾은 다음, 커서를 해당 텍스트에 맞춘 상태에서 문자 E(`x/E/`)가 나타나는 모든 곳을 찾고, 다시 커서를 해당 텍스트에 맞춘 상태에서 `c/e/` 명령을 실행해서 해당 문자를 소문자로 변경하는 것입니다. 명령의 주소(쉼표로 지정된 전체 파일)는 명령어 가장 왼쪽 부분에만 지정된다는 점에 유의합니다. 나머지 부분들은 왼쪽에 있는 부분들이 실행됨에 따라 자동으로 ‘.’ (현재 텍스트)가 설정됩니다.

또 다른 간단한 예로, 앞서 해결한 문제인 파일 내에서 Emacs 라는 단어가 포함된 모든 줄을 출력하는 경우를 생각해 보겠습니다:

```
,x/.*\n/ g/Emacs/p
general introduction to the commands in Emacs and to try to show
the method in the madness that is the Emacs command structure.
```

이 명령어는 파일을 줄 단위로 분할하고(`,x/.*\n/`), Emacs(`g/Emacs/`)라는 문자열이 포함된 각 줄에, `.` 을 해당 줄(Emacs 와 일치하는 부분이 아님)로 설정해서 `p` 명령어로 해당 줄을 출력하도록 처리합니다. 입력 수고를 줄이기 위해, `.*\n` 은 `x` 명령어에 흔히 사용하는 패턴이므로, `x` 명령어 뒤에 곧바로 공백이 따를 경우 `.*\n` 패턴으로 간주됩니다.

따라서 위의 명령은 다음과 같이 좀 더 간결하게 작성할 수 있습니다:

```
,x g/Emacs/p
```

이전에 사용했던 해결책은

```
,x/Emacs/+-p
```

였는데, 이는 파일 내에서 Emacs 가 일치하는 각 위치에 점(.)을 설정하고 `+-p` 명령어를 실행하는 방식입니다(`+-p` 구문은 점(.)으로 끝나는 줄을 출력한다는 점을 기억합니다).

두 명령 모두 대개 동일한 결과를 산출합니다(`+-p` 형식은 한 줄에 Emacs 가 두 번 포함되면 해당 줄을 두 번 출력합니다). 어느 쪽이 더 나을까요?

- `,x/Emacs/+-p` 는 입력하기 쉽고, 파일이 크고 해당 문자열의 출현 횟수가 적을 경우는 훨씬 빠르겠지만, 이는 사실 매우 특이한 예외적인 경우입니다.
- `,x/.*\n/ g/Emacs/p` 는 좀 더 느리지만—각 줄을 따로 분리한 다음 일치하는 부분이 있는지 검사하기 때문입니다—하지만 개념적으로 좀 더 깔끔하고, 일반화하기도 쉽습니다.

예를 들어, 다음 Emacs 매뉴얼의 일부를 살펴보겠습니다:

```
command name="append-to-file", key="[unbound]"
Takes the contents of the current buffer and appends it to the
named file. If the file doesn’t exist, it will be created.
command name="apropos", key="ESC-?"
Prompts for a keyword and then prints a list of those commands
whose short description contains that keyword. For example,
if you forget which commands deal with windows, just type
"@b[ESC-?]@t[window]@b[ESC]".
```

이 텍스트는 비어 있지 않은 줄들로 구성된 그룹들로 이루어져 있으며, 각 그룹 내의 텍스트는 간단한 형식을 따릅니다. ‘apropos’ 명령어에 대한 설명을 찾는다고 가정합니다. 여기서 문제는 파일을 개별 설명들로 분할한 다음, ‘apropos’ 에 대한 설명을 찾아 출력하는 것입니다. 해결 방법은 간단합니다:

```
,x/(.+\n)+/ g/command name="apropos"/p
command name="apropos", key="ESC-?"
Prompts for a keyword and then prints a list of those commands
whose short description contains that keyword. For example,
if you forget which commands deal with windows, just type
"@b[ESC-?]@t[window]@b[ESC]".
```

정규 표현식 (`.+\n)+` 는 각각 하나 이상의 문자로 구성된 하나 이상의 줄, 즉 빈 줄 사이에 있는 텍스트를 일치시킵니다. 따라서 `,x/(.+\n)+/` 는 각 설명을 추출하고, `g/command name="apropos"/` 는 ‘apropos’ 에 대한 설명을 선택하며, `p` 명령어는 이를 출력합니다.

변수 n 이 포함된 C 프로그램이 있는데, 이를 num 으로 변경한다고 가정합니다. 다음 명령은 첫 번째 시도입니다:

```
,x/n/ c/num/
```

하지만 이 명령은 명백한 결함이 있습니다. 식별자 n 뿐만 아니라 파일 내의 모든 n 문자를 변경하기 때문입니다. 좀 더 나은 해결책은 `x` 명령어를 사용해서 식별자만 추출한 다음, `g` 명령어를 사용해서 n 문자를 찾는 것입니다:

```
,x/[a-zA-Z_][a-zA-Z_0-9]*/ g/n/ v/../ c/num/
```

보기에는 끔찍해 보이지만, 왼쪽에서 오른쪽으로 읽어 보면 꽤 이해하기 쉽습니다. C 식별자는 알파벳이나 밑줄(_) 뒤에 0개 이상의 영숫자나 밑줄이 오는 형태로, 즉 정규 표현식 `[a-zA-Z_][a-zA-Z_0-9]*` 와 일치하는 것입니다. `g` 명령어는 n 문자를 포함하는 식별자를 선택하고, `v` 명령어는 일종의 트릭으로, 두 글자 이상을 포함하는 식별자는 제외합니다. 따라서 `c/num/` 은 단독으로 사용한 n 문자만 적용됩니다.

여기에는 여전히 문제가 하나 더 있습니다. 바로 문자 상수 `\n` 에 포함된 n 문자는 변경하지 않아야 한다는 점입니다. `x` 명령어와 상호 보완적인 `y` 명령어가 있는데, 이것이 바로 여기에 필요한 것입니다. `y/패턴/명령어` 는 패턴에 일치하는 부분들 사이의 텍스트에 해당 명령어를 실행합니다. `x` 명령어가 선택한다면 `y` 명령어는 거부합니다.

다음은 최종 명령어입니다:

```
,y/\\n/ x/[a-zA-Z_][a-zA-Z_0-9]*/ g/n/ v/../ c/num/
```

`y/\\n/` (리터럴 문자로 처리하기 위해 백슬래시를 두 번 사용)은 두 글자 시퀀스 `\n` 을 처리 대상에서 제외하므로, 명령어의 나머지 부분은 이를 건드리지 않습니다. 여기서 좀 더 처리할 수 있는 작업이 있습니다.

예를 들어, 코드 내 주석을 보호하기 위해 앞에 `y` 명령어를 하나 더 붙일 수도 있습니다. 이 예제는 더 이상 자세히 설명하지 않겠지만, sam의 반복 및 조건부 명령어를 어떻게 조합해서 흥미로운 작업을 수행할 수 있는지 대략적인 감을 잡으셨기를 바랍니다.



# Grouping

명령을 배열하는 또 다른 방법이 있습니다. 명령을 중괄호 `{...}` 로 묶으면, 명령을 병렬로 실행할 수 있습니다.

이 예제는 `=` 명령어를 사용해서 dot (현재 텍스트)의 줄 번호와 문자 번호를 표시하고, `p` 명령어로 원래 파일에서 Emacs 가 나타나는 위치를 보고합니다:

```
,p
This manual is organized in a rather haphazard manner. The first
several sections were written hastily in an attempt to provide a
general introduction to the commands in Emacs and to try to show
the method in the madness that is the Emacs command structure.
,x/Emacs/{
=
+-p
}
3; #171,#176
general introduction to the commands in Emacs and to try to show
4; #234,#239
the method in the madness that is the Emacs command structure.
```

(세미콜론 앞의 숫자는 줄 번호이며, # 문자로 시작하는 숫자는 문자 번호입니다.)

좀 더 흥미로운 예로, Emacs 가 나오는 모든 부분을 vi 로, vi 가 나오는 모든 부분을 Emacs 로 바꾸는 경우를 가정합니다. 다음과 같이 입력할 수 있습니다.

```
,x/Emacs|vi/{
    g/Emacs/ c/vi/
    g/vi/ c/Emacs/
}
```

또는 심지어

```
,x/[a-zA-Z]+/{
    g/Emacs/ v/....../ c/vi/
    g/vi/ v/.../ c/Emacs/
}
```

와 같이 입력해서 단어 속에 포함된 문자열은 변경되지 않도록 처리할 수 있습니다.



# Multiple Changes

위의 예시에서 Emacs 가 vi 로 변경된 후, 중괄호 안의 두 번째 명령이 왜 다시 원래대로 되돌리지 않았는지 궁금할 수 있습니다. 그 이유는 명령들이 병렬로 실행되기 때문입니다.

어떤 최상위 sam 명령 내에서는, 파일에 대한 모든 변경 사항이 해당 명령에서 어떤 변경도 적용되기 이전의 파일 상태를 참조합니다. 모든 변경 사항이 결정된 이후에는, 변경 사항들이 모두 동시에 적용됩니다. 이는 앞서 언급한 것 같이, 복합 명령 내의 명령들이 변경 사항이 적용되기 이전의 파일 상태를 인식한다는 것을 의미합니다. 이런 평가 방식은 어떤 면에서는 (예: Emacs 와 vi 의
교환 같이) 작업을 좀 더 쉽게 만들어 주지만, 어떤 면에서는 좀 더 어렵게 만듭니다.

예를 들어, `p` 명령어를 사용해서 변경 사항이 발생하는 즉시 이를 출력하는 것은 불가능합니다. `p` 명령어가 실행될 때 변경 사항은 아직까지 발생하지 않았기 때문입니다. 이로 인한 간접적인
파급 효과로, 변경 사항은 파일 전체에 걸쳐 순차적으로 발생해야 하며, 서로 겹쳐서는 안 됩니다.



# Unix

sam에는 유닉스 프로세스에 연결하는 몇 가지 명령어가 있습니다. 가장 간단한 것은 `!` 명령어로, 이 명령어는 입출력을 터미널에 연결한 상태로 명령을 실행합니다.

```
!date
Wed May 28 23:25:21 EDT 1986
!
```

(다운로드 모드로 실행 시, 입력은 `/dev/null` 로 연결되며 출력의 첫 몇 줄만 표시됩니다. 나머지 초과된 내용은 `$HOME/sam.err` 파일에 저장됩니다.) 마지막 `!` 문자는 명령이 완료되었음을 나타내는 프롬프트입니다. 좀 더 흥미로운 것은 `>` 로, 현재 텍스트를 유닉스 명령의 표준 입력으로 제공합니다:

```
1,2 >wc
2 22 131
!
```

`>` 의 반대 개념은 당연히 `<` 입니다. 이는 현재 텍스트를 유닉스 명령의 표준 출력으로 대체합니다:

```
1 <date
!
1p
Wed May 28 23:26:44 EDT 1986
```

마지막 명령어는 `|` 로, `<` 와 `>` 의 조합입니다. 현재 텍스트가 유닉스 명령어의 표준 입력으로 제공되고, 유닉스 명령어의 표준 출력이 수집되어 원래 텍스트를 대체하는 데 사용됩니다. 예를 들어,

```
,| sort
```

는 파일에 대해 `sort(1)` 를 실행해서 텍스트의 각 줄을 사전순으로 정렬합니다. `<`, `>` 및 `|` 는 유닉스 셸 연산자가 아니라 sam의 명령어라는 점에 유의합니다.

다음 예제는 `tr(1)` 을 사용해서 Emacs 가 나타나는 모든 부분을 대문자로 변환합니다:

```
,x/Emacs/ | tr a-z A-Z
```

`tr` 은 Emacs 가 나타나는 각 위치마다 한 번씩 실행됩니다. 물론, 이 예제는 간단한 `c` 명령을 사용해서 좀 더 효율적으로 처리할 수도 있었지만, 여기 좀 더 까다로운 예제가 있습니다. 입력으로 유닉스 메일함이 주어졌을 때, 모든 Subject 헤더를 서로 다른 fortune 문구로 변환하는 것입니다:

```
,x/ˆSubject:.*\n/ x/[ˆ:]*\n/ < /usr/games/fortune
```

(정규 표현식 `[ˆ:]` 는 `:` 과 줄바꿈을 제외한 모든 문자를 의미하며, 부정 연산자 `ˆ` 는 문자 목록에서 줄바꿈 문자를 제외합니다.) 다시 말해, `/usr/games/fortune` 은 각 ‘Subject’ 줄마다 한 번씩 실행되므로, 각 ‘Subject’ 줄은 서로 다른 fortune 문구로 변경됩니다.


# A few other text commands

완전성을 기하기 위해, 텍스트를 조작하는 세 가지 명령에 대해 언급해야겠습니다. `m` (*move*)명령은 현재 텍스트를 명령 뒤에 (반드시 지정해야 하는) 주소로 지정한 텍스트 뒤쪽으로 이동시킵니다. 따라서

```
/Emacs/+- m 0
```

은 Emacs 가 포함된 다음 줄을 파일의 맨 앞으로 이동시킵니다. 마찬가지로, `t` (*transfer* - 또 다른 역사적인 문자)는 텍스트를 복사합니다:

```
/Emacs/+- t 0
```

은 파일 맨 앞에 ‘Emacs’ 가 포함된 다음 줄의 복사본을 생성합니다.

세 번째 명령어는 좀 더 흥미롭습니다. 바로 치환을 수행하는 `s` 명령어입니다. 구문은 `s/패턴/치환문자열/` 입니다. 이 명령어는 현재 텍스트 내에서 패턴이 처음 나타나는 위치를 찾아 치환문자열로 바꾸며, 점(.) 변수에는 치환 작업의 전체 주소가 저장됩니다.

```
1p
This manual is organized in a rather haphazard manner. The first
s/haphazard/thoughtless/
p
This manual is organized in a rather thoughtless manner. The first
```

대체 텍스트에서 `&` 문자가 나타나는 부분은 패턴과 일치하는 텍스트를 나타냅니다.

```
s/T/"&&&&"/
p
"TTTT"his manual is organized in a rather thoughtless manner. The first
```

두 가지 변형이 있습니다. 첫 번째는 `s` 명령어 뒤에 숫자를 지정해서 패턴 중 어느 부분을 대체할지 지정할 수 있다는 점이며, 기본값은 첫 번째입니다.

```
s2/is/was/
p
"TTTT"his manual was organized in a rather thoughtless manner. The first
```

두 번째는 `g` (*global*) 접미사를 붙이면 첫 번째 발생 위치뿐만 아니라 모든 발생 위치가 대체된다는 점입니다.

```
s/[a-zA-Z]/x/g
p
"xxxx"xxx xxxxxx xxx xxxxxxxxx xx x xxxxxx xxxxxxxxxxx xxxxxxx xxx xxxxx
```

이 모든 예제에서 ‘dot’ 이 줄 전체로 설정된 채로 남아 있다는 점에 유의합니다.

[*substitute* 대체 명령어는 한 줄 내에서 변경을 가할 수 있는 유일한 방법이기 때문에 ed에서 매우 중요합니다. 반면, 줄 개념이 그다지 중요하지 않은 sam에서는 그 유용성이 떨어집니다. 예를 들어, ed의 많은 대체 관용구들은 sam의 기본 명령어도 잘 처리됩니다. 다음 명령어들을 살펴보시기 바랍니다.

```
s/good/bad/
s/good//
s/good/& bye/
```

를 가정합니다. 이 명령들은 sam에서는

```
/good/c/bad/
/good/d
/good/a/ bye/
```

와 동등하며, 원하는 텍스트가 이미 ‘dot’ 이므로 문맥 검색 작업은 불필요할 가능성이 높습니다. 또한, 다음과 같은 ed 관용구를 주의합니다:

```
1,$s/good/bad/
```

이는 각 줄의 첫 번째 ‘good’ 을 변경하지만, sam에서 동일한 명령을 사용하면 전체 파일에서 첫 번째 ‘good’ 만 변경됩니다. 올바른 sma 버전은

```
,x s/good/bad/
```

지만, 실제로 의도한 것은

```
,x/good/ c/bad/
```

일 가능성이 높습니다. sam은 다른 규칙에 따라 작동합니다.]


# Files

지금까지 단일 파일만 다루었지만, sam은 다중 파일 편집기입니다. 한 번에 하나의 파일만 편집할 수 있지만, 편집할 ‘현재’ 파일을 변경하는 것은 매우 쉽습니다. 이를 수행하는 방법을 알아보려면, 몇 개의 파일이 포함된 sam이 필요합니다. 가장 쉬운 방법은 편집할 유닉스 파일 이름 목록을 지정해서 sam을 실행하는 것입니다.

```
$ echo *.ms
conquest.ms death.ms emacs.ms famine.ms slaughter.ms
$ sam -d *.ms
-. conquest.ms
```

(네, 기사가 전통 순서대로 나타나지 않아서 죄송합니다.) sam이 출력한 이 줄은 유닉스 파일 conquest.ms 가 읽혀졌으며, 이제 "현재 파일" 이 되었음을 나타냅니다. sam은 관련된 sam 파일이 현재 파일이 될 때까지 유닉스 파일을 읽지 않습니다.

`n` (*name*)명령어는 모든 파일의 이름을 출력합니다:

```
n
-. conquest.ms
- death.ms
- emacs.ms
- famine.ms
- slaughter.ms
```

이 목록은 마우스 3번 버튼을 클릭해서 GUI 메뉴에서 확인할 수 있습니다. `f` (*filename*)명령어는 현재 파일의 이름만 알려줍니다:

```
f
-. conquest.ms
```

파일 이름 왼쪽에 있는 문자들은 해당 파일에 대한 유용한 정보를 나타냅니다.

- 마이너스 기호는 파일에 열려 있는 창이 하나면 플러스 기호로, 두 개 이상 열려 있으면 별표로 바뀝니다.
- 마침표(dot의 또 다른 의미)는 현재 파일을 나타냅니다.
- 파일의 앞부분에 있는 공백은 sam이 인식하는 한 해당 파일이 연관된 유닉스 파일의 내용과 다를 경우 아포스트로피로 바뀝니다.

이는 파일에 변경 사항을 적용하면 명확해집니다.

```
1d
f
’-. conquest.ms
```

'실행 취소' 명령으로 파일을 복원하면 아포스트로피는 다시 사라집니다.

```
u
f
-. conquest.ms
```

`f 명령을 사용해서 새 이름을 지정하면 파일 이름을 변경할 수 있습니다:

```
f pestilence.ms
’-. pestilence.ms
```

`f` 명령어는 파일의 새로운 상태를 출력합니다. 즉, 이름이 지정되면 이름을 변경하고, 그렇지 않더라도 이름을 출력합니다. 파일 이름 변경 작업도 실행 취소할 수 있습니다.

```
u
f
-. conquest.ms
```

sam을 다운로드 모드 상태에서 실행하면 메뉴에서 원하는 파일을 선택하면 현재 파일을 변경할 수 있습니다(동일한 파일을 다시 선택하면 해당 파일로 열린 창들이 순차적으로 전환됩니다). 그렇지 않은 경우, `b` 명령어를 사용해서 원하는 파일을 선택할 수 있습니다:[^2]

[^2]: 버그로 인해 다운로드 모드 상태에서 `b` 명령어가 작동하지 않습니다. 어차피 메뉴를 사용하는 것이 좀 더 편리하고, 명령 언어를 통한 파일 선택 방식이 앞으로 변경될 예정이기 때문에 이 버그는 수정되지 않았습니다.

```
b emacs.ms
-. emacs.ms
```

다시 말해, Unix 파일 emacs.ms 가 처음으로 읽혔기 때문에 sam은 파일 이름을 출력합니다(실제로는 암시적인 `f` 명령을 실행합니다). sam이 알지 못하는 파일을 요청하는 것은 오류지만, `B` (대문자)명령을 사용하면 sam의 메뉴에 새 파일이 추가되고 해당 파일이 현재 파일로 설정됩니다.

```
b flood.pic
? no ‘flood.pic’ files.
B flood.pic
-. flood.pic
n
- conquest.ms
- death.ms
- emacs.ms
- famine.ms
-. flood.pic
- slaughter.ms
```

`b` 와 `B` 명령어 모두 파일 이름 목록을 받아들입니다. `b` 명령어는 목록의 첫 번째 파일만 가져오는 반면, `B` 명령어는 목록에 있는 모든 파일을 불러옵니다.

목록은 한 줄에 직접 입력할 수도 있고—`B devil.tex satan.tex 666.tex emacs.tex`—유닉스 명령어로 생성할 수도 있습니다—`B <echo *.tex` 후자의 형식은 유닉스 명령어가 필요합니다. sam은 셸 파일 이름 메타문자를 인식하지 못하므로, `B *.tex` 명령어는 `*.tex` 라는 이름의 단일 파일을 불러오려고 시도합니다. (`<` 형식은 물론 sam의 `<` 명령어에서 파생된 것입니다.) `B` 명령어에 부속해서 실행할 수 있는 유용한 명령어는 `echo` 명령 뿐만이 아닙니다. 예를 들어,

```
B <grep -l Emacs *
```

는 Emacs 라는 문자열을 포함하는 파일만 불러옵니다.

마지막으로, 특별한 경우를 살펴보면: 인수가 없는 `B` 명려어는 sam 내에 이름 없는 빈 파일을 생성합니다.

`B` 명려어와 보완된 명령어는 `D` 명령어입니다:

```
D devil.tex satan.tex 666.tex emacs.tex
```

는 sam의 메모리에서(유닉스 시스템의 디스크 파일이 아닌) 해당 파일(들)을 제거합니다. 파일 이름을 지정하지 않은 `D` 명령어는 sam에서 현재 파일을 제거합니다.

현재 파일을 유닉스 파일과 연관 짓는 세 가지 명령이 있습니다. `w` (*write*)명령은 파일을 디스크에 기록합니다. 인수를 지정하지 않으면, sam에서 현재 파일과 연관된 유닉스 파일에
파일 전체를 기록합니다(기본 주소가 ‘.’ 가 아닌 유일한 명령입니다). 물론, 다음과 같은 명백한 구문을 사용해서 쓰기 대상 주소와 다른 파일 이름을 지정할 수도 있습니다:

```
1,2w /tmp/revelations
/tmp/revelations: #44
```

sam은 파일 이름과 파일에 쓰인 문자 수를 응답으로 반환합니다. GUI 버튼 3 메뉴의 *write* 명령은 인수를 지정하지 않은 `w` 명령어와 기능이 동일합니다.

나머지 두 명령어인 `e` (*edit*)와 `r` (*read*)은 유닉스 파일에서 데이터를 읽어옵니다. `e` 명령어는 현재 파일의 내용을 지우고, 지정된 파일에서 데이터를 읽어오며(명시적으로 파일명이 지정되지 않은 경우 현재 파일의 이전 이름을 사용함), 파일 이름을 설정합니다. 이는 `B` 명령어와 유사하지만, 정보를 새로운 파일이 아닌 현재 파일에 넣습니다. 따라서 파일 이름을 지정하지 않고 `e` 명령어를 실행하면 sam의 유닉스 파일 복사본을 쉽게 갱신할 수 있습니다. [ed와 달리, `e` 명령어는 파일이 수정된 경우도 오류 메시지를 표시하지 않습니다. 잘못된 경우 되돌릴 수 있는 사항에 대해서는 보호하지 않는다는 원칙 때문입니다.]

전체 텍스트를 대체하는 것이 주된 역할이므로, `e` 명령어는 주소를 절대 받지 않습니다.

`r` 명령어는 `e` 명령어와 비슷하지만, 파일을 지우지 않습니다. 유닉스 파일의 텍스트가 ‘.’ 을 대체하거나, 주소가 지정된 경우 지정된 텍스트를 대체합니다.

```
r emacs.ms
```

는 본질적으로

```
<cat emacs.ms
```

와 동일한 효과를 냅니다. `r` 및 `w` 명령어는 현재 파일에 이름이 아직까지 정의되지 않은 경우 파일 이름을 지정하며, `e` 명령어는 파일에 이미 이름이 있더라도 이름을 지정합니다.

텍스트 조각 대신 파일을 순회하는, `x` 명령어와 유사한 명령어가 하나 있습니다. 바로 `X` (대문자)명령어입니다. 구문도 간단합니다. `x` 명령어와 똑같이 `X/패턴/명령어` 형식입니다. (이 명령어의 대응된 명령어는 `Y` 명령어로, `y` 명령어와 유사합니다.)

이 명령어는 메뉴 항목(즉, `f` 명령어로 출력된 줄)이 패턴과 일치하는 각 파일에서 명령어를 실행하는 효과를 냅니다. 예를 들어, 아포스트로피 문자는 수정된 파일을 나타내므로,

```
X/’/ w
```

는 변경된 파일을 디스크에 저장합니다. 다음은 좀 더 긴 예시입니다. C 소스 파일에서 특정 변수가 사용된 모든 부분을 찾는 경우입니다:

```
X/\.c$/ ,x/variable/+-p
```

`f` 명령어로 변수가 어떤 파일에 나타나는지 확인할 수 있습니다:

```
X/\.c$/ ,g/variable/ {
    f
    ,x/variable/+-{
        =
        p
    }
}
```


여기서 `g` 명령어는 해당 변수가 포함된 파일 이름만 출력되도록 보장합니다(단, sam이 명령어 실행 중에 읽어들이는 파일 이름을 함께 출력해서 혼란을 줄 수 있으니 주의합니다).

`=` 명령어는 파일 내에서 변수가 나타나는 위치를 표시하고, `p` 명령어는 해당 줄을 출력합니다.

`D` 명령어는 `X` 명령어의 처리 대상으로 사용할 때 유용합니다. 다음 예제는 특정 변수가 포함되지 않은 모든 C 파일을 메뉴에서 삭제합니다:

```
X/\.c$/ ,v/variable/ D
```

`X` 명령어에 패턴이 지정되지 않으면, 모든 파일에서 명령어(기본값은 `f`)가 실행되므로

```
X D
```

를 실행하면 sam을 정리해서 새로 시작할 수 있습니다. 하지만 더 이상의 작업을 진행하기보다 지금은 중단하겠습니다:

```
q
$
```

일부 파일 조작 명령은 되돌릴 수 있습니다. `f`, `e`, `r` 명령어를 되돌리면 파일의 이전 상태로 복원되지만, `w`, `B`, `D` 명령어는 되돌릴 수 없습니다. 물론 `q` 명령도 이와 마찬가지입니다.
