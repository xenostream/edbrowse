**ABSTRACT**

Sam은 비트맵 디스플레이용으로 설계된 대화형 다중 파일 텍스트 편집기입니다. 텍스트 기반 명령어가 마우스 기반의 잘라내기 및 붙여넣기 인터페이스를 보완해서, 복잡하거나 반복적인 편집 작업을 쉽게 처리할 수 있게 해줍니다. 이 언어의 특징은 "수정 대상 텍스트의 구조를 설명하기 위해 정규 표현식을 조합한다" 는 점입니다. 파일을 데이터베이스로 취급하고 변경 사항을 원자적 트랜잭션으로 기록하는 방식은 구현 지침이며, 일반적인 ‘실행 취소’ 메커니즘을 간단하게 만들어 줍니다.

Sam은 저대역폭 스트림으로 연결된 두 개의 프로세스로 구현되며, 한 프로세스는 디스플레이를 처리하고 다른 프로세스는 편집 알고리즘을 처리합니다. 따라서 디스플레이 프로세스는 비트맵 터미널에서, 편집기는 로컬 호스트에서 실행하거나, 두 프로세스 모두 비트맵을 지원하는 호스트에서 실행하거나, 디스플레이 프로세스는 터미널에서, 편집기는 원격 호스트에서 실행할 수 있습니다. 디스플레이 프로세스를 비활성화하면 비트맵 터미널 없이도 실행할 수 있습니다.

이 논문은 『Software—Practice and Experience』 제17권 제11호, 813-845쪽(1987년 11월)에서 재인쇄된 것입니다. 이 논문은 Plan 9 매뉴얼에 업데이트되지 않았습니다. Sam은 논문이 작성된 이후 크게 변하진 않았지만, 이를 둘러싼 시스템은 확실히 변화했습니다. 그럼에도 불구하고, 여기에 실린 설명은 여전히 이 편집기를 이해하는 데 가장 훌륭한 입문 자료로 남아 있습니다.


# Introduction

Sam은 잘라내기 및 붙여넣기 방식의 대화형 편집 기능과 정규 표현식 구성을 기반으로 한 매우 독특한 명령어를 결합한 대화형 텍스트 편집기입니다. 이 편집기는 두 개의 프로그램으로 구성되어 있습니다. 하나는 ‘호스트 부분’ 으로, UNIX 시스템에서 실행되어 명령어를 구현하고 파일 액세스를 제공합니다. 다른 하나는 ‘터미널 부분’ 으로, 마우스와 비트맵 디스플레이가 장착된 컴퓨터에서 비-동기적으로 실행되며 화면 표시와 대화형 편집을 지원합니다. 호스트 부분은 마우스나 디스플레이 도움 없이도, 마치 기존의 라인 에디터처럼 명령어를 사용해서 텍스트를 편집하기 위해 일반 터미널에서 단독으로 실행될 수도 있습니다. 대부분의 경우, 터미널 부분은 Blit1 터미널(실제로는 Blit의 양산 버전인 Teletype DMD 5620)에서 실행되며, 이 터미널의 호스트 연결은 일반적인 9600-bps-RS232 링크입니다. SUN 컴퓨터는 호스트와 디스플레이 프로세스가 파이프로 연결된 단일 시스템에서 실행됩니다.

Sam은 해석되지 않은 ASCII 텍스트를 편집합니다. MacWrite,² Bravo,³ Tioga⁴ 또는 Lara⁵와 달리, 이 프로그램은 여러 글꼴, 그래픽 또는 표를 지원하는 기능이 없습니다. 또한 이들 프로그램과 달리, Sam은 풍부한 명령어를 갖추고 있습니다. (이 논문 전체에서 ‘명령어’ 라는 용어는 텍스트 명령어를 의미하며, 마우스로 실행되는 명령어는 ‘마우스 언어’ 를 형성합니다.) Sam은 프로그래머가 사용하기 위한 편집기로 개발되었으며, 정규 표현식으로 구동되는 견고한 명령어를 갖춘 프로그램에 편리한 마우스 기반 인터페이스를 제공함으로써 UNIX 텍스트 편집기 ed⁶,⁷의 스타일과 대화형 잘라내기-붙여넣기 편집기의 스타일을 결합하려고 시도합니다. 명령어는 마우스 언어보다 더 많이 발전했으며, 변경 사항을 지정하기 위해 데이터 흐름과 유사한 구문을 사용해서 파일을 단순한 줄의 순서 이상으로 풍부하게 설명할 수 있는 표기법을 갖추게 되었습니다.

이런 대화형 스타일은 Blit용 초기 잘라내기-붙여넣기 편집기인 jim¹과 Blit 윈도우 시스템인 mux⁸의 영향을 받았습니다. Mux는 원래의 Blit 윈도우 시스템인 mpx¹를 잘라내기-붙여넣기 편집 기능과 통합해서, 파일 대신 명령 세션의 출력(및 입력)을 편집하는, 일종의 다중화된 jim 버전을 형성합니다.

이 논문의 첫 번째 부분은 명령어 언어와 마우스 언어를 설명하고, 이 둘이 어떻게 상호작용하는지 다룹니다. 그 다음 구현에 대한 설명이 이어지며, 먼저 호스트 부분의 구현을 다루고, 그 다음 터미널 부분의 구현을 다룹니다. sam의 설계에 영향을 미친 원칙 중 하나는 "파일 크기나 줄 길이에 상한과 같은 명시적인 제한이 없어야 한다" 는 것입니다. 두 번째 고려 사항은 "효율성" 입니다. 이 두 가지 목표를 동시에 달성하려면, 명령어 언어의 제어 하에 수천 건의 변경을 수행하는 동안에도 파일을 줄 단위로 분할하지 않고 거대한 문자열(파일)을 효율적으로 조작할 수 있는 방법이 필요합니다. sam의 방법은 파일을 트랜잭션 데이터베이스로 취급해서 변경 사항을 원자적 업데이트로 구현하는 것입니다. 이런 업데이트는 쉽게 되돌려 변경 사항을 ‘실행 취소’ 할 수 있습니다. 효율성은 프로그램의 두 부분 내부 및 부분 간에 디스크 트래픽과 데이터 이동을 최소화하는 일련의 캐시를 통해 달성됩니다.

SAM의 터미널 부분은 상당히 간단합니다. 흥미로운 점은 어느 한쪽에서 변경을 시작할 수 있음에도 편집기의 두 부분이 어떻게 동기화를 유지하는가? 하는 것입니다. 이는 통신을 조직화하고 두 부분 모두에서 병렬로 유지되는 데이터 구조를 통해 달성됩니다.

논문 마지막 부분에는 sam의 개발 과정을 기록하고, 개발 및 사용 과정에서 얻은 교훈을 논의합니다.

이 논문은 분량이 많지만, 대체로 적당한 길이의 두 편의 논문, 즉 sam의 사용자 인터페이스에 대한 설명과 그 구현에 대한 논의로 구성되어 있습니다. 구현이 사용자 인터페이스의 영향을 크게 받고, 그 반대의 경우도 마찬가지이기 때문에 이 두 편은 하나로 묶여 있습니다.


# The Interface

Sam은 여러 파일을 다루는 텍스트 편집기입니다. 실행 시 파일 이름을 지정할 수 있습니다:

sam file1 file2 ...

또한 새 파일을 추가하거나 불필요한 파일을 삭제하는 명령어가 있습니다. 파일은 특정 명령을 완료하는 데 필요한 경우만 읽힙니다. 편집 작업은 파일을 읽을 때 생성된 내부 복사본에 적용되며, 이 복사본과 연결된 UNIX 파일은 명시적인 명령을 통해서만 변경됩니다. 설명을 단순화하기 위해, 여기서는 내부 복사본을 ‘파일’ 이라고 하고, 디스크에 저장된 원본을 ‘디스크 파일’ 이라고 부릅니다.

Sam은 일반적으로 마우스로 조작하는 잘라내기 및 붙여넣기 편집기를 제공하는 비트맵 디스플레이에 연결됩니다. 이 모드에서도 명령어는 여전히 그대로 사용할 수 있습니다. ‘sam 창’ 이라는 특수 창에 입력한 텍스트는 현재 파일에 실행될 명령어로 해석됩니다. 잘라내기 및 붙여넣기 편집 기능은 어떤 창에서든 사용할 수 있으며, 심지어 ‘sam 창’ 에서 명령어를 구성할 때도 사용할 수 있습니다. `-d` (‘no download’ 의 약자) 옵션을 사용해서 sam을 실행할 때 활성화되는 다른 작동 모드는 마우스나 비트맵 디스플레이를 사용하지 않지만, 일반 터미널에서도 대화형으로 또는 스크립트를 통해 텍스트 명령어를 사용해서 편집할 수 있습니다.

다음 섹션은 우선 명령어 언어(`sam -d` 모드 및 sam 창에서)를 설명하고, 그 다음으로 마우스 인터페이스를 설명합니다. 이 두 언어는 거의 독립적이지만, 아래에서 설명할 "현재 텍스트" 를 통해 연결됩니다.



# The Command Language

파일은 문자의 배열(즉, 문자열)인 내용, 관련 디스크 파일의 이름, 내용이 디스크 파일의 내용과 일치하는지 여부를 나타내는 수정 비트, 그리고 ‘현재 텍스트’ 또는 ‘dot’ 이라는 내용의 부분 문자열로 구성됩니다(그림 1 및 2 참조). 현재 텍스트가 빈 문자열인 경우, dot은 문자 사이에 위치합니다. dot의 값은 현재 텍스트의 위치이며, dot의 내용은 dot에 포함된 문자들입니다. Sam은 텍스트에 열(column)이나 필드(field) 같은 2차원적 해석을 부여하지 않으며, 텍스트는 항상 1차원적입니다. 대부분의 UNIX 프로그램에서 이해하는 텍스트의 ‘줄(line)’ 개념, 즉 줄바꿈 문자로 종료되는 문자 시퀀스조차도 약하게 지원됩니다.

현재 파일은 편집 명령이 참조하는 파일입니다. 따라서 현재 텍스트는 현재 파일 내의 dot입니다. 명령이 특정 파일이나 텍스트를 명시적으로 지정하지 않는 경우, 해당 명령은 현재 텍스트에 적용되는 것으로 간주됩니다. 당분간 여러 파일이 존재한다는 점은 무시하고, 단일 파일 편집을 가정해 보겠습니다.

그림 1. 편집 메뉴가 표시된 전형적인 SAM 화면. SAM(명령어 언어) 창이 중앙에 위치하고, 그 위와 아래에 파일 창이 있습니다. (이 사용자 인터페이스를 통해 이런 창들을 서로 인접하게 배치하기 쉽습니다.) 부분적으로 가려진 창은 세 번째 파일 창입니다. 가장 위쪽의 창은 굵은 테두리로 표시된 대로, 키 입력 및 마우스 조작이 적용되는 창입니다. 각 창의 현재 텍스트는 반전색으로 강조 표시되어 있습니다. SAM 창의 현재 텍스트는 수직 막대로 표시된 마지막 가시화된 줄의 빈 문자열입니다. 그림 2도 참조합니댜.

명령어의 이름은 "한 글자로 구성" 됩니다. 파일을 디스크에 쓰는 것 같은 편집과 무관한 명령어를 제외하고, 대부분의 명령어는 dot의 텍스트를 변경하고 dot을 변경된 텍스트로 설정합니다. 예를 들어, 삭제 명령어인 `d` 는 dot의 텍스트를 삭제하고 이를 빈 문자열로 대체한 뒤, dot을 그 결과로 설정합니다. 변경 명령어인 `c` 는 dot을 임의의 구두점 문자(일반적으로 슬래시)로 구분된 텍스트로 대체합니다. 따라서,

```
c/Peter/
```

는 dot의 텍스트를 문자열 Peter 로 대체합니다. 마찬가지로,

```
a/Peter/
```

(추가)는 dot 뒤에 문자열을 추가하고,

```
i/Peter/
```

(삽입)은 dot 앞에 삽입합니다. 이 세 명령어 모두 dot을 새로운 텍스트인 ‘Peter’ 로 설정합니다.

줄바꿈은 명령어의 구문 일부입니다. 줄바꿈 문자는 어휘적으로 명령어를 종료시킵니다. 그러나 삽입된 텍스트 내에서는 줄바꿈은 암시적으로 처리되지 않습니다. 하지만 여러 줄의 텍스트를 삽입하는 것은 종종 편리하기 때문에, sam은 이런 경우를 위한 특별한 구문을 제공합니다:

```
a
some lines of text
to be inserted in the file,
terminated by a period
on a line by itself
.
```

한 줄 구문에서는 C 언어와 유사한 이스케이프 기호를 사용해서 줄바꿈 문자를 지정할 수 있으므로,

```
c/\n/
```

는 ‘dot’을 하나의 줄바꿈 문자로 대체합니다.

Sam에는 또한 `s` 라는 대체 명령어가 있습니다:

```
s/표현식/대체문자열/
```

(정규) 표현식에서 ‘dot’에 대한 첫 번째 일치 항목을 대체 문자열로 바꿉니다. 따라서 ‘dot’이 문자열 “Peter” 인 경우, 다음 명령어

```
s/t/st/
```

는 이를 “Pester” 로 변경합니다. 일반적으로 `s` 명령어는 불필요하지만, ed에서 계승된 것이며 몇 가지 편리한 변형이 있습니다. 예를 들어, 대체 텍스트에 `&` 로 지정된 일치 텍스트를 포함시킬 수 있습니다:

```
s/Peter/Oh, &, &, &, &!/
```

또한 텍스트에 프로그램을 적용하는 세 가지 명령어가 있습니다:

```
< UNIX 프로그램
```

은 dot을 UNIX 프로그램의 출력 결과로 대체합니다. 마찬가지로, `>` 명령어는 dot을 표준 입력으로 프로그램을 실행하고, `|` 는 두 가지 기능 모두 수행합니다. 예를 들어,

```
| sort
```

은 dot을 표준 정렬 유틸리티를 적용한 결과로 대체합니다. 다시 말하지만, 이런 sam 명령어에서 줄바꿈은 특별한 의미를 가지지 않습니다!! 이 명령어들이 처리하는 텍스트와 그 결과물은 반드시 줄바꿈으로 구분되는 것은 아니지만, UNIX 프로그램과의 연동을 위해서는 관례를 따르기 위해 줄바꿈이 필요할 수도 있습니다.

한 가지 더, `p` 명령어는 dot의 내용을 출력합니다. 표 I은 sam의 명령어를 요약한 것입니다.

dot의 값은 명령어에 주소를 지정해서 변경할 수 있습니다. 가장 간단한 주소는 줄 번호입니다:

```
3
```

은 파일 세 번째 줄을 가리키므로,

```
3d
```

는 파일의 세 번째 줄을 삭제하며, 암묵적으로 줄 번호를 재지정해서 기존 4번 줄이 이제 3번 줄이 됩니다. (이것은 sam이 줄을 직접 다루는 몇 안되는 경우 중 하나입니다.)

0번 줄은 파일 시작 부분의 빈 문자열입니다. 명령어가 주소로만 구성되면 `p` 명령어로 간주되므로, 별다른 수식 없이 3 을 입력하면 터미널에 3번 줄이 출력됩니다. 그 외에도 몇 가지 기본적인 주소가 있습니다. 마침표(.)는 현재 텍스트를 가리키고, 달러 기호($)는 파일 끝의 null 문자열을 가리킵니다.

주소는 항상 파일의 단일 부분 문자열입니다. 따라서 주소 3 은 파일의 두 번째 줄바꿈 이후부터 세 번째 줄바꿈까지의 문자를 가리킵니다. 복합 주소는 쉼표 연산자

```
address1,address2
```

로 구성되며, address1 시작부터 address2 끝까지의 부분 문자열을 가리킵니다. 예를 들어, `3,5p` 명령어는 파일의 세 번째 줄부터 다섯 번째 줄까지를 출력하고, `.,$d` 는 점(.)의 시작부터 파일 끝까지의 텍스트를 삭제합니다.

이런 주소들은 모두 파일 내의 절대 위치이지만, sam에는 `+` 또는 `-` 로 표시되는 상대 주소도 있습니다. 예를 들어,

```
$-3
```

파일 끝에서 세 번째 줄을 가리키며,

```
.+1
```

은 점 뒤의 줄을 가리킵니다. `+` 나 `-` 의 왼쪽에 주소가 나타나지 않으면 점(닷)이, 오른쪽에 아무것도 나타나지 않으면 1이 가정됩니다. 따라서 `.+1` 은 단순히 더하기 기호 하나로 축약될 수 있습니다.

`+` 연산자는 첫 번째 인자의 끝을 기준으로 작용하는 반면, `-` 연산자는 시작을 기준으로 작용합니다. 따라서 `.+1` 은 점 뒤의 첫 번째 줄을, `.-` 는 점 앞의 첫 번째 줄을, `+-` 는 점의 끝이 포함된 줄을 가리킵니다. (점은 여러 줄에 걸쳐 있을 수 있으며, `+` 는 점의 끝이 있는 줄 뒤의 줄을 선택하고, `-` 는 한 줄 뒤로 이동합니다.)

마지막 주소 유형은 정규 표현식으로, 이 표현식과 일치하는 텍스트를 가리킵니다. 표현식은 다음과 같이 슬래시로 묶입니다.

```
/표현식/
```

이 표현식들은 UNIX 프로그램 `egrep` 에서 사용되는 것과 동일하며, 클로저, 대안 등 다양한 구문을 포함합니다. 이들은 표현식과 일치하는 가장 왼쪽에 위치한 가장 긴 문자열, 즉 검색이 시작된 지점 이후의 첫 번째 일치 항목을 찾으며, 동일한 위치에서 시작하는 일치 항목이 두 개 이상인 경우 그중 가장 긴 항목을 선택합니다. (여기서는 UNIX 프로그램의 정규 표현식 구문에 대해 이미 알고 있다고 가정합니다.9) 예를 들어,

```
/x/
```

는 파일에서 다음 x 문자와 일치하고,

```
/xx*/
```

는 다음 x가 하나 이상 연속된 부분과 일치하며,

```
/x|Peter/
```

는 다음 x 또는 Peter 와 일치합니다. 다른 UNIX 프로그램과의 호환성을 위해 ‘모든 문자’ 연산자인 마침표(.)는 줄바꿈과 일치하지 않으므로,

```
/.*/
```

점(.)부터 줄 끝까지의 텍스트와 일치하지만, 줄바꿈 문자는 제외하므로 줄 경계를 넘어 일치하지는 않습니다.

정규 표현식은 항상 상대 주소입니다. 기본 방향은 앞이므로, /Peter/ 는 실제로 +/Peter/ 의 약어입니다. 마이너스 기호를 사용하면 검색 방향을 반대로 할 수 있으므로,

```
-/Peter/
```

는 점(.) 앞의 첫 번째 Peter 를 찾습니다. 정규 표현식은 다른 주소 형식과 함께 사용할 수 있으므로, 0+/Peter/ 는 파일에서 첫 번째 Peter 를 찾고, $-/Peter/ 는 마지막 Peter 를 찾습니다. 표 II에는 Sam의 주소들이 요약되어 있습니다.

지금까지 다룬 언어는 ed나 vi 같은 UNIX 텍스트 편집기를 사용하는 사람들에게는 낯설지 않을 것입니다.9 게다가 정규 표현식과 줄 번호를 제외하면, 이런 명령어로 수행할 수 있는 편집 작업들은 마우스 기반 인터페이스를 통해 처리하는 것이 훨씬 더 편리합니다. 실제로, 아래에서 자세히 설명할 sam의 마우스 언어는 간단한 변경을 수행하는 데 주로 사용되는 수단입니다. 그러나 대규모이거나 반복적인 변경의 경우, 텍스트 기반 언어가 수동 인터페이스보다 더 뛰어난 성능을 발휘합니다.

‘Peter’ 라는 문자열이 한 번만 나타나는 것을 삭제하는 대신, 모든 ‘Peter’ 를 제거한다고 가정합니다. 여기에는 특정 텍스트가 나타나는 각 위치에 대해 명령을 실행하는 반복자가 필요합니다. Sam의 반복자는 추출(*extract*)을 의미하는 `x` 라고 합니다.

```
x/표현식/명령
```

은 dot 내에서 지정된 표현식과 일치하는 모든 항목을 찾고, 각 일치 항목에 dot을 일치된 텍스트로 설정한 뒤 명령을 실행합니다. 따라서 모든 ‘Peter’ 를 삭제하려면 다음과 같이 입력합니다.

```
0,$ x/Peter/ d
```

(이 예제에서 공백은 가독성을 높이기 위한 것이며, sam은 이를 요구하지도 않고 해석하지도 않습니다.) 이는 파일 전체(0,$) 범위에서 “Peter” 라는 문자열이 나타나는 위치를 검색하고, 각 위치에 점(.)을 설정해서 `d` 명령을 실행합니다. (대조적으로, 이와 유사한 ed 명령은 “Peter” 가 포함된 모든 줄을 삭제하는 반면, sam은 “Peter” 라는 문자열만 삭제합니다.) 주소 `0,$` 는 흔하게 사용되므로, 쉼표 하나로 축약할 수 있습니다. 또 다른 예로,

```
, x/Peter/ p
```

는 파일 내 각 출현 위치마다 ‘Peter’ 를 하나씩, 그 사이에 다른 텍스트(인스턴스를 구분하는 줄바꿈조차 없이) 없이 나열해서 출력합니다.

물론, `x` 에 의해 추출된 텍스트는 정규 표현식으로 선택될 수 있으며, 이 경우 어떤 일치 집합이 선택될지 결정하는 것이 복잡해집니다. 일치 항목들이 겹칠 수 있기 때문입니다. 이 문제는 ‘dot’의 시작 부분부터 ‘left-most-longest’ 규칙을 사용해서 일치 항목을 생성하고, 각 일치 항목을 이전 항목의 끝 부분부터 검색함으로써 해결됩니다. 정규 표현식은 빈 문자열과도 일치할 수 있지만, 비어 있지 않은 일치 항목과 인접한 빈 문자열 일치는 절대 선택되지 않습니다. 적어도 하나의 문자가 그 사이에 있어야 합니다. 예를 들어,

```
, c/AAA/
x/B*/ c/-/
, p
```

를 실행하면 다음과 같은 결과가 출력됩니다.

```
-A-A-A-
```

를 출력합니다. 이는 패턴 B* 가 A 를 분리하는 빈 문자열과 일치하기 때문입니다.

`x` 명령어는 유사한 구문을 가진 보충 명령어 `y` 가 있으며, 이 명령어는 dot을 표현식의 일치 결과 사이의 텍스트로 설정해서 명령어를 실행합니다. 예를 들어,

```
, c/AAA/
y/A/ c/-/
, p
```

위의 예제와 동일한 결과를 산출합니다.

`x` 및 `y` 명령어는 반복 구조이며, sam에는 이에 대응하는 한 쌍의 조건부 명령어가 있습니다. 이들의 구문은 다음과 같이 유사합니다:

```
g/표현식/명령어
```

(*guard*)는 dot에 표현식과 일치하는 부분이 포함될 경우 해당 명령어를 정확히 한 번만 실행합니다. 이는 각 일치 항목마다 명령어를 실행하는 `x` 와는 다릅니다. `x` 는 반복을 수행하는 반면, `g` 는 dot의 값을 변경하지 않고 단순히 테스트만 수행합니다. 따라서,

```
, x/Peter/ d
```

는 ‘Peter’ 가 나타나는 모든 부분을 삭제하지만,

```
, g/Peter/ d
```

는 텍스트 어디든 ‘Peter’ 가 나타나면 파일 전체를 삭제(빈 문자열로 만듦)합니다! 이와 대조되는 조건부 명령어는 `v` 로, 표현식과 일치하는 부분이 없을 때 명령어를 실행합니다.

이런 제어 구조와 유사한 명령어들을 조합해서 복잡한 작업을 구성할 수 있습니다. 예를 들어, ‘Peter’ 라는 문자열이 포함된 텍스트 줄을 출력하려면:

```
, x/.*\n/ g/Peter/ p
```

`x` 는 파일을 줄 단위로 나누고, `g` 는 ‘Peter’ 가 포함된 줄을 선택하며, `p` 는 해당 줄들을 출력합니다. 이 명령어는 `x` 명령어에 대한 주소(전체 파일)를 지정하지만, `g` 에는 명시적인 주소가 없기 때문에 `x` 명령어가 생성한 점(.)의 값, 즉 각 줄에 적용됩니다. sam의 모든 명령어는 파일을 디스크에 쓰는 명령어를 제외하고 기본적으로 점(.)을 주소로 사용합니다.

이런 연쇄 처리는 무한히 계속될 수 있습니다.

```
, x/.*\n/ g/Peter/ v/SaltPeter/ p
```

는 ‘Peter’ 가 포함된 줄은 출력하지만, ‘SaltPeter’ 가 포함된 줄은 출력하지 않습니다.



# Structural Regular Expressions

`sed` 나 `awk` 같은 비-상호작용형 편집기를 포함한 다른 UNIX 텍스트 편집기와 달리,7 sam은 여러 줄로 구성된 ‘레코드’ 가 포함된 파일을 처리하는 데 적합합니다. 예를 들어, 빈 줄로 구분된 다음과 같은 형식의 레코드로 구성된 온라인 전화번호부가 있습니다.

```
Herbert Tic
44 Turnip Ave., Endive, NJ
201-5555642
Norbert Twinge
16 Potato St., Cabbagetown, NJ
201-5553145

...
```

이 형식은 정규 표현식으로 다음과 같이 표현할 수 있습니다.

```
(.+\n)+
```

즉, 공백이 아닌 한 줄 이상의 연속된 줄을 의미합니다. 따라서 Mr. Tic의 전체 기록을 출력하는 명령어는 다음과 같습니다.

```
, x/(.+\n)+/ g/^Herbert Tic$/ p
```

그리고 전화번호만 추출하는 명령어는 다음과 같습니다.

```
, x/(.+\n)+/ g/^Herbert Tic$/ x/^[0-9]*-[0-9]*\n/ p
```

후자의 명령어는 파일을 레코드 단위로 분할하고, Mr. Tic의 레코드를 선택한 뒤, 해당 레코드에서 전화번호를 추출해서 마지막으로 그 번호를 출력합니다.

좀 더 복잡한 문제는 C 프로그램에서 특정 변수(예를 들어 n)의 이름을 num으로 변경하는 것입니다. 가장 먼저 떠오르는 시도인

```
, x/n/ c/num/
```

은 심각한 결함이 있습니다. 변수 n뿐만 아니라 문장 어디서나 나타나는 n을 모두 변경해 버리기 때문입니다. 일단 모든 변수를 추출한 다음, n과 정확히 일치하는 변수만 선별해야 합니다:

```
, x/[A-Za-z_][A-Za-z_0-9]*/ g/n/ v/../ c/num/
```

패턴 [A-Za-z_][A-Za-z_0-9]* 는 C 언어의 식별자와 일치합니다. 다음으로 g/n/ 은 n을 포함하는 항목을 선택합니다. 그런 다음 v/../ 은 두 개(또는 그 이상)의 문자를 포함하는 항목을 제외하고, 마지막으로 c/num/ 은 나머지(식별자 n)를 num으로 변경합니다. 이 버전은 확실히 훨씬 더 잘 작동하지만, 여전히 문제가 있을 수 있습니다. 예를 들어, C의 문자 및 문자열 상수에서 \n 시퀀스는 줄바꿈 문자로 해석되는데, 이를 \num으로 변경하고 싶지는 않습니다. 이 문제는 `y` 명령을 사용해서 미연에 방지할 수 있습니다:

```
, y/\\n/ x/[A-Za-z_][A-Za-z_0-9]*/ g/n/ v/../ c/num/
```

(정규 표현식의 어휘적 관례 때문에 두 번째 `\` 문자가 필요합니다), 또는 문자 상수와 문자열을 아예 배제할 수도 있습니다:

```
,y/’[^’]*’/ y/“[^”]*"/ x/[A-Za-z_][A-Za-z_0-9]*/ g/n/ v/../ c/num/
```

이 버전의 `y` 명령어들은 모든 문자 상수와 문자열을 고려 대상에서 제외합니다. 남은 유일한 문제는 이런 시퀀스 내에서 `\’` 또는 `\"` 가 나타날 가능성을 처리하는 것이지만, 이 어려움을 해결하는 방법은 쉽게 알 수 있습니다.

이런 조합된 명령어의 핵심은 단계적인 정교화입니다. 명령어의 간단한 버전을 먼저 시도해 보고, 충분하지 않다면 한두 개의 절을 추가해서 다듬을 수 있습니다. (실수는 되돌릴 수 있습니다. 아래를 참조합니다. 또한, 마우스 언어를 사용하면 매번 명령을 다시 입력할 필요가 없습니다.) 그 결과로 생성된 명령 체인은 셸 파이프라인을 다소 연상시킵니다.7 하지만 수정된 데이터를 전달하는 파이프라인과 달리, sam 명령은 데이터의 ‘뷰’ 를 전달합니다. 명령의 각 단계에서 처리되는 텍스트는 동일하지만, 어떤 부분이 선택될지는 단계별로 정교화되어, 최종 단계에서 올바른 부분이 확보되면 명령줄의 마지막 단계에서 최종적으로 변경이 이루어집니다.

다른 UNIX 프로그램에서는 정규 표현식이 sam의 `g` 명령어와 같이 선택 용도로만 사용되며, `x` 나 `y` 명령어 같이 추출 용도로는 절대 사용되지 않습니다. 예를 들어, `awk` 의 패턴은 처리할 행을 선택하는 데 사용되지만, 입력 텍스트의 형식을 설명하거나 줄바꿈이 없는 텍스트를 처리하는 데는 사용할 수 없습니다. `x` 명령어 같이 내용의 본질이 아닌 텍스트의 구조를 기술하기 위해 정규 표현식을 사용하는 방식에는 ‘구조적 정규 표현식’ 이라는 이름이 붙여졌습니다. 위 예시와 같이 이런 표현식이 조합되면 표현력이 매우 뛰어납니다. 이에 대한 자세한 내용은 다른 곳에서 다루고 있습니다.10



# Multiple files

am에는 주로 입출력과 관련된 몇 가지 명령어가 있습니다.

```
e discfilename
```

현재 파일의 내용과 이름을 지정한 디스크 파일의 내용과 이름으로 대체합니다.

```
w discfilename
```

지정한 디스크 파일에 내용을 기록합니다.

```
r discfilename
```

dot을 지정한 디스크 파일의 내용으로 대체합니다. 이 모든 명령어는 파일명이 지정되지 않은 경우 현재 파일의 이름을 사용합니다. 마지막으로,

```
f discfilename
```

명령은 파일과 연관된 이름을 변경하고 그 결과를 표시합니다:

```
’-. discfilename
```

이 출력은 파일의 "메뉴 줄" 이라고 불리는데, 이는 버튼 3 메뉴(다음 절에서 설명)에 있는 파일 줄의 내용이기 때문입니다. 처음 세 문자는 파일의 상태를 간결하게 나타내는 표기법입니다. 아포스트로피는 "파일이 수정되었음" 을 의미합니다. 마이너스 기호는 해당 파일에 대해 열려 있는 창의 수를 나타냅니다(다음 절 참조): `-` 는 없음을, `+` 는 하나를, `*` 는 둘 이상을 의미합니다. 마지막으로, 마침표는 이 파일이 "현재 파일임" 을 나타냅니다. 이 문자들은 잠시 후에 설명할 `X` (대문자)명령을 제어하는 데 유용합니다.

Sam은 일련의 디스크 파일(예: 프로그램의 전체 소스 코드)을 인수로 지정해서 실행할 수 있으며, 필요에 따라 파일을 추가하거나 삭제할 수 있습니다.

```
B discfile1 discfile2 ...
```

명시된 파일을 Sam 목록에 추가하고,

```
D discfile1 discfile2 ...
```

Sam의 메모리에서 해당 항목을 제거합니다(관련 디스크 파일에 영향을 미치지 않음). 이 두 명령어 모두 셸7(UNIX 명령어 인터프리터)을 사용해서 목록을 생성하는 구문을 가지고 있습니다:

```
B <echo *.c
```

는 모든 C 소스 파일을 추가하고,

```
B <grep -l variable *.c
```

는 특정 변수를 참조하는 모든 C 소스 파일을 추가합니다(UNIX 명령어 `grep -l` 은 인수로 지정된 정규 표현식과 일치하는 내용을 포함하는 모든 파일을 나열합니다). 마지막으로, 인수를 지정하지 않은 `D` 는 현재 파일을 삭제합니다.

현재 파일을 변경하는 방법은 두 가지가 있습니다:

```
b 파일명
```

는 지정한 파일을 현재 파일로 설정합니다. `B` 명령어도 동일한 기능을 수행하지만, 새로운 파일을 sam의 목록에 추가하기도 합니다. (물론 실제로는 텍스트 명령어가 아닌 마우스 조작을 통해 현재 파일이 선택되는 경우가 대부분입니다.) 다른 방법은 파일을 참조하는 주소 형식을 사용하는 것입니다:

```
“표현식” 주소
```

는 메뉴 줄이 해당 표현식과 일치하는 파일(정확히 하나만 일치해야 함)에서 평가된 주소를 가리킵니다. 예를 들어,

```
“peter.c” 3
```

는 이름이 peter.c 와 일치하는 파일의 세 번째 줄을 가리킵니다. 이는 이동(`m`) 및 복사(`t`) 명령에서 가장 유용합니다:

```
0,$ t “peter.c” 0
```

는 현재 파일의 복사본을 peter.c 파일의 맨 앞에 만듭니다.

`X` 명령어는 `x` 와 마찬가지로 반복 구조이지만, 문자열 대신 파일을 참조합니다:

```
X/표현식/명령어
```

는 메뉴 줄이 표현식과 일치하는 모든 파일에서 해당 명령어를 실행합니다. 가장 대표적인 예는 다음과 같습니다.

```
X/’/ w
```

이는 수정된 모든 파일을 디스크에 기록합니다. `Y` 는 `X` 의 보집합입니다. 즉, 메뉴 행이 다음 표현식과 일치하지 않는 모든 파일에 대해 명령을 실행합니다:

```
Y/\.c/ D
```

이는 이름에 .c 가 포함되지 않은 모든 파일을 삭제합니다. 즉, 모든 C 소스 파일은 유지하고 나머지는 삭제합니다.

중괄호를 사용하면 명령을 그룹화할 수 있으므로,

```
{
    명령1
    명령2
}
```

는 구문상으로는 두 개의 명령을 실행하는 단일 명령입니다. 따라서,

```
X/\.c/ ,g/variable/ {
    f
    , x/.*\n/ g/variable/ p
}
```

는 C 소스 파일에서 variable 이 나타나는 모든 위치를 찾아내고, 각 일치 항목의 파일 이름과 줄 번호를 출력합니다. 복합 연산의 정확한 의미론은 아래의 구현 섹션에서 설명합니다.

마지막으로, 되돌리기 명령어 `u` 는 영향을 받은 파일의 수와 상관없이 마지막 명령어를 되돌립니다. 되돌리기 작업을 여러 번 수행하면 더 과거로 거슬러 올라가므로,

```
u
u
```

(`u2` 로 축약할 수 있음)는 마지막 두 명령어를 되돌립니다. 그러나 되돌리기 작업 자체는 다시 되돌릴 수 없으며, 파일을 추가하거나 삭제하는 명령어도 마찬가지입니다. 다만 `e` 명령어를 포함해서 그 외 모든 작업은 되돌릴 수 있습니다. 예를 들어:

```
e 파일명
u
```

는 파일 이름, 점(.) 및 수정 비트를 포함해서 파일의 상태를 완전히 복원합니다. 실행 취소 기능 때문에 잠재적으로 위험한 명령은 확인 절차로 보호되지 않습니다. 오직 `D` 명령만, 즉 자체 복원에 필요한 정보를 파괴하는 명령만 보호됩니다. `D` 명령은 수정된 파일을 삭제하지 않지만, 동일한 파일에 대해 두 번째 `D` 명령을 실행하면 무조건 성공합니다. sam을 종료하는 `q` 명령도 마찬가지로 보호됩니다.



# Mouse Interface

Sam은 대개 비트맵 디스플레이와 마우스에 연결해서 대화형 편집을 위해 실행됩니다. 일반 마우스 기반 `sam` 과 `sam -d` 의 명령어 언어에서 유일한 차이점은, 명령어 없이 주소만 지정된 경우 `sam -d` 는 해당 주소가 가리키는 텍스트를 출력하는 반면, 일반 `sam` 은 화면에서 해당 텍스트를 강조 표시한다는 점입니다. 사실, ‘dot’은 항상 강조 표시됩니다(그림 2 참조).

그림 2. sam 창. 왼쪽 하단의 스크롤 바는 파일을 나타내며, 거품 모양 아이콘(썸)은 창에 표시된 부분의 비율을 보여줍니다. 편리한 탐색을 위해 마우스로 스크롤 바를 조작할 수 있습니다. 강조 표시된 현재 텍스트는 한 줄에 다 들어갈 필요는 없습니다. 여기서는 부분 줄 하나, 전체 줄 하나, 그리고 마지막 부분 줄 하나로 구성되어 있습니다.

각 파일은 화면에 0개 이상의 창을 열어둘 수 있습니다. 언제든지 sam 전체에서 단 하나의 창만이 "현재 창", 즉 입력 및 마우스 동작이 적용되는 창이 됩니다. 이는 sam 창(명령을 입력할 수 있는 창)이거나 파일 창 중 하나일 수 있습니다. 파일에 여러 개의 창이 열려 있을 때, 각 창에 표시된 파일의 이미지는 항상 최신 상태로 유지됩니다. 현재 파일은 명령의 영향을 가장 최근에 받은 파일입니다. 따라서 sam 창이 현재 창인 경우, 현재 창은 현재 파일에 속한 창이 아닙니다. 그러나 파일의 각 창은 고유한 dot 값을 가지며, 단일 파일의 창을 전환할 때 해당 파일의 dot 값은 해당 창의 값으로 변경됩니다. 따라서 창 전환은 매우 직관적이고 편리한 방식으로 이루어집니다.

Blit의 마우스는 왼쪽에서 오른쪽으로 번호가 매겨진 세 개의 버튼이 있습니다. 3번 버튼에는 창을 조작하는 명령어 목록이 있으며, 그 뒤에는 `f` 명령어로 출력되는 것과 정확히 동일한 ‘메뉴 줄’ 목록이 파일별로(창별로가 아닌) 하나씩 나열되어 있습니다. 이 메뉴 줄들은 파일 이름 순으로 정렬되어 있습니다. 목록이 길 경우, Blit 메뉴 소프트웨어는 다루기 힘든 긴 목록 대신 스크롤 가능한 메뉴를 생성해서 편리하게 관리할 수 있도록 합니다. 메뉴를 사용해서 목록에서 파일을 선택하면 해당 파일이 현재 파일이 되고, 그 파일에서 가장 최근에 활성화된 창이 현재 창이 됩니다. 하지만 해당 파일이 이미 현재 파일인 경우, 메뉴에서 파일을 선택하면 해당 파일의 창들이 순차적으로 전환됩니다. 이런 간단한 방법을 통해 파일의 창을 선택하기 위한 별도의 메뉴가 필요하지 않습니다. 해당 파일에 열려 있는 창이 없는 경우, sam은 마우스 커서를 변경해서 사용자에게 창을 생성하도록 안내합니다.

버튼 3 메뉴의 명령어들은 간단명료하며(그림 3 참조), Blit의 창 시스템인 mux,8에서 창을 조작하는 명령어와 유사합니다. `New` 는 새 파일을 생성하고, 마우스로 그은 사각형의 크기에 따라 결정되는 빈 창 하나를 제공합니다. `Zerox` 는 선택할 창을 묻는 메시지를 표시한 후 해당 창의 복제본을 만듭니다. 이것이 하나의 파일에 여러 창을 생성하는 방법입니다. `Reshape` 는 지정된 창의 크기를 변경하고, `close` 는 해당 창을 삭제합니다. 만약 해당 창이 파일에서 열려 있는 마지막 창이라면, `close` 를 실행하기 전에 먼저 해당 파일에 `D` 명령을 수행합니다. `Write` 는 파일에 대한 `w` 명령과 동일하며, 순전히 편의상 메뉴에 포함된 것입니다. 마지막으로, `~~sam~~` 은 명령어와 파일 이름 사이에 나타나는 메뉴 항목입니다. 이를 선택하면 sam 창이 현재 창으로 설정되어, 이후 입력하는 내용은 명령어로 해석됩니다.

그림 3. 3번 버튼의 메뉴. 왼쪽의 검은색 사각형은 스크롤 막대이며, 메뉴가 너무 길어져 다루기 어려워지는 것을 방지하기 위해 표시된 길이만큼만 제한되어 있습니다. `~~sam~~` 줄 위에는 명령어 목록이 있고, 그 아래는 `f` 명령어와 똑같은 방식으로 표시된 파일 목록이 있습니다.

sam이 `new`, `zerox` 또는 `reshape` 명령에 응답해서 창을 갱신하도록 요청할 때, 마우스 커서가 일반적인 화살표에서 작은 화살표가 달린 사각형 형태로 바뀝니다. 이 상태에서 마우스를 사용해서 한 모서리에서 3번 버튼을 누른 후 반대쪽 모서리에서 버튼을 놓음으로써 임의의 사각형을 지정할 수 있습니다. 좀 더 편리한 방법은 3번 버튼을 한 번 클릭하는 것인데, 그러면 sam은 커서를 포함하고 sam 창에 인접한 최대 크기의 직사각형을 생성합니다. sam 창을 화면 중앙에 배치하면, 사용자는 두 영역(위쪽 하나, 아래쪽 하나)을 정의해서, 서로 완전히 겹치는 창들을 번거로움 없이 쌓아 올릴 수 있습니다(그림 1 참조). 이 간단한 사용자 인터페이스 기법 덕분에 창 생성이 눈에 띄게 쉬워집니다.

잘라내기 및 붙여넣기 편집기는 본질적으로 Smalltalk-80 편집기와 동일합니다.11 화면에는 항상 ‘dot’의 텍스트가 강조 표시됩니다. 문자를 입력하면 dot이 해당 문자로 대체되고, dot은 해당 문자 뒤의 빈 문자열로 설정됩니다. 따라서 일반적인 입력으로 텍스트를 삽입할 수 있습니다. 버튼 1은 선택에 사용됩니다. 버튼을 누른 상태에서 마우스를 이동한 후 버튼을 놓으면, 버튼을 누른 지점과 놓은 지점 사이의 텍스트가 선택(dot에 설정)됩니다. 같은 지점에서 버튼을 누르고 놓으면 빈 문자열이 선택되는데, 이를 "클릭" 이라고 합니다. 빠르게 두 번 클릭(더블 클릭)하면 더 큰 객체를 선택합니다. 예를 들어, 단어 내에서 더블 클릭하면 해당 단어가 선택되고, 왼쪽 괄호 안쪽에서 더블 클릭하면 괄호 안에 포함된 텍스트가 선택됩니다(중첩된 괄호를 올바르게 처리함). 둥근 괄호, 따옴표 등도 마찬가지입니다. 더블 클릭 규칙은 프로그래머를 우선시 하는 경향을 반영합니다. 만약 sam이 워드 프로세싱에 중점을 더 두었다면, 더블 클릭은 아마 문장 같은 언어적인 구조를 선택했을 것입니다.

현재 창 밖에서 1번 버튼을 누르면, 지정한 창이 현재 창으로 설정됩니다. 이는 창과 파일을 전환하는 가장 쉬운 방법입니다.

2번 버튼을 누르면 편집 기능 메뉴가 표시됩니다(그림 4 참조). 이 기능들은 대부분 선택된 텍스트에 적용됩니다. `cut` 은 선택된 텍스트를 삭제하고 `snarf 버퍼` 라는 숨겨진 버퍼에 이를 저장하며, `paste` 는 선택된 텍스트를 snarf 버퍼의 내용으로 대체하고, `snarf` 는 선택된 텍스트를 snarf 버퍼로 복사하며, `look` 은 선택된 텍스트가 문자 그대로 나타나는 다음 위치를 앞으로 검색하고, `<mux>` 는 sam이 실행 중인 창 시스템과 snarf 버퍼를 교환합니다. 마지막으로, 가장 최근에 사용된 정규 표현식은 메뉴 항목으로 표시되어, 해당 표현식과 일치하는 다음 발생 위치를 앞으로 검색할 수 있습니다.

그림 4. 버튼 2의 메뉴. 맨 아래 항목은 가장 최근에 사용된 정규식을 추적하며, 이는 리터럴 텍스트일 수도 있습니다.

명령어 언어와 마우스 언어 간의 관계는 전적으로 ‘.’ 기호와 마우스 버튼 1로 선택한 텍스트가 동일하다는 점에 기인합니다. 예를 들어, C 서브루틴에서 일련의 변경을 수행하려면 서브루틴을 시작하는 왼쪽 중괄호를 더블 클릭해서 ‘dot’을 설정할 수 있으며, 이렇게 하면 명령어 언어에 대한 ‘dot’이 설정됩니다. 그런 다음 같은 창에 입력된 주소 지정 없는 명령어는 해당 함수의 시작 중괄호와 종료 중괄호 사이에 있는 텍스트에만 적용됩니다. 여기서 핵심은 원하는 대상을 선택한 다음, 메뉴 선택이든 직접 입력한 명령이든 상관없이 그 대상에 대해 무엇을 처리할지 지시하는 것입니다. 물론, 명령이 완료된 후에는 화면에 ‘dot’의 값이 강조 표시됩니다. 마우스 인터페이스와 명령 언어 간의 이런 관계는 설명하기는 다소 어색하지만, 실제로 사용해 보면 편리하고 심지어 자연스럽게 느껴집니다.
