GitHub Flavored Asciidoc (GFA)


이 Gist는 GitHub Flavored Asciidoc의 일부 의미론을 반영하기 위해 작성되었습니다. GitHub는 .adoc, .asc, .asciidoc 확장자를 가진 파일을 렌더링할 때 Asciidoctor를 안전 모드로 사용합니다. 이 기능은 표준 저장소뿐만 아니라 Gist에서도 작동합니다.


대부분의 사람들은 GitHub에서 문서를 작성할 때 마크다운을 사용하는 것 같습니다. 마크다운은 훌륭하고 사용하기 쉽지만, 저는 종종 Asciidoc의 추가적인 의미 체계가 정말 유용한 기술 문서나 교육 자료를 작성하곤 합니다.


# GitHub 전용 사용자 지정(GitHub-Specific customizations)

문서가 GitHub에서 렌더링되는지, 아니면 Asciidoctor나 유사한 도구를 사용해서 오프라인에서 렌더링되는지에 따라 설정을 조정해야 할 때가 종종 있습니다. 헤더에서 `ifdef` 전처리기 매크로를 간단히 사용하면 됩니다:

```
ifdef::env-github[]
:imagesdir: foo/
endif::[]
```

`ifdef` 와 `endif` 사이에 있는 모든 내용은 GitHub에서 렌더링될 때만 처리됩니다.



# 목차(Table of Contents)

종종 (이 문서처럼) 추가적인 구성이 필요한 긴 문서를 작성하게 됩니다. Asciidoc은 사용자가 지정한 제목 구조를 기반으로 목차(TOC)를 자동으로 생성해 줍니다. 이는 웹 콘텐츠나 PDF(오프라인에서 렌더링될 때)에 특히 유용합니다.

GitHub에서 목차를 사용하려면 다음과 같이 작성합니다.

```
:toc:
:toc-placement!:

다음은 서문 단락이지만, 사실 목차는 어디에나 배치할 수 있습니다! Lorem ipsum foo bar baz.

toc::[]
```

`:toc:` 지시어는 “`:toc:` 프로세서를 활성화하겠다” 는 것을 나타냅니다. `:toc-placement!:` 지시어는 GitHub에서 제대로 작동하지 않는 현재의 배치 전략을 무효화합니다. 이는 “목차가 배치될 위치를 직접 지정하겠다” 는 것을 의미합니다.

마지막으로, `toc::[]` 는 Asciidoctor에게 이 위치에서 문서 전체에 대한 목차를 렌더링하도록 지시합니다.



# 주의 사항(dmonitions)

주의 사항은 콘텐츠와 별도로 표시되는 편리한 텍스트 블록입니다. 이는 본문 흐름과 다소 어긋나지만 독자의 주의를 끌어야 할 내용을 설명할 때는 매우 유용합니다. `ifdef` 부분과 `:` 로 시작하는 나머지 줄들은 헤더에 포함시켜야 합니다.

전처리기 지시어 `ifdef` 는 GitHub 환경이 사용 중인지 확인합니다. 반대의 경우를 처리하려면 `ifndef` 를 사용해서 블록을 생성합니다. 이 문서의 헤더를 살펴보면 제가 이 문서를 어떻게 처리했는지 확인할 수 있습니다.

경고 문구에 아이콘을 조건부로 활성화하는 예시:

```
ifdef::env-github[]
:tip-caption: :bulb:
:note-caption: :information_source:
:important-caption: :heavy_exclamation_mark:
:caution-caption: :fire:
:warning-caption: :warning:
endif::[]

[NOTE]
====
참고 사항 예시.
Asciidoctor 마크업에서 gemoji 아이콘을 사용할 수 있습니다.
문서의 `tip-caption`, `note-caption`, `important-caption` 속성에 아이콘 이름을 할당합니다.
====

TIP: 잘 작동합니다!

IMPORTANT: Asciidoctor는 정말 훌륭합니다. 잊지 마세요!

CAUTION: GitHub 문서의 헤더에 `...-caption` 문서 속성을 추가하는 것을 잊지 마세요.

WARNING: Asciidoctor를 사용하지 않을 이유가 없습니다.
```

다음과 같이 표시됩니다:


ℹ️ | 참고 사항 예시입니다. Asciidoctor 마크업에서 gemoji 아이콘을 사용할 수 있습니다. 문서의 tip-caption, note-caption, important-caption 속성에 아이콘 이름을 지정합니다.
💡 | 작동하네요!
❗ | Asciidoctor는 정말 대단합니다. 잊지 마세요!
🔥 | GitHub에서 문서 헤더에 …​-caption 문서 속성을 추가하는 것을 잊지 마세요.
⚠️ | Asciidoctor를 사용하지 않을 이유가 없습니다.


# 이미지(Images)

이미지는 일반적인 이미지 구문을 사용하면 예상대로 작동합니다:

```
image::my_filename.png[]
```

절대 URL을 지정할 수도 있습니다:

```
image::https://avatars3.githubusercontent.com/u/3137042?v=3&s=200[]
```

하지만 주의할 점이 하나 있습니다. 이미지를 인라인으로 렌더링하려면 `:imagesdir:` 지시문에 절대 경로를 제공해야 합니다. GitHub는 이 경로가 이미지가 위치한 상위 디렉터리로 연결되는 전체 HTTPS 경로로 구성됩니다. 모든 이미지를 저장소에 업로드했다면, 이미지 중 하나의 원본 링크를 확인합니다. URL에서 디렉터리 부분만 선택해서 다음 위치에 입력합니다:

```
ifdef::env-github[]
:imagesdir: https://gist.githubusercontent.com/path/to/gist/revision/dir/with/all/images
endif::[]
```

ℹ️ | Gist를 작성할 때는 모든 파일이 하나의 평면 디렉터리에 있어야 합니다. 이미지를 업로드하려면 먼저 Gist에 파일을 생성한 다음 클론해야 합니다. 로컬에 클론한 후에는 하위 디렉터리를 생성하지 않는 한 원하는 내용을 무엇이든 추가할 수 있습니다.



# 콜아웃(Callouts)

콜아웃은 코드를 설명하는 훌륭한 방법이며, 사실 제가 asciidoc을 살펴보게 된 두 가지 주요 이유 중 하나입니다(다른 하나는 admonition 블록입니다). Asciidoctor는 코드에 번호를 삽입하며, 이 번호를 코드 목록 뒤에서 참조할 수 있습니다.

```
[source]
 ----
\ifdef::env-github[] <1> (1)
:imagesdir: https://gist.githubusercontent.com/path/to/gist/revision/dir/with/all/images
endif::[]
\ifndef::env-github[] <2>
:imagesdir: ./
endif::[]
 ----
<1> `ifdef` 를 사용해서 온라인 렌더링에 맞게 사용자 정의하기 (2)
<2> `ifndef`를 사용해서 오프라인 환경에 맞게 사용자 정의합니다
```

1. 리스트 본문의 설명은 아이콘 형태로 표시되거나 괄호 안에 포함됩니다.

1. 아래 블록을 사용하면 코드 예제를 방해하지 않으면서 설명할 수 있습니다
